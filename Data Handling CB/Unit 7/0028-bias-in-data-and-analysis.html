Bias in Data and Analysis

Lesson 2 introduced sampling bias; Lesson 17 showed it can hide behind a small margin of error. This lesson widens the lens: bias doesn't only enter through how data is collected — it can enter at almost every stage this course has covered.

← Lesson 27 Lesson 29 → Contents Glossary →

Back in Lesson 2: sampling bias is a systematic mismatch between a sample and the population it's meant to represent, arising from the collection method itself. This lesson returns to that idea one more time, in full — not just as a statistical caveat, but as one of several places bias enters an analysis, several of which this course has already quietly touched.

Where bias enters, stage by stage

Bias isn't only a collection-stage problem Collection — Lesson 2's sampling bias: a landline-only poll systematically excludes people without landlines. Cleaning — Unit 5's judgment calls (which rows counted as duplicates, which missing values were dropped) can introduce bias if those judgment calls aren't applied evenly across groups — for example, if incomplete records are disproportionately common for one demographic and are dropped rather than flagged. Analysis — choosing which variables to include in a regression (Lesson 18), or which segments to highlight in a chart (Unit 6), can emphasize a misleading pattern even from unbiased source data, especially if a confounding variable (Lesson 16) correlated with a protected characteristic is never checked. Historical bias — a dataset can be a completely accurate record of a biased past process (e.g. historical hiring data reflecting decades of discriminatory hiring practice), meaning any analysis built directly on it, including automated systems trained on it, will reproduce that same historical pattern going forward unless it's explicitly corrected for.
Why this lesson revisits Lesson 2's sampling bias specifically, one more time Lesson 17 already showed that sampling bias is invisible to a margin of error calculation — but that lesson's point was narrowly statistical: how confident can you be in a number. This lesson's point is broader and more consequential: an analysis built on a systematically unrepresentative sample doesn't just produce an imprecise number, it can shape a real decision — a product feature, a resource allocation, a hiring model — in a way that structurally disadvantages whichever group the sample happened to underrepresent. The same root cause from Lesson 2 (a non-random subset standing in for the whole) resurfaces here with a different, higher-stakes consequence: not "how wrong is my estimate," but "who does this decision actually leave out or harm."
Worked example A retail company trains a model to predict "likely to churn" customers using five years of historical customer-service data. That data turns out to have been collected mostly from customers who called a support line in English, systematically underrepresenting customers who primarily used a different language and a different (unrecorded) support channel. The resulting model is less accurate for that underrepresented group — not because of anything about the group itself, but because Lesson 2's sampling bias was baked into the training data from the start, and nothing in the modeling process itself corrects for it.
