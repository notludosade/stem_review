Unit 1 — Foundations of Data

Qualitative vs. quantitative data

Qualitative data describes qualities or categories (a color, a comment); quantitative data is inherently numeric and measurable (a height, a count).

Levels of measurement

Nominal (unordered categories), ordinal (ordered categories with no fixed distance), interval (fixed distance, no true zero), and ratio (fixed distance with a true zero) — determining which operations and statistics validly apply to a variable.

Structured, semi-structured, unstructured data

Structured data fits neatly into rows and columns; semi-structured data has tags or markers but no fixed schema (like JSON); unstructured data has no inherent tabular organization (like free text or images).

Sampling bias

A systematic mismatch between a sample and the population it's meant to represent, arising from the collection method itself — e.g. a landline-only poll excluding people without landlines.

Primary vs. secondary data

Primary data is collected first-hand for the purpose at hand (a survey you run yourself); secondary data was collected by someone else for a different original purpose and reused.

Data quality dimensions

Accuracy (is it correct), completeness (is anything missing), consistency (does it agree with itself across records), timeliness (is it current enough to be useful), and validity (does it conform to the expected format or rules).

Unit 2 — Spreadsheet Foundations

Relative, absolute, and mixed reference

A relative reference shifts when copied to a new cell; an absolute reference (with $) stays fixed; a mixed reference locks only the row or only the column.

Lookup / join (in a spreadsheet)

Pulling a matching value from one table into another based on a shared key column — the spreadsheet-level version of a database join.

Pivot table

A tool for summarizing a large table by dragging fields into Rows, Columns, Values, and Filters — recomputing aggregates instantly as the field layout changes.

Data validation

Rules applied at the point of entry (like a dropdown list) that prevent invalid or inconsistent values from being entered in the first place, rather than requiring cleanup later.

Unit 3 — Databases and SQL

Relational database / relational model

Data organized into tables (rows and columns) linked to one another by shared key values, rather than duplicated across one flat file.

Primary key / foreign key

A primary key uniquely identifies each row in its own table; a foreign key is a column in one table that references a primary key in another, forming the link between them.

SELECT / WHERE

SELECT specifies which columns to return from a query; WHERE filters which rows are included, evaluated against each row before any aggregation happens.

INNER JOIN / LEFT JOIN

An INNER JOIN returns only rows with a match in both tables; a LEFT JOIN keeps every row from the left table, filling in NULLs where no match exists on the right.

GROUP BY / HAVING

GROUP BY collapses rows sharing a value into aggregated groups; HAVING filters those resulting groups, whereas WHERE can only filter individual rows before grouping happens.

Subquery / CTE

A subquery is a query nested inside another; a CTE (common table expression) names that nested query up front, making a multi-step query more readable.

Unit 4 — Statistics for Data Handling

Mean, median, mode

Three measures of a typical value: the arithmetic average, the middle value when sorted, and the most frequent value — each behaving differently under skew and outliers.

Standard deviation / IQR

Standard deviation measures typical spread around the mean; the interquartile range (IQR) measures the spread of the middle 50% of values and is more resistant to outliers.

Distribution / skew

A distribution describes how values are spread across their range; a skewed distribution has a longer tail on one side (right-skewed or left-skewed), unlike a symmetric normal distribution.

Correlation vs. causation

Correlation means two variables move together; causation means one variable's change actually produces the other's — correlation alone never establishes causation.

Confounding variable

A third factor that influences both variables in an observed correlation, creating the appearance of a direct relationship between them where none may exist.

Confidence interval / margin of error

A confidence interval gives a range likely to contain the true population value; the margin of error is the interval's half-width — neither one detects or corrects for sampling bias.

Simple linear regression / R-squared

Simple linear regression fits a straight line describing how one variable predicts another; R-squared measures how much of the outcome's variation that line actually explains.

Unit 5 — Data Cleaning & Preparation

MCAR / MAR / MNAR

Frameworks for why data is missing: completely at random (no pattern), at random (related to other observed variables), or not at random (related to the missing value itself) — the last being the most dangerous to ignore.

Imputation

Filling in a missing value with an estimate (such as the mean or median), as distinct from simply deleting the row or flagging it as missing.

Outlier (IQR rule)

A value falling more than 1.5×IQR beyond the first or third quartile — a signal to investigate, not an automatic instruction to delete; may be a data-entry error or a genuine extreme value.

Trimmed mean

An average computed after removing a fixed percentage of the most extreme values, reducing the influence of genuine outliers without discarding the row entirely.

Fuzzy duplicate / deduplication

A fuzzy duplicate refers to the same real-world entity recorded with slightly different values (e.g. "NY" vs. "New York"); deduplication is the process of identifying and merging both exact and fuzzy duplicates.

Standardization

Making values that mean the same thing look the same across a dataset — consistent case, spelling, formatting, and category names.

Cleaning log

A written record of each cleaning judgment call made and why, so the decisions behind an analysis-ready dataset stay checkable rather than invisible.

Unit 6 — Data Visualization & Storytelling

Chart-type matching

Choosing a chart based on the question being asked: bar for comparison, line for trend, stacked bar or pie for part-to-whole, scatter plot for relationship, histogram for distribution.

Truncated axis / dual axes

A truncated y-axis exaggerates apparent differences by not starting at zero; dual axes can imply a relationship between two series that isn't really there by scaling each independently.

Data-ink ratio

The proportion of a chart's ink devoted to actual data versus decoration — maximizing it means cutting clutter that doesn't convey information.

Context → Finding → Implication

A data-story structure: why the question matters (Context), what the data actually shows (Finding), and what should be done or believed as a result (Implication) — kept honest by not overstating causation in the Implication step.

Unit 7 — Data Ethics, Privacy & Governance

PII (personally identifiable information)

Data that can identify a specific individual, either directly (a name, an ID number) or indirectly through quasi-identifiers that become identifying when combined (birthdate, zip code, gender).

Anonymization (removal / masking / aggregation / generalization)

Techniques for reducing re-identification risk: deleting identifiers, obscuring part of a value, rolling values up into groups, or replacing a specific value with a broader category.

Historical bias

Bias present even in perfectly accurate data, because the data faithfully reflects a discriminatory past process — meaning analysis built on it reproduces that same pattern going forward.

GDPR / CCPA / HIPAA

Major data-protection frameworks: GDPR (EU personal data and the right to be forgotten), CCPA (California residents' right to know and opt out of data sale), and HIPAA (U.S. health information, including its de-identification standard).

Data governance

An organization's internal policies for who can access data, how long it's retained, how it's classified, and how compliance with external regulation is actually implemented day to day.

Unit 8 — Data Careers & Capstone

Data Analyst / Data Engineer / Data Scientist / BI Analyst

Four common data roles distinguished by which parts of the pipeline they focus on: querying and reporting, building pipelines and infrastructure, statistical/ML modeling, and dashboard-centric reporting, respectively — with blurry, non-standardized boundaries in practice.

Data portfolio

A collection of complete, end-to-end projects showing an entire pipeline — raw data, cleaning decisions, queries, statistical reasoning, and final chart — not just a polished final result.

Case-study interview

An interview format presenting a realistic business scenario and dataset, evaluating a candidate's live reasoning process — clarifying questions, structured approach, and confounder-checking — rather than one exact correct answer.
