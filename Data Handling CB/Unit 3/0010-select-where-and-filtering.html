SELECT, WHERE, and Filtering

SQL — Structured Query Language — is how you actually ask a database a question. This lesson covers the two clauses that answer "which columns" and "which rows": SELECT and WHERE.

← Lesson 9 Lesson 11 → Contents Glossary →

Every SQL query used in this course runs against standard, portable SQL — the same core syntax works essentially unchanged across PostgreSQL, MySQL, SQLite, and most other relational databases.

SELECT: choosing columns

Syntax SELECT column1, column2 FROM table_name; returns the named columns from every row of the table. SELECT * FROM table_name; returns every column. Example: SELECT name, region FROM customers; returns just the name and region columns, from every row in the customers table.

WHERE: filtering rows

Syntax SELECT columns FROM table_name WHERE condition; returns only rows matching condition. Example: SELECT name FROM customers WHERE region = 'West'; returns names only for customers in the West region. Conditions can use =, <> (not equal), <, >, <=, >=, and can be combined with AND / OR: WHERE region = 'West' AND order_total > 100.

ORDER BY and LIMIT

Syntax ORDER BY column sorts the results (add DESC for descending; ascending is the default). LIMIT n returns only the first n rows. Example: SELECT name, order_total FROM orders ORDER BY order_total DESC LIMIT 5; returns the 5 highest order totals, largest first.

Query execution order (conceptually)

Why the clause order in a query doesn't match the order SQL evaluates it A query is written SELECT ... FROM ... WHERE ... ORDER BY ..., but SQL doesn't evaluate it top to bottom. Conceptually, it first figures out FROM (which table), then applies WHERE (filtering rows), and only then applies SELECT (choosing which columns of the surviving rows to show), with ORDER BY and LIMIT applied last, after filtering. This is why a condition in WHERE can reference a column that isn't even listed in SELECT — filtering happens on the full row, before column selection narrows what's displayed.
Worked example SELECT name, order_total FROM orders WHERE region = 'West' AND order_total > 200 ORDER BY order_total DESC LIMIT 3; — reading it in evaluation order: start with the orders table, keep only rows where region is West and order_total exceeds 200, then show just the name and order_total columns of those surviving rows, sorted largest-total-first, keeping only the top 3.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the difference between what SELECT and WHERE each control in a query?

Column choice (SELECT) and row filtering (WHERE) are two separate, independent jobs in a query.

2. Why can a WHERE condition reference a column that isn't listed in the SELECT clause at all?

Filtering happens against the full row before column selection narrows the display, which is exactly why WHERE isn't limited to SELECT's chosen columns.

3. What does ORDER BY order_total DESC LIMIT 3 return?

DESC sorts largest to smallest, and LIMIT 3 keeps only the first 3 of that sorted result.

4. Fill in the blank: the SQL clause used to filter which rows are returned based on a condition is ___.

WHERE is the clause that restricts a query's results to rows matching a specific condition.

5. Fill in the blank: the SQL clause used to restrict a query's results to only the first n rows is ___.

LIMIT caps the number of rows returned, typically paired with ORDER BY to get a meaningful "top N" result.
