Subqueries and CTEs

Some questions need the answer to one query before you can even write the next one. Subqueries and CTEs are how SQL builds a query out of smaller queries, closing out this unit's core toolkit.

← Lesson 12 Lesson 14 → Contents Glossary →

Consider: "which customers placed an order with a total above the overall average order total?" You need the overall average first, then compare each customer's orders against it — one query nested inside another.

Subqueries

Definition A subquery is a query nested inside another query, usually in parentheses. SELECT name FROM orders WHERE order_total > (SELECT AVG(order_total) FROM orders); — the parenthesized inner query computes one number (the overall average), and the outer query then filters against it. Subqueries can also appear in place of a table, in the FROM clause, when you need to query the result of another query.

Common Table Expressions (CTEs)

Syntax WITH regional_totals AS (SELECT region, SUM(order_total) AS total FROM orders GROUP BY region) SELECT * FROM regional_totals WHERE total > 10000; — a CTE, introduced with WITH, names a subquery's result (regional_totals) so the main query can refer to it like a regular table. Functionally, a CTE and an equivalent subquery-in-FROM often produce the identical result — the difference is readability: naming the intermediate result and giving it a plain-English label makes a multi-step query easy to read top to bottom, rather than parsing inward through nested parentheses.
Why CTEs are usually preferred once a query has more than one step A deeply nested subquery — a subquery inside a subquery inside a subquery — becomes difficult to read in the same way Lesson 5's deeply nested IF statements did: correct, but hard to verify by eye and easy to break with one misplaced parenthesis. A CTE breaks a multi-step calculation into named, sequential pieces, each independently readable, closely mirroring how you'd actually explain the logic out loud: "first compute regional totals, then filter to the big ones."
Worked example: a query built from Unit 3's whole toolkit WITH customer_spend AS (SELECT customers.region, SUM(orders.order_total) AS total_spend FROM orders INNER JOIN customers ON orders.customer_id = customers.customer_id GROUP BY customers.region) SELECT region, total_spend FROM customer_spend WHERE total_spend > (SELECT AVG(total_spend) FROM customer_spend); — a CTE joins and groups to get each region's total spend, then the outer query keeps only regions spending above the average of those regional totals, using a subquery to compute that average. This single query uses JOIN (Lesson 11), GROUP BY (Lesson 12), a CTE, and a subquery together.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a subquery?

A subquery's defining trait is being nested inside another query, with the outer query consuming its result.

2. What is the main practical benefit of a CTE (WITH clause) over an equivalent nested subquery?

The functional result is often identical — the real win is readability from naming each step.

3. Why are deeply nested subqueries compared to Lesson 5's deeply nested IF statements?

Both are readability/fragility concerns at depth, not correctness limits — which is why both lessons point toward a more legible alternative (lookup tables, CTEs) once nesting grows.

4. Fill in the blank: a named, reusable subquery result introduced with a WITH clause is called a ___ (an abbreviation for Common Table Expression).

CTE is the standard abbreviation for a WITH-clause-defined, named intermediate query result.

5. Fill in the blank: the SQL keyword used to introduce a Common Table Expression is ___.

WITH is the keyword that opens a CTE definition before the main query that uses it.
