1. A Books table needs a primary key, and includes columns ISBN, Title, Author, and Publication Year. Which column is the right choice?

A primary key must uniquely identify every row and never be blank — ISBN is the only column here guaranteed to satisfy both.

2. Fill in the blank: storing a Publisher ID in a Books table, instead of repeating each publisher's full name and address on every book row, is an example of ___ — splitting data into linked tables so any fact is stored in exactly one place.

Normalization is the principle behind splitting data this way, so updating a publisher's details only ever requires changing one row.

3. A table employees has columns emp_id, department, salary. Rows: (1, Sales, 55000), (2, IT, 72000), (3, Sales, 61000), (4, Sales, 40000). What does SELECT emp_id FROM employees WHERE department = 'Sales' AND salary > 50000; return?

WHERE filters on department = Sales and salary > 50000 first — emp 4's salary of 40000 fails that second condition — then SELECT displays only emp_id from the two surviving rows.

4. Fill in the blank: the SQL clause used to sort a query's results by a chosen column, with DESC added for descending order, is ___.

ORDER BY sorts the result set; ascending is the default unless DESC is added.

5. In SELECT emp_id FROM employees WHERE salary > 50000 ORDER BY salary DESC;, which best describes the conceptual evaluation order?

Filtering on the full row happens before column selection narrows the display, which is exactly why WHERE can reference a column that SELECT never displays.

6. students: (201, Maya), (202, Liam), (203, Noah). enrollments: (e1, student_id 201), (e2, student_id 202), (e3, student_id 777 — no such student). Answer both parts:

(a) An INNER JOIN of enrollments to students on student_id would exclude which enrollment?

(b) A LEFT JOIN from students to enrollments would still include Noah (student_id 203) in the result, with the enrollment columns filled in as what?

INNER JOIN silently drops rows with no match on either side — e3's invalid student_id has no match, so it's excluded. LEFT JOIN keeps every row from the left table regardless, filling NULL where no match exists.

7. A table sales: (s1, North, 100), (s2, South, 150), (s3, North, 300), (s4, North, 50), (s5, South, 200). SELECT region, COUNT(*) AS n, SUM(amount) AS total_sum FROM sales GROUP BY region;. Answer both parts:

(a) How many rows fall into the North group?

(b) Fill in the blank: SUM(amount) for the South group equals ___.

North has three rows (100, 300, 50). South has two rows (150 and 200), summing to 350. GROUP BY collapses each region into one row with its own aggregate values.

8. A query needs to keep only regions whose total sales exceed $400. Answer both parts:

(a) Which clause should filter on the condition SUM(amount) > 400, applied after grouping?

(b) Why can't the other clause do this instead?

WHERE filters raw rows before GROUP BY computes any aggregate, so it has nothing to compare a summed total against — that's exactly what HAVING is for.

9. Using the same sales table from question 7 (amounts 100, 150, 300, 50, 200 — average 160): SELECT sale_id FROM sales WHERE amount > (SELECT AVG(amount) FROM sales);. Answer both parts:

(a) What does the subquery (SELECT AVG(amount) FROM sales) compute?

(b) Which sale_ids does the outer query return?

The subquery computes the overall average (160); the outer query keeps only rows exceeding it — 300 and 200 both exceed 160, while 100, 150, and 50 don't.

10. A multi-step query names an intermediate result with WITH regional_totals AS (...) before its main SELECT. Answer both parts:

(a) What is the main practical benefit of writing this as a CTE instead of an equivalent nested subquery?

(b) Fill in the blank: the SQL keyword that introduces this named result is ___.

A CTE (introduced with WITH) and an equivalent subquery often produce the identical result — the real advantage is readability from naming each step.
