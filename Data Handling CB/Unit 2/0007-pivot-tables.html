Pivot Tables

A thousand-row order log is unreadable by eye. A pivot table turns it into a handful of summary numbers — total sales by region, by month, by product — in seconds, without writing a single SUMIF.

← Lesson 6 Lesson 8 → Contents Glossary →

Lesson 5's SUMIFS can already answer "total sales in the West region." But answering "total sales broken down by every region, and by every month, all at once" with SUMIFS means writing one formula per region-month combination. A pivot table answers that whole grid in one step.

What a pivot table is

Definition A pivot table is a tool that automatically groups and summarizes rows of raw data into a compact table, without altering the original data. You choose which column(s) become row groupings, which become column groupings, and which numeric column gets aggregated (summed, averaged, counted) inside the resulting grid.

The four building blocks

Structure Every pivot table is built from four choices: Rows (a column whose distinct values become row labels, e.g. Region), Columns (a column whose distinct values become column labels, e.g. Month), Values (the numeric column to aggregate, and how — sum, average, count, e.g. Sum of Order Total), and Filters (a column used to restrict the whole table to a subset, e.g. only orders where Status = "Completed"). Dragging "Region" into Rows and "Order Total" into Values (summed) instantly produces a table of total sales per region — the same answer as writing a separate SUMIF per region, generated automatically.
Worked example An orders sheet has one row per order: Region, Month, Product Category, Order Total. Dragging Region into Rows, Month into Columns, and Order Total into Values (Sum) produces a grid: each row is a region, each column is a month, and each cell is that region's total sales in that month — a full region-by-month breakdown built in seconds, with no formulas written at all.
Why pivot tables don't touch the original data A pivot table is a separate, generated view — it reads from the raw data but never modifies it, and it can be rebuilt instantly from scratch if the underlying data changes (most spreadsheet tools have a "refresh" action for exactly this). This matters because it means experimenting with different groupings costs nothing: dragging Product Category into Rows instead of Region, to see the same totals sliced a different way, doesn't risk damaging the source data the way editing formulas directly into the raw sheet would.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does a pivot table do to the original underlying data?

The pivot table is a generated view built from the data, not an edit to it — which is exactly why it can be freely rebuilt or reconfigured.

2. In a pivot table with Region in Rows, Month in Columns, and Sum of Order Total in Values, what does each individual cell in the grid represent?

Each cell aggregates exactly the rows matching both its row label and column label — that intersection is the whole point of the Rows × Columns grid.

3. What role does the Filters area of a pivot table play?

Filters narrow the scope of the whole summary without touching Rows, Columns, or Values — and without altering the source data.

4. Fill in the blank: the pivot table area where you choose a numeric column and an aggregation method (sum, average, count) is called ___.

Values is where the actual number being aggregated, and how, is chosen — distinct from Rows and Columns, which only choose groupings.

5. Fill in the blank: a tool that automatically groups and summarizes raw data rows into a compact grid, without altering the original data, is called a ___.

The defining traits are automatic grouping/summarizing and leaving the source data untouched.
