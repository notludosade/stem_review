Data Validation & Clean Input

Lesson 3 named consistency and validity as data quality dimensions. This lesson gives you the spreadsheet tools that prevent those problems at the moment data is entered, rather than needing to fix them afterward.

← Lesson 7 Lesson 9 → Contents Glossary →

Units 5 covers cleaning data that's already messy. This lesson is about the cheaper alternative: stopping bad data from entering the sheet in the first place, using the spreadsheet's own built-in controls.

Dropdown lists (data validation from a list)

Tool Restricting a column to a fixed set of allowed values — e.g. Region can only be "North," "South," "East," or "West" — via a dropdown eliminates the "USA" vs. "United States" inconsistency problem from Lesson 3 entirely: if the only options are the correct ones, a typo or inconsistent variant literally cannot be typed in.

Validation rules

Tool Beyond fixed lists, validation rules can require a cell to be a number within a range (e.g. a percentage between 0 and 100), a date, or text matching a specific pattern. Entering a value outside the rule triggers a warning or an outright rejection, depending on how strictly the rule is configured.

Conditional formatting as a QA signal

Tool Conditional formatting changes a cell's appearance (color, bold, icon) based on a rule — e.g. highlighting any "Order Total" cell that's negative, or any date more than a year old. It doesn't prevent bad data the way validation does, but it makes existing problems visually obvious at a glance across thousands of rows, functioning as an ongoing quality check rather than a one-time entry gate.
Worked example A shared order-entry sheet has a "Status" column. Without validation, five different people might type "done," "Done," "complete," "Complete," and "COMPLETE" for the same status — five inconsistent values Lesson 3 would flag as a consistency problem. Restricting the column to a dropdown with exactly "Pending," "Completed," and "Cancelled" makes that inconsistency structurally impossible, at the moment of entry, for every future row.
Why prevention beats cleanup Fixing inconsistent data after the fact (the subject of Unit 5) requires first noticing the problem, then deciding which variant is "correct," then finding and correcting every instance — work that grows with every row already entered. Validation at entry time costs a few minutes to set up once and then prevents the problem for every row entered afterward, at zero ongoing cost. Neither replaces the other: validation only controls what's typed going forward, so cleanup is still needed for a sheet's existing history, but a sheet with validation from day one needs far less of it.

Check your recall

No peeking back up — answer from memory first, then check.

1. How does a dropdown-based validation rule eliminate the "USA" vs. "United States" inconsistency problem?

A dropdown limits the possible inputs to exactly the approved list, making the inconsistent variant structurally impossible to enter.

2. What is the key functional difference between data validation and conditional formatting?

Validation is a gate at entry time; conditional formatting is a visual signal applied after data already exists in the sheet.

3. Why doesn't validation eliminate the need for the cleanup techniques taught in Unit 5?

Validation is forward-looking only — a sheet's pre-existing rows still need the cleanup techniques Unit 5 covers.

4. Fill in the blank: restricting a column's entries to a fixed set of allowed values, so a user selects rather than types, is commonly implemented as a ___ list.

A dropdown list is the standard mechanism for restricting entry to a known set of valid values.

5. Fill in the blank: changing a cell's visual appearance based on a rule (e.g. highlighting negative order totals), used as an ongoing quality check rather than a prevention gate, is called ___.

Conditional formatting flags existing problems visually; it doesn't prevent entry the way validation does.
