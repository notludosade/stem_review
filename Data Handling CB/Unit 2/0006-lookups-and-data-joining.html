Lookups and Data Joining in Spreadsheets

Real data rarely lives in one table. This lesson teaches the spreadsheet functions that pull matching information from a second table — the same operation Unit 3 will teach again, in a different tool, called a join.

← Lesson 5 Lesson 7 → Contents Glossary →

Suppose you have an orders sheet with a customer ID in every row, and a separate customers sheet with each customer's name and region next to their ID. To add the customer's name to the orders sheet, you need to look up each order's customer ID in the customers sheet and pull back the matching name. That's a lookup.

VLOOKUP

Function =VLOOKUP(lookup_value, table_array, col_index, [FALSE]) searches for lookup_value in the first column of table_array, then returns the value from col_index columns over in that same row. Example: =VLOOKUP(A2, Customers!A:C, 2, FALSE) looks up the customer ID in cell A2 within the Customers sheet's column A, and returns the matching value from column B (the 2nd column of the range). The final FALSE argument requests an exact match — leaving it off risks a wrong, approximate match.
VLOOKUP's real limitation VLOOKUP only searches the first column of its range and can only look rightward from there. If the ID you're searching by isn't in the leftmost column of the lookup table, VLOOKUP simply can't find it — you'd have to rearrange the source sheet, which isn't always possible or safe.

INDEX-MATCH

Functions =MATCH(lookup_value, lookup_array, 0) returns the position of a value within a range (the 0 requests an exact match). =INDEX(array, row_num) returns the value at a given position within a range. Combined — =INDEX(Customers!B:B, MATCH(A2, Customers!A:A, 0)) — this finds where the ID matches in column A, then returns the corresponding value from column B, regardless of which side of which column A is on. INDEX-MATCH fixes VLOOKUP's directionality limitation at the cost of being two functions instead of one.

XLOOKUP

Function =XLOOKUP(lookup_value, lookup_array, return_array) — e.g. =XLOOKUP(A2, Customers!A:A, Customers!B:B) — is a newer function (available in current Excel and Google Sheets) that does what INDEX-MATCH does in one call, searches in either direction, and defaults to an exact match without needing an extra argument. Where available, it's generally the cleanest choice; VLOOKUP and INDEX-MATCH remain essential to recognize since they appear constantly in existing spreadsheets you didn't build yourself.
Worked example: joining two tables by a shared key Orders sheet: column A = Customer ID, column B = Order Total. Customers sheet: column A = Customer ID, column B = Customer Name, column C = Region. To add the customer's region onto each order row: =XLOOKUP(A2, Customers!A:A, Customers!C:C) in a new column C of the Orders sheet, then copy down. Every order row now carries its customer's region, pulled from a completely separate table — matched purely by the shared Customer ID column that exists in both.
This is the same operation as a SQL join What just happened — combining two tables by matching a shared key column — is exactly what Unit 3 will call a join, done in a database instead of a spreadsheet. The shared Customer ID plays the same role a lookup key plays here. Lesson 11 will return to this exact orders/customers example when introducing SQL's JOIN syntax — same underlying operation, different tool, worth recognizing as the same idea rather than two unrelated skills.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is VLOOKUP's main limitation compared to INDEX-MATCH or XLOOKUP?

VLOOKUP's rightward-only, leftmost-column search is exactly the constraint INDEX-MATCH and XLOOKUP were built to remove.

2. In INDEX-MATCH, what does the MATCH function return?

MATCH only finds the position; INDEX is what actually pulls the value from that position in a different range.

3. Why is joining two spreadsheet tables with a lookup function described as "the same operation" as a SQL join?

The underlying idea — match rows across two tables using a shared key — is identical; only the tool and syntax differ, which is exactly why Lesson 11 revisits this same example.

4. Fill in the blank: the newer function that combines INDEX-MATCH's flexibility into a single call, searching in either direction with an exact match by default, is called ___.

XLOOKUP was designed specifically to remove VLOOKUP's directionality limit without needing two nested functions.

5. Fill in the blank: the SQL term (introduced in Unit 3) for combining two tables by matching rows on a shared key column, the same operation a spreadsheet lookup performs, is called a ___.

A join is the database term for exactly the same table-combining idea a lookup function performs in a spreadsheet.
