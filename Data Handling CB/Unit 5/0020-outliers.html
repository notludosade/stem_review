Outliers

Lesson 14 showed the mean bending toward one CEO's $2M salary. This lesson is about the values that cause that bending in the first place — how to find them, and the harder question of what to do once you have.

← Lesson 19 Lesson 21 → Contents Glossary →

An outlier is a value that lies unusually far from the rest of a dataset. Lesson 14's CEO salary was an outlier by definition — but notice that "unusually far" is doing a lot of work in that sentence, and pinning it down precisely is the first real task.

Detecting outliers

Two common rules IQR rule: using Lesson 14's interquartile range (IQR = Q3 − Q1), flag any value below Q1 − 1.5×IQR or above Q3 + 1.5×IQR as an outlier — a rule built on the spread measure that, unlike range, resists distortion by extreme values in the first place. Standard-deviation rule: flag any value more than roughly 2 or 3 standard deviations from the mean — this works well for roughly normal distributions (Lesson 15) but is less reliable on skewed data, since a skewed distribution's own mean and standard deviation are already pulled by the same extreme values you're trying to detect.

Outlier or error?

Why the very first question is never "should I remove this?" An extreme value has two very different possible origins: it might be a data-entry or measurement error (a height recorded as "512" instead of "5'12\""... actually "5.12" meant as feet-inches, or a age of "999"), or it might be a genuine, correctly recorded extreme value (a real CEO's real $2M salary, a real once-in-a-decade weather event). These demand opposite treatment. An error should be corrected or removed — it isn't real information. A genuine extreme value is real information, and removing it just because it's inconvenient for a calculation is a way of quietly changing what question you're actually answering (see the worked example below). The detection rules above only flag "unusual" — they cannot tell you which of the two you're looking at. That judgment call requires looking at the specific data point in context, not just running a formula.
What to do once you've judged which kind it is If it's an error and the true value is knowable, correct it. If it's an error and the true value isn't recoverable, treat it like Lesson 19's missing data (delete or impute). If it's a genuine extreme value, keep it in the full dataset, but consider reporting a robust summary statistic alongside the mean (Lesson 14's median, or a trimmed mean that discards a fixed percentage from each end) so a reader isn't misled by one data point's outsized pull — and never silently drop a real value just because it makes the average look worse.
Worked example A company's per-employee training-hours dataset includes one entry of "4,000 hours" in a year — impossible for one employee (that's more hours than exist in a year at typical working schedules), almost certainly a data-entry error (likely minutes, not hours, or a decimal-point slip). This should be corrected or flagged, not left in an average. Contrast: the same dataset's highest *real* value, a training-intensive new hire who logged 400 hours, is unusual but plausible — it stays in the dataset, though the summary might report the median alongside the mean so that one number doesn't overstate the "typical" employee's training load.

Check your recall

No peeking back up — answer from memory first, then check.

1. Using the IQR rule, a value is flagged as an outlier when it falls below or above what threshold?

The 1.5×IQR rule builds directly on the interquartile range from Lesson 14, a spread measure that resists distortion by extreme values.

2. Why is the very first question about a detected outlier never simply "should I remove this?"

Distinguishing error from genuine extreme value is a judgment call requiring context, not something the detection formula itself resolves.

3. Why is the standard-deviation rule for outlier detection less reliable on a skewed distribution (Lesson 15) than on a roughly normal one?

The IQR rule is generally preferred for skewed data precisely because quartile-based spread resists this same distortion.

4. Fill in the blank: the outlier-detection method that flags values beyond 1.5 times the ___ below Q1 or above Q3 is generally preferred for skewed data.

The IQR rule resists the same distortion that skew introduces into the mean and standard deviation.

5. Fill in the blank: an average computed after discarding a fixed percentage of the most extreme values from each end of the sorted data is called a ___.

A trimmed mean is a robust alternative summary statistic that reduces (without fully removing) the influence of extreme values.
