1. A "delivery date" field has several rows containing "01/01/1900" as a placeholder, standing in for a date that was never actually recorded. Why is this more dangerous than a true blank cell?

A blank is at least recognizable as missing; a sentinel value like "01/01/1900" hides in plain sight as a plausible-looking date.

2. Fill in the blank: older respondents in a digital-literacy survey are more likely to skip an optional question, but conditional on age, whether they skip isn't related to what their actual answer would have been. This category of missingness is abbreviated ___.

MAR (Missing At Random) describes missingness related to something else observed — here, age — but not to the missing value itself.

3. A dataset has Q1 = 50 and Q3 = 90. Using the 1.5×IQR rule, which of these values would be flagged as an outlier?

IQR = 90 − 50 = 40, so 1.5×IQR = 60. The upper threshold is 90 + 60 = 150. Only 160 exceeds that threshold.

4. A customer list has "Maria Garcia, 555-201-4488" in one row and "M. Garcia, 5552014488" in another, referring to the same real person with a shortened name and stripped formatting. What is this called?

A fuzzy duplicate refers to the same real-world entity but is recorded slightly differently, so it can't be caught by a simple equality check the way an exact duplicate can.

5. Fill in the blank: documenting each data-cleaning decision — what changed, why, and what rule was applied — so someone else can trust and reproduce the result, means keeping a ___.

A cleaning log is what turns a cleaned dataset back into something someone else can trust, question, and reproduce.

6. A customer database is missing a "signup date" value for 2% of rows, and this pattern appears essentially random (MCAR — unrelated to any observed or unobserved value). Answer both parts:

(a) Since this is MCAR, which strategy is safest here?

(b) If instead the blanks were concentrated among customers who signed up through one specific referral partner (MAR), what risk would dropping those rows introduce?

Dropping rows is safe only when missingness is unrelated to any pattern (MCAR); once missingness relates to something observable like referral source (MAR), dropping rows quietly distorts the remaining data.

7. A website's response-time data is right-skewed, with most requests clustered near 2 seconds but a long tail of much slower requests. Answer both parts:

(a) Why is the standard-deviation outlier rule less reliable here than on roughly normal data?

(b) Which detection rule is generally preferred for this kind of skewed data instead?

The IQR rule is generally preferred for skewed data precisely because quartile-based spread resists the same distortion that skew introduces into the mean and standard deviation.

8. A customer database includes one row listing "50,000 orders" placed by a single customer in one year, and a separate, real row for a genuine big spender who placed "500 orders" in that same year. Answer both parts:

(a) Which entry is almost certainly a data-entry error rather than a genuine extreme value?

(b) For the genuine extreme value (500 orders), what should a careful analyst do?

An error should be corrected or removed since it isn't real information; a genuine extreme value is real information and should stay, ideally alongside a robust summary statistic.

9. A merged customer list has the same phone number appearing as "555-201-4488" in one row and "5552014488" in another. Answer both parts:

(a) Fill in the blank: unifying both into one consistent format is called ___.

(b) Which of these is another common standardization task, besides fixing formatting like this one?

Standardization covers case, whitespace, formatting, and category values — unifying all of them into one consistent form across the dataset.

10. Lesson 22 recommends a specific working order: standardize, then deduplicate, then handle missing data, then check for outliers. Answer both parts:

(a) Why does deduplication happen before checking for outliers?

(b) What should happen first in this workflow, and why?

Each step in this order makes the next one more trustworthy by removing a source of noise that could otherwise disguise or mimic the next problem being checked for.
