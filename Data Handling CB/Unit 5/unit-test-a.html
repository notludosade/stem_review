1. A dataset's "age" column contains several entries of "999" where the real age was never recorded. Why is this more dangerous than a true blank cell?

A blank is at least recognizable as missing; a sentinel value hides in plain sight as a plausible-looking number.

2. Fill in the blank: a survey's income question is disproportionately skipped by the very highest earners — the chance of the value being missing is related to the value itself. This category of missingness is abbreviated ___.

MNAR (Missing Not At Random) is the case where the missingness itself correlates with the unseen value — the most dangerous case to drop or naively fill.

3. A dataset has Q1 = 10 and Q3 = 30. Using the 1.5×IQR rule, which of these values would be flagged as an outlier?

IQR = 30 − 10 = 20, so 1.5×IQR = 30. The upper threshold is 30 + 30 = 60. Only 65 exceeds that threshold.

4. A customer list has "Robert Chen, 555-3321" in one row and "Rob Chen, (555) 033-21" in another, referring to the same real person but recorded with a nickname and a formatting difference. What is this called?

A fuzzy duplicate refers to the same real-world entity but is recorded slightly differently, so it can't be caught by a simple equality check the way an exact duplicate can.

5. Fill in the blank: a short written record of what was changed during data cleaning, why, and what rule was used, is called a ___.

A cleaning log is what turns a cleaned dataset back into something someone else can trust, question, and reproduce.

6. A customer database is missing a "region" value for 3% of rows, and this pattern appears essentially random (MCAR — unrelated to any observed or unobserved value). Answer both parts:

(a) Since this is MCAR, which strategy is safest for a regional analysis?

(b) If instead the blanks were concentrated among customers who signed up through one specific channel (MAR), what risk would dropping those rows introduce?

Dropping rows is safe only when missingness is unrelated to any pattern (MCAR); once missingness relates to something observable like signup channel (MAR), dropping rows quietly distorts the remaining data.

7. Household income data is right-skewed, with a long tail toward very high incomes. Answer both parts:

(a) Why is the standard-deviation outlier rule less reliable here than on roughly normal data?

(b) Which detection rule is generally preferred for this kind of skewed data instead?

The IQR rule is generally preferred for skewed data precisely because quartile-based spread resists the same distortion that skew introduces into the mean and standard deviation.

8. A company's training-hours dataset includes one entry of "4,000 hours" logged by an employee in a single year, and a separate, real entry of "400 hours" logged by an unusually dedicated new hire. Answer both parts:

(a) Which entry is almost certainly a data-entry error rather than a genuine extreme value?

(b) For the genuine extreme value (400 hours), what should a careful analyst do?

An error should be corrected or removed since it isn't real information; a genuine extreme value is real information and should stay, ideally alongside a robust summary statistic.

9. A merged customer list has "NY", "N.Y.", and "New York" all appearing in a single state column for the same state. Answer both parts:

(a) Fill in the blank: mapping all three spellings to one canonical value is called ___.

(b) Which of these is another common standardization task, besides fixing category values like this one?

Standardization covers case, whitespace, formatting, and category values — unifying all of them into one consistent form across the dataset.

10. Lesson 22 recommends a specific working order: standardize, then deduplicate, then handle missing data, then check for outliers. Answer both parts:

(a) What should happen first in this workflow, and why?

(b) Why does deduplication happen before checking for outliers?

Each step in this order makes the next one more trustworthy by removing a source of noise that could otherwise disguise or mimic the next problem being checked for.
