Data Quality

"Garbage in, garbage out" isn't a cliché — it's the single most common reason a technically correct analysis reaches a wrong conclusion. This lesson gives you a checklist for judging whether a dataset is good enough to trust.

← Lesson 2 Lesson 4 → Contents Glossary →

Lesson 2 asked where data comes from. This lesson asks a related but distinct question: regardless of source, is this specific dataset actually fit to answer the question in front of you? A dataset can come from a perfectly sound collection method and still be low quality — full of typos, gaps, and inconsistencies picked up during storage, transfer, or manual entry.

Five dimensions of data quality

Definitions Accuracy — does the data correctly reflect reality? (A recorded age of 200 is inaccurate.) Completeness — are there gaps, missing fields, or missing records? Consistency — does the same fact appear the same way everywhere? (One row says "USA," another says "United States" — same fact, inconsistent representation.) Timeliness — is the data current enough for the question being asked? (Last year's inventory counts won't answer "what's in stock right now.") Validity — does the data conform to the format and rules it's supposed to? (A "state" field containing a phone number is invalid, regardless of whether it's accurate anywhere else.)
Why these are separate dimensions, not one "good/bad" label A dataset can score well on one dimension and poorly on another, and knowing which one is broken determines the fix. A sales dataset might be perfectly accurate and complete, but inconsistent (dates stored as "1/5/24" in some rows and "2024-01-05" in others) — that's a formatting fix, not a data-recollection problem. A dataset might be consistent and valid but not timely — every value is well-formed and was accurate when collected, but it's a year stale. Treating "data quality" as a single yes/no question hides which specific problem you actually have, and Unit 5's cleaning lessons are organized around exactly this breakdown: missing data addresses completeness, deduplication and standardization address consistency, and so on.
Same number, different quality problems A "revenue" column showing $0 for a given month could mean: the store was genuinely closed that month (accurate), the data wasn't recorded yet (incomplete — should be blank, not zero), or a system error logged zero instead of the real figure (inaccurate). The number alone can't tell you which — you have to know the data's context to tell a true zero from a missing value wearing a zero's clothing. This exact ambiguity is why Unit 5 treats "how missing data was recorded" as a first question, not an afterthought.

Check your recall

No peeking back up — answer from memory first, then check.

1. A dataset has "USA" in some rows and "United States" in others for the same country. Which data quality dimension does this violate?

Both representations are factually accurate — the problem is that the same real-world fact doesn't look the same everywhere in the data.

2. Why is it useful to separate data quality into distinct dimensions (accuracy, completeness, consistency, timeliness, validity) rather than one overall "good/bad" judgment?

Different quality problems need different fixes — a formatting fix for inconsistency looks nothing like a fix for stale, untimely data.

3. Why can't a "$0" revenue value be interpreted correctly without additional context?

The same numeric value can arise from genuinely different underlying situations, which is exactly why missing-data handling requires context, not just the raw number.

4. Fill in the blank: the data quality dimension that asks whether a value conforms to the expected format or rules for its field (e.g. a phone number appearing in a "state" field) is called ___.

Validity is about conforming to expected format/rules, independent of whether the value happens to be accurate elsewhere.

5. Fill in the blank: the data quality dimension that asks whether data is current enough to answer the question at hand (e.g. last year's inventory counts for a "what's in stock right now" question) is called ___.

Timeliness is independent of accuracy — a value can be perfectly accurate for when it was recorded and still be too stale to use now.
