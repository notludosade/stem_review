Proxy Variables and Hidden Discrimination

Removing a protected field from your data doesn't remove its influence.

Lesson 16 → Contents Glossary →

A common, well-intentioned fix once bias like Lesson 13's zip code example is discovered is: "just don't collect that field." Drop race, drop gender, drop age from the dataset entirely, and the model can't discriminate on something it never sees. This lesson explains why that fix is incomplete on its own — the zip code field itself is the demonstration. Nobody fed race into that shipping rule, and it discriminated anyway.

Removing the sensitive field, calling it fixed 
fields_used_for_credit_score = [
    "income", "debt_ratio", "payment_history",
    "zip_code", "years_at_address",  # dropped "race" — done, right?
]
Checking remaining fields for proxy correlation 
fields_used_for_credit_score = [
    "income", "debt_ratio", "payment_history",
]
# zip_code and years_at_address were tested for correlation with
# race and income using the held-out demographic evaluation set
# from Lesson 14, and dropped once the correlation showed up

Dropping "race" from the input fields feels like the responsible move, and it is necessary — but not sufficient. zip_code, years_at_address, first name, even shopping category history can each function as a proxy variable: a field that doesn't name a protected characteristic but predicts it closely enough that a model can reconstruct its effect without ever seeing it directly.

Definition Proxy variable (or "proxy discrimination") is a field that correlates strongly enough with a protected characteristic — race, gender, age, disability status, religion — that using it produces close to the same discriminatory outcome as using the protected characteristic directly, even though the protected field was never included.

You can't eliminate proxies by inspection alone

The hard part is that a proxy relationship isn't usually visible by reading the field name. Nobody looks at "zip code" or "years at current address" and immediately thinks "protected characteristic." Finding a proxy requires the same measurement discipline as Lesson 14's fairness testing: run the model or rule against a demographic evaluation set and check whether its outputs correlate with group membership, not just whether its inputs mention group membership.

Why it matters here "We don't collect race" is a true and commonly-cited defense that doesn't actually settle the fairness question — and treating it as if it does is how well-intentioned teams end up shipping a discriminatory system while genuinely believing they removed the risk. The fix isn't "collect even less" — it's "measure the actual outcome," which is what Lesson 14 already set up the machinery for.
