Open Source Licenses Are Not Interchangeable

"It's on GitHub" is not the same as "you can do whatever you want with it."

Lesson 17 → Contents Glossary →

Units 1 through 5 were about how your own code treats the people who use it. This unit turns the lens around: how you treat the people whose code you use. Every public repository has a license attached — sometimes explicit, sometimes by omission — and that license is a legal document with real terms, not a formality to skip past on the way to pip install.

Copying code without checking the license 
# Found this parsing function on GitHub, looks solid, copied it in.
# Never checked what license the repo was under.
def parse_config(path):
    ...  # 40 lines, copied verbatim from a random repo
Checking the license before depending on the code 
# Repo is MIT licensed — permissive, requires keeping the copyright
# notice. Added to THIRD_PARTY_NOTICES.md with attribution.
# https://github.com/example/parser-lib  (MIT License)
def parse_config(path):
    ...

Licenses fall along a spectrum. Permissive licenses (MIT, Apache 2.0, BSD) let you use, modify, and redistribute code with minimal obligations — usually just keeping the original copyright notice. Copyleft licenses (GPL, AGPL) let you use and modify the code too, but require that anything you build on top of it — sometimes your entire application — be released under the same license when distributed. Using a GPL-licensed library inside proprietary software you plan to sell closed-source isn't a style choice; for many interpretations of the GPL, it's a license violation.

Definition Copyleft is a licensing approach that grants broad usage rights on the condition that derivative works are released under the same license terms — designed to keep open source code and its derivatives open, rather than letting them be absorbed into closed-source products for free.

"No license" doesn't mean "public domain"

A repository with no LICENSE file at all is not an invitation to use the code freely — under default copyright law in most countries, the absence of a license means the author retains all rights, and technically no one else has permission to use, copy, or modify the code at all. This is a common and understandable mistake: the code is visible, so it feels available. Visibility and permission are different things.

Why it matters here License violations aren't abstract — companies have been sued, forced to open-source proprietary products, or made to pay damages over exactly this kind of unchecked dependency. Beyond the legal exposure, using someone's work without honoring the terms they attached to it is the same kind of disrespect this whole course has been arguing against, just aimed at a fellow developer instead of an end user.

Check your recall

1. What's the main difference between a permissive license and a copyleft license?

MIT/Apache/BSD are permissive; GPL/AGPL are copyleft and can require your own code to be released under the same terms.

2. What does it mean, legally, when a public GitHub repository has no LICENSE file?

Visible on GitHub and legally usable are two different things — default copyright law applies in the absence of an explicit license.

3. Why can using a GPL-licensed library inside closed-source commercial software be a problem?

This is copyleft's defining trait — the obligation can propagate to the whole distributed work, not just the borrowed piece.

4. Fill in the blank: a license that requires derivative works to carry the same license terms, keeping the code and its derivatives open, is called ___.

See the definition box above.

5. Fill in the blank: MIT, Apache 2.0, and BSD are examples of ___ licenses, which impose minimal obligations beyond keeping the copyright notice.

The opposite end of the spectrum from copyleft — see the paragraph introducing both categories.
