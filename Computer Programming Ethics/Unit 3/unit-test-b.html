1. A to-do list app's signup form does not ask for a home address or phone number. What principle from Lesson 7 does this reflect?

Lesson 7 gives this exact contrast: a to-do list app doesn't need a phone number, and collecting only what a product actually needs is data minimization.

2. Fill in the blank: the EU regulation Lesson 7 cites, whose Article 5(1)(c) requires data to be limited to what's necessary, is the ___.

The General Data Protection Regulation — its influence extends well beyond the EU, since many companies apply its rules globally.

3. According to Lesson 7, what is the main downside of collecting a field the product never actually uses?

An unused field doesn't improve the product, but it does add something a breach can expose and something the user has to trust you with.

4. Why does Lesson 8 call application logging a common, accidental leak point?

Logging is usually treated as an invisible debugging convenience, so it doesn't get the same review a database schema or API response would.

5. What is the general shape of the logging mistake described in Lesson 8?

Lesson 8 names this exact pattern: logging an entire object — a request, a form submission, a database row — instead of just what's needed for debugging.

6. Answer both parts about the signup form example in Lesson 7:

(a) Fill in the blank: date_of_birth is only requested later in the fixed example, if the feature that actually needs it — age-restricted ___ — is used.

(b) Why is "we might need it later" not treated as a good reason to collect a field, according to Lesson 7?

(a) The fixed example collects only email and password up front, adding date_of_birth later only if age-restricted content is actually used. (b) Data sitting unused is a liability from the moment it's collected, whether or not the feature ever ships.

7. Answer both parts about Lesson 8's discussion of logging practices:

(a) Why are application logs, once a request is logged, often riskier than the primary database, according to Lesson 8?

(b) Fill in the blank: the OWASP Logging Cheat Sheet lists passwords, session tokens, and credit card numbers among data categories that should never appear in logs in any ___.

(a) Lesson 8's definition box notes that logs are a second copy of your data, created automatically, often with none of the protections applied to the first copy. (b) Not even partial or truncated versions of these categories should appear.

8. Answer both parts about why calling data "anonymized" can be dishonest:

(a) Fill in the blank: matching data back to a real person by combining several individually-harmless remaining fields is called ___.

(b) Why does Lesson 9 call mislabeling data as "anonymized" a form of dishonesty?

(a) See Lesson 9's definition box — none of the remaining fields are dangerous alone. (b) This ties back to "be honest and trustworthy" from Unit 1 — telling users their data is anonymized when it can still be re-identified is a factual misrepresentation.

9. Answer both parts about the anonymize() function shown in Lesson 9:

(a) Besides name and email, which fields does Lesson 9 say typically remain after a naive anonymize() function runs?

(b) Fill in the blank: Sweeney's research is widely cited because it showed that roughly ___ percent of the U.S. population could be uniquely identified from just those three fields.

(a) These are exactly the fields Lesson 9's code example leaves behind after deleting name and email. (b) Roughly 87% of the U.S. population was found to be uniquely identifiable from ZIP code, birth date, and sex combined.

10. Answer both parts about the higher bar true anonymization has to clear:

(a) What does Lesson 9 say true anonymization usually requires, beyond just deleting one field?

(b) Fill in the blank: replacing a name with a user_id is useful, but the original identity can still be recovered with the mapping table — this technique is called ___, not full anonymization.

(a) True anonymization is a much higher bar, requiring the data not be re-identifiable even in principle. (b) Pseudonymization is a real, useful technique — the mistake is only in calling it full anonymization.
