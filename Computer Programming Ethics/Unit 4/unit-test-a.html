1. A user gets only the message "Something went wrong. Please try again." after a failed action. What's the honest-failure problem with stopping there?

An error can be truthful without being useful — a vague message clears the "don't lie" bar but fails the "give something actionable" bar this unit draws.

2. Fill in the blank: revealing stack traces, database hostnames, or internal file paths to an end user or attacker is a security weakness known as ___ ___.

This sits under OWASP's broader "Security Misconfiguration" category — internal details that help an attacker understand and exploit a system.

3. A payment endpoint fails internally. Answer both parts about how to respond honestly and safely:

(a) Which response correctly balances honesty to the user with safety for the system?

(b) Fill in the blank: the detailed technical error data itself should be written to a ___ that only the development team can access, not returned in the response.

(a) A plain message plus a reference ID gives the user something honest and actionable without handing over internals. (b) The full technical detail belongs in a log the team can search, connected back to the user's report only through the reference ID.

4. Why is logging a raw exception object still risky, even though ordinary users never see server logs directly?

A log is a second data store with its own, often weaker, protections — the same "log leak" concern that applies to any second copy of sensitive data.

5. A payment failure needs to be logged for later debugging. Answer both parts:

(a) Which is the safer logging approach?

(b) Fill in the blank: deliberately removing or masking sensitive fields — passwords, tokens, card numbers — before a message is written to a log is called ___ ___.

(a) Named fields chosen deliberately are more useful for debugging and safer than whatever the raw exception happens to contain. (b) This deliberate removal or masking of sensitive fields is log scrubbing.

6. What security advantage does passing a dictionary of named fields to a logger have over building one long f-string sentence?

An f-string can silently absorb an entire object's contents; a dictionary of named fields makes each included piece of data explicit and deliberate.

7. Answer both parts about how a system should respond when a check it depends on can't run:

(a) Fill in the blank: a system that defaults to the safer, more restrictive state when it hits an unresolved error is described as ___.

(b) Which code correctly implements a fail-closed permissions check?

(a) A locked door failing this way is the canonical example — the safer, more restrictive default on an unresolved error. (b) Returning False on the exception path denies access rather than silently granting it during an outage.

8. Why is a fail-open default on a permissions check especially risky?

An outage and an active attack can happen at the same time, or one can cause the other — exactly when you'd want the check enforced most.

9. Fail-closed isn't automatically the more ethical choice in every situation. Answer both parts:

(a) Why are electronic building door locks deliberately designed to fail open during a power outage?

(b) Fill in the blank: choosing fail-open or fail-closed correctly requires reasoning about which failure mode does less ___ for the specific thing being guarded, not defaulting to one out of convenience.

(a) A fire exit is the classic case for fail-open — safety during an emergency outweighs a temporary security gap. (b) The judgment call is about which failure mode does less harm, reasoned through deliberately rather than defaulted to.

10. "Honest error messages" doesn't mean "unfiltered error messages." Answer both parts:

(a) Which of the following would violate the honesty requirement, even if it revealed zero technical detail?

(b) Fill in the blank: within the two boundaries of never claiming false success and never hiding that a failure happened, the amount of ___ shown to the user versus logged internally is a real design decision.

(a) Claiming success on a failed request breaks honesty outright, regardless of how little or much technical detail is shown. (b) Everything within those two honesty boundaries is a design decision about how much detail to surface where.
