Passwords Are Never Stored, They're Hashed

The fourth red flag from Unit 1: plaintext sensitive data, and the fix that's become a hard industry rule.

Lesson 7 → Contents Glossary →

If a database of usernames and plaintext passwords is ever read by the wrong person — a breach, a misconfigured backup, an insider — every one of those accounts is compromised instantly, and so is every other account where a user reused that same password. This isn't a rare edge case; password reuse is common enough that a single leaked plaintext database routinely causes damage far outside the original system.

Hashing: a one-way function

Definition A hash function takes an input of any size and produces a fixed-size output, deterministically — the same input always produces the same output — but there's no practical way to reverse it: you can't recover the original input from the hash. Encryption, by contrast, is deliberately reversible with the right key. Passwords are hashed, not encrypted, because the system should never need to recover the original password at all — only check whether a newly-typed one matches.
Storing the password directly 
def create_user(username, password):
    db.execute(
        "INSERT INTO users (username, password) VALUES (?, ?)",
        (username, password)
    )
Hashing before storing 
import bcrypt

def create_user(username, password):
    hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt())
    db.execute(
        "INSERT INTO users (username, password_hash) VALUES (?, ?)",
        (username, hashed)
    )

def check_login(username, password):
    stored_hash = db.get_password_hash(username)
    return bcrypt.checkpw(password.encode(), stored_hash)

Logging in doesn't compare passwords directly — it hashes the newly-typed password and compares hashes. The real password is never stored anywhere, so there's nothing in plaintext for a breach to expose. Java's Spring Security, JavaScript's bcryptjs/argon2 packages, and C++ libraries like libsodium all provide the same kind of function — the algorithm name changes, the shape of the fix doesn't.

Why not just hash it once, simply?

Notice bcrypt.gensalt() in the example — a random salt mixed into each password before hashing, so two users with the same password get different stored hashes, and an attacker can't precompute a table of hashes for common passwords in advance. bcrypt (and modern alternatives like Argon2) are also deliberately slow — a general-purpose hash function like SHA-256 is too fast, letting an attacker try billions of guesses per second against a stolen hash. The OWASP Password Storage Cheat Sheet is the field's authoritative, regularly-updated answer to "which algorithm, and how" — worth checking whenever this comes up in a real project, since recommendations shift as computing power grows.

Why it matters here This is "avoid harm" and "respect confidentiality" made concrete in a single design decision. Nobody has to trust that the developers promise not to look at plaintext passwords — a properly hashed system makes it structurally impossible, even for the developers themselves.

Check your recall

1. Why are passwords hashed instead of encrypted?

Login only requires checking whether a new password matches — never recovering the original — which is exactly what a one-way hash allows and encryption doesn't need to.

2. What problem does adding a random salt to each password solve?

Without a salt, two users with the same password get identical hashes, and an attacker can look them up in a precomputed table instead of guessing each one individually.

3. Why is a fast, general-purpose hash like SHA-256 a poor choice for passwords specifically?

bcrypt and Argon2 are deliberately slow and tunable, which is exactly the opposite of what you want from a general-purpose hash — speed is a feature there, but a liability for password storage.

4. Fill in the blank: a function that deterministically maps input to a fixed-size output with no practical way back is called a ___.

See the definition box above — this one-way property is exactly why it fits password storage.

5. Fill in the blank: random data mixed into a password before hashing, so identical passwords produce different stored hashes, is called a ___.

bcrypt.gensalt() in the example generates one automatically for each password.
