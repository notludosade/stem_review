1. Which of these is an example of a "red flag" when reading code for ethical issues?

Silently swallowing an error hides a real failure from both the user and anyone debugging later — exactly the kind of dishonesty-by-omission this course flags.

2. Fill in the blank: the professional guidelines many software engineers follow, including principles on honesty and avoiding harm, are called the ACM ___ of Ethics.

The ACM Code of Ethics is one of the two professional codes this unit covers, alongside the Software Engineering Code.

3. Why is hardcoding an API key directly in source code risky, even in a private repository?

Secrets committed to source code tend to leak eventually — through git history, logs, screen shares, or a repository going public — which is why environment variables exist.

4. Fill in the blank: storing passwords should never use plain encryption, because it can be reversed; instead, passwords should be ___, a one-way transformation.

Hashing (unlike encryption) is one-way, so even the service storing the password can't recover the original.

5. What is the principle of data minimization?

The easiest way to protect data you didn't collect is simply not collecting it in the first place.

6. Fill in the blank: simply deleting a person's name from a dataset is not true anonymization, because other fields can often be combined to ___ the individual.

Combinations of seemingly harmless fields (zip code, birth date, gender) can re-identify most individuals, per Sweeney's well-known finding.

7. Why should a user-facing error message differ from what's written to the developer log?

Different audiences need different detail — the developer log can be verbose and technical, while the user-facing message stays honest but safe to expose.

8. Fill in the blank: a system designed to deny access by default when something goes wrong, rather than silently allowing it, is described as ___ (as opposed to fail-open).

Fail-closed is the safer default when guarding something sensitive; fail-open trades safety for availability, which isn't always the right call.

9. How can an algorithm discriminate against a protected group even if that group's attribute (e.g., race) is never explicitly used as a feature?

Dropping a protected field isn't enough on its own — correlated fields (zip code, school, etc.) can act as proxies that reintroduce the same bias.

10. Fill in the blank: a 100% test pass rate says nothing about whether a model has ___ impact across different groups unless tests specifically check for it.

Ordinary correctness tests don't check for disparate impact across groups — that requires dedicated fairness tests.

11. What is the key practical difference between a permissive license (like MIT) and a copyleft license (like GPL)?

Copyleft's defining feature is that it propagates its own terms to derivative works; permissive licenses let you do almost anything, including relicensing.

12. Fill in the blank: using a well-known package's misspelled name to trick developers into installing malicious code is called ___.

Typosquatting relies on a developer mistyping a popular package name and installing an attacker's lookalike instead.

13. A single senior developer on a team consistently hashes passwords, checks licenses, and fails closed — but never reviews anyone else's code and never writes down why. When she leaves the company, three of her past decisions get silently reverted within a year. What does this course's final argument say was missing?

Individual discipline matters, but only review and documentation make it survive turnover — this scenario is exactly that failure mode.

14. Fill in the blank: this course's closing argument is that ethical code stops being expensive once it becomes a ___ practiced by a whole team — through review and documentation — rather than a one-time effort by a single careful developer.

Habit only becomes durable through review and recorded reasoning, not one person's memory.
