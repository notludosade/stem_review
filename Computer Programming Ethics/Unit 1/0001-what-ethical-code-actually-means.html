What "Ethical Code" Actually Means

Every line of code is a decision. This course is about learning to notice which decisions matter.

Lesson 2 → Contents Glossary →

It's tempting to think of "ethics" as something that lives outside code — a policy document, a lawyer's sign-off, a training video you click through once a year. It isn't. Ethics lives inside the function bodies themselves, in choices that look purely technical but aren't. This first lesson is about seeing that clearly, before this course touches a single line of Python, Java, JavaScript, or C++ syntax in depth.

Two functions, same name, different world

Both of the functions below are called deleteAccount(). Both compile. Both "work," in the sense that nothing crashes. Read them and ask: if you were the user who clicked "Delete my account," which one actually happened to you?

What it looks like it does 
function deleteAccount(userId) {
  // Hide the account from the UI
  users[userId].hidden = true;
  // Data stays in the database, fully intact
}
What "delete" actually means 
function deleteAccount(userId) {
  db.execute("DELETE FROM users WHERE id = ?", [userId]);
  db.execute("DELETE FROM user_data WHERE user_id = ?", [userId]);
  logDeletion(userId, new Date());
}

The first version isn't a bug — it compiles, it runs, it probably even passes a test that checks users[userId].hidden === true. It's a decision, made by whoever wrote it, to make the button lie. That gap — between what code appears to do and what it actually does — is where this entire course lives.

Definition A dark pattern is code deliberately written so its visible behavior misleads the person using it — often to retain data, money, or attention the user believed they were opting out of.

Why this isn't just "be a good person"

"Don't be evil" is not a specification. It doesn't tell you what to check before merging a pull request. The field has already done the work of turning broad good intentions into something checkable: the ACM Code of Ethics and Professional Conduct, adopted in its current form in 2018, lays out concrete principles — contribute to society, avoid harm, be honest and trustworthy, respect privacy, be fair — that apply whether or not you're an ACM member. Why it matters here "Avoid harm" is not abstract when you're the one writing deleteAccount(). It means: does this function do what its name and its UI promise? If not, that's the harm — and it was a choice, not an accident.
