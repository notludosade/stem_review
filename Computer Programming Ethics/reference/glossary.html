Why Ethics Lives in Code

Dark pattern

Code deliberately written so its visible behavior misleads the person using it — often to retain data, money, or attention the user believed they were opting out of.

Principle

A general commitment — "avoid harm" — that has to be interpreted for a specific decision. Not a rule with a single correct mechanical answer; a lens you apply.

Injection vulnerability

A flaw where untrusted input is inserted directly into a command, query, or expression, letting an attacker change what that command does. On the OWASP Top 10 for over a decade.

Secure by Default

Secret

Any credential — API key, password, signing key, access token — that grants access to something and must not be readable by people who shouldn't have that access.

Environment variable

A value set outside the program (by the operating system or a hosting platform), read at startup instead of written into the source.

Input validation

Checking that external data meets expected type, range, format, and value constraints before it's used — rejecting or correcting it if it doesn't, rather than trusting it by default.

Hash function

A function that deterministically maps an input of any size to a fixed-size output, with no practical way to reverse it back to the original input.

Salt

Random data mixed into a password before hashing, so identical passwords produce different stored hashes and precomputed hash tables stop working.

Privacy & Data Minimization

Data minimization

The practice of collecting only the data a system actually needs to do its job — not data that might be useful someday.

Log leak

Unintentional exposure of sensitive data through application logs, monitoring systems, or error trackers — channels with typically weaker access controls and longer retention than the primary database.

Re-identification

Matching supposedly anonymous data back to a specific real person, usually by combining several individually-harmless remaining fields.

Pseudonymization

Replacing a direct identifier with a reversible stand-in (e.g. a user ID instead of a name) — not the same as true anonymization, which aims to prevent re-identification even in principle.

Transparency & Honest Failure

Information disclosure

A security weakness where a system reveals internal details — stack traces, file paths, database structure, versions — that help an attacker understand and exploit it.

Log scrubbing

Removing or masking sensitive fields before a message is written to a log, rather than trusting that sensitive data never ends up in a log statement by accident.

Structured logging

Passing a set of explicitly named fields to a logger instead of a freeform sentence, making what's included easier to search and harder to overshare by accident.

Fail-closed

A system defaults to the safer, more restrictive state when it hits an error it can't resolve — also called "fail-secure." Correct for something like a locked door.

Fail-open

A system defaults to letting things proceed when it hits an error it can't resolve. Correct for something like a fire exit during a power outage — not universal.

Bias & Fairness in Algorithms

Algorithmic bias

A systematic, unfair difference in how a program's output treats different groups, even when no line of code explicitly references group membership.

Disparate impact

When a policy or system that appears neutral produces significantly different outcomes for different groups. Doesn't require intent — only a measurable outcome gap.

Proxy variable

A field that correlates strongly enough with a protected characteristic that using it reproduces close to the same discriminatory outcome, without ever naming that characteristic directly. Also called proxy discrimination.

Licensing, Attribution & Open Source Trust

Copyleft

A licensing approach that grants broad usage rights on the condition that derivative works are released under the same license terms, keeping the code and its derivatives open.

Attribution

Crediting the original author or source of code, text, or an idea you've reused or adapted — the mechanism by which a license's terms are actually honored.

Supply chain compromise

An attack that targets software indirectly, by compromising a trusted dependency, build tool, or distribution channel rather than the software itself.

Code as a Professional Artifact

Code review

The practice of having at least one other person examine code before it's merged or shipped — for correctness, and for the security, privacy, fairness, and licensing patterns covered across this course.

Architecture Decision Record (ADR)

A short, standalone document capturing one significant technical decision: the context, options considered, the choice made, and the reasoning — kept alongside the code.
