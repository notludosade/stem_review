1. A system automatically schedules containers onto available machines, restarts crashed ones, and adjusts running counts. What is this system called?

The orchestrator is the automated system handling scheduling, health, and scaling.

2. Fill in the blank: the whole collection of nodes managed together as a single system is called a ___.

A cluster is the full group of nodes scheduled as one system.

3. Why does a control plane schedule pods based on capacity across the whole cluster, rather than one node at a time?

A cluster-wide view is exactly what lets the control plane place pods well.

4. Fill in the blank: when a crashed pod is automatically replaced without any human noticing or intervening, this is called ___.

Self-healing is the orchestrator's unattended recovery back to desired state.

5. What is a replica count?

Replica count is the desired-state number the orchestrator continuously enforces.

6. A team runs 300 containers by hand across dozens of machines, constantly replaced by new deploys. Answer both parts:

(a) Tracking this manually is best described as...

(b) This is why orchestration is described in this unit as...

Orchestration's necessity grows directly out of the scale containers make possible.

7. A cluster contains four physical machines, each capable of running several pods. Answer both parts:

(a) Each individual machine is called a...

(b) The orchestrator schedules workloads onto these machines as...

Nodes are the machines; pods are the scheduled unit placed onto them.

8. A new pod needs scheduling, and one node in the cluster already has significantly more free capacity than the others. Answer both parts:

(a) The decision of where to place this pod is coordinated by...

(b) This coordination happens...

Automated, cluster-wide scheduling is the control plane's core job.

9. A pod crashes, dropping the running count below the desired replica count. Answer both parts:

(a) The orchestrator detects this gap and...

(b) This behavior is a direct parallel to which earlier concept?

Self-healing is the same automatic-failover instinct, applied at the pod level.

10. Orchestrator-level scaling adjusts pod count in response to CPU usage or request rate. Answer both parts:

(a) This is conceptually the same idea as...

(b) The specific thing being added or removed here is...

Orchestrator scaling applies elasticity's core idea to pods instead of whole servers.
