1. What does "the wall" refer to in the traditional Dev/Ops split?

The wall is an organizational handoff, not a technical or network boundary.

2. Fill in the blank: the set of cultural practices and shared responsibility uniting Dev and Ops around shipping reliable software together, which tools support but don't create by themselves, is called ___.

DevOps is a cultural and organizational shift; the tools in this course exist to support it, not replace it.

3. Why is a build artifact deployed unchanged, rather than rebuilt from source at every later stage of the pipeline?

Reusing the exact tested artifact guarantees what ships is exactly what was verified.

4. What does CI actually control about merge conflicts, since conflicts themselves can't be fully prevented?

Frequent integration bounds how much divergence can build up before it has to be reconciled.

5. Fill in the blank: a collection of automated tests that check code still behaves correctly, run by a CI server on every merge, is called a ___.

A test suite is only as useful as its coverage is trustworthy.

6. Why is a flaky test arguably more dangerous than a test that's simply, consistently wrong?

Eroded trust in red builds undermines the entire purpose of automated checks.

7. What is the core difference between Continuous Delivery and Continuous Deployment?

The presence or absence of a manual release gate is the entire distinction.

8. Fill in the blank: gradually sending an increasing percentage of real traffic to a new version, starting small, is called a ___ release.

A canary release exposes only a slice of users first, expanding only once that slice looks healthy.

9. Why might a rollback not be safe after a deploy that included a database migration?

A schema change that already ran can leave reverted code mismatched with the current database state.

10. What does Infrastructure as Code mean?

IaC treats infrastructure definitions like source code, provisioned by a tool rather than clicked by hand.

11. Fill in the blank: an operation where running it once has the same effect as running it many times is called ___, a property declarative IaC tools are built around.

Idempotency is what makes reapplying a declarative configuration file always safe.

12. What does reconciliation actually do, in the context of configuration drift?

Reconciliation is what actually catches and corrects drift once it exists.

13. What does a container orchestrator actually do?

Orchestration is fundamentally about managing many containers across many machines automatically.

14. Fill in the blank: the smallest deployable unit an orchestrator schedules, usually one container, is called a ___.

A pod, not an individual container, is the actual unit the orchestrator schedules.

15. What does an orchestrator do when a pod crashes and the running count drops below the desired replica count?

Self-healing means the orchestrator reconciles actual state against desired state automatically.

16. What is the key difference between a log and a metric?

Logs capture detailed individual events; metrics capture cheap, sampled trends over time.

17. Fill in the blank: the desensitization that sets in when alerts fire too often or for non-actionable conditions, causing people to start ignoring them, is called ___.

Alert fatigue is the alerting equivalent of a flaky test eroding trust in a red build.

18. What is the incident commander's role during an incident?

The incident commander coordinates; someone else may well be the one actually debugging.

19. What do the DORA metrics measure?

The DORA metrics are the shared measuring stick behind nearly every practice this course covered.

20. Fill in the blank: manual, repetitive operational work with no lasting value, growing roughly with system size unless automated away, is called ___.

Toil is exactly the kind of work every unit in this course tried to automate away, at least partially.
