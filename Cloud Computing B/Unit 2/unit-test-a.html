1. What does "continuous" refer to in Continuous Integration?

CI is defined by frequent integration, not by anything running nonstop.

2. Fill in the blank: when two changes touch overlapping code in a way that can't be combined automatically, requiring manual reconciliation, this is a ___.

Merge conflicts are unavoidable; CI's job is to keep each one small.

3. What does a CI server do automatically on every merge?

The CI server reacts to the merge itself, running build and test automatically.

4. Fill in the blank: running cheap, fast checks like linting before slow checks like end-to-end tests, so a trivial error is caught in seconds, is called ___.

Fail-fast ordering doesn't change correctness — it changes how quickly a developer gets an answer.

5. Why should a build log usually be read starting from the first failure, not the last line of output?

The first failure is usually the real root cause; later ones are frequently fallout.

6. A team merges a feature branch once every three weeks instead of daily. Answer both parts:

(a) Compared to daily merging, this branch's eventual merge will likely be...

(b) This practice of merging early and often is the core idea behind...

Delaying integration doesn't prevent conflict — it lets it accumulate into something much larger.

7. Two developers each edit the same configuration file for five days without merging. Answer both parts:

(a) The eventual merge conflict, compared to merging daily, will be...

(b) A risk of this large, delayed merge is that it might...

Large, infrequent merges are harder to reason about and more likely to lose already-fixed work.

8. A build's lint stage passes, but its unit test stage fails. Answer both parts:

(a) The overall build status is...

(b) In a fail-fast pipeline, the stages after the failed one would...

Any single failing stage makes the overall build red, and later stages are typically skipped.

9. A ten-minute end-to-end suite runs before a two-second lint check in a poorly ordered pipeline. Answer both parts:

(a) If the code has a trivial typo, this ordering means the developer finds out...

(b) Reordering so lint runs first would mainly improve...

Fail-fast ordering is about feedback speed, not about making the code itself more correct.

10. A test fails once, then passes on rerun against the exact same, unchanged code. Answer both parts:

(a) This behavior is best described as a...

(b) Left unaddressed, this behavior mainly risks...

Flaky tests erode trust in the whole point of automated checks over time.
