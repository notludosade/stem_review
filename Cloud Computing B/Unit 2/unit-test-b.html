1. A team merges every developer's changes into a shared branch several times a day, automatically building and testing each merge. What practice is this?

Frequent, automatically-checked merging is the defining practice of CI.

2. Fill in the blank: CI cannot eliminate this entirely, but it does keep its size small by merging frequently — the ___ that happens when overlapping edits can't be combined automatically.

Conflicts are an unavoidable consequence of parallel edits; CI bounds how large each one gets.

3. What does a "green" build status mean?

Green specifically means the build and every test in the suite succeeded.

4. Fill in the blank: ordering a pipeline so cheap checks run before expensive ones, so a trivial mistake is caught in seconds rather than after a long suite finishes, is called the ___ principle.

Fail-fast ordering changes how quickly feedback arrives, not whether the code is correct.

5. A test passes and fails inconsistently against the exact same, unchanged code. What is this called?

Inconsistent results against unchanged code is the defining trait of a flaky test.

6. Two developers merge into the shared main branch every single day instead of keeping a long-lived feature branch. Answer both parts:

(a) Compared to a three-week feature branch, this daily approach produces conflicts that are...

(b) This daily-merge approach is the defining practice of...

Frequent merging bounds divergence, which is the entire point of CI.

7. A feature branch sits unmerged for six weeks while the shared mainline changes substantially underneath it. Answer both parts:

(a) The eventual merge is likely to be...

(b) A specific risk of this delayed merge is that the original author may have...

Both the size of the conflict and the loss of context grow the longer integration is delayed.

8. A CI server's integration test stage fails, but the earlier lint and unit test stages both passed. Answer both parts:

(a) The overall build status is...

(b) This failure was triggered automatically by...

Any single failing stage turns the whole build red, and the CI server runs automatically on every merge.

9. A pipeline is reordered so a two-second lint check runs before a ten-minute end-to-end suite. Answer both parts:

(a) For code with a trivial lint error, this reordering means the developer now finds out...

(b) This reordering is an example of the...

Fail-fast ordering gets a developer their answer as quickly as possible.

10. Reading a build log with several failure messages. Answer both parts:

(a) The most reliable place to start diagnosing is...

(b) Later failure messages in the same log are often...

Diagnosing from the first failure backward is usually faster than chasing every symptom.
