Software Engineer Capstone

An open-ended build, not a quiz — this project exists to see whether you've actually proved yourself on Computer Programming 1, Computer Programming 2, Computer Programming Ethics, and Software Engineering.

← Software Engineer Pathway All Projects →

The Brief

Design, build, and document a small multi-file application in any of the four languages this pathway taught — Python, Java, JavaScript, or C++. It doesn't need to be original or ambitious in scope; it needs to be engineered, not just written. The bar is whether it would survive a real code review, not whether it would impress anyone with its features.

Deliverables

  • A working program split across at least 3 files with a real separation of concerns
  • At least one class hierarchy using inheritance or composition
  • At least one deliberate error-handling path — not just hoping nothing crashes
  • A short test suite, even 5–10 cases, that would actually catch a regression
  • A real git history: several commits with messages that explain why, not just what
  • A one-page design note explaining one architecture or design-pattern decision, and what you gave up by making it
  • A short "ethics pass": one deliberate decision you made because of a security, privacy, or licensing concern

Reflection

Answer in your own words. There's no grading here — just save your answers below.

1. Computer Programming 1 taught you to break a problem into functions before writing any code. Walk through how you decomposed this project — what was the first split you made, and did it survive contact with the actual build?

2. Where did a data structure or complexity idea from Computer Programming 2 (recursion, a specific structure, a memory consideration) drive a real decision — and what would have gone wrong with the naive alternative?

3. Which unit from Computer Programming Ethics (security, privacy, fairness, licensing) actually changed something you built, not just something you thought about? Be specific about the before and after.

4. What's one bug your test suite caught (or would have caught) that you wouldn't have found by just running the program yourself?

5. Name the one architectural decision from Software Engineering's design-patterns or architecture units that you're least sure about. What's the trade-off, and what would make you revisit it?

6. Looking back across all four courses, what's the one habit from this pathway you expect to keep using even outside a course — and which one did you have to force yourself to do?
