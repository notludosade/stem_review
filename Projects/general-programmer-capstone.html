General Programmer Capstone

An open-ended build, not a quiz — this project exists to see whether you've actually proved yourself across all nine General Programmer courses: Computer Programming 1, Computer Programming 2, Computer Programming Ethics, Computer Programming 2+, Software Engineering, Data Handling: CB, Systems Programming & Architecture: CS, Computer Networking Fundamentals, and Advanced Algorithms.

The Brief

Design, build, and document a multi-file application that talks over the network to its own small data layer — a real client-server exchange, not just a script. It doesn't need to be original or ambitious in scope; it needs to show that nine courses' worth of fundamentals actually add up to one coherent piece of engineering, from the algorithm choices down to what happens in memory while it runs.

Deliverables

  • A working client and server, communicating over a real protocol (HTTP or raw sockets), split across at least 4 files with a genuine separation of concerns
  • At least one place where you deliberately chose a specific algorithm or data structure for its complexity, and can say what the naive alternative would have cost
  • A small persistent data layer (even a single SQL table) that the server reads from and writes to correctly under repeated use
  • One documented systems-level constraint your design respects — a memory limit, a fixed-size buffer, or an explicit note on what happens under concurrent access
  • A short test suite that would actually catch a regression, plus a real git history with commit messages that explain why, not just what
  • A one-page design note naming one architecture or design-pattern decision and what you gave up by making it
  • A short "ethics pass": one decision you made because of a security, privacy, or licensing concern

Reflection

Answer in your own words. There's no grading here — just save your answers below.

1. Computer Programming 1 and 2 taught you to decompose a problem and pick real data structures. What was the first split you made in this project, and where did a data structure choice from CP2 actually change the design?

2. Which unit from Computer Programming Ethics changed something you built here, not just something you thought about? Be specific about the before and after.

3. Name the interview-style pattern from Computer Programming 2+ (or the proof behind it from Advanced Algorithms) that shows up in this project, and what its actual time or space complexity buys you over the obvious approach.

4. Which architectural decision from Software Engineering are you least sure about? What's the trade-off, and what would make you revisit it?

5. How does your data layer handle a query or write that goes wrong — describe the actual failure path, using a Data Handling: CB idea (constraints, validation, a specific SQL guarantee).

6. What's the systems-level constraint you documented (memory, a buffer, concurrency), and what would actually break first if you ignored it under real load?

7. Walk through one real request end to end, the way Computer Networking Fundamentals taught you to trace a client-server exchange — client to server and back, naming the actual layers involved.

8. Looking back across all nine courses, which one changed how you'd approach a brand-new problem the most — and which fundamental did you almost skip that turned out to matter?
