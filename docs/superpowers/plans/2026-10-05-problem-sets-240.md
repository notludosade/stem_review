# Problem Sets ×4 (240 per set) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every one of the 20 regular Problem Sets grows from 60 to 240 questions (6 topics × 40), keeping the original 60 byte-identical and every saved-progress ID stable.

**Architecture:** In `public/assets/problem-banks.js`, each topic becomes a template plus a list of 40 parameter tuples: the original 10 (unchanged) followed by 30 drawn from a bounded, domain-valid grid by a new `topicTuples` helper that skips anything whose prompt already exists. 240 hand-written concept questions fill the 8 concept topics. `scripts/check-problem-banks.js` audits it all.

**Tech Stack:** Plain browser JS (UMD-style IIFE also loaded by Node for the audit), Node `assert`-style check scripts in `npm test`.

**Spec:** `docs/superpowers/specs/2026-10-05-problem-sets-240-design.md`

## Global Constraints

- 240 per regular set, 6 topics × 40; Timed Mastery `timedQuestions` pools unchanged (500 each).
- Original 60 per set byte-identical (JSON dump diff), same IDs. New IDs: older courses continue per-topic (`calc-limit-11…40`); `generatedCourse` courses continue sequentially (`la-61…240`).
- New grid values must be domain-valid (probabilities/hit rates in (0,1), CIDR /8–/30, n-bit strings exactly n bits, positive physical quantities, factorial/Fibonacci/2ⁿ/geometric answers ≤ 10⁶, interval points strictly inside) and stay near the original ranges.
- Grids stay small enough to materialize (≤ ~10,000 tuples each).
- Concept questions: 4 choices, exactly one correct, explanation, `meta: { kind: 'concept', expected }`; no "all/none of the above"; terms match the course's own lessons; re-derived on a second read before commit.
- During rollout the audit accepts 60 (10/topic) or 240 (40/topic) per set; the final task requires 240. Commit every task; push only at the end.

## Deviation from the usual plan format (stated up front)

This plan specifies every helper and audit change as exact code and every topic's new grid as an exact table (below), but does **not** pre-write the ~100 mechanical template conversions or the 240 concept questions verbatim: the conversions follow the one worked pattern shown in Task 2, and the concept questions are content authored in Tasks 5–6 under the stated rules. Writing them here would duplicate the entire change in the plan.

## Shared code (Task 1 adds these to `problem-banks.js`, after `addFromGrid`)

```js
  const regular10 = (tupleAt) => Array.from({ length: 10 }, (_, i) => tupleAt(i));
  // A topic's 40 parameter tuples: the original 10 (unchanged, so their
  // questions and saved-progress IDs never move) + `extra` drawn evenly
  // from a bounded grid, skipping any tuple whose prompt is already in the
  // topic. `build(...tuple)` only needs to return an object with `prompt`.
  const topicTuples = (regular, gridTuples, build, extra = 30) => {
    const seen = new Set(regular.map((tuple) => build(...tuple).prompt));
    const picked = [];
    const candidates = [...spread(gridTuples, Math.min(extra, gridTuples.length)), ...gridTuples];
    for (const tuple of candidates) {
      if (picked.length === extra) break;
      const prompt = build(...tuple).prompt;
      if (seen.has(prompt)) continue;
      seen.add(prompt);
      picked.push(tuple);
    }
    if (picked.length < extra) throw new Error(`Only ${picked.length} fresh tuples for "${build(...regular[0]).prompt}"`);
    return [...regular, ...picked];
  };
  // Older courses (per-topic IDs): push all 40 of a topic through its template.
  const addTopic = (questions, idPrefix, regular, gridTuples, make) => {
    topicTuples(regular, gridTuples, (...t) => make('', ...t)).forEach((tuple, i) => {
      questions.push(make(`${idPrefix}-${i + 1}`, ...tuple));
    });
  };
  // Balanced mix of several grids (e.g. arithmetic + geometric sequences):
  // spread each to `each` tuples so one large grid can't crowd out the rest.
  const mixGrids = (each, ...grids) => grids.flatMap((g) => spread(g, Math.min(each, g.length)));
```

`generatedCourse` becomes:

```js
  // Each topic: [name, make(...params) → { prompt, answer, explanation, meta, tolerance }, regular(i) → params, gridTuples].
  // The original 60 come first with today's sequential IDs (<prefix>-1…60);
  // the 180 new ones follow as <prefix>-61…240, topic by topic.
  const generatedCourse = (prefix, topics) => {
    const questions = [];
    const push = (topic, item) => questions.push(qNumber(`${prefix}-${questions.length + 1}`, topic, item.prompt, item.answer, item.explanation, item.meta, item.tolerance));
    const all = topics.map(([topic, make, regular, gridTuples]) => [topic, make, topicTuples(regular10(regular), gridTuples, make)]);
    all.forEach(([topic, make, tuples]) => tuples.slice(0, 10).forEach((t) => push(topic, make(...t))));
    all.forEach(([topic, make, tuples]) => tuples.slice(10).forEach((t) => push(topic, make(...t))));
    return questions;
  };
```
