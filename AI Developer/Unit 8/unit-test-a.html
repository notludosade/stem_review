1. What is latency, as defined in Lesson 25?

elapsed = time.time() - start measures exactly this: the gap between sending a request and getting a result back.

2. Fill in the blank: Lesson 25 notes that a real API call has a genuine dollar cost, typically priced per ___ of input and output.

LLM API pricing is per-token, counting both what's sent in and what comes back out.

3. triage_ticket_cached computes key = hashlib.sha256(ticket_text.encode()).hexdigest() before checking the cache dictionary. Answer both parts:

(a) Why hash the ticket text into a fixed-length key first?

(b) Fill in the blank: storing a previous result so an identical future request skips repeating the work is called a ___.

(a) A hash gives identical inputs an identical key, so a repeat lookup reliably finds the same entry. (b) That store of previous results is a cache.

4. For a support-ticket tool where two tickets about the same issue are almost never worded identically, answer both parts:

(a) Why might triage_ticket_cached's hash-based cache rarely produce a hit in practice?

(b) Fill in the blank: the lesson suggests a smarter cache could instead be keyed on ___ from Unit 6, to catch near-duplicate wording, not just exact text.

(a) A hash-based cache only matches byte-identical text, which rarely happens for free-form ticket wording. (b) Embeddings-based similarity, unlike exact hashing, can recognize near-duplicate meaning.

5. What is drift, as defined in Lesson 26?

Drift is specifically the gap between training-time data and current real-world data widening over time.

6. Fill in the blank: continuously logging a deployed system's inputs, outputs, and performance over time, rather than checking it once and assuming that holds forever, is called ___.

That ongoing, continuous logging is exactly what monitoring is.

7. Six months after launch, the fraction of tickets triage_ticket_monitored labels "high" urgency has slowly climbed week over week, even though the actual tickets coming in haven't gotten more urgent. Answer both parts:

(a) What does this pattern most likely indicate?

(b) Fill in the blank: this kind of slow trend could never be noticed from a single request — it only shows up because of ongoing ___ of logged predictions over time.

(a) A steady trend with no real change in the underlying tickets is exactly the signal monitoring exists to catch. (b) Only continuous logging and review — monitoring — surfaces a trend like this.

8. PROMPT_VERSIONS stores every prompt version by name in a dictionary, rather than overwriting the current prompt in place. Why?

Overwriting the only copy of a prompt would make reverting to it impossible once a regression is caught.

9. PINNED_MODEL = "gpt-4o-mini-2024-07-18" is used instead of the movable name "gpt-4o-mini". Answer both parts:

(a) Why pin an exact, dated snapshot like this?

(b) Fill in the blank: using an exact, fixed model or prompt version instead of one that can change silently over time is called version ___.

(a) An unpinned alias can silently point to a different underlying model over time. (b) That practice of locking in an exact version is called version pinning.

10. Monitoring flags that ACTIVE_VERSION = "v2" is producing worse results than the previous prompt. Answer both parts:

(a) What is the correct next step, per Lesson 27?

(b) Fill in the blank: reverting to a previous known-good version once a new one is found to have regressed is called a ___.

(a) rollback() exists precisely for this — reverting fast instead of patching a regression under pressure. (b) That reversion is called a rollback.
