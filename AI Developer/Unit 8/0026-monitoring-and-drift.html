Monitoring and Drift

A model evaluated once, at launch, tells you nothing about how it's behaving six months later — and the real world it's judging keeps changing underneath it.

Lesson 27 → Contents Glossary →

Monitoring is continuously logging a deployed system's inputs, outputs, and performance over time, rather than checking it once and assuming that holds forever. Monitoring exists to catch drift: a gradual mismatch between what a model learned and the real-world data it now sees, which quietly degrades accuracy without any code ever actually changing.

Python — logging predictions for later review 
import json
from datetime import datetime, timezone

def triage_ticket_monitored(ticket_text):
    result = triage_ticket(ticket_text)   # from Lesson 23

    log_entry = {
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "input": ticket_text,
        "urgency": result["urgency"],
    }
    with open("triage_log.jsonl", "a") as f:
        f.write(json.dumps(log_entry) + "\n")

    return result

Every call appends one line to triage_log.jsonl — a simple, durable record of what came in and what the model decided. On its own, a single log entry proves nothing. The value shows up over time: if the fraction of tickets marked "high" urgency slowly climbs week over week with no real change in the tickets themselves, or if a human reviewer starts disagreeing with the model's calls more often than before, that's drift showing up in the data — a sign the model's original training no longer matches current reality closely enough, and it may need retraining, a better prompt, or a different approach entirely.

Definition Monitoring is continuously logging a deployed system's inputs, outputs, and performance over time. Drift is a gradual mismatch between what a model learned and the real-world data it currently encounters, degrading its performance without any code change.
Why it matters here Unit 2 built a test set specifically so evaluation would be honest and one-time — but "one-time" was only ever meant for development. Once deployed, the real world keeps moving, and only ongoing monitoring can catch a model quietly falling out of step with it. Lesson 27 asks what to actually do once drift, or any other regression, is caught.
