Human-in-the-Loop and Your Responsibility as a Developer

Bias can hide in data. Hallucination can hide behind fluent confidence. The last safeguard, when a decision actually matters, is never fully automating it away.

Contents Glossary →

Human-in-the-loop means a system is designed so a person reviews or confirms a model's output before it takes effect, rather than acting on it automatically — especially for decisions with real consequences for someone's life, money, health, or safety. Lesson 23's fallback already gestured at this: routing an uncertain case to a human rather than guessing was a deliberate design choice, not a limitation to eventually remove.

Python — routing high-stakes cases to a human 
def triage_ticket_with_review(ticket_text):
    result = triage_ticket_versioned(ticket_text)   # from Lessons 23 and 27

    consequential = result["urgency"] == "high"
    if consequential:
        result["needs_human_review"] = True
        # queued for a person to confirm before any automatic action is taken

    return result

Nothing about this code is technically difficult — the entire safeguard is the decision to add needs_human_review at all, for exactly the cases where being wrong matters most. That decision doesn't come from a training run or a metric; it comes from you, as the developer, judging which outputs are safe to automate fully and which ones genuinely need a person in the loop. No lesson in this course can make that judgment call for you on a real project — it depends on what's actually at stake.

Definition Human-in-the-loop is a system design where a person reviews or confirms a model's output before it takes effect, rather than the system acting on it fully automatically.
Why it matters here Computer Programming Ethics, Lesson 12, "When Code Should Refuse to Run," and Lesson 21's ethics checklist already cover a developer's responsibility for what their code does in the world — that reasoning applies in full here, and isn't re-derived. What Units 6 through 9 add is specific to AI: bias that hides inside training data instead of source code, hallucinations that sound exactly as confident right or wrong, and a need for human oversight precisely because these systems can act at a scale and speed no individual reviewer ever could.
