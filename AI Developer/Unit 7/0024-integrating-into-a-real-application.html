Integrating Into a Real Application

Lesson 23's function works when called directly in Python. A real user never calls a Python function directly — they submit a form, and something has to receive it.

Lesson 25 → Contents Glossary →

An API endpoint is a specific URL a web application listens on, ready to receive a request and return a response — the same idea as Lesson 18's chat completion endpoint, just one you build yourself instead of calling someone else's. Wiring triage_ticket behind one is mostly about input validation: checking that what actually arrived matches what the function expects, before it's ever passed in.

Python — FastAPI 
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()

class TicketRequest(BaseModel):
    text: str = Field(min_length=1, max_length=5000)

@app.post("/triage")
def triage_endpoint(request: TicketRequest):
    try:
        return triage_ticket(request.text)
    except Exception:
        raise HTTPException(status_code=502, detail="triage service unavailable")

TicketRequest declares exactly what a valid request looks like — a non-empty string no longer than 5000 characters. FastAPI checks every incoming request against this shape automatically, before triage_endpoint ever runs, and rejects anything that doesn't match with a clear error instead of letting bad input reach triage_ticket and fail in some more confusing way further in. Notice that triage_ticket itself, from Lesson 23, didn't need a single change to be reused here — that's exactly the payoff of having built and tested the core logic as a plain, separate function first.

Definition An API endpoint is a specific URL a web application listens on to receive a request and return a response. Input validation is checking that incoming data matches an expected shape before it's used.
