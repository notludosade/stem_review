Building the Core Logic

Take a concrete example that Lesson 22's reasoning actually points to: a support-ticket triage tool. Rules alone can't judge urgency from free-form text, and the task is specific enough that a general pretrained API doesn't fully solve it out of the box — so it needs a small amount of real logic layered on top of a chat completion call, asking for structured output: a response shaped as data, like JSON, rather than free-form prose that would need fragile parsing afterward.

Python — core triage logic 
import json
from openai import OpenAI

client = OpenAI()

def triage_ticket(ticket_text):
    try:
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            temperature=0,
            response_format={"type": "json_object"},
            messages=[
                {"role": "system", "content": (
                    'Classify the ticket urgency as "low", "medium", or "high" '
                    'and reply with JSON: {"urgency": "...", "reason": "..."}'
                )},
                {"role": "user", "content": ticket_text},
            ],
        )
        result = json.loads(response.choices[0].message.content)
        if result.get("urgency") not in ("low", "medium", "high"):
            raise ValueError("unexpected urgency value")
        return result
    except (json.JSONDecodeError, ValueError, KeyError):
        return {"urgency": "medium", "reason": "could not classify automatically"}

response_format={"type": "json_object"} tells the model to reply with valid JSON instead of ordinary prose, and the system message spells out the exact shape expected — this is few-shot prompting's cousin from Lesson 20, describing the desired structure directly rather than showing it through examples. But no external system is ever fully guaranteed to behave — the model could still return unexpected values, or the request could fail outright. The try/except block provides a fallback: a safe default result returned when something goes wrong, so one malformed response degrades to "flag this for a human" instead of crashing the whole tool.

Definition Structured output is a model response shaped as data, such as JSON, instead of free-form prose. A fallback is a safe default behavior used when the primary logic fails or returns something unexpected.
Why it matters here triage_ticket is a plain function with no web framework, no database, and no user interface anywhere in it — that's deliberate. Testing the core logic in isolation, with ordinary function calls and printed results, is far easier than testing it through a live application.
