1. A team wants to automatically flag emails as spam or not spam. Before touching any AI approach, what does Lesson 22 say they should build first?

A baseline is the simplest working solution, built first so anything fancier has something concrete to beat.

2. Fill in the blank: per Lesson 22's decision order, a task that is common and general — like translating a sentence — has likely already been solved well by a ___ API, making custom training unnecessary.

choose_approach checks task_is_common_and_general and points straight to a pretrained API before ever considering training something from scratch.

3. A developer wants a chat completion call to return {"category": "refund", "confidence": "high"} instead of a paragraph of prose. What should they ask the model for?

response_format={"type": "json_object"} is exactly this: it requests a shaped, parseable response instead of prose.

4. Fill in the blank: Lesson 23 writes triage_ticket as a plain function with no web framework in it specifically so the core logic can be ___ in isolation, before it's ever wired into a real application.

Testing a plain function with ordinary function calls is far easier than testing it through a live application.

5. A web application needs a specific URL that listens for incoming requests and returns a response. What is this called?

An API endpoint is exactly this: a specific URL a web application listens on to receive a request and return a response.

6. A developer is building a tool. Answer both parts about which approach to reach for first:

(a) If a handful of if-statements would already classify the input correctly, what does Lesson 22 recommend?

(b) Fill in the blank: whichever approach is chosen first should be evaluated as a ___ that any more complex approach must then beat.

(a) When rules alone genuinely solve the task, they're faster to build and easier to debug than any model. (b) That simplest working solution, built first for comparison, is exactly what a baseline is.

7. triage_ticket wraps its API call in a try/except block. Answer both parts:

(a) If the model returns malformed JSON that json.loads can't parse, what happens?

(b) Fill in the blank: this safe default behavior, used when the primary logic fails, is called a ___.

(a) The try/except block exists exactly for this: catching a bad response and returning something safe instead of crashing. (b) That safe default is called a fallback.

8. Inside triage_ticket, after parsing the JSON, the code checks: if result.get("urgency") not in ("low", "medium", "high"): raise ValueError(...). Answer both parts:

(a) Why is this check necessary even after the model was explicitly asked for one of those three values?

(b) Fill in the blank: an urgency value outside the three allowed categories triggers a ___, which the except block then catches.

(a) No external system, including a model asked for structured output, is fully guaranteed to behave as requested. (b) That check raises a ValueError, which the surrounding except block catches.

9. A FastAPI endpoint declares class TicketRequest(BaseModel): text: str = Field(min_length=1, max_length=5000). Answer both parts:

(a) What does this accomplish?

(b) Fill in the blank: checking that incoming data matches an expected shape before it's used is called input ___.

(a) FastAPI checks every incoming request against this shape automatically, rejecting anything that doesn't match. (b) That practice is called input validation.

10. triage_ticket, written in Lesson 23 with no web framework in it, is dropped into the FastAPI endpoint in Lesson 24 completely unchanged. Answer both parts:

(a) Why didn't it need any changes?

(b) Fill in the blank: separating a feature's core ___ from the application wiring around it is exactly what makes it reusable like this.

(a) It was built and tested as a self-contained function, independent of any web framework. (b) Keeping core logic separate from application wiring is exactly what makes it reusable.
