P vs. NP & Polynomial-Time Reductions

Every algorithm in this course so far ran in polynomial time. This unit asks the question those algorithms all quietly avoided: are there problems where no polynomial-time algorithm exists at all — or is even believed to?

← Lesson 29 Lesson 31 → Contents Glossary →

Every algorithm this course has built — sorting, shortest paths, max-flow, string matching, segment trees — runs in time polynomial in its input size, and that has always been treated as the mark of "efficiently solvable." This unit studies problems where no polynomial-time algorithm is known, and asks whether that's a gap in human cleverness or a genuine mathematical wall. The tool for making that question precise is the polynomial-time reduction: a way of proving one problem is "at least as hard as" another, without solving either.

Two classes of decision problem

P — polynomial time P is the class of decision problems (yes/no questions) solvable by some algorithm running in O(nᵏ) time for a constant k, where n is the input size. Every problem this course solved efficiently — is this graph connected, what's the shortest path, does this pattern occur in this text — is in P: an explicit polynomial-time algorithm was given for each.
NP — nondeterministic polynomial time NP is the class of decision problems where, whenever the answer is "yes," there exists a certificate (a piece of evidence) that can be verified in polynomial time — even if no one knows how to find that certificate quickly. For example: "does this graph have a Hamiltonian cycle?" has no known polynomial-time algorithm to answer, but if the answer is yes, a proposed cycle is a certificate that's trivial to check in O(n) time (walk it, confirm every edge exists and every vertex appears exactly once).
Why P ⊆ NP Every problem in P is also in NP: if a decision problem can be solved outright in polynomial time, then "verifying" a yes-answer can simply ignore whatever certificate is offered and re-solve the problem from scratch in the same polynomial time. The open question that gives this unit its name is whether the containment goes the other way too — whether every problem whose yes-answers are efficiently checkable is also efficiently solvable. This is the P vs. NP problem, one of the seven Clay Millennium Prize problems, unresolved since it was first posed in the 1970s.

Polynomial-time reductions — comparing hardness without solving anything

Definition Problem A reduces to problem B in polynomial time (written A ≤ₚ B) if there is a polynomial-time algorithm that transforms any instance of A into an instance of B, such that the transformed instance is a "yes" for B exactly when the original instance was a "yes" for A. Critically, the reduction only transforms the input — it never actually solves A or B.
Why a reduction transfers hardness, not easiness If A ≤ₚ B, then a polynomial-time algorithm for B immediately gives one for A: transform the A-instance into a B-instance (polynomial time), solve it with B's algorithm, and return that answer. Reading this contrapositively is the entire point of this unit: if A is known to have no polynomial-time algorithm, then B can't have one either — because if it did, chaining it after the reduction would give A one too, a contradiction. A ≤ₚ B says "B is at least as hard as A," which is exactly the tool needed to prove one problem is hard by relating it to another already known to be hard.
Worked example — Independent Set ≤ₚ Vertex Cover Independent Set: does graph G=(V,E) have a set of k vertices, no two adjacent? Vertex Cover: does G have a set of k vertices touching every edge? The reduction: given (G, k) for Independent Set, output (G, |V|−k) for Vertex Cover — same graph, transformed integer. This is correct because S is an independent set of G exactly when V∖S is a vertex cover of G (no edge has both endpoints in S means every edge has at least one endpoint in V∖S, and vice versa). The transformation is O(1) — it doesn't even touch the graph, only the number k — so Independent Set ≤ₚ Vertex Cover: an efficient algorithm for one immediately gives one for the other.
Why this course cares about reductions specifically A reduction is a completely different proof tool than anything used in earlier units. Units 1–7 proved upper bounds — "this algorithm solves this problem in this much time." A reduction proves a relative claim — "this problem is at least as hard as that one" — without ever exhibiting an algorithm at all. Lesson 31 uses exactly this tool, at scale, to show that an enormous number of natural problems (scheduling, packing, satisfiability, routing) are all, in a precise sense, exactly as hard as each other.

1. What does it mean for a decision problem to be in NP?

NP is about efficient verifiability of a yes-answer's certificate, not about how the answer itself is found.

2. Why does P ⊆ NP hold?

Solvability in polynomial time trivially implies verifiability in polynomial time, which is exactly the containment direction that's settled.

3. If A ≤ₚ B, and A is known to have no polynomial-time algorithm, what can be concluded about B?

This contrapositive reading is the entire mechanism by which reductions transfer known hardness from one problem onto another.

4. Fill in the blank: a problem is in NP if every "yes" instance has a ___ that can be checked in polynomial time, even when finding one isn't known to be efficient.

The certificate is the piece of evidence a verifier checks; NP membership is entirely about this checking step being fast.

5. Fill in the blank: a polynomial-time ___ transforms instances of one problem into instances of another, preserving the yes/no answer, without solving either problem directly.

The reduction is purely a transformation of input, which is exactly what lets it transfer hardness between problems.
