Common NP-Complete Problems

Cook-Levin proved SAT is NP-complete directly, from the definition of NP itself. Every problem in this lesson is proven NP-complete the easier way — a short reduction from SAT, 3-SAT, or another problem already known to be NP-complete.

← Lesson 31 Lesson 33 → Contents Glossary →

Lesson 31 established SAT (and 3-SAT) as NP-complete via Cook-Levin's direct construction. This lesson chains outward from that seed: 3-SAT ≤ₚ Independent Set, Independent Set ≤ₚ Vertex Cover (already shown in Lesson 30), Hamiltonian Cycle is NP-complete by a separate reduction from 3-SAT, and — the problem this course has been building toward since Lesson 19 — the traveling salesman problem is NP-complete via a short reduction from Hamiltonian Cycle.

3-SAT ≤ₚ Independent Set

The construction Given a 3-SAT formula with k clauses, build a graph with one triangle of 3 vertices per clause (one vertex per literal in that clause), plus an edge between any two vertices representing a literal and its negation (e.g. x₁ in one clause's triangle and ¬x₁ in another's). Claim: the formula is satisfiable exactly when this graph has an independent set of size k.
Why this reduction is correct An independent set can contain at most one vertex per triangle (any two vertices within a triangle are connected), so a size-k independent set must pick exactly one literal per clause — satisfying that clause. The cross-triangle edges between a literal and its negation prevent the independent set from picking contradictory truth values for the same variable across different clauses. So a size-k independent set corresponds exactly to choosing one true literal per clause with no variable assigned inconsistently — precisely a satisfying assignment. Since Independent Set is trivially in NP (a candidate set is a certificate, checkable in polynomial time by confirming no two chosen vertices are adjacent), and 3-SAT is NP-hard, this reduction makes Independent Set NP-complete too.
Vertex Cover is NP-complete "for free," by transitivity Lesson 30 showed Independent Set ≤ₚ Vertex Cover. Reductions chain: since every NP problem reduces to Independent Set (Independent Set is now known NP-hard), and Independent Set reduces to Vertex Cover, every NP problem reduces to Vertex Cover too — making Vertex Cover NP-hard, and (since a candidate cover is a trivially checkable certificate) NP-complete. No new construction was needed; transitivity of reductions did the entire proof.

Hamiltonian Cycle

Statement (proof cited, not reproduced) Given a graph G, does it contain a cycle visiting every vertex exactly once? Hamiltonian Cycle is NP-complete, via a reduction from 3-SAT that's more involved than the Independent Set construction above (it builds elaborate per-variable and per-clause "gadget" subgraphs) — see the citation below for the full construction.

The traveling salesman problem, finally proven NP-complete

Hamiltonian Cycle ≤ₚ TSP (decision version) Given a graph G=(V,E) (a Hamiltonian Cycle instance), build a complete weighted graph on the same vertices: edge weight 1 if the edge is in E, weight 2 if it isn't. Ask the TSP decision question: is there a tour visiting every vertex with total weight ≤ |V|? Since |V| edges are traversed in any tour, a tour of weight exactly |V| must use only weight-1 edges — meaning it only uses edges of the original graph G, exactly a Hamiltonian cycle in G. A tour using even one weight-2 edge costs at least |V|+1. So a tour of weight ≤ |V| exists exactly when G has a Hamiltonian cycle.
This is Lesson 19's promised answer Lesson 19 introduced bitmask DP for TSP, noting it was one of Unit 8's "canonical NP-hard problems," with the precise reason deferred to this lesson. That reason is exactly the reduction above: Hamiltonian Cycle (already NP-complete, via 3-SAT) reduces to TSP's decision version in polynomial time (the weight-assignment step touches every edge once, so it's O(|V|²) for a complete graph), and TSP is in NP (a proposed tour is a certificate, checkable in O(|V|) time by summing its edge weights) — making TSP NP-complete. Bitmask DP's Θ(n²·2ⁿ) runtime was never in tension with this: it's still exponential, just a better exponential than brute force's Θ(n!).
Other well-known NP-complete problems (stated, not proven here) Subset Sum (does some subset of a set of integers sum to exactly a target value?) reduces from 3-SAT via a clever digit-encoding construction. Graph Coloring (can a graph's vertices be colored with k colors so no edge joins two same-colored vertices?) reduces from 3-SAT for any k≥3. Both follow the same pattern as everything above: pick a problem already known NP-complete, and reduce it into the new problem in polynomial time.

Check your recall

No peeking back up — answer from memory first, then check.

1. In the 3-SAT ≤ₚ Independent Set reduction, why can an independent set contain at most one vertex from any single clause's triangle?

Triangle edges force at most one vertex per clause to be selected, which is exactly what makes each selected vertex correspond to one satisfied literal per clause.

2. Why does Vertex Cover become NP-complete "for free" once Independent Set is shown NP-complete?

Transitivity of reductions is precisely what lets a single new reduction (Independent Set to Vertex Cover) inherit NP-hardness from Independent Set's already-established hardness.

3. In the Hamiltonian Cycle ≤ₚ TSP reduction, why does a tour of total weight exactly |V| correspond precisely to a Hamiltonian cycle in the original graph?

Since |V| edges are always traversed, hitting exactly weight |V| forces every single edge used to be weight 1, i.e. an edge that actually exists in G.

4. Fill in the blank: chaining A ≤ₚ B and B ≤ₚ C to conclude A ≤ₚ C relies on the ___ of polynomial-time reductions.

Transitivity is exactly what let Vertex Cover inherit NP-hardness without a fresh from-scratch construction.

5. Fill in the blank: TSP's decision version is proven NP-complete by a polynomial-time reduction from ___, using a 1-vs-2 edge weight trick.

This is exactly the reduction Lesson 19 deferred — the precise reason TSP has no known polynomial-time algorithm.
