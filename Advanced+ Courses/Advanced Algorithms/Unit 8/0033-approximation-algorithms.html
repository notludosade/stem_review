Approximation Algorithms

NP-hard problems have no known polynomial-time algorithm for an exact answer. This lesson asks the practical follow-up: what provable guarantee can a fast algorithm still make, if not exactness?

← Lesson 32 Lesson 34 → Contents Glossary →

Lesson 32 showed Vertex Cover, TSP, and a family of related problems are NP-complete — no polynomial-time algorithm is known to solve them exactly. But "no exact algorithm" doesn't mean "nothing useful can be computed." An approximation algorithm runs in polynomial time and returns a solution provably within some bounded factor of the true optimum, even without ever computing that optimum directly.

Approximation ratio

Definition For a minimization problem, an algorithm is a c-approximation (c ≥ 1) if, for every instance, it runs in polynomial time and returns a solution of cost at most c times the true optimal cost OPT. (For maximization, the inequality flips: at least OPT/c.) Smaller c is a stronger guarantee; c=1 would mean solving the problem exactly.

Vertex Cover — a 2-approximation via a matching argument

Algorithm 
function approxVertexCover(G):
    C = {}
    E' = copy of G.edges
    while E' is not empty:
        pick any edge (u, v) from E'
        add u and v to C
        remove every edge in E' touching u or v
    return C
Why this is a 2-approximation Let M be the set of edges actually picked by the loop. No two edges in M share an endpoint — the moment an edge is picked, every edge touching either of its endpoints is removed, so the next pick can't share a vertex with it. That makes M a matching. Any vertex cover — including the optimal one — must include at least one endpoint from every edge in M (since M's edges still need covering), and since M's edges are pairwise disjoint, covering all of them requires at least |M| distinct vertices: OPT ≥ |M|. The algorithm's cover C has exactly 2|M| vertices (both endpoints of every picked edge), so |C| = 2|M| ≤ 2·OPT — a 2-approximation, using nothing more than counting a matching's disjointness.

LP relaxation and rounding — a second route to the same guarantee

Vertex Cover as an integer program Vertex Cover can be written as: minimize Σxᵥ subject to xᵤ+xᵥ ≥ 1 for every edge (u,v), and xᵥ ∈ {0,1} for every vertex. This is an integer linear program (ILP) — solving it exactly is exactly as hard as Vertex Cover itself (it's the same problem, just written algebraically). But relaxing the integrality constraint to 0 ≤ xᵥ ≤ 1 turns it into a genuine linear program (LP), solvable in polynomial time by standard LP methods.
Why the LP's optimal value bounds the true optimum — this is the "LP duality's cousin" Lesson 17 pointed to Every feasible integer solution (every xᵥ ∈ {0,1} satisfying the constraints) is also a feasible fractional solution (0 ≤ xᵥ ≤ 1 is satisfied by any 0/1 value). So the LP's feasible region is a strict superset of the ILP's, meaning the LP's minimum can only be less than or equal to the ILP's minimum: LP_OPT ≤ ILP_OPT. This is exactly the same style of reasoning Lesson 17 used for max-flow min-cut — a second, differently-structured problem (there, a cut; here, a relaxed LP) whose value certifies a bound on the first problem's optimum without solving the first problem directly. Max-flow min-cut got an exact certificate (equality); LP relaxation only gets a one-sided bound — but that's still exactly enough to prove an approximation ratio, since it substitutes for OPT in the argument below.
Rounding Solve the LP relaxation to get fractional xᵥ* values, then round: set xᵥ=1 if xᵥ* ≥ 0.5, else xᵥ=0. Every constraint xᵤ+xᵥ ≥ 1 is still satisfied after rounding — for any edge, xᵤ*+xᵥ* ≥ 1 means at least one of xᵤ*, xᵥ* is ≥ 0.5, so at least one of xᵤ, xᵥ rounds to 1. The rounded solution is a valid vertex cover.
Why rounding also gives a 2-approximation Rounding a variable to 1 only happens when its fractional value was ≥ 0.5 — so each rounded variable contributes at most 2× its fractional value to the cost. Summed over all vertices, the rounded solution's cost is at most 2·(LP optimal cost), which is at most 2·OPT (from the bound above). Two entirely different algorithms — the matching-based greedy loop and LP-relaxation-with-rounding — land on the identical 2-approximation guarantee, via genuinely different arguments.
Approximability is not uniform across NP-hard problems Not every NP-hard problem admits as clean a guarantee as Vertex Cover's factor of 2. TSP with the triangle inequality (edge weights satisfying d(a,c) ≤ d(a,b)+d(b,c)) has a 1.5-approximation (Christofides' algorithm); general TSP (no triangle inequality) has no polynomial-time constant-factor approximation at all, unless P=NP — a fact provable via a reduction from Hamiltonian Cycle similar in spirit to Lesson 32's. Approximability itself turns out to be a rich hierarchy, not a single fallback bolted onto every hard problem.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does it mean for an algorithm to be a "2-approximation" for a minimization problem?

The approximation ratio is a worst-case multiplicative bound on solution cost relative to the true optimum, holding for every instance.

2. In the greedy Vertex Cover algorithm, why does OPT ≥ |M| for the matching M of picked edges?

The pairwise-disjoint structure of a matching is exactly what forces any valid cover to spend at least one vertex per matched edge.

3. Why does LP_OPT ≤ ILP_OPT hold for the Vertex Cover relaxation?

A superset feasible region for a minimization problem can only produce a value at or below the more constrained integer optimum.

4. Fill in the blank: the greedy Vertex Cover algorithm's approximation guarantee relies on the picked edges forming a ___ — a set of edges with no shared endpoints.

The matching's pairwise-disjoint edges are exactly what forces any cover to spend at least one vertex per picked edge.

5. Fill in the blank: the LP-rounding scheme sets xᵥ=1 exactly when the fractional solution's xᵥ* is at least ___, which is what keeps every constraint satisfied after rounding.

Since xᵤ*+xᵥ* ≥ 1 for every edge, at least one endpoint must have fractional value ≥ 0.5, guaranteeing it rounds up to 1.
