Kruskal's & Prim's Algorithms

Two greedy algorithms that look nothing alike — one grows a forest by cheapest edge globally, the other grows a single tree by cheapest edge locally — both provably build a minimum spanning tree.

← Lesson 9 Lesson 11 → Contents Glossary →

CP2+'s Unit 6 covered Union-Find as a data structure (Lesson 21, "Union-Find & Redundant Connection") without proving anything about its amortized cost — that proof is Unit 6 of this course. Here, Union-Find gets used as a tool inside a genuinely different problem: given a connected, weighted, undirected graph, find a minimum spanning tree (MST) — a subset of edges connecting all vertices with no cycles, of minimum total weight. Two classic greedy algorithms solve it, and this lesson's job is to state both precisely; the next lesson proves both correct at once with a single unifying theorem.

Kruskal's algorithm — global greedy over edges

Algorithm 
function kruskal(graph):
    sort all edges by weight, ascending
    initialize Union-Find with each vertex in its own set
    mst = []
    for (u, v, weight) in sorted edges:
        if find(u) != find(v):        // adding this edge creates no cycle
            union(u, v)
            append (u, v, weight) to mst
    return mst
Why Union-Find is exactly the right tool here Kruskal's algorithm needs to answer one repeated question: would adding this edge create a cycle? Two vertices already in the same connected component would form a cycle if joined again; two vertices in different components never would. That's exactly the "same set or different sets" query Union-Find answers in (amortized, per Unit 6) near-constant time — without it, checking for a cycle after each candidate edge would require a full graph traversal, costing Θ(V+E) per check instead of near Θ(1).

Prim's algorithm — local greedy from a growing tree

Algorithm 
function prim(graph, start):
    visited = {start}
    mst = []
    while visited does not cover all vertices:
        find the minimum-weight edge (u, v) with u in visited, v not in visited
        add (u, v) to mst
        add v to visited
    return mst
Why Prim's needs a priority queue, and where it echoes CP2+ Prim's repeated "find the minimum-weight edge crossing the visited boundary" is structurally the same operation Dijkstra's algorithm performs when it repeatedly extracts the closest unvisited vertex (CP2+ Lesson 22, "Dijkstra's Algorithm & Network Delay Time") — both maintain a priority queue of candidate edges/distances and repeatedly extract the minimum. The difference is what each algorithm optimizes: Dijkstra tracks cumulative distance from a fixed source; Prim tracks a single edge's own weight, with no accumulation at all. Recognizing this shared "grow a frontier via a priority queue" shape is exactly the kind of structural pattern-matching CP2+ trained and this course now formalizes with a proof.
Runtime Kruskal's: sorting all E edges costs Θ(E log E); each of the E Union-Find operations costs amortized near-Θ(1) (proved in Unit 6), for total Θ(E log E). Prim's, implemented with a binary heap priority queue: each of the V vertex extractions costs O(log V), and each of the E edges may trigger one heap update at O(log V), for total O(E log V). Both are close to Θ(E log V) in practice — the choice between them in practice usually comes down to graph density (Kruskal's favors sparse graphs; Prim's with a heap favors denser ones) rather than a fundamental asymptotic gap.
Why they can produce different-looking MSTs on the same graph If a graph has ties in edge weight, Kruskal's and Prim's may build genuinely different trees (both minimum-weight overall, but different in which edges appear) depending on tie-breaking order. This is expected, not a bug: a minimum spanning tree need not be unique whenever edge weights repeat — only its total weight is guaranteed identical across every valid MST, a fact the next lesson's cut property makes precise.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does Kruskal's algorithm use Union-Find instead of a full graph traversal to check for cycles?

Union-Find's near-Θ(1) same-set query is exactly what a repeated cycle-check needs — a full traversal would work but be far more expensive to repeat on every candidate edge.

2. What structural feature does Prim's algorithm share with Dijkstra's algorithm?

The shared shape is a priority-queue-driven frontier expansion; the difference is what quantity is minimized (single edge weight for Prim's, cumulative path distance for Dijkstra's).

3. Why can Kruskal's and Prim's produce different-looking spanning trees on the same graph, and why isn't that a contradiction?

An MST is only guaranteed unique in total weight, not in exact edge set, whenever ties in edge weight exist — both algorithms are correct even when they disagree on which edges to include.

4. Fill in the blank: Kruskal's algorithm only skips an edge when adding it would create a ___ , which Union-Find detects via a same-set query.

Two vertices already in the same Union-Find set are already connected, so joining them again would close a cycle rather than extend the tree.

5. Fill in the blank: Prim's algorithm relies on a ___ to efficiently find the minimum-weight edge crossing the visited/unvisited boundary at each step.

A priority queue (typically a binary heap) is what makes repeated minimum-edge extraction efficient, echoing the exact structure Dijkstra's algorithm uses for its own repeated minimum-distance extraction.
