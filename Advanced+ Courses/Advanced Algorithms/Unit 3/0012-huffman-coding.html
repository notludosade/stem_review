Huffman Coding

A greedy algorithm for building the shortest possible prefix-free binary code for a set of symbols with known frequencies — proved optimal with the same exchange-argument machinery as interval scheduling and MSTs.

← Lesson 11 Lesson 13 → Contents Glossary →

Fixed-length encoding gives every symbol the same number of bits, regardless of how often it appears. If some symbols are far more common than others, a prefix-free code (no codeword is a prefix of another, so a bitstream can be decoded unambiguously without delimiters) that assigns shorter codewords to more frequent symbols can compress the total encoding significantly. Huffman coding builds an optimal such code, greedily, by repeatedly merging the two least-frequent symbols into a combined node — and it closes this unit by applying the exact exchange-argument proof pattern from Lessons 9 and 11 to a genuinely different kind of problem.

The algorithm

Algorithm 
function huffman(symbols, frequencies):
    create a leaf node for each symbol, with its frequency, inserted into a min-priority queue
    while priority queue has more than one node:
        left = extract-min(queue)
        right = extract-min(queue)
        merged = new internal node with weight = left.weight + right.weight
        merged.left = left, merged.right = right
        insert merged into queue
    return the single remaining node as the root of the code tree
    // codeword for each symbol = path from root to its leaf (0 = left, 1 = right)
Worked example Symbols A:5, B:9, C:12, D:13, E:16, F:45 (frequencies). Merge the two smallest, A(5)+B(9)=14. Queue now: 14, C:12, D:13, E:16, F:45. Merge two smallest: C(12)+D(13)=25. Queue: 14, 25, E:16, F:45. Merge two smallest: 14+E(16)=30. Queue: 25, 30, F:45. Merge: 25+30=55. Queue: 55, F:45. Merge: 55+45=100 — done. Tracing paths from the root gives F (the most frequent symbol) a 1-bit code, while A and B (the least frequent) get 4-bit codes — exactly the frequency-weighted trade-off the algorithm is designed to produce.
Theorem — Huffman coding produces an optimal prefix-free code Among all prefix-free binary codes for a given symbol/frequency set, the Huffman tree minimizes the total encoded length ∑(frequency(s) · depth(s)) over all symbols s.
Proof sketch — exchange argument, again Key lemma: in some optimal code tree, the two least-frequent symbols are siblings at the maximum depth. Proof: take any optimal tree; if the two least-frequent symbols x, y are not already siblings at max depth, find whichever symbols are at max depth (call them p, q) and swap: exchange x with p and y with q in the tree. Since x, y have the smallest frequencies and p, q were already at the deepest level (depth ≥ depth of x, y in the original tree), this swap cannot increase the total weighted depth — an exchange-argument step identical in spirit to Lesson 9's interval-scheduling swap. Repeating (or directly constructing) this shows some optimal tree has x, y as deepest siblings — exactly the pair Huffman's algorithm merges first. Once merged into a single node of combined weight, the remaining problem is identical in structure to the original but with one fewer symbol — an inductive step (Lesson 5's strong induction, reapplied) completes the argument: if merging the two smallest is optimal for n symbols assuming it's optimal for n−1, it's optimal for all n.
Runtime n−1 merges, each doing two extract-min and one insert on a binary heap of size O(n), giving Θ(n log n) total — dominated by the priority queue operations, the same building block Prim's algorithm (Lesson 10) relies on for its own frontier extraction.
Why this closes the unit Three different-looking problems — interval scheduling, minimum spanning trees, optimal prefix codes — turned out to share the exact same proof technique: assume an optimal solution differs from greedy's, exhibit a specific non-worsening swap, and conclude by induction that greedy matches optimal. Recognizing "this is a greedy problem" is a CP2+-level pattern-matching skill; recognizing "this greedy problem can be proven correct with an exchange argument, and here's the specific swap" is the rigor this unit adds on top of it.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does Huffman's algorithm merge the two least-frequent symbols first, rather than the two most-frequent?

Rare symbols should get the longest codewords since they contribute least to the total encoded length per extra bit; merging the two smallest first is exactly what pushes them deepest in the resulting tree.

2. What does the key lemma in Huffman's correctness proof establish?

This lemma is exactly what licenses Huffman's first greedy move — merging the two least-frequent symbols — as consistent with some optimal solution.

3. After the key lemma, what completes Huffman's correctness proof?

The lemma justifies the first merge; strong induction (Lesson 5) on the shrinking symbol set is what extends that single-step justification into a proof for all n.

4. Fill in the blank: Huffman coding builds a ___ code, meaning no codeword is ever a prefix of another, allowing unambiguous decoding without delimiters.

The prefix-free property is exactly what a binary tree's leaf-only-codeword structure guarantees, since no leaf's root-path can be a prefix of another leaf's root-path.

5. Fill in the blank: Huffman's Θ(n log n) runtime comes from repeated extract-min and insert operations on a ___ , the same structure Prim's algorithm relies on.

Both algorithms lean on the same O(log n)-per-operation priority queue machinery, just applied to different quantities (edge weight for Prim's, merged node weight for Huffman's).
