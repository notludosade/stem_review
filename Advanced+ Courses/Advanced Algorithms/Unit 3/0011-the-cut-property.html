The Cut Property

One theorem about graph cuts proves Kruskal's and Prim's correct simultaneously, even though the two algorithms don't look like they're doing the same thing at all.

← Lesson 10 Lesson 12 → Contents Glossary →

A cut of a graph is a partition of its vertices into two nonempty sets S and V−S. An edge crosses the cut if it has one endpoint in each set. The cut property is a single statement about cuts and minimum spanning trees that, once proved, immediately certifies both Kruskal's and Prim's algorithms as correct — because both algorithms, at every step, are doing nothing more than repeatedly applying this one property.

The theorem

Theorem — the cut property For any cut (S, V−S) of a connected weighted graph, if edge e is the unique minimum-weight edge crossing that cut, then e belongs to every minimum spanning tree of the graph.
Proof — by exchange argument (Lesson 9's technique, reapplied) Suppose for contradiction that some MST T does not contain e. Adding e to T creates exactly one cycle (T is a spanning tree, so adding any edge not already in it closes exactly one cycle). Since e crosses the cut (S, V−S), and the cycle it creates must cross back, that cycle contains at least one other edge f that also crosses the cut (a cycle crossing a partition must cross it an even number of times, so at least twice — once via e). Since e is the unique minimum-weight edge crossing the cut, weight(f) > weight(e). Remove f and keep e: T′ = T − f + e is still a spanning tree (removing f breaks the cycle back into a tree, and e keeps it connected), and weight(T′) = weight(T) − weight(f) + weight(e) < weight(T). This contradicts T being minimum. So e must be in every MST after all.
How Kruskal's algorithm is just repeated application of this theorem When Kruskal's algorithm considers the next edge e (sorted by weight, ascending) and finds find(u) ≠ find(v), let S be u's current connected component in the partially-built forest. Every edge considered so far either was rejected (both endpoints already in the same component) or added (crossing some earlier cut); e is the minimum-weight edge among all edges not yet considered, and it crosses the cut (S, V−S) — so it is, at this moment, the minimum-weight edge crossing that cut among remaining candidates, satisfying the cut property's hypothesis (ties are handled by an arbitrary but fixed tie-break, which the proof accommodates by considering e "a" minimum edge rather than requiring strict uniqueness). The cut property guarantees e belongs to some MST, so adding it is always safe.
How Prim's algorithm is the same theorem from the other side At every step of Prim's algorithm, let S be the set of visited vertices and V−S the rest. Prim's picks the minimum-weight edge crossing exactly this cut (S, V−S) by construction. That is a direct, literal instance of the cut property's hypothesis — Prim's algorithm doesn't need a separate correctness proof at all; it's reading the cut property off a differently-shaped cut (visited vs. unvisited) than Kruskal's does (one connected component vs. the rest), and drawing the identical conclusion each time.
Why one theorem unifies two very different-looking algorithms Kruskal's and Prim's look unrelated — one sorts all edges globally and grows a forest, the other grows a single tree greedily from one starting vertex — but the cut property shows they're both just choosing, at each step, a cut and then taking its minimum crossing edge. The only difference is which cut each algorithm happens to look at on a given step. This is exactly the kind of unifying structural insight this course is built to surface: two algorithms that seem to require two separate correctness arguments turn out to need only one, once you find the right level of abstraction.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does the cut property state?

The cut property is specifically about the minimum-weight edge crossing a given cut being forced into every MST, which is the fact both Kruskal's and Prim's exploit at every step.

2. In the cut property's proof, why does swapping f for e strictly decrease the spanning tree's weight?

The uniqueness of e as the minimum crossing edge is exactly what forces weight(f) > weight(e), which is what makes the swap strictly improve the tree and produce the needed contradiction.

3. Why does Prim's algorithm not need its own separate correctness proof beyond the cut property?

Prim's step is exactly "take the minimum edge crossing this particular cut," which the cut property already certifies as belonging to some MST — no additional argument is needed.

4. Fill in the blank: adding edge e to a spanning tree T that doesn't already contain it creates exactly one ___ , since T was already fully connected without it.

A spanning tree already connects every vertex with the minimum number of edges, so any extra edge necessarily closes exactly one cycle rather than zero or more than one.

5. Fill in the blank: Kruskal's and Prim's differ only in which ___ they examine at each step — Kruskal's uses connected components, Prim's uses visited-versus-unvisited.

Both algorithms are repeatedly applying the same cut property; the only difference is the specific partition of vertices each one happens to be looking at on a given step.
