Suffix Arrays, First Look

KMP and Rabin-Karp both answer one query — where does this one pattern occur? — against a text they scan fresh each time. A suffix array preprocesses the text once, then answers any pattern query against it in O(m log n).

← Lesson 28 Lesson 30 → Contents Glossary →

Both KMP (Lesson 27) and Rabin-Karp (Lesson 28) answer "does pattern P occur in text T?" by scanning T once per query, at Θ(n+m) each. If the same text T is queried against hundreds or thousands of different patterns — a genuinely common situation (a search engine's index, a genome being queried against many candidate gene sequences) — repeating a full Θ(n) scan every time is wasteful. A suffix array preprocesses T once into a sorted structure that then answers any single pattern query in O(m log n), independent of n beyond that one-time preprocessing cost.

The structure

Definition The suffix array of a string T (length n) is an array SA[0..n−1] of the integers 0..n−1, permuted so that T's suffixes, starting at each of those positions, appear in sorted (lexicographic) order. That is, T[SA[0]..], T[SA[1]..], ..., T[SA[n−1]..] is the list of all n suffixes of T, sorted alphabetically. SA itself stores only the starting positions, not the suffix strings — those are implicit, recoverable from T and a starting index.
Worked example For T = "banana" (append a sentinel character smaller than everything, conventionally "$", giving "banana$"), the 7 suffixes are: "banana$" (0), "anana$" (1), "nana$" (2), "ana$" (3), "na$" (4), "a$" (5), "$" (6). Sorted alphabetically: "$" (6), "a$" (5), "ana$" (3), "anana$" (1), "banana$" (0), "na$" (4), "nana$" (2). So SA = [6, 5, 3, 1, 0, 4, 2].
Why a sorted array of suffixes answers pattern queries Every occurrence of pattern P in T is, by definition, the start of some suffix of T that begins with P. Since SA sorts every suffix alphabetically, every suffix starting with P occupies one contiguous block within SA (identical to how every word starting with a given prefix sits contiguously in a sorted dictionary) — so finding all occurrences of P reduces to binary search for the boundaries of that block, comparing P against the suffix at SA[mid] at each step. Each comparison costs O(m) (comparing P against up to m characters of a suffix), and binary search takes O(log n) steps, giving O(m log n) total per query — no re-scan of the whole text required.
Binary search using the suffix array 
function search(T, SA, P):
    lo, hi = 0, |SA|
    while lo < hi:                              // find leftmost suffix >= P
        mid = (lo + hi) / 2
        if suffixAt(T, SA[mid]) < P: lo = mid + 1
        else: hi = mid
    // lo is now the first index whose suffix could start with P;
    // a second, mirrored binary search finds the right boundary,
    // and every SA[i] between the two boundaries is a match position
The cost this defers to preprocessing Building a suffix array by sorting all n suffixes with a naive comparison sort costs O(n² log n) (each of O(n log n) comparisons costs up to O(n) to compare two suffixes character by character) — expensive, but paid only once per text, not once per query. (Faster O(n log n) and even O(n) construction algorithms exist, using techniques beyond this lesson's scope — cited below — but even the naive construction already pays off once enough pattern queries are asked against the same fixed text.) This is the same "pay more upfront, save on every repeated query" trade-off Lesson 22's segment tree makes relative to re-scanning an array from scratch on every range query.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does a suffix array SA[0..n−1] store?

SA stores integer starting positions only; the suffixes themselves stay implicit, recoverable from T plus a position.

2. Why do all occurrences of a pattern P in T correspond to a single contiguous block within the suffix array?

Lexicographic sorting groups every suffix sharing a given prefix into one contiguous run, exactly what makes binary search for the block's boundaries valid.

3. Why is a suffix array preferred over repeating KMP or Rabin-Karp when many different patterns will be searched against the same fixed text?

Amortizing a one-time preprocessing cost across many queries is exactly the trade-off that makes suffix arrays worthwhile when query count is high.

4. Fill in the blank: a ___ stores the starting positions of every suffix of a text, sorted so that the suffixes they reference appear in lexicographic order.

This is the structure's defining property and the source of its name.

5. Fill in the blank: once a suffix array is built, a pattern query finds all matches by performing a ___ over the sorted suffixes to locate the contiguous block starting with the pattern.

Binary search over the sorted array is what turns the query cost into O(m log n) instead of a linear rescan.
