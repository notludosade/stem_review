Knuth-Morris-Pratt (KMP)

Naive substring search re-scans from scratch after every mismatch, costing Θ(nm) in the worst case. KMP precomputes exactly how much of a partial match can be reused after a mismatch, bringing search down to Θ(n+m).

← Lesson 26 Lesson 28 → Contents Glossary →

The substring search problem: given a text of length n and a pattern of length m, find every position where the pattern occurs in the text. The naive approach tries every starting position i in the text, comparing the pattern character-by-character against text[i..i+m−1], giving up and moving to i+1 on the first mismatch. Worst case (e.g. text "aaaaaaaaab" against pattern "aaab"), this touches Θ(m) characters at nearly every one of Θ(n) starting positions, for Θ(nm) total. Knuth-Morris-Pratt (KMP) exploits a simple observation the naive approach throws away: when a mismatch happens partway through a match, the characters already matched tell you something about the text — enough to skip ahead without ever re-examining a text character already looked at.

The failure function — the pattern's self-knowledge

Definition For a pattern P of length m, define the failure function (also called the LPS array, for "longest proper prefix which is also a suffix") lps[i] = the length of the longest proper prefix of P[0..i] that is also a suffix of P[0..i], for each i from 0 to m−1. ("Proper" means not the entire string P[0..i] itself.) For example, for P = "ababd": lps[0]=0 (single character, no proper prefix), lps[1]=0 ("ab" — no proper prefix equals a suffix), lps[2]=1 ("aba" — prefix "a" equals suffix "a"), lps[3]=2 ("abab" — prefix "ab" equals suffix "ab"), lps[4]=0 ("ababd" — the mismatch on "d" resets it).
Why lps tells you exactly how far to fall back after a mismatch Suppose the pattern has matched the text up through P[0..i−1] (i characters matched) and then mismatches at P[i]. Those i matched characters are also, right now, sitting in the text — meaning the text currently contains P[0..i−1] at this position. If P[0..i−1] has a proper prefix of length lps[i−1] that's also its own suffix, then that same substring of length lps[i-1] must also be sitting at the end of the just-matched text region — so it's safe to resume comparing from P[lps[i−1]] against the same text position, without rechecking any earlier text character. Falling back by exactly lps[i−1] (rather than restarting from P[0] against the very next text position, as the naive approach does) is what avoids ever re-examining a text character once it's been looked at.
Building the failure function — O(m) 
function buildLPS(P):
    lps = array of length |P|, lps[0] = 0
    len = 0                          // length of current matching prefix/suffix
    i = 1
    while i < |P|:
        if P[i] == P[len]:
            len += 1
            lps[i] = len
            i += 1
        elif len > 0:
            len = lps[len - 1]        // fall back within the pattern itself
        else:
            lps[i] = 0
            i += 1
    return lps
Searching with the failure function — O(n) 
function kmpSearch(text, pattern):
    lps = buildLPS(pattern)
    i = 0                             // index into text
    j = 0                             // index into pattern
    while i < |text|:
        if text[i] == pattern[j]:
            i += 1
            j += 1
            if j == |pattern|:
                report match at position i - j
                j = lps[j - 1]        // continue searching for overlapping matches
        elif j > 0:
            j = lps[j - 1]            // fall back, i never decreases
        else:
            i += 1
Why the search loop is Θ(n), not Θ(nm) — an amortized argument The index i into the text only ever increases, never decreases — every branch of the loop either advances i, or (on a fallback) leaves i unchanged while only j decreases. Since j can increase at most n times total across the whole run (bounded by how many times i advances) and each fallback strictly decreases j, the total number of fallback steps across the entire search is bounded by the total number of times j was ever incremented — an argument with the same flavor as Lesson 25's potential-based accounting, treating j's value as a budget that fallbacks can only spend down, never overdraw beyond what advances had built up. This gives Θ(n) total for the search, plus Θ(m) to build the failure function, for Θ(n+m) overall.
