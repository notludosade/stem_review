1. Naive substring search tries every starting position in the text, comparing character-by-character and restarting from scratch at the first mismatch. What is its worst-case time complexity, in terms of text length n and pattern length m?

A text like "aaaaaaaaab" against pattern "aaab" forces the naive approach to touch Θ(m) characters at nearly every one of Θ(n) starting positions, since a mismatch restarts the pattern comparison from scratch rather than reusing any information.

2. For a pattern P, what does lps[i] represent?

This prefix-that-is-also-a-suffix length is the entire mechanism KMP uses to decide how much of a partial match can be reused after a mismatch, rather than restarting the pattern from scratch.

3. Even after two windows' hashes match in Rabin-Karp, why must the algorithm still perform a direct character-by-character comparison before reporting a match?

Hashing compresses an m-character window into a single number modulo q, an inherently lossy operation, so a collision — two different strings sharing a hash — is always possible in principle, making direct verification necessary for correctness.

4. What does a suffix array SA[0..n−1], built for a text T of length n, actually store?

SA stores only integer starting positions; the suffixes themselves stay implicit, recoverable from T plus a starting index at any time.

5. Fill in the blank: if many (or adversarially-crafted) windows collide with the pattern's hash, Rabin-Karp's running time degrades in the worst case to Θ(___), identical to the naive approach.

Frequent hash collisions force frequent O(m) verifications at nearly every one of the n windows, erasing the average-case speed advantage entirely.

6. Consider the KMP failure function (LPS array) for pattern P = "aabaa". Answer both parts:

(a) What is lps[4] (0-indexed) for this pattern?

(b) Fill in the blank: building the entire lps array for a pattern of length m takes Θ(___) time.

(a) The full array is lps = [0, 1, 0, 1, 2]: "aa" (prefix "a" = suffix "a") gives lps[1]=1, "aab" resets to lps[2]=0, "aaba" gives lps[3]=1, and "aabaa" gives lps[4]=2 since prefix "aa" equals suffix "aa". (b) buildLPS makes a single pass with i advancing except on fallbacks bounded by len's own growth, giving Θ(m) overall.

7. During a KMP search, suppose the pattern has matched the text through P[0..j−1] and then mismatches at P[j]. Answer both parts:

(a) Where does the search resume comparing from in the pattern, without ever moving the text index i backward?

(b) Fill in the blank: because i never decreases and the total fallback steps are bounded by the total number of times the pattern index was ever advanced, the entire KMP search loop runs in Θ(___) total, in terms of text length alone.

(a) The pseudocode's fallback branch sets j = lps[j−1] while i is left untouched, reusing the already-matched text region instead of re-scanning it. (b) This is an amortized argument: i's monotonic advance bounds the total "budget" fallback steps can ever spend, giving Θ(n) for the search loop (plus Θ(m) to build lps, for Θ(n+m) overall).

8. Rabin-Karp's rolling hash update formula, when sliding the window one position to the right (dropping s[0], adding character c), is newHash = ((hash − s[0]·bᵐ⁻¹)·b + c) mod q. Answer both parts:

(a) What does multiplying by b accomplish in this update?

(b) Fill in the blank: this O(1)-updatable hash technique — the entire reason hashing every window of the text is affordable — is called a ___ hash.

(a) Subtracting s[0]·bᵐ⁻¹ removes the departing character's (highest-order) contribution, and multiplying by b shifts every remaining term up one power to reflect its new position, before c is added at the lowest-order slot. (b) "Rolling" names exactly this O(1) incremental update, avoiding a full rescan of the window's characters.

9. For T = "mama" with an appended sentinel, giving "mama$", the suffixes sorted lexicographically are "$", "a$", "ama$", "ma$", "mama$" — so SA = [4, 3, 1, 2, 0]. Answer both parts:

(a) What is SA[2]?

(b) Fill in the blank: once a suffix array is built, a pattern query locates every occurrence by performing a ___ over the sorted suffixes to find the contiguous block starting with the pattern.

(a) SA[2] is the third suffix in sorted order, "ama$", which starts at position 1 in T. (b) Every suffix starting with the same pattern sorts into one contiguous run, so binary search for that block's boundaries — comparing the pattern against the suffix at SA[mid] — locates every match in O(m log n).

10. Building a suffix array by naively sorting all n suffixes costs up to O(n² log n), paid once per text rather than once per query. Answer both parts:

(a) Why is this upfront cost worthwhile when many different patterns will be queried against the same fixed text?

(b) Fill in the blank: this "pay more upfront, save on every repeated query" trade-off is the same one an earlier lesson's ___ tree makes relative to re-scanning an array from scratch on every range query.

(a) Amortizing a one-time preprocessing cost across many queries is exactly the trade-off that makes suffix arrays worthwhile once query count is high. (b) The segment tree preprocesses an array once to answer range queries in O(log n) each, the same "pay once, save repeatedly" idea suffix arrays apply to pattern queries.
