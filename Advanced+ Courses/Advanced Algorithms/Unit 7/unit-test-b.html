1. Text "aaaaaaaaab" against pattern "aaab" is a classic worst case for naive substring search, which restarts the pattern comparison from scratch after every mismatch. What is the overall worst-case complexity, in terms of n (text length) and m (pattern length)?

Nearly every one of Θ(n) starting positions triggers a Θ(m)-character comparison before the mismatch is found, since no information from a failed attempt is carried into the next one.

2. Fill in the blank: the array that records, for every prefix of a pattern P, the length of the longest proper prefix of that prefix which is also its suffix, is called the pattern's ___ (also known as the failure function).

This precomputed array is the entire mechanism that lets KMP skip ahead safely after a mismatch, instead of restarting the pattern from its very first character.

3. Two different substrings can hash to the same value under Rabin-Karp's rolling hash. What does this fact require the algorithm to do before reporting a match?

Because hashing compresses a window into a bounded-size number, collisions are always possible in principle — so trusting a hash match without verification would silently produce false positives.

4. Which of the following is true of a suffix array built for a text T of length n?

SA is a permutation of starting positions ordered by the lexicographic order of the suffixes they point to — the suffix strings themselves stay implicit, never stored directly.

5. Under what circumstance does Rabin-Karp's running time degrade to match the naive algorithm's Θ(nm) worst case?

Frequent collisions force frequent full-length verifications across the n windows, which is exactly what erases the average-case speed advantage — the rolling update itself always stays O(1).

6. Consider the KMP failure function (LPS array) for pattern P = "abcab". Answer both parts:

(a) What is lps[3] (0-indexed) for this pattern?

(b) Fill in the blank: once the lps array is built (an O(m) step), searching a text of length n with this pattern takes an additional Θ(___) time, for a combined Θ(n+m) total.

(a) The full array is lps = [0, 0, 0, 1, 2]: "ab" and "abc" never repeat a prefix as a suffix, but "abca" gives lps[3]=1 (prefix "a" equals suffix "a") and "abcab" gives lps[4]=2 (prefix "ab" equals suffix "ab"). (b) The search loop itself is Θ(n), which combines with the Θ(m) build step for Θ(n+m) overall.

7. In the KMP search loop, the text index i is never decremented under any circumstance — every branch either advances i or leaves it unchanged. Answer both parts:

(a) What happens to the pattern index j on a fallback (a mismatch with j > 0)?

(b) Fill in the blank: the total number of fallback steps across an entire search is bounded by the total number of times j was ever incremented, which is itself bounded by how many times ___ advanced.

(a) The fallback branch sets j = lps[j−1] and never touches i, which is exactly what avoids ever re-examining a text character already looked at. (b) i's monotonic advance across the text is the budget that bounds how many times j can ever be incremented, which in turn bounds the total fallback steps — the amortized argument behind KMP's Θ(n) search.

8. Rabin-Karp treats a length-m string as a number in base b: hash(s) = (s[0]·bᵐ⁻¹ + s[1]·bᵐ⁻² + ... + s[m−1]) mod q. Answer both parts:

(a) In the update newHash = ((hash − s[0]·bᵐ⁻¹)·b + c) mod q, what does subtracting s[0]·bᵐ⁻¹ accomplish?

(b) Fill in the blank: this entire update runs in ___ time per window slide, regardless of how long the window is.

(a) s[0] held the highest power of b in the old window, so subtracting its contribution before shifting and adding c is what lets the new hash be built directly from the old one. (b) The subtraction, multiplication, and addition are each O(1) arithmetic, so the whole update is O(1) — no rescanning of the window's characters at all.

9. For T = "abab" with an appended sentinel, giving "abab$", the sorted suffixes are "$", "ab$", "abab$", "b$", "bab$" — so SA = [4, 2, 0, 3, 1]. Answer both parts:

(a) What is SA[3]?

(b) Fill in the blank: all suffixes beginning with the pattern "ab" occupy one contiguous block in this sorted order (SA[1] and SA[2]), the same way every word sharing a prefix sits together in a sorted ___.

(a) SA[3] is the fourth suffix in sorted order, "b$", which starts at position 3 in T. (b) Lexicographic sorting groups every suffix sharing a given prefix into one contiguous run, which is exactly what makes binary search for a block's boundaries valid.

10. A genome being queried against thousands of candidate gene sequences is a realistic scenario for using a suffix array instead of repeating KMP or Rabin-Karp from scratch each time. Answer both parts:

(a) Why does a suffix array outperform repeating KMP or Rabin-Karp in this scenario?

(b) Fill in the blank: this upfront construction cost is paid only ___ per text, not once per every pattern query asked against it.

(a) Amortizing the preprocessing cost across many queries is exactly what makes it worthwhile once a text is queried often enough. (b) Even the naive O(n² log n) construction pays off once enough pattern queries are asked against the same fixed text, since it is paid a single time, not repeated per query.
