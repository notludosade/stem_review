1. For a sum-segment tree built over the array [3, 1, 4, 2] (indices 0–3), what value is stored at the node covering range [2, 3]?

The node covering [2,3] aggregates arr[2]+arr[3] = 4+2 = 6. The root (covering [0,3]) would store 10, and the node covering [0,1] would store 3+1=4.

2. Answer both parts about segment tree operations:

(a) Why does a range query touch only O(log n) nodes instead of scanning all n leaves?

(b) Fill in the blank: after updating a single array element, only the ___ nodes on its root-to-leaf path need their aggregate recomputed.

(a) Bounded extra work per level, summed across a logarithmic number of levels, is exactly what gives the Θ(log n) total for a query. (b) Every other node's range doesn't contain the updated index at all, so its aggregate provably can't change.

3. Answer both parts about a Fenwick tree's lowbit trick:

(a) What is lowbit(20), computed as 20 & (−20)?

(b) Fill in the blank: so tree[20] covers the range (20−4, 20], meaning indices ___ through 20.

(a) 20 in binary is 10100; its lowest set bit is 100 = 4. (b) That makes the covered range (16,20], i.e., indices 17, 18, 19, and 20.

4. Fill in the blank: a Fenwick tree only naturally supports operations that are associative and ___ (like sum, where subtraction undoes addition) — not operations like min or max that can't be undone.

Range-sum queries rely on prefixSum(r) − prefixSum(l−1), which only works because subtraction can undo addition — an operation like min has no equivalent "undo" step.

5. During an AVL insertion, ancestor v ends up with balance(v) = 2 (left-heavy) and balance(v.left) ≥ 0. Which rebalancing case is this, and what fixes it?

balance(v) = 2 means v is left-heavy, and balance(v.left) ≥ 0 means the imbalance is concentrated on the outer (left) side — the Left-Left case, fixed with one single right rotation at v.

6. Answer both parts about why the AVL balance invariant forces logarithmic height:

(a) The minimum node count N(h) for an AVL tree of height h satisfies N(h) ≥ 1 + N(h−1) + N(h−2). What recurrence does this resemble?

(b) Fill in the blank: since N(h) grows exponentially in h, height h itself can grow no faster than ___ in the number of nodes n.

(a) Both recurrences add together the two immediately preceding terms, which is exactly what produces exponential growth in h. (b) Inverting that exponential relationship is what proves AVL height is bounded at Θ(log n), never Θ(n).

7. In the union-by-rank proof, a tree's root has rank r. What is the minimum number of nodes such a tree must contain?

By induction, a tree's rank only increases from r to r+1 when two rank-r trees (each already proven to have at least 2ʳ nodes) merge, giving at least 2ʳ+2ʳ=2ʳ⁺¹ nodes — so any rank-r tree has at least 2ʳ nodes.

8. Answer both parts about path compression and its combined guarantee with union by rank:

(a) What does path compression do during a find(x) call?

(b) Fill in the blank: combined with union by rank, path compression bounds a sequence of m operations on n elements to O(m·___), a function that grows so slowly it's at most 4 for any n that could ever be physically represented.

(a) That relinking is path compression's entire benefit — it shortens every future find through any of those nodes. (b) α is the inverse Ackermann function, making the amortized cost per operation "practically O(1)" even though it isn't a true constant.

9. After inserting "cat", "car", "card", and "dog" into an empty trie, how many edges does a query startsWith("ca") need to walk?

startsWith("ca") walks exactly 2 edges (c, then a) from the root — the same shared path that "cat", "car", and "card" all pass through, regardless of how many words extend it.

10. Answer both parts about choosing between a trie and a hash set:

(a) When should a hash set be preferred over a trie for storing a set of strings?

(b) Fill in the blank: a boolean flag such as isWord is needed at each trie node to distinguish a complete stored word from a node that is merely a ___ of a longer word.

(a) The choice comes down to whether the query workload actually needs prefix structure, not raw performance on plain membership queries alone. (b) Without that flag, every node along any inserted string's path would look identical, with no way to tell a real stored word from a mere waypoint.
