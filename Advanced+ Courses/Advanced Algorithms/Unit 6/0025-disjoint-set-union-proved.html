Disjoint Set Union, Proved

Kruskal's algorithm (Lesson 10) and Tarjan's SCC algorithm (Lesson 15) both leaned on Union-Find being "amortized near-constant time" without proof. This lesson pays that debt, using the potential method Lesson 4 introduced.

← Lesson 24 Lesson 26 → Contents Glossary →

CP2+ Lesson 21 ("Union-Find & Redundant Connection") introduced find and union with path compression, and stated informally that both run in "nearly O(1)" — technically O(α(n)), the inverse Ackermann function — without proving it. This course has since leaned on that claim twice more: Lesson 10 used it to justify Kruskal's Θ(E log E) runtime, and Lesson 15 cited it (by analogy) when explaining why Tarjan's SCC algorithm only needs O(1) extra bookkeeping per vertex. This lesson finally proves it, building on the potential method from Lesson 4.

The structure — a forest of trees

Representation Union-Find represents a collection of disjoint sets as a forest: each element has a parent pointer, and each tree's root is that set's representative. find(x) walks parent pointers from x up to its root. union(x, y) links the two roots together, merging their trees. Without any care about which root gets attached to which, a long sequence of unpredictable unions can produce a tree that's really a chain — depth Θ(n), exactly the same failure mode an unbalanced BST has (Lesson 24) — making find degrade to Θ(n).

Optimization 1: union by rank — a real, complete proof

The technique Track a rank(v) for each tree root, initialized to 0. When union merges two trees, attach the lower-rank root as a child of the higher-rank root (breaking ties arbitrarily, incrementing the surviving root's rank by 1 in that case only). This never lets a tree's height exceed its root's rank.
Theorem: any tree with root rank r has at least 2ʳ nodes Proof by induction on the number of unions performed. Base case: a tree of rank 0 is a single node, and 2⁰ = 1. Inductive step: a tree's rank only increases from r to r+1 at the moment two trees of equal rank r are merged (any other merge keeps the surviving root's rank unchanged, per the rule above). By the inductive hypothesis, each of those two rank-r trees already has at least 2ʳ nodes, so the merged rank-(r+1) tree has at least 2ʳ + 2ʳ = 2ʳ⁺¹ nodes. By induction, the claim holds for every rank ever reached. This is the identical "count nodes, get an exponential lower bound on size as a function of a height-like quantity" argument AVL trees used (Lesson 24) — there it bounded height via balance factor, here it bounds height via rank.
Corollary: union by rank alone bounds every find to O(log n) Since a tree's root has rank r only if the tree has at least 2ʳ nodes, and the whole structure has at most n nodes total, no root can ever have rank exceeding log₂n. A second fact — that rank strictly increases along any parent-pointer path from a node to its root, since union by rank never attaches a higher-rank tree under a lower-rank one — means a path from any node to its root passes through strictly increasing ranks, so its length is bounded by the maximum rank, O(log n). Union by rank alone, with no path compression at all, already guarantees every single find call costs O(log n) worst case — not just amortized.

Optimization 2: path compression

The technique 
function find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])   // point x directly at the root
    return parent[x]

function union(x, y):
    rootX = find(x)
    rootY = find(y)
    if rootX == rootY: return
    if rank[rootX] < rank[rootY]: parent[rootX] = rootY
    elif rank[rootX] > rank[rootY]: parent[rootY] = rootX
    else: parent[rootY] = rootX; rank[rootX] += 1
Every node visited on the way up during a find gets relinked to point directly at the root, flattening the path for every future find through any of those nodes — exactly the kind of self-improving structure CP2+ Lesson 21 used without formally justifying its cost.

Combined: the inverse Ackermann bound

Theorem (Tarjan, 1975) With both union by rank and path compression, a sequence of m find/union operations on n elements costs O(m·α(n)) total — an amortized O(α(n)) per operation, where α is the inverse Ackermann function: the number of times the (extraordinarily fast-growing) Ackermann function must be applied to reach a value ≥ n. α(n) grows so slowly that α(n) ≤ 4 for any n that could ever physically be represented in memory — making O(α(n)) "practically O(1)" in every real sense, even though it is not a true constant.
Why this is a genuinely harder proof, and where it comes from The full proof extends the potential method from Lesson 4, but with a potential function that groups ranks into O(α(n)) tiers using a tower-of-twos-style grouping, then argues that potential can only decrease a bounded number of times within each tier before a node's ancestor rank jumps to the next one — giving an O(α(n)) amortized charge per operation instead of Lesson 4's simpler telescoping argument. This is Tarjan's original 1975 proof, and it runs several pages of careful bookkeeping — long enough that we state the theorem and its proof shape here rather than reproduce all of it. The full derivation is in CP-Algorithms' Disjoint Set Union article (the same source CP2+ Lesson 21 already pointed to) and in CLRS Chapter 21.
Why this closes the loop on three earlier forward-references Lesson 10's Kruskal's algorithm needed "near-constant" same-set queries to keep its total runtime at Θ(E log E) rather than Θ(E·V); this theorem is exactly what makes that arithmetic hold. Lesson 15's comparison of Tarjan's SCC algorithm to Lesson 4's amortized-analysis vocabulary was pointing at this same family of proof — a data structure whose *individual* operations look expensive in the worst case, but whose amortized cost across any sequence is nearly constant, certified by a potential function.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does union by rank alone (without path compression) guarantee every tree has height O(log n)?

The exponential node-count lower bound as a function of rank, combined with strictly increasing ranks along any root path, is exactly what bounds height logarithmically.

2. What does path compression do during a find operation?

Path compression's entire benefit comes from shortening future paths by relinking visited nodes directly to the root during the current find.

3. Why is α(n) (the inverse Ackermann function) described as "practically O(1)" even though it is not a true mathematical constant?

Inverse Ackermann is unbounded in principle but grows so slowly that it never exceeds small single-digit values for any realistic input size.

4. Fill in the blank: union by rank attaches the lower-___ tree's root as a child of the higher-___ tree's root, incrementing the surviving root's value only when the two are equal.

Rank is the height-like quantity union by rank uses to decide which root should become the parent.

5. Fill in the blank: Tarjan's full inverse-Ackermann proof extends Lesson 4's ___ method, using a more intricate function that groups ranks into tiers rather than a single telescoping sum.

The same potential-method machinery from Lesson 4 underlies this proof, just with a more elaborate potential function than the dynamic array's.
