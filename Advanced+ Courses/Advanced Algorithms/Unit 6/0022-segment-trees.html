Segment Trees

Answering "what's the sum (or min, or max) of this range?" after every update, on an array that keeps changing, needs more than a running total. A segment tree answers both range queries and point updates in Θ(log n).

← Lesson 21 Lesson 23 → Contents Glossary →

Given an array that supports two operations — update a single element, and query the sum (or min/max) of a range [l, r] — a naive approach makes updates Θ(1) but range queries Θ(n) (scan the whole range), or precomputes prefix sums for Θ(1) queries but Θ(n) updates (every prefix sum after the changed index must be recomputed). A segment tree is a binary tree over the array that gets both operations down to Θ(log n), by storing precomputed aggregates at every level of a recursive halving — an idea structurally close to the recursion tree method (Lesson 2), but built once and then queried repeatedly rather than solved and discarded.

The structure

Definition A segment tree over an array of size n is a binary tree where each node represents a contiguous range [lo, hi]. The root represents the whole array [0, n−1]; each internal node's two children split its range in half ([lo, mid] and [mid+1, hi]); each leaf represents a single array index. Every node stores the aggregate (sum, min, or max — whichever operation this instance is built for) of its entire range, computed once at build time from its two children's aggregates.
Build — O(n) 
function build(arr, node, lo, hi):
    if lo == hi:
        tree[node] = arr[lo]
        return
    mid = (lo + hi) / 2
    build(arr, 2*node, lo, mid)
    build(arr, 2*node+1, mid+1, hi)
    tree[node] = tree[2*node] + tree[2*node+1]   // combine children
Range query — O(log n) 
function query(node, lo, hi, l, r):               // query range [l, r]
    if r < lo or hi < l: return 0                  // no overlap
    if l <= lo and hi <= r: return tree[node]      // fully covered
    mid = (lo + hi) / 2
    return query(2*node, lo, mid, l, r) + query(2*node+1, mid+1, hi, l, r)
Why the query is Θ(log n), not Θ(n) At each level of the tree, a query range can only partially overlap at most two "boundary" nodes on each side — every other node visited at that level is either fully outside (skipped) or fully inside (returned immediately, no further recursion). Since the tree has Θ(log n) levels and the boundary nodes contribute at most a constant number of extra visits per level, total work is Θ(log n) — a proof shape similar in spirit to the recursion tree method (Lesson 2), summing bounded work across a logarithmic number of levels.
Point update — O(log n) 
function update(node, lo, hi, index, newValue):
    if lo == hi:
        tree[node] = newValue
        return
    mid = (lo + hi) / 2
    if index <= mid: update(2*node, lo, mid, index, newValue)
    else: update(2*node+1, mid+1, hi, index, newValue)
    tree[node] = tree[2*node] + tree[2*node+1]     // recompute after child changes
Only the Θ(log n) nodes on the root-to-leaf path for the updated index need recomputing, since every other node's range doesn't contain that index at all.
Why this matters for problems Union-Find and Dijkstra's can't touch Neither Union-Find (CP2+ Lesson 21) nor Dijkstra's (CP2+ Lesson 22) can answer "what's the minimum edge weight in this range of a sorted list, after several updates" — that's a fundamentally different question, about ranges of an ordered sequence rather than connectivity or shortest paths. Segment trees are the standard tool whenever a problem needs repeated range queries interleaved with point updates, which is common enough in competitive programming to be considered foundational infrastructure, not a niche technique.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does each node of a segment tree store?

Each node's stored aggregate covers exactly its own range, computed from combining its two children's aggregates.

2. Why does a range query on a segment tree take Θ(log n) instead of Θ(n)?

Bounded extra work per level, across a logarithmic number of levels, is exactly what gives the Θ(log n) total.

3. Why does a point update only need to recompute Θ(log n) nodes, rather than the whole tree?

Nodes whose range doesn't include the updated index have aggregates that provably can't change, so only the single root-to-leaf path needs recomputation.

4. Fill in the blank: every segment tree node stores an ___ (such as a sum, minimum, or maximum) summarizing its entire range, computed from its two children.

This precomputed aggregate at every level is exactly what avoids a full linear scan on every query.

5. Fill in the blank: both range queries and point updates on a segment tree run in Θ(___) time, a large improvement over a naive Θ(n) array scan.

Both operations only ever touch a logarithmic number of nodes, thanks to the tree's recursive range-halving structure.
