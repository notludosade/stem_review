1. A divide-and-conquer algorithm recursively calls itself on subproblems of size n/3 and 2n/3. Why does proving it correct require strong induction rather than ordinary induction?

Ordinary induction's single "assume n−1" step can't reach a jump to n/3 or 2n/3, so the hypothesis needs to hold for every smaller size simultaneously — exactly what strong induction supplies.

2. An inversion is a pair of indices i < j with arr[i] > arr[j]. When splitting an array into halves L and R for counting inversions, which kind of inversion can ONLY be detected during the merge step, not by either recursive call alone?

Recursion on L only ever compares indices inside L, and likewise for R — a pair straddling both halves is structurally invisible to either recursive call, which is exactly why the merge step must detect it.

3. In median-of-medians, why does dividing the array into groups of 5 (rather than groups of 3) produce a usable worst-case guarantee?

The 3n/10 fraction comes directly from each "median ≤ pivot" group contributing 3 elements ≤ pivot (the median plus 2 below it); groups of 3 give too weak a fraction to force the recursion to shrink fast enough.

4. Why does the naive divide-and-conquer approach to matrix multiplication (splitting into 4 blocks, 8 recursive multiplications) fail to beat schoolbook Θ(n³)?

With a=8, b=2, n^(log_b a) = n³ exactly matches schoolbook's exponent, so the naive 8-multiplication block recursion offers no asymptotic improvement — the whole point of Strassen's trick is cutting the count to 7.

5. Fill in the blank: strong induction alone proves the recursive calls trustworthy; the non-recursive ___ step (like merge, or mergeAndCount) always needs its own separate, direct correctness argument.

Induction covers "trust the subproblems"; it says nothing about whether the code stitching subproblem answers together is itself correct — that needs a separate, direct proof.

6. A divide-and-conquer algorithm finds the maximum of an array by splitting it into two halves, recursively finding each half's maximum, then returning the larger of the two. Answer both parts:

(a) What is the correct base case for this proof?

(b) Fill in the blank: the inductive step must directly show that taking the larger of the two recursively-found half-maxima equals the true maximum of the whole ___-element array.

(a) A size-1 array has an unambiguous maximum (the element itself) and needs no recursive call, making it the natural base case. (b) Every element of the array is in exactly one of the two halves, and each half's recursively-found value is (by hypothesis) that half's true maximum, so the larger of the two must be the true maximum of the whole n-element array — the direct argument the combine step needs.

7. During mergeAndCount on left half L = [2, 5, 8] and right half R = [1, 3, 9] (both already sorted from the recursive calls), answer both parts:

(a) Fill in the blank: the total number of cross-inversions detected while merging L and R is ___.

(b) Why does adding this cross-inversion bookkeeping to the merge step not change the algorithm's overall asymptotic runtime?

(a) Tracing the merge: R[0]=1 < L[0]=2, so count += (3−0) = 3 remaining L elements; later R[1]=3 < L[1]=5, so count += (3−1) = 2. Total = 3 + 2 = 5, matching the direct pair count: 2>1, 5>1, 8>1, 5>3, 8>3. (b) Adding an O(1) increment per comparison doesn't change the recurrence's asymptotic shape, so it stays Θ(n log n) exactly as in plain merge sort.

8. The recurrence T(n) ≤ T(n/5) + T(7n/10) + Θ(n) for median-of-medians is verified by guessing T(n) ≤ cn. Answer both parts:

(a) What must be true of the coefficient 1/5 + 7/10 for the substitution proof to succeed?

(b) Fill in the blank: since 1/5 + 7/10 = 9/10 < 1, the substitution method confirms T(n) = O(___) — linear time despite two recursive calls.

(a) The coefficient 9/10 < 1 is exactly what lets a sufficiently large constant c absorb the added Θ(n) term, confirming the guess T(n) ≤ cn holds for all n. (b) This matches the lesson's conclusion: worst-case linear-time selection, with no randomness required.

9. Strassen's algorithm gives T(n) = 7T(n/2) + Θ(n²). Answer both parts:

(a) What is n^(log₂7), the exponent that determines the algorithm's overall runtime?

(b) Fill in the blank: since f(n)=n² is polynomially smaller than n^(log₂7)≈n^2.807, this is Master Theorem Case ___, giving T(n) = Θ(n^(log₂7)).

(a) log₂(7) ≈ 2.807, since 2^2.807 ≈ 7 — strictly less than 3, which is exactly why Strassen's algorithm beats schoolbook. (b) Case 1 (leaves dominate) applies because f(n)=n² grows polynomially slower than n^(log₂7).

10. In the correctness proof for countInversions, every inversion in the array falls into exactly one of three categories. Answer both parts:

(a) What are the three categories, and why do they cover every possible inversion?

(b) Fill in the blank: the total inversion count returned is countL + countR + ___, matching the sum computed by mergeAndCount.

(a) Any pair of indices either both lie in L, both lie in R, or one lies in each — an exhaustive partition of every possible inversion. (b) countInversions returns exactly countL + countR + crossCount, the sum of all three categories.
