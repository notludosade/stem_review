Advanced Algorithms

CP2+ built the practical toolkit for interviews and contests. This course goes back through the same territory and asks for proof — why greedy works, why Union-Find is fast, why some problems have no known efficient algorithm at all. Requires Computer Programming 1 and Computer Programming 2.

Unit 1 — Algorithm Analysis, Rigorously
Lesson 1

Asymptotic Notation, Formally

CP2 taught you to read Big-O by intuition — drop constants, keep the fastest-growing term. This lesson gives you the actual quantifier-based definitions underneath that intuition, so you can prove a bound instead of eyeballing it.

 Lesson 2

The Recursion Tree Method

Before the Master Theorem gives you a formula, learn to solve a recurrence by drawing it out — because the formula only covers recurrences with a specific shape, and the tree method is what you fall back on when it doesn't.

 Lesson 3

The Master Theorem

The last lesson kept solving different recurrences to the same three patterns by hand. The Master Theorem is the formula that names those three patterns and tells you which one applies without drawing a single tree.

 Lesson 4

Amortized Analysis

A dynamic array's push is "O(1)" — except for the occasional resize, which is O(n). This lesson makes precise what "occasional" buys you, with three methods that all answer the same question: what's the true average cost per operation over a long sequence?

Unit 2 — Divide and Conquer
Lesson 5

Correctness by Strong Induction

Unit 1 built the tools to analyze how fast a recursive algorithm runs. This lesson builds the tool to prove it's actually correct — every divide-and-conquer proof in this unit is the same three-step induction argument wearing a different problem.

 Lesson 6

Counting Inversions & Merge Sort

A classic divide-and-conquer trick: piggyback a second computation on top of merge sort's existing structure, for free, because the merge step already does the comparisons you need.

 Lesson 7

Median of Medians

Quickselect finds the k-th smallest element in expected O(n) time, but a bad pivot makes it O(n²) in the worst case. Median-of-medians fixes that by spending extra work choosing a pivot that's provably good — worst-case O(n), not just expected.

 Lesson 8

Strassen's Algorithm

The schoolbook way to multiply two n×n matrices is Θ(n³). Strassen's algorithm shows that's not optimal — by trading one of eight recursive multiplications for extra additions, it gets the exponent below 3 entirely.

Unit 3 — Greedy Algorithms & MSTs
Lesson 9

Exchange Arguments

CP2+'s greedy lesson taught you to recognize the pattern and trust that the locally-best choice works. This lesson proves it — with the one technique that turns "seems locally optimal" into "provably optimal."

 Lesson 10

Kruskal's & Prim's Algorithms

Two greedy algorithms that look nothing alike — one grows a forest by cheapest edge globally, the other grows a single tree by cheapest edge locally — both provably build a minimum spanning tree.

 Lesson 11

The Cut Property

One theorem about graph cuts proves Kruskal's and Prim's correct simultaneously, even though the two algorithms don't look like they're doing the same thing at all.

 Lesson 12

Huffman Coding

A greedy algorithm for building the shortest possible prefix-free binary code for a set of symbols with known frequencies — proved optimal with the same exchange-argument machinery as interval scheduling and MSTs.

Unit 4 — Advanced Graph Algorithms
Lesson 13

Bellman-Ford

Dijkstra's algorithm breaks the instant an edge weight goes negative. Bellman-Ford handles negative weights correctly — and, as a side effect, can detect a negative cycle that would make "shortest path" meaningless in the first place.

 Lesson 14

Floyd-Warshall

Running Bellman-Ford from every vertex would solve all-pairs shortest paths in Θ(V²E). Floyd-Warshall does it in Θ(V³) with a three-line dynamic program — by asking a single, elegant question about intermediate vertices.

 Lesson 15

Strongly Connected Components: Kosaraju's & Tarjan's

Two entirely different-looking algorithms — one runs DFS twice on the graph and its reverse, the other runs DFS once and tracks a clever stack invariant — both partition a directed graph into its maximal mutually-reachable clusters.

 Lesson 16

Ford-Fulkerson

Given a network of pipes with capacities, how much can flow from a source to a sink at once? Ford-Fulkerson answers this by repeatedly finding an augmenting path — and its correctness depends on a construction that lets flow "undo" a bad earlier decision.

 Lesson 17

Max-Flow Min-Cut

The maximum flow through a network exactly equals the minimum-capacity cut separating source from sink — a theorem that both proves Ford-Fulkerson correct and gives a second, completely different lens for the same number.

Unit 5 — Advanced Dynamic Programming
Lesson 18

DP on Trees

CP2+'s DP lessons solved problems over sequences and grids. When the underlying structure is a tree instead, the recurrence changes shape — each subproblem combines results from a variable number of children rather than looking back one or two fixed positions.

 Lesson 19

Bitmask DP: The Traveling Salesman Problem

Some DP states aren't a position or an index — they're an entire subset of items visited so far, encoded as the bits of an integer. This turns a problem with no known polynomial solution into one solvable in exponential-but-far-better-than-brute-force time.

 Lesson 20

Matrix Chain Multiplication

Matrix multiplication is associative, so a chain of matrices can be parenthesized many different ways — all producing the same result, but at wildly different computational costs. This lesson finds the cheapest parenthesization with an interval-based DP.

 Lesson 21

Matrix Exponentiation

Computing the nth Fibonacci number the ordinary DP way takes Θ(n) steps. Recasting the recurrence as a matrix power and using repeated squaring computes it in Θ(log n) — a technique that generalizes to any linear recurrence.

Unit 6 — Advanced Data Structures
Lesson 22

Segment Trees

Answering "what's the sum (or min, or max) of this range?" after every update, on an array that keeps changing, needs more than a running total. A segment tree answers both range queries and point updates in Θ(log n).

 Lesson 23

Fenwick Trees

Segment trees solve range-sum-with-updates in general. When the only aggregate needed is sum, a Fenwick tree solves the same problem with a smaller, simpler structure — built entirely from a bit trick on the index itself.

 Lesson 24

AVL Rotations

An ordinary binary search tree's Θ(log n) search only holds if the tree stays balanced — a bad insertion order can degrade it to a Θ(n) linked list. AVL trees fix this by rebalancing automatically after every insertion and deletion.

 Lesson 25

Disjoint Set Union, Proved

Kruskal's algorithm (Lesson 10) and Tarjan's SCC algorithm (Lesson 15) both leaned on Union-Find being "amortized near-constant time" without proof. This lesson pays that debt, using the potential method Lesson 4 introduced.

 Lesson 26

Tries

Storing a set of strings in a hash set answers "is this string present?" but nothing about shared prefixes. A trie restructures storage entirely around prefixes, making prefix queries as fast as membership queries.

Unit 7 — String Algorithms
Lesson 27

Knuth-Morris-Pratt (KMP)

Naive substring search re-scans from scratch after every mismatch, costing Θ(nm) in the worst case. KMP precomputes exactly how much of a partial match can be reused after a mismatch, bringing search down to Θ(n+m).

 Lesson 28

Rabin-Karp & Rolling Hashes

KMP avoids redundant comparisons by exploiting the pattern's own structure. Rabin-Karp takes a completely different approach: hash every window of the text, and only bother comparing characters when hashes collide.

 Lesson 29

Suffix Arrays, First Look

KMP and Rabin-Karp both answer one query — where does this one pattern occur? — against a text they scan fresh each time. A suffix array preprocesses the text once, then answers any pattern query against it in O(m log n).

Unit 8 — Complexity & Intractability
Lesson 30

P vs. NP & Polynomial-Time Reductions

Every algorithm in this course so far ran in polynomial time. This unit asks the question those algorithms all quietly avoided: are there problems where no polynomial-time algorithm exists at all — or is even believed to?

 Lesson 31

NP-Completeness & the Cook-Levin Theorem

Lesson 30 showed reductions transfer hardness between two problems. This lesson asks: is there a problem so general that every problem in NP reduces to it? Cook and Levin proved yes — and named the first one.

 Lesson 32

Common NP-Complete Problems

Cook-Levin proved SAT is NP-complete directly, from the definition of NP itself. Every problem in this lesson is proven NP-complete the easier way — a short reduction from SAT, 3-SAT, or another problem already known to be NP-complete.

 Lesson 33

Approximation Algorithms

NP-hard problems have no known polynomial-time algorithm for an exact answer. This lesson asks the practical follow-up: what provable guarantee can a fast algorithm still make, if not exactness?

 Lesson 34

Capstone — From Asymptotic Notation to Intractability

The whole course, traced as one dependency chain: how a rigorous language for runtime, applied relentlessly across data structures, graphs, and strings, eventually meets problems where no efficient algorithm is believed to exist at all.
