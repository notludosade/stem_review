Strongly Connected Components: Kosaraju's & Tarjan's

Two entirely different-looking algorithms — one runs DFS twice on the graph and its reverse, the other runs DFS once and tracks a clever stack invariant — both partition a directed graph into its maximal mutually-reachable clusters.

← Lesson 14 Lesson 16 → Contents Glossary →

CP2+'s Lesson 18 ("Representing Graphs & DFS") taught depth-first search as a traversal tool. A strongly connected component (SCC) of a directed graph is a maximal set of vertices where every vertex can reach every other vertex in the set via directed edges. Finding all SCCs is a genuinely different problem from ordinary traversal — reachability in a directed graph isn't symmetric, so "connected" from Lesson 18's undirected framing doesn't directly apply. Two classical algorithms solve it, both built entirely from DFS, in ways that reveal a different subtlety about directed reachability each.

Kosaraju's algorithm — DFS twice, once on the reverse graph

Algorithm 
function kosaraju(graph):
    // pass 1: DFS on the original graph, recording finish order
    finishOrder = []
    for each unvisited vertex v:
        dfs(graph, v, marking visited, appending v to finishOrder on finish)

    reversedGraph = reverse every edge in graph

    // pass 2: DFS on the reversed graph, in decreasing finish-time order
    components = []
    for v in reverse(finishOrder):
        if v not yet visited in this pass:
            component = dfs(reversedGraph, v, marking visited)
            append component to components
    return components
Why reversing the graph and using finish order works If u and v are in the same SCC, they can reach each other in both the original graph and its reverse (reversing all edges preserves mutual reachability within a component, though it can destroy reachability between different components). Processing vertices in decreasing order of first-pass finish time guarantees that when the second-pass DFS starts from a vertex v, it can only reach vertices in v's own SCC or in components that come strictly "after" it in a partial order over SCCs — never bleeding into a different, not-yet-fully-explored component. This exploits a fact from CP2+'s topological-sort lesson (Lesson 20, "Topological Sort & Course Scheduling"): finish-time ordering from a first DFS pass encodes a valid dependency order, here applied to components rather than individual vertices.
Runtime Θ(V+E): two full DFS passes, each linear, plus Θ(V+E) to build the reversed graph.

Tarjan's algorithm — one DFS pass with a low-link value

Key idea Tarjan's algorithm runs a single DFS, maintaining for each vertex v two numbers: disc[v] (the order v was first discovered) and low[v] (the smallest disc value reachable from v's DFS subtree, including via at most one back-edge to an ancestor still on the current DFS stack). A vertex v is the "root" of an SCC exactly when low[v] = disc[v] — meaning nothing in v's subtree can reach back above v. When such a root is found, every vertex still on an explicit stack down to and including v forms one complete SCC, and can be popped off together.
Why Tarjan's needs only one DFS pass, while Kosaraju's needs two Kosaraju's uses two full passes because it needs a decreasing-finish-time visiting order — the first pass's only job is to compute that order, information a single, uninterrupted DFS doesn't produce until the very end. Tarjan's algorithm instead tracks the low-link value incrementally as the DFS unwinds, so it can identify each completed SCC the moment its root vertex finishes, without needing a full second pass. This is the same kind of trade — do more per-step bookkeeping instead of a second whole pass — that Lesson 4's amortized analysis techniques are built to formally justify (the low-link bookkeeping adds only O(1) work per vertex/edge, not asymptotically more).
Runtime Θ(V+E): a single DFS pass, with O(1) extra bookkeeping per vertex and edge.
Why both are worth knowing, not just the faster one Both run in the same Θ(V+E) asymptotic time — Tarjan's isn't asymptotically faster, just a single pass instead of two, which matters for constant-factor performance and for cases where building an explicit reversed graph is inconvenient (e.g., implicit or streamed graphs). Kosaraju's, in exchange, is considerably easier to state and prove correct from first principles, which is exactly why it's presented first here.

1. What does it mean for a set of vertices to form a strongly connected component?

Mutual reachability, at maximal scope, is exactly the defining property of a strongly connected component.

2. Why does Kosaraju's algorithm run its second DFS pass on the reversed graph, in decreasing finish-time order from the first pass?

The finish-time ordering encodes a dependency order between components, which is exactly what keeps each second-pass DFS run contained to a single SCC.

3. In Tarjan's algorithm, what does low[v] = disc[v] signal?

This equality is the precise moment an SCC is complete and can be popped off the explicit stack as one unit.
