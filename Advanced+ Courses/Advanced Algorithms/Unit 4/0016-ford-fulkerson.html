Ford-Fulkerson

Given a network of pipes with capacities, how much can flow from a source to a sink at once? Ford-Fulkerson answers this by repeatedly finding an augmenting path — and its correctness depends on a construction that lets flow "undo" a bad earlier decision.

← Lesson 15 Lesson 17 → Contents Glossary →

A flow network is a directed graph where each edge (u, v) has a capacity c(u, v) ≥ 0, with a designated source s and sink t. A flow assigns each edge a value f(u, v) ≤ c(u, v) such that, for every vertex except s and t, total flow in equals total flow out (conservation). The maximum flow problem asks for the flow of largest total value leaving s (equivalently, arriving at t). Ford-Fulkerson solves it by a beautifully simple repeated step — but getting that step right requires one non-obvious construction.

The residual graph — the construction that makes it work

Definition — residual graph Given a flow f, the residual graph Gf has, for each original edge (u, v) with capacity c and current flow f(u,v): a forward edge (u, v) with residual capacity c − f(u,v) (remaining room to push more flow), and a backward edge (v, u) with residual capacity f(u,v) (room to "undo" flow already sent).
Why the backward edge is essential, not optional Without backward edges, a greedy algorithm that picks a "good-looking" path early can get stuck: imagine sending flow along a path that turns out, in hindsight, to have been the wrong choice compared to a different routing. The backward edge is exactly what lets a later augmenting path effectively cancel that earlier flow and reroute it — it's the mechanism that makes a purely greedy, no-backtracking algorithm still reach the true optimum, since "backtracking" is folded directly into the graph structure the algorithm searches.

The algorithm

Algorithm 
function fordFulkerson(graph, s, t):
    f(u, v) = 0 for every edge                  // start with zero flow
    while there exists a path from s to t in the residual graph G_f:
        find such a path P (any path — via DFS or BFS)
        bottleneck = minimum residual capacity of any edge along P
        for each edge (u, v) in P:
            if (u, v) is a forward edge: f(u, v) += bottleneck
            if (u, v) is a backward edge: f(v, u) -= bottleneck   // undo flow
        rebuild G_f with the updated flow
    return total flow value (sum of flow out of s)
Worked example — one augmenting path undoing a previous choice S→A (cap 10), S→B (cap 10), A→B (cap 1), A→T (cap 10), B→T (cap 10). First augmenting path S→A→T sends 10 (bottleneck at S→A or A→T, both cap 10). Second path S→B→T sends 10. Total flow so far: 20 — and this happens to already be optimal in this instance, since S has total outgoing capacity 20 and T has total incoming capacity 20. But if instead the first path chosen had been S→A→B→T (bottleneck 1, since A→B has cap 1), only 1 unit would flow that way; a second path S→A→T could still send up to 9 more (residual capacity on A→T is now 10−1=9), and a third S→B→T could send 10 — total 1+9+10 = 20 again, reaching the same optimum via a different sequence of augmenting paths, exactly the "any order works" flexibility the algorithm's correctness proof establishes.
Runtime and Edmonds-Karp Each augmenting path increases flow by at least 1 (assuming integer capacities), so the algorithm terminates, but a poor choice of path (via DFS) can take as many as O(max flow value) iterations, each costing O(E) to find a path — pathologically slow if capacities are large. The Edmonds-Karp refinement — always choosing the shortest augmenting path (via BFS) — bounds the number of iterations by O(VE), giving Θ(VE²) total, independent of the capacity values. This is the same "choice of traversal changes the guarantee" idea Lesson 15 highlighted between Kosaraju's and Tarjan's, applied here to bounding iteration count rather than pass count.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a residual graph's backward edge used for?

The backward edge is exactly the mechanism that lets a greedy, no-explicit-backtracking algorithm still reach the true maximum flow.

2. What determines how much flow an augmenting path can add?

You can only push as much flow as the tightest edge along the path allows — that minimum is the bottleneck.

3. Why does the Edmonds-Karp refinement (always using BFS to find the shortest augmenting path) improve on plain Ford-Fulkerson?

Plain Ford-Fulkerson's iteration count can depend on capacity magnitudes; Edmonds-Karp's shortest-path choice removes that dependency.

4. Fill in the blank: the amount of flow added along an augmenting path equals the ___ — the smallest residual capacity of any edge on that path.

No more flow can be pushed along a path than its tightest edge allows.

5. Fill in the blank: Ford-Fulkerson repeatedly searches for a path from source to sink in the ___ graph, which includes both forward capacity-remaining edges and backward flow-undoing edges.

The residual graph is the single data structure that both encodes remaining capacity and enables undoing earlier flow choices.
