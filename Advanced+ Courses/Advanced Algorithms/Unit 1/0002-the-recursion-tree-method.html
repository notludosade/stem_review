The Recursion Tree Method

Before the Master Theorem gives you a formula, learn to solve a recurrence by drawing it out — because the formula only covers recurrences with a specific shape, and the tree method is what you fall back on when it doesn't.

← Lesson 1 Lesson 3 → Contents Glossary →

A recursive algorithm's runtime is described by a recurrence: an equation like T(n) = 2T(n/2) + n, meaning "the work on an input of size n equals the work of the recursive calls, plus the work done outside them." CP2 introduced recursion as a way to write code; this course needs to answer a sharper question — given a recurrence, what closed-form function of n does it solve to? The recursion tree method answers that by literally drawing the recursion as a tree, one level per recursive call, and summing the work level by level.

Building the tree

Method For T(n) = a·T(n/b) + f(n): draw a root labeled with the non-recursive work f(n) at size n. Give it a children, each a subproblem of size n/b, each labeled with its own non-recursive work f(n/b). Recurse: each of those has a children of size n/b², and so on, until subproblems hit the base case. Sum the labels level by level, then sum across all levels to get T(n).
Worked example — T(n) = 2T(n/2) + n Level 0 (root): 1 node, work n. Level 1: 2 nodes, each of size n/2, each doing n/2 work — total n. Level 2: 4 nodes, each of size n/4, each doing n/4 work — total n. Every level does exactly n total work, regardless of depth. The tree has log₂n levels (since size n/2ᵏ hits 1 when k = log₂n), so total work is n · log₂n = Θ(n log n) — this is exactly merge sort's recurrence, and it's no accident the tree method reproduces the answer you already know.
Worked example — T(n) = T(n/2) + n (uneven split from the balanced case) Only one child per node this time. Level 0: work n. Level 1: 1 node of size n/2, work n/2. Level 2: work n/4. The per-level work is a geometric series n + n/2 + n/4 + ... which sums to 2n — dominated entirely by the root. T(n) = Θ(n). The lesson here generalizes: when per-level work shrinks geometrically going down the tree, the root dominates and the answer is just Θ(f(n)).
Why the per-level total is the pattern to watch The recursion tree method's real insight isn't the tree itself — it's noticing whether the total work per level stays constant, grows, or shrinks as you go deeper. Constant per level (times log n levels) gives Θ(f(n) log n). Work concentrated at the leaves (a children growing faster than the shrinkage in f) gives a total dominated by the leaf level. Work concentrated at the root (shrinking geometrically) gives Θ(f(n)). This three-way split is exactly the intuition the Master Theorem in the next lesson turns into a formula.
Worked example — an uneven recurrence the Master Theorem can't touch T(n) = T(n/3) + T(2n/3) + n has two differently-sized subproblems, so it isn't even in the a·T(n/b) + f(n) form the Master Theorem requires. The tree method still works: every level's leaves sum their sizes to at most n (since n/3 + 2n/3 = n, and this holds recursively down every root-to-leaf path), so every level does at most n total work. The tree's depth is uneven — the all-n/3 path reaches the base case in log₃n levels, the all-2n/3 path takes log_{3/2}n levels, which is longer — so the total is bounded by n times the longest path length, giving T(n) = O(n log n). This is exactly why the tree method is the fallback: it handles shapes the formula was never built for.

Check your recall

No peeking back up — answer from memory first, then check.

1. In the recursion tree for T(n) = 2T(n/2) + n, why is every level's total work the same?

a=2 doubles the node count each level while each node's subproblem size halves, so per-node work halving exactly cancels the doubling in node count.

2. For T(n) = T(n/2) + n, why does the root dominate the total instead of the leaves?

A single child per node with halving size means each level's work is half the previous level's, so the geometric series is dominated by its first (root) term.

3. Why can't T(n) = T(n/3) + T(2n/3) + n be solved directly with the Master Theorem?

The Master Theorem's form assumes every subproblem has the identical size n/b; unevenly-sized subproblems fall outside that form entirely, which is exactly when you fall back to the tree method.

4. Fill in the blank: the recursion tree method's key move is summing the non-recursive work ___ by ___, then adding across all of them.

Summing level by level, then across levels, is exactly what turns a recursive definition into a closed-form total.

5. Fill in the blank: when per-level work shrinks going down the tree, it forms a ___ series whose sum is dominated by its first term — the root.

A shrinking geometric series converges to a constant multiple of its largest (first) term, which is why the root's work dominates the whole recurrence in that case.
