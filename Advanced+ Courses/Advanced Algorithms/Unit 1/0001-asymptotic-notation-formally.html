Asymptotic Notation, Formally

CP2 taught you to read Big-O by intuition — drop constants, keep the fastest-growing term. This lesson gives you the actual quantifier-based definitions underneath that intuition, so you can prove a bound instead of eyeballing it.

← Course Contents Lesson 2 → Contents Glossary →

Computer Programming 2's Unit 3 taught Big-O as a practical skill: count nested loops, drop lower-order terms, drop constants, and you have a good-enough growth-rate label. That intuition is correct, but it hides a precise mathematical claim. This course proves things about algorithms — that a greedy choice is optimal, that a recurrence solves to a specific bound, that one problem reduces to another — and proofs need definitions with no hand-waving in them. Asymptotic notation is the first place that matters, because every later proof in this course states its conclusion in these terms.

The formal definition of O

Definition — Big-O f(n) = O(g(n)) if there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀.
Why the constants and the threshold both matter The constant c is what lets you ignore multiplicative overhead — "3n² operations" and "500n² operations" are both O(n²), because you're free to pick c = 500. The threshold n₀ is what lets you ignore small-input behavior — an algorithm can do something bizarre for n < 100 and still be O(n²), as long as the bound holds from some point onward. Both escape hatches exist for the same reason: asymptotic notation describes long-run growth rate, not exact runtime, and exact runtime is dominated by implementation details that have nothing to do with the algorithm's actual structure.
Worked proof — 3n² + 5n = O(n²) Claim: 3n² + 5n = O(n²). Pick c = 8 and n₀ = 1. For all n ≥ 1, n ≤ n², so 5n ≤ 5n², giving 3n² + 5n ≤ 3n² + 5n² = 8n². That's exactly the form f(n) ≤ c·g(n) for n ≥ n₀, so the definition is satisfied. Notice the proof only had to produce some working c and n₀ — not the best possible ones.

Ω and Θ: the other two directions

Definition — Big-Omega (lower bound) f(n) = Ω(g(n)) if there exist positive constants c and n₀ such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀. Where O is an upper bound on growth, Ω is a lower bound.
Definition — Big-Theta (tight bound) f(n) = Θ(g(n)) if f(n) = O(g(n)) and f(n) = Ω(g(n)) — equivalently, there exist positive constants c₁, c₂, n₀ such that c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀. Θ is the notation for "grows at exactly this rate," and it's the one you should reach for whenever you actually know the tight bound.
Why CP2 mostly said O when it meant Θ In casual use, "this algorithm is O(n log n)" almost always means the algorithm's runtime is exactly proportional to n log n — that's a Θ claim wearing an O label. The distinction matters here because some of this course's proofs genuinely need a one-directional bound. A reduction proof (Unit 8) only needs an upper bound on how much work a transformation adds — O, not Θ — because it's establishing "at most this much extra cost," not "exactly this much."

Little-o and little-ω: strict versions

Definition — little-o and little-ω f(n) = o(g(n)) if for every positive constant c, there exists n₀ such that f(n) < c·g(n) for all n ≥ n₀ — equivalently, lim(n→∞) f(n)/g(n) = 0. This is a strict version of O: g(n) grows strictly faster than f(n), not just "at least as fast, up to a constant." Little-ω is the symmetric strict version of Ω.
Telling O apart from o n² = O(n²) is true — g can equal f up to a constant. But n² = o(n²) is false, since the limit n²/n² = 1 ≠ 0. Meanwhile n = o(n²) is true, since n/n² = 1/n → 0. The little-o notation is what you'll use in Unit 6 to state that one data structure's operation is asymptotically negligible next to another's.

Check your recall

No peeking back up — answer from memory first, then check.

1. In the formal definition of f(n) = O(g(n)), what are c and n₀ for?

c makes the bound insensitive to constant factors; n₀ makes it insensitive to behavior before some threshold — together they capture only long-run growth rate.

2. Why is f(n) = Θ(g(n)) a strictly stronger claim than f(n) = O(g(n))?

O alone only says "grows no faster than"; Θ additionally says "grows no slower than," which together pin down the exact asymptotic rate.

3. Which statement is true: n² = o(n²), or n = o(n²)?

Little-o requires the ratio to vanish in the limit, which rules out a function being little-o of itself but allows a strictly slower-growing function.

4. Fill in the blank: Ω(g(n)) is a formal ___ bound on f(n)'s growth, the mirror image of O's upper bound.

O caps growth from above; Ω guarantees growth from below — Θ is exactly the overlap of both.

5. Fill in the blank: the whole point of the c and n₀ in these definitions is to make asymptotic notation ignore multiplicative ___ and small-input exceptions.

Asymptotic notation is deliberately blind to constant factors and to a finite prefix of small inputs, since it's meant to describe long-run growth rate only.
