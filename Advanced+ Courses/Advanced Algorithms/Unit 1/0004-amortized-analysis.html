Amortized Analysis

A dynamic array's push is "O(1)" — except for the occasional resize, which is O(n). This lesson makes precise what "occasional" buys you, with three methods that all answer the same question: what's the true average cost per operation over a long sequence?

← Lesson 3 Lesson 5 → Contents Glossary →

Worst-case analysis asks "what's the most expensive this operation can ever be?" — a fair question, but sometimes a misleading one. A dynamic array's push is O(1) almost every time and O(n) on the rare occasion it must resize; reporting "O(n) worst case" for every push is technically true but wildly pessimistic about a sequence of many pushes. Amortized analysis answers a different, often more useful question: over a sequence of n operations, what's the average cost per operation, guaranteed — not on average over random inputs, but guaranteed for every possible sequence.

The running example: a dynamic array that doubles

Setup A dynamic array starts with capacity 1. Each push either fits in the current capacity (cost 1) or, if full, allocates a new array of double the capacity, copies every existing element over, then inserts (cost = old size + 1). The question: over n pushes starting from empty, what is the total cost, and therefore the amortized cost per push?

Method 1: aggregate analysis

Method Sum the total cost of all n operations directly, then divide by n. Resizes happen when the array holds 1, 2, 4, 8, ..., 2^(k-1) elements — i.e. at most log₂n times. The k-th resize costs about 2^(k-1) (copying the existing elements). Total resize cost is 1+2+4+...+n/2 < n (geometric series). Adding the n unit-cost pushes themselves, total cost < n + n = 2n. Amortized cost per push = 2n/n = O(1).
Why aggregate analysis is the simplest and most limited method Aggregate analysis directly answers the question with no bookkeeping overhead — but it only produces one number, the average, and gives no way to reason about intermediate points in the sequence or to prove a per-operation credit invariant that later analysis (like proving an amortized bound holds even under interleaved operation types) might need. The next two methods rebuild the same O(1) answer with machinery that generalizes further.

Method 2: the accounting method

Method Charge each operation an amortized cost that may differ from its actual cost, such that the sum of amortized costs is always ≥ the sum of actual costs. The difference accumulates as credit stored on data structure elements, which future expensive operations draw down instead of being charged their true cost.
Applying it to the dynamic array Charge every push an amortized cost of 3, regardless of whether it resizes. A push that doesn't resize costs 1 actually, banking 2 credit on the newly inserted element. When a resize happens at size m (doubling from m to 2m), it must copy all m existing elements — but the m/2 elements added since the last resize each still hold their banked 2 credit, contributing m credit, exactly enough to pay for copying all m elements (2 credit pays to move 2 elements' worth of copying, roughly — the accounting is arranged so the banked credit from the newest half of the array exactly covers the whole copy). Since every operation is charged a flat 3, and the invariant "credit never goes negative" holds by this bookkeeping, the amortized cost per push is O(1) — matching aggregate analysis, but now with an explicit invariant (credit ≥ 0) that a proof can point to directly.

Method 3: the potential method

Method Define a potential function Φ mapping the data structure's state to a nonnegative real number, with Φ(initial state) = 0. The amortized cost of an operation is defined as ĉᵢ = cᵢ + Φ(after) − Φ(before), where cᵢ is the actual cost. Because the Φ terms telescope across a sequence of operations, ∑ĉᵢ = ∑cᵢ + Φ(final) − Φ(initial) ≥ ∑cᵢ (since Φ(final) ≥ 0 = Φ(initial)) — so a bound on amortized cost is automatically a valid bound on total actual cost.
Applying it to the dynamic array Define Φ = 2·(size) − capacity. Right after a resize, size = capacity/2, so Φ = 2·(capacity/2) − capacity = 0 — potential resets to its minimum. Just before the next resize, size = capacity, so Φ = 2·capacity − capacity = capacity — potential has grown to exactly cover the upcoming copy cost. For a non-resizing push: cᵢ=1, and Φ increases by 2 (size goes up by 1, contributing +2 to Φ, capacity unchanged), so ĉᵢ = 1 + 2 = 3. For a resizing push at size m: cᵢ = m+1 (copy m elements, insert 1), Φ(before) = 2m − m = m, Φ(after) = 2(m+1) − 2m = 2, so ĉᵢ = (m+1) + (2 − m) = 3. Both cases give the same amortized cost, ĉᵢ = 3 = O(1) — proving the O(1) bound holds for every individual operation, not just the sequence average, which is exactly what aggregate analysis alone couldn't give you.
Why the potential method is the one this course leans on later The potential method's per-operation guarantee — not just a sequence average — is exactly what's needed to analyze data structures where operations interleave unpredictably, like Union-Find with path compression (Unit 6), where you can't assume a fixed pattern of operations to sum over in advance. Whenever this course needs to prove an amortized bound for a structure under arbitrary interleavings of its operations, it reaches for a potential function.

Check your recall

No peeking back up — answer from memory first, then check.

1. What question does amortized analysis answer that plain worst-case analysis doesn't?

Amortized analysis bounds the average cost per operation guaranteed over any sequence — a worst-case-over-sequences guarantee, not a probabilistic one.

2. In the accounting method for the dynamic array, what does "credit" on an element represent?

Charging more than the actual cost on cheap operations banks the surplus as credit, which is drawn down exactly when an expensive operation (a resize) needs to pay for work beyond its own charged amount.

3. Why does the potential method's telescoping sum guarantee that a bound on amortized cost implies a bound on total actual cost?

The intermediate Φ terms cancel in the sum, leaving only the boundary terms — and since potential can't go negative, the amortized total never undershoots the true total.

4. Fill in the blank: the ___ method defines ĉᵢ = cᵢ + Φ(after) − Φ(before), giving a per-operation amortized bound rather than just a sequence-wide average.

The potential method is the one of the three that certifies each individual operation's amortized cost, which is why later structures with unpredictable operation interleavings (like Union-Find) rely on it.

5. Fill in the blank: a dynamic array achieves O(1) amortized push specifically because its capacity grows by ___ rather than by a fixed increment each resize.

Doubling makes resizes exponentially rarer as the array grows, which is exactly what keeps the total resize cost linear in n instead of quadratic — a fixed increment would force a resize (and a full copy) every constant number of pushes.
