DP on Trees

CP2+'s DP lessons solved problems over sequences and grids. When the underlying structure is a tree instead, the recurrence changes shape — each subproblem combines results from a variable number of children rather than looking back one or two fixed positions.

← Lesson 17 Lesson 19 → Contents Glossary →

CP2+'s Lessons 26–30 covered dynamic programming over sequences (strings, arrays) and grids, where each state typically depends on one or two neighboring states (i−1, or i−1 and j−1). DP on trees keeps the same core idea — define a state, express it recursively in terms of smaller substates, memoize — but the recursion structure is dictated by the tree itself: a node's answer depends on combining the answers of all its children, an arity that varies node to node.

The canonical problem — maximum weight independent set on a tree

Problem Given a tree with a weight on each vertex, select a subset of vertices with no two adjacent (an independent set) maximizing total weight.
The state — two values per node For each vertex v, define: include(v) = maximum weight achievable in v's subtree if v is selected; exclude(v) = maximum weight achievable in v's subtree if v is not selected. Recurrence: include(v) = weight(v) + Σ exclude(c) over all children c (if v is picked, no child can be picked, since they're adjacent to v); exclude(v) = Σ max(include(c), exclude(c)) over all children c (if v isn't picked, each child is free to be picked or not, independently). The answer for the whole tree is max(include(root), exclude(root)).
Why two states per node, not one A single "best answer for this subtree" value isn't enough to combine correctly at the parent level, because whether v's own answer used v or not changes what's legal for v's parent to do. This is the tree-DP analogue of a pattern CP2+'s DP lessons also used — carrying extra state (like "last action taken") to make a locally-optimal-looking combination actually valid — except here the extra state is forced by the tree's adjacency structure rather than a sequence position.
Algorithm — post-order traversal 
function treeDP(v, parent):
    includeSum = weight(v)
    excludeSum = 0
    for each child c of v (c != parent):
        treeDP(c, v)                      // recurse first: children before parent
        includeSum += exclude[c]
        excludeSum += max(include[c], exclude[c])
    include[v] = includeSum
    exclude[v] = excludeSum
The recursive call on every child must complete before v's own include/exclude can be computed — a direct consequence of the recurrence depending on children's values, forcing a post-order (children-before-parent) traversal.
Runtime Θ(V): each vertex is visited exactly once, and the work at each vertex (excluding recursive calls) is proportional to its number of children, so total work across all vertices sums to Θ(V) (each edge contributes O(1) work exactly once).
Why this generalizes beyond one problem The include/exclude pattern here is one instance of a broader technique: whenever a tree problem's answer at a node depends on some property of its children's answers (count, max, sum, or a small combination of these), a post-order DP with a handful of values per node solves it in Θ(V) — this shape reappears constantly in competitive programming (tree diameter, minimum vertex cover on trees, counting subtrees with a given property) with only the combination rule at each node changing.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does DP on trees typically need a post-order traversal rather than a pre-order one?

The recurrence's dependency direction (parent needs child values) is what forces children to be resolved before their parent.

2. In the maximum weight independent set on trees problem, why does each node need two DP values (include and exclude) instead of one?

Carrying whether the node itself was included is what lets the parent correctly decide whether picking itself would create an adjacency conflict.

3. What is the runtime of the maximum weight independent set DP on a tree with V vertices, and why?

Each vertex and edge contributes only constant work exactly once, giving a linear total.

4. Fill in the blank: DP on trees generally requires a ___ traversal, resolving every child's values before computing its parent's.

Children-before-parent ordering is exactly what post-order traversal guarantees.

5. Fill in the blank: in an independent set, no two selected vertices may be ___ , which is why picking a node forces every one of its children to be excluded.

The adjacency restriction is the defining rule of an independent set and is exactly what the include(v) recurrence encodes.
