Bitmask DP: The Traveling Salesman Problem

Some DP states aren't a position or an index — they're an entire subset of items visited so far, encoded as the bits of an integer. This turns a problem with no known polynomial solution into one solvable in exponential-but-far-better-than-brute-force time.

← Lesson 18 Lesson 20 → Contents Glossary →

The traveling salesman problem (TSP): given n cities and the distance between every pair, find the shortest tour that visits every city exactly once and returns to the start. Brute force tries all (n−1)! orderings — utterly infeasible past roughly n=12. TSP is one of Unit 8's canonical NP-hard problems (no known polynomial algorithm exists, and Lesson 32 will show precisely why, via reduction), but that doesn't mean brute force is the only alternative — bitmask DP solves it exactly in Θ(n²·2ⁿ), a large improvement over Θ(n!) even though it's still exponential.

The state — a subset encoded as bits

Setup Represent "which cities have been visited so far" as an n-bit integer mask, where bit i is 1 if city i has been visited. There are 2ⁿ possible masks — one per subset of cities. Define dp[mask][j] = the minimum cost to start at city 0, visit exactly the set of cities in mask, and end at city j (where j must itself be a member of mask).
Why bits, specifically A subset of up to ~20 cities has exponentially many possible values, but each one maps to a unique integer 0 through 2ⁿ−1 via its bit pattern — so "the state is a subset" becomes "the state is an array index," letting an ordinary array (not a hash map or tree) store dp[mask][j] directly. Bitwise operations then make manipulating subsets fast: mask | (1<<k) adds city k to the set, mask & (1<<k) checks membership, both in O(1), which is exactly the per-transition speed the recurrence below depends on.
Recurrence dp[mask][j] = min over every city i in mask, i≠j, of ( dp[mask without j][i] + dist(i, j) ). In words: to end at j having visited exactly this set, some other city i in the set (other than j) must have been visited immediately before j — so consider every candidate "previous city" i, and take the best. Base case: dp[{0}][0] = 0 (start at city 0, having visited only city 0, at cost 0). Final answer: min over all j≠0 of ( dp[full mask][j] + dist(j, 0) ) — every city visited, ending at j, plus the trip back to the start.
Algorithm 
function tsp(dist, n):
    dp = array indexed by [mask][j], initialized to infinity
    dp[1][0] = 0                                  // mask=1 means only city 0 visited
    for mask in 1..(2^n - 1):
        for j in 0..n-1:
            if (mask & (1 << j)) == 0: continue    // j not in this mask, skip
            if dp[mask][j] == infinity: continue
            for k in 0..n-1:

Runtime Θ(n²·2ⁿ): 2ⁿ masks, each with n choices of j and (in the transition) n choices of k, giving n² work per mask. For n=20, that's roughly 20²·2²⁰ ≈ 4×10⁸ — large, but computable, versus 19! ≈ 1.2×10¹⁷ for brute force. This is the concrete difference between "exponential" and "factorial" growth that makes bitmask DP the standard approach for TSP up to a few dozen cities.
Why this doesn't contradict TSP being NP-hard Θ(n²·2ⁿ) is still exponential in n — it's an improvement in the constant inside the exponent (2ⁿ instead of n!), not a polynomial-time algorithm. TSP being NP-hard (Unit 8) means no polynomial-time algorithm is known (or, under the standard complexity-theoretic assumption P≠NP, believed to exist) — bitmask DP is the best known exact approach for moderate n, not a refutation of NP-hardness.

1. What does dp[mask][j] represent in the bitmask DP formulation of TSP?

The pair (mask, j) fully specifies both which cities have been visited and where the partial tour currently ends, which is exactly the information the recurrence needs.

2. Why does representing a subset of cities as a bitmask make this DP practical?

The array-indexable, O(1)-updatable nature of bitmask-encoded subsets is exactly what makes the DP's transitions fast.

3. Why doesn't bitmask DP's Θ(n²·2ⁿ) runtime contradict TSP's classification as NP-hard?

2ⁿ is exponential regardless of the polynomial factor n² multiplying it, so this remains consistent with no known polynomial-time solution existing.

4. Fill in the blank: encoding "which cities have been visited" as a ___ lets a subset be represented as a single integer with O(1) membership and update checks.

This encoding is the entire technique's namesake and its core enabling idea.

5. Fill in the blank: bitmask DP's Θ(n²·2ⁿ) runtime is still ___ in n, just with a smaller base than the n! of brute force.

2ⁿ growth is exponential, just with a dramatically smaller base than the factorial growth of brute-force enumeration.
