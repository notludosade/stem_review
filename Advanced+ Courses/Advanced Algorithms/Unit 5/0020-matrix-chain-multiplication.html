Matrix Chain Multiplication

Matrix multiplication is associative, so a chain of matrices can be parenthesized many different ways — all producing the same result, but at wildly different computational costs. This lesson finds the cheapest parenthesization with an interval-based DP.

← Lesson 19 Lesson 21 → Contents Glossary →

Multiplying a p×q matrix by a q×r matrix costs p·q·r scalar multiplications (the standard schoolbook cost, ignoring Strassen's improvement from Lesson 8, which doesn't change which parenthesization is cheapest, just the constant for each individual multiply). Given a chain of matrices A₁A₂...Aₙ, matrix multiplication is associative, so every legal parenthesization computes the exact same final matrix — but the total scalar-multiplication cost can differ by orders of magnitude depending on the order chosen. This problem introduces a DP shape indexed by an interval of the chain, distinct from both the "which prefix" state of sequence DP and the "which subset" state of Lesson 19's bitmask DP.

Why order matters — a concrete example

Worked example Three matrices: A₁ (10×100), A₂ (100×5), A₃ (5×50). Parenthesizing as (A₁A₂)A₃: A₁A₂ costs 10·100·5=5,000, producing a 10×5 result; then (A₁A₂)A₃ costs 10·5·50=2,500. Total: 7,500. Parenthesizing as A₁(A₂A₃) instead: A₂A₃ costs 100·5·50=25,000, producing a 100×50 result; then A₁(A₂A₃) costs 10·100·50=50,000. Total: 75,000 — ten times more expensive, despite computing the identical final matrix. The order of multiplication, not just the operation itself, is a genuine optimization problem.

The DP

State Let dims[0..n] be the matrix dimensions, so matrix Aᵢ has size dims[i−1] × dims[i]. Define dp[i][j] = the minimum cost to multiply the chain Aᵢ...Aⱼ into a single matrix (for i ≤ j; dp[i][i] = 0, a single matrix needs no multiplication).
Recurrence dp[i][j] = min over every split point k (i ≤ k < j) of ( dp[i][k] + dp[k+1][j] + dims[i−1]·dims[k]·dims[j] ). Reasoning: some multiplication must be the last one performed for the whole chain Aᵢ...Aⱼ — it multiplies the result of Aᵢ...Aₖ (a dims[i−1]×dims[k] matrix) by the result of Aₖ₊₁...Aⱼ (a dims[k]×dims[j] matrix). Trying every possible split point k and taking the best mirrors the same "try every way to combine two subproblems, take the optimum" logic Lesson 7's median-of-medians and Lesson 6's merge sort both used — but here the two subproblems are determined by an interval split, not a fixed midpoint.
Algorithm 
function matrixChainOrder(dims, n):
    dp = n x n table, dp[i][i] = 0 for all i
    for length in 2..n:                        // length of the chain being solved
        for i in 1..(n - length + 1):
            j = i + length - 1
            dp[i][j] = infinity
            for k in i..(j - 1):
                cost = dp[i][k] + dp[k+1][j] + dims[i-1]*dims[k]*dims[j]
                dp[i][j] = min(dp[i][j], cost)
    return dp[1][n]
Why the outer loop goes by increasing chain length dp[i][j]'s recurrence depends on dp[i][k] and dp[k+1][j], both strictly shorter chains than [i,j] — so every subproblem of length L must be fully solved before any subproblem of length L+1 can be computed. Iterating the outer loop by increasing length (rather than by i or j directly) is what guarantees every dependency is already resolved when needed — the same "smaller subproblems must be finished first" discipline Floyd-Warshall's k-outermost loop (Lesson 14) enforced, just organized around chain length instead of an allowed-intermediate-vertex count.
Runtime Θ(n³): Θ(n²) intervals [i,j], each considering up to n split points k.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why can different parenthesizations of the same matrix chain product have very different computational costs, even though they compute the same result?

Matrix multiplication is associative (same final result) but not cost-invariant, since intermediate result sizes vary by parenthesization order.

2. What does the split point k represent in the matrix chain multiplication recurrence?

Unlike a fixed-midpoint split (as in ordinary merge sort), k ranges over every possible split point, since the optimal split isn't known in advance.

3. Why must the DP's outer loop iterate by increasing chain length, rather than by increasing i or j directly?

Length-based ordering directly matches the recurrence's dependency structure, guaranteeing every needed subproblem is already solved.

4. Fill in the blank: the matrix chain DP tries every possible ___ point k for the last multiplication, taking whichever minimizes total cost.

Since the optimal split isn't known in advance, every candidate must be tried and compared.

5. Fill in the blank: the cost of multiplying two matrices depends on their ___ , which is exactly what makes different parenthesizations of the same chain cost differently.

Intermediate matrix dimensions vary with parenthesization order, and those dimensions directly determine each multiplication's cost.
