Memory Management for Game Assets

Systems Programming's Unit 2 covered the heap and what happens when memory isn't managed carefully. A game console or phone has a hard, fixed memory budget — and a AAA game's assets, loaded all at once, would blow past it many times over.

← Lesson 16 Lesson 18 → Contents Glossary →

A single open-world game might ship with hundreds of gigabytes of textures, models, and audio on disk. No gaming device has hundreds of gigabytes of fast memory available to a single game — most have a few gigabytes, shared with the operating system and everything else running. Every asset an engine loads is a bet against a hard, unforgiving ceiling.

A budget, not a suggestion

Definition A memory budget is the fixed amount of fast memory (RAM, or dedicated video memory on the GPU) a game is allowed to use for its assets at any one time, set by the target hardware, not chosen by the developer. An asset manager tracks every currently-loaded asset against that budget, and when a newly-needed asset would push memory past the limit, something already loaded has to be evicted — unloaded from memory — usually the asset judged least likely to be needed again soon.

Worked example A player walks from a forest zone into a cave. The forest's high-resolution foliage textures aren't visible or needed anymore, but they're still sitting in memory, taking up space the cave's rock and torch textures now need. The asset manager evicts the forest textures — the least-recently-needed assets — freeing exactly enough budget to load what the cave now requires, all without the player ever consciously noticing memory changed hands at all.
Why this connects directly to Systems Programming's heap lesson, at a much larger scale A memory leak (loading an asset and never properly releasing its reference) is exactly as dangerous here as in any C program — except a leaked 200 MB texture doesn't just waste space quietly, it can push a whole console over budget and crash the game outright within minutes, not run slowly for days like a leaking server might. Asset memory management is the same reference-counting and lifetime-tracking problem from that unit, just with a much smaller, much harder ceiling and much less room for error.

Check your recall

No peeking back up — answer from memory first, then check.

1. What determines a game's memory budget?

The budget is set externally by the hardware the game runs on.

2. What does "evicting" an asset mean?

Eviction is unloading from memory, not deleting the underlying file.

3. Why is a leaked asset arguably more dangerous on a game console than a similar leak in a long-running server?

A small, fixed budget means a leak's consequences arrive much faster and harder than on a server.

4. Fill in the blank: the fixed amount of fast memory a game may use for assets at any one time is its ___.

The memory budget is the hard ceiling asset loading has to respect.

5. Fill in the blank: when a needed asset would push memory past budget, an existing asset is ___ to make room.

Eviction frees space by unloading an asset judged least likely to be needed soon.
