Rigid Body Physics and Integration

Lesson 13 answered "are these two things touching?" This lesson answers the question underneath everything else in physics: given a force like gravity, how does an object's position actually change, frame by frame?

← Lesson 13 Lesson 15 → Contents Glossary →

Real-world motion follows continuous calculus — velocity is the derivative of position, acceleration is the derivative of velocity. A computer can't work with continuous calculus directly; it can only take small discrete steps. Integration, in this context, is exactly how physics engines approximate that continuous motion using discrete timesteps.

A rigid body's state, updated one step at a time

Definition A rigid body is an object physics treats as a solid, non-deformable shape with mass, position, and velocity, that forces (gravity, a push, a collision response) can act on. Numerical integration is the process of updating a rigid body's velocity and position over each small timestep by accumulating the effect of forces. The simplest version, Euler integration, does this in two lines per step: first update velocity using the current acceleration, then update position using the updated velocity — each step's result feeding directly into the next. 
// semi-implicit Euler integration, run once per fixed timestep (Unit 2)
velocity += acceleration * dt;   // gravity pulls velocity down over time
position += velocity * dt;       // position moves according to the *new* velocity

Try it: drop a ball, watch integration happen live

Interactive: Euler integration under gravity

Step 0 — velocity: 0.0 m/s, position: 0.0 m fallen.

Worked example Gravity's acceleration is roughly -9.8 m/s² (downward). At dt = 0.1s, step one: velocity becomes 0 + (-9.8)(0.1) = -0.98 m/s, then position moves by -0.98 × 0.1 = -0.098 m. Step two: velocity becomes -0.98 + (-9.8)(0.1) = -1.96 m/s, then position moves a further -1.96 × 0.1 = -0.196 m. Each step's position change grows, because velocity itself is still accumulating — exactly the accelerating fall a dropped object should show, built entirely from two additions repeated every fixed step.
Why the timestep size directly affects accuracy — tying straight back to Unit 2 Euler integration is an approximation: it assumes acceleration and velocity stay constant across one single timestep, which is only ever approximately true. A larger timestep accumulates more error per step (which is exactly why Lesson 5's fixed timestep matters for physics specifically) — too large, and a fast-enough object can integrate straight through a thin wall in one step, the same tunneling problem Lesson 5 named for a different reason. Smaller, more frequent, fixed steps are what keep that error small enough to be invisible in practice.

1. In semi-implicit Euler integration, what gets updated first each step?

Velocity updates first, and position update then uses that fresh velocity value.

2. What is a rigid body, in physics simulation terms?

Rigid bodies are non-deformable solids that forces act on, as defined at the top of the lesson.

3. Why does a larger integration timestep introduce more error?

The constant-during-one-step assumption is exactly what breaks down more at larger step sizes.
