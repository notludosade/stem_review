Collision Detection Basics: AABB, Broad Phase, Narrow Phase

Rendering (Unit 4) draws objects that pass through each other with no complaint at all. Making a wall stop a character, or a bullet register a hit, needs an entirely separate system — physics, and it starts with the simple question: are these two things touching?

← Unit 4, Lesson 12 Lesson 14 → Contents Glossary →

Checking whether two exact, detailed 3D meshes overlap — triangle by triangle — is expensive, and checking every object against every other object that way, every frame, is far too slow for a game with more than a handful of objects. Engines solve this with a cheap approximation first, and only reach for expensive exact checks when the approximation says it's worth it.

Boxes first, exact shapes only if the boxes overlap

Definition An AABB (Axis-Aligned Bounding Box) is the smallest rectangle (or box, in 3D) that fully contains an object, with its edges always aligned to the world's x/y axes — never rotated. Testing whether two AABBs overlap is extremely cheap: just four comparisons of min/max coordinates. Broad phase collision detection uses cheap AABB checks (or similar tricks like a spatial grid) to quickly throw out the vast majority of object pairs that obviously can't be touching. Narrow phase then runs the expensive, exact collision test only on the small handful of pairs broad phase couldn't rule out.

Worked example A scene has 500 objects. Checking every pair exactly would mean roughly 125,000 expensive mesh-vs-mesh tests every frame — far too slow. Broad phase's cheap AABB checks (or a spatial grid that only compares objects in nearby cells) might narrow that down to 40 pairs whose bounding boxes actually overlap. Narrow phase then runs the expensive exact check on just those 40 — a workload that's now entirely manageable, sixty times a second.
Why an AABB overlap check is cheap enough to run on every pair Because an AABB is never rotated, checking overlap reduces to comparing ranges on two independent axes: boxes A and B overlap only if A's x-range overlaps B's x-range and A's y-range overlaps B's y-range. That's four simple number comparisons — no square roots, no trigonometry, nothing that scales with how detailed the underlying mesh actually is. It's also, deliberately, an overestimate: an AABB overlap doesn't guarantee the real shapes touch (two round objects can have overlapping boxes while the circles themselves don't touch), which is exactly why narrow phase still has to confirm it.

Axis-aligned specifically means the box never rotates, which is what keeps the overlap test cheap.

Broad phase is a cheap filter, not the final, exact test.
