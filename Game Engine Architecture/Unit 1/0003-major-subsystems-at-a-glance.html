Major Subsystems at a Glance

Rendering, physics, audio, input, and scripting — five subsystems that show up in nearly every engine, in some form. This lesson is a map of the territory before the rest of the course zooms into each region.

← Lesson 2 Unit 2, Lesson 4 → Contents Glossary →

None of these subsystems work in isolation — the render subsystem needs to know where physics put every object, and the scripting layer needs to reach into almost all of them. But each one is still a distinct piece of engineering, usually owned by different code (and, at a real studio, different specialists) inside the engine.

The five you'll see everywhere

Definition A subsystem is a self-contained part of an engine responsible for one category of work, with its own internal data and update logic, that other parts of the engine and game code interact with through a defined interface rather than by reaching into its internals directly.

Interactive: the five core subsystems

Worked example A single moment in a game — the player fires a weapon — touches nearly every subsystem in order: input detects the button press, scripting (or game code) decides that means "spawn a bullet," physics moves that bullet forward each frame and checks what it hits, rendering draws the bullet and any muzzle flash, and audio plays the gunshot sound. No single subsystem "is" the gunshot — it's the coordinated result of five separate systems, each doing one narrow job.
Why engines separate these instead of one big update function It would be technically possible to write one giant function that does physics math, then drawing, then sound, all mixed together. Real engines don't, because separating subsystems lets each one be developed, tested, optimized, and even replaced independently — a studio can swap in a different physics engine without touching rendering code, precisely because the two were never tangled together in the first place. This is the same coupling-and-cohesion principle Software Engineering covered, applied to one of the most performance-sensitive kinds of software that exists.
