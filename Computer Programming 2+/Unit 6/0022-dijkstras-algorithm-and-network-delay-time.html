Dijkstra's Algorithm & Network Delay Time

Closing this unit by bringing Unit 5's heap back for a graph where edges finally have a cost.

← Lesson 21 Contents Glossary →

Problem: a signal is sent from node k across a weighted, directed graph, where each edge (u, v, w) takes w time to travel. Find how long it takes for the signal to reach every node, or -1 if some node is unreachable. Lesson 19's BFS finds shortest paths perfectly when every edge costs the same "one step" — but here, edges cost different amounts, so plain BFS no longer guarantees the first arrival is the shortest one.

The idea Dijkstra's algorithm is Lesson 19's BFS with one change: instead of a plain queue that processes nodes in the order they were discovered, it uses a min-heap (Unit 5) that always processes the node with the smallest known distance-so-far next. Pop the closest unprocessed node, lock in its distance, and relax its neighbors — push each one with its updated (shorter) candidate distance if the new path beats what's known so far.
Python 
import heapq
from collections import defaultdict

def network_delay_time(times, n, k):
    graph = defaultdict(list)
    for u, v, w in times:
        graph[u].append((v, w))

    dist = {}
    heap = [(0, k)]              # (distance so far, node) — a min-heap ordered by distance
    while heap:
        d, node = heapq.heappop(heap)
        if node in dist:
            continue             # already locked in with a shorter distance
        dist[node] = d
        for neighbor, weight in graph[node]:
            if neighbor not in dist:
                heapq.heappush(heap, (d + weight, neighbor))

    return max(dist.values()) if len(dist) == n else -1
Java 
int networkDelayTime(int[][] times, int n, int k) {
    Map<Integer, List<int[]>> graph = new HashMap<>();
    for (int[] time : times) {
        graph.computeIfAbsent(time[0], x -> new ArrayList<>()).add(new int[] { time[1], time[2] });
    }

    Map<Integer, Integer> dist = new HashMap<>();
    PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);   // min-heap by distance
    heap.offer(new int[] { 0, k });

    while (!heap.isEmpty()) {
        int[] curr = heap.poll();
        int d = curr[0], node = curr[1];
        if (dist.containsKey(node)) continue;   // already locked in with a shorter distance
        dist.put(node, d);
        for (int[] edge : graph.getOrDefault(node, new ArrayList<>())) {
            int neighbor = edge[0], weight = edge[1];
            if (!dist.containsKey(neighbor)) heap.offer(new int[] { d + weight, neighbor });
        }
    }

    if (dist.size() != n) return -1;
    return Collections.max(dist.values());
}
JavaScript 
// Reuses the MinHeap class introduced in Lesson 15, with a comparator by distance
function networkDelayTime(times, n, k) {
  const graph = new Map();
  for (const [u, v, w] of times) {
    if (!graph.has(u)) graph.set(u, []);
    graph.get(u).push([v, w]);
  }

  const dist = new Map();
  const heap = new MinHeap((a, b) => a[0] - b[0]);   // min-heap by distance
  heap.push([0, k]);

  while (heap.data.length > 0) {
    const [d, node] = heap.pop();
    if (dist.has(node)) continue;   // already locked in with a shorter distance
    dist.set(node, d);
    for (const [neighbor, weight] of graph.get(node) || []) {
      if (!dist.has(neighbor)) heap.push([d + weight, neighbor]);
    }
  }

  if (dist.size !== n) return -1;
  return Math.max(...dist.values());
}
C++ 
int networkDelayTime(std::vector<std::vector<int>>& times, int n, int k) {
    std::unordered_map<int, std::vector<std::pair<int,int>>> graph;
    for (auto& t : times) graph[t[0]].push_back({t[1], t[2]});

    std::unordered_map<int, int> dist;
    std::priority_queue<std::pair<int,int>, std::vector<std::pair<int,int>>, std::greater<>> heap;
    heap.push({0, k});   // min-heap by distance (pair compares first element first)

    while (!heap.empty()) {
        auto [d, node] = heap.top(); heap.pop();
        if (dist.count(node)) continue;   // already locked in with a shorter distance
        dist[node] = d;
        for (auto& [neighbor, weight] : graph[node]) {
            if (!dist.count(neighbor)) heap.push({d + weight, neighbor});
        }
    }

    if ((int)dist.size() != n) return -1;
    int maxDist = 0;
    for (auto& [node, d] : dist) maxDist = std::max(maxDist, d);
    return maxDist;
}

Each edge can push at most one heap entry, so with E edges the heap does O(E log E) work, which simplifies to O(E log V) since E can never exceed V². This is Lesson 15's heap-push/pop cost, just paid once per edge instead of once per array element.

Why it matters here Dijkstra's algorithm is not a new traversal — it's Lesson 19's BFS with its queue swapped for Unit 5's min-heap, sorting by distance instead of by discovery order. That single swap is what makes it correct on weighted graphs where BFS would otherwise commit to a path too early. Recognizing "shortest path, but edges have different costs" as the trigger for "BFS plus a heap" ties together nearly everything this unit and Unit 5 have covered.

Check your recall

1. What single change turns Lesson 19's BFS into Dijkstra's algorithm?

Sorting by distance instead of discovery order is what lets Dijkstra handle unequal edge weights correctly.

2. Why does plain BFS fail to find shortest paths once edges have different weights?

A path with more hops but lower total weight could easily be shorter than one BFS reaches first.

3. When a node is popped from the heap and already has a recorded distance, what should happen?

The heap can contain stale, larger-distance entries for a node already finalized with a smaller one.

4. Fill in the blank: Dijkstra's algorithm is BFS with its queue replaced by a min-___ sorted by distance.

This is the exact structure introduced in Unit 5, reused here for a new purpose.

5. Fill in the blank: Dijkstra's algorithm is needed once a graph becomes ___, meaning its edges no longer all cost the same amount.

Plain BFS remains correct and simpler whenever every edge has identical cost.
