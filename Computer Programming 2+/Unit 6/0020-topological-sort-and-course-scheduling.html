Topological Sort & Course Scheduling

A directed graph — where edges only go one way — introduces a new question: is there any valid order to do everything in at all?

← Lesson 19 Lesson 21 → Contents Glossary →

Problem: there are numCourses courses, and a list of prerequisite pairs [course, prereq] meaning prereq must be taken before course. Determine whether it's possible to finish every course at all. Every edge here is directed — "prereq → course" is not the same as "course → prereq" — and a valid ordering exists if and only if the graph has no cycle.

The idea Kahn's algorithm finds a topological order (or proves none exists) using BFS. Track each course's in-degree — how many prerequisites still point into it. Start a queue with every course that has in-degree zero (nothing blocks it). Process the queue: for each course removed, decrement the in-degree of everything it unlocks, adding any that drop to zero. If every course eventually gets processed, no cycle exists. If some are left over, they're stuck in a cycle blocking each other forever.
Python 
from collections import deque

def can_finish(num_courses, prerequisites):
    graph = [[] for _ in range(num_courses)]
    in_degree = [0] * num_courses
    for course, prereq in prerequisites:
        graph[prereq].append(course)
        in_degree[course] += 1

    queue = deque(c for c in range(num_courses) if in_degree[c] == 0)
    visited = 0
    while queue:
        node = queue.popleft()
        visited += 1
        for neighbor in graph[node]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
    return visited == num_courses     # false means a cycle blocked some courses
Java 
boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> graph = new ArrayList<>();
    int[] inDegree = new int[numCourses];
    for (int i = 0; i < numCourses; i++) graph.add(new ArrayList<>());
    for (int[] pair : prerequisites) {
        int course = pair[0], prereq = pair[1];
        graph.get(prereq).add(course);
        inDegree[course]++;
    }

    Queue<Integer> queue = new LinkedList<>();
    for (int c = 0; c < numCourses; c++) if (inDegree[c] == 0) queue.add(c);

    int visited = 0;
    while (!queue.isEmpty()) {
        int node = queue.poll();
        visited++;
        for (int neighbor : graph.get(node)) {
            inDegree[neighbor]--;
            if (inDegree[neighbor] == 0) queue.add(neighbor);
        }
    }
    return visited == numCourses;   // false means a cycle blocked some courses
}
JavaScript 
function canFinish(numCourses, prerequisites) {
  const graph = Array.from({ length: numCourses }, () => []);
  const inDegree = new Array(numCourses).fill(0);
  for (const [course, prereq] of prerequisites) {
    graph[prereq].push(course);
    inDegree[course]++;
  }

  const queue = [];
  for (let c = 0; c < numCourses; c++) if (inDegree[c] === 0) queue.push(c);

  let visited = 0;
  while (queue.length > 0) {
    const node = queue.shift();
    visited++;
    for (const neighbor of graph[node]) {
      inDegree[neighbor]--;
      if (inDegree[neighbor] === 0) queue.push(neighbor);
    }
  }
  return visited === numCourses;   // false means a cycle blocked some courses
}
C++ 
bool canFinish(int numCourses, std::vector<std::vector<int>>& prerequisites) {
    std::vector<std::vector<int>> graph(numCourses);
    std::vector<int> inDegree(numCourses, 0);
    for (auto& pair : prerequisites) {
        int course = pair[0], prereq = pair[1];
        graph[prereq].push_back(course);
        inDegree[course]++;
    }

    std::queue<int> q;
    for (int c = 0; c < numCourses; c++) if (inDegree[c] == 0) q.push(c);

    int visited = 0;
    while (!q.empty()) {
        int node = q.front(); q.pop();
        visited++;
        for (int neighbor : graph[node]) {
            if (--inDegree[neighbor] == 0) q.push(neighbor);
        }
    }
    return visited == numCourses;   // false means a cycle blocked some courses
}

Building the graph and in-degree array costs O(V + E). The BFS itself visits each node once and each edge once, also O(V + E) — so the whole algorithm is O(V + E) overall, the same bound as ordinary BFS from Lesson 19, just tracking one extra counter per node.

Why it matters here Kahn's algorithm is Lesson 19's multi-source BFS wearing a different hat: instead of seeding the queue with "already rotten" oranges, it's seeded with "already unblocked" courses, and instead of tracking distance, it's tracking whether every node eventually gets freed. Any problem phrased as "given these dependencies, can everything be scheduled" — build order, task scheduling, package installation order — is this same in-degree-counting BFS underneath.

Check your recall

1. What does a course's in-degree represent in this problem?

A course with in-degree zero has nothing left blocking it and can start the queue.

2. If the queue empties before every course has been visited, what does that indicate?

A cycle means every course in it always has at least one unmet prerequisite, so none can ever reach in-degree zero.

3. How does Kahn's algorithm here relate to Lesson 19's multi-source BFS?

Both seed a queue with every valid starting point at once and process level by level, tracking a counter as they go.

4. Fill in the blank: a valid course order exists if and only if the prerequisite graph contains no ___.

Any cycle means each course in it depends on another that depends back on it.

5. Fill in the blank: prerequisite edges only go one way, making this a ___ graph rather than the undirected grids from Lessons 18 and 19.

"Prereq unlocks course" is not the same relationship as "course unlocks prereq."
