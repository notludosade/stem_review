Representing Graphs & Depth-First Search

A tree is a graph with an extra rule: no cycles, and exactly one path between any two nodes. Drop that rule, and traversal needs one new safeguard.

← Lesson 17 Lesson 19 → Contents Glossary →

A graph is a set of nodes connected by edges — no restriction on how many connections a node can have, or whether following edges can loop back on itself. The most common representation is an adjacency list: a map (or array) from each node to the list of nodes it directly connects to, for example {0: [1, 2], 1: [0, 3], 2: [0], 3: [1]}. A 2D grid — like a map of land and water — is secretly a graph too: each cell is a node, and it's implicitly connected to its (up to four) neighbors.

The idea Because a graph can contain cycles, DFS needs a way to avoid revisiting the same node forever. Problem: given a grid of '1' (land) and '0' (water), count the number of islands — groups of connected land cells. Run DFS from every unvisited land cell, marking every cell it reaches as visited; each DFS that starts is exactly one new island.
Python 
def num_islands(grid):
    rows, cols = len(grid), len(grid[0])

    def dfs(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols or grid[r][c] != '1':
            return
        grid[r][c] = '0'          # mark visited by sinking the land
        dfs(r + 1, c)
        dfs(r - 1, c)
        dfs(r, c + 1)
        dfs(r, c - 1)

    islands = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                islands += 1
                dfs(r, c)
    return islands

int numIslands(char[][] grid) {

JavaScript 
function numIslands(grid) {
  const rows = grid.length, cols = grid[0].length;
  function dfs(r, c) {
    if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] !== '1') return;
    grid[r][c] = '0';               // mark visited by sinking the land
    dfs(r + 1, c);
    dfs(r - 1, c);
    dfs(r, c + 1);
    dfs(r, c - 1);
  }
  let islands = 0;
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === '1') {
        islands++;
        dfs(r, c);
      }
    }
  }
  return islands;
}
C++ 
void dfs(std::vector<std::vector<char>>& grid, int r, int c) {
    int rows = grid.size(), cols = grid[0].size();
    if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] != '1') return;
    grid[r][c] = '0';                // mark visited by sinking the land
    dfs(grid, r + 1, c);
    dfs(grid, r - 1, c);
    dfs(grid, r, c + 1);
    dfs(grid, r, c - 1);
}

int numIslands(std::vector<std::vector<char>>& grid) {
    int islands = 0;
    for (int r = 0; r < (int)grid.size(); r++) {
        for (int c = 0; c < (int)grid[0].size(); c++) {
            if (grid[r][c] == '1') {
                islands++;
                dfs(grid, r, c);
            }
        }
    }
    return islands;
}

Marking a visited cell by overwriting it (sinking land to water) avoids needing a separate visited set, but mutates the input — a separate boolean grid is the alternative when the input can't be changed. Either way, each cell is visited at most once, so this is O(rows · cols) time and, worst case, O(rows · cols) space on the call stack if the entire grid is one connected island.

Why it matters here This is Lesson 11's tree DFS with exactly one addition: a visited check, because a graph (unlike a tree) can lead back to somewhere already seen. That single addition is the entire conceptual gap between "I know tree traversal" and "I know graph traversal" — everything else about recursing into neighbors and processing them is identical. Grids are also worth recognizing as graphs on sight: any "connected region," "reachable cells," or "spreading" problem on a grid is a graph problem wearing a 2D array's clothes.

Check your recall

1. What is the key structural difference between a tree and a general graph?

A tree is really just a graph with the added guarantee of no cycles and exactly one path between any two nodes.

2. Why does graph DFS need a visited check that tree DFS didn't need?

Trees guarantee no cycles exist, so revisiting was never possible there in the first place.

3. In the island-counting solution, what does starting a new DFS call from a cell represent?

Every unvisited land cell found in the outer loop starts a fresh DFS that sinks its entire connected island at once.

4. Fill in the blank: mapping each node to the list of nodes it directly connects to is called an ___ list.

This is the most common way to represent a graph in code.

5. Fill in the blank: marking a cell as ___ (whether by a separate set or by mutating the input) is the one addition graph DFS needs beyond tree DFS.

Without this, a cycle would send the traversal into an infinite loop.
