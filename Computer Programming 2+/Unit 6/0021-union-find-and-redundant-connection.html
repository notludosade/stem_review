Union-Find & Redundant Connection

Some connectivity questions don't need a traversal at all — just a structure that answers "are these two already connected?" in near constant time.

← Lesson 20 Lesson 22 → Contents Glossary →

Problem: a graph started as a tree (n nodes, n − 1 edges, no cycles) and one extra edge was added, creating exactly one cycle. Given the edges in the order they were added, find the one edge that — if removed — restores the tree. Re-running DFS from scratch after every single edge would work, but it's wasteful. Union-Find (also called Disjoint Set Union) answers "are these two nodes already connected?" without any traversal at all.

The idea Every node starts as its own separate group, tracked by a parent array where each node initially points to itself. find(x) follows parent pointers up to the group's root. union(x, y) finds both roots and links one under the other. Process edges one at a time: if union ever discovers both endpoints already share a root, that edge connects two nodes already connected — it's the redundant one.
Python 
def find_redundant_connection(edges):
    parent = list(range(len(edges) + 1))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path compression: shorten the chain
            x = parent[x]
        return x

    def union(x, y):
        root_x, root_y = find(x), find(y)
        if root_x == root_y:
            return False        # already connected: this edge creates the cycle
        parent[root_x] = root_y
        return True

    for u, v in edges:
        if not union(u, v):
            return [u, v]

    int rootX = find(x), rootY = find(y);
    if (rootX == rootY) return false;    // already connected: this edge creates the cycle
    parent[rootX] = rootY;
    return true;

int[] findRedundantConnection(int[][] edges) {
    parent = new int[edges.length + 1];

    return new int[0];

function findRedundantConnection(edges) {
  const parent = Array.from({ length: edges.length + 1 }, (_, i) => i);

  function find(x) {
    while (parent[x] !== x) {

C++ 
std::vector<int> parent;

int find(int x) {
    while (parent[x] != x) {
        parent[x] = parent[parent[x]];   // path compression: shorten the chain
        x = parent[x];
    }
    return x;
}

bool unite(int x, int y) {
    int rootX = find(x), rootY = find(y);
    if (rootX == rootY) return false;    // already connected: this edge creates the cycle
    parent[rootX] = rootY;
    return true;
}

std::vector<int> findRedundantConnection(std::vector<std::vector<int>>& edges) {
    parent.resize(edges.size() + 1);
    for (int i = 0; i < (int)parent.size(); i++) parent[i] = i;

    for (auto& edge : edges) {
        if (!unite(edge[0], edge[1])) return edge;
    }
    return {};
}

Path compression — making every visited node point directly at the root during find — keeps the parent chains flat, so both find and union run in nearly O(1) time in practice (technically O(α(n)), where α is the inverse Ackermann function — for any input size that could ever exist, α(n) ≤ 4). Processing all edges is then O(n · α(n)), effectively linear.

Why it matters here Union-Find solves an entire category of problems DFS/BFS could also solve, but far more efficiently when the real question is repeated "are these connected yet?" checks rather than a one-time full traversal — detecting cycles while building a graph edge by edge, counting connected components, or checking whether a sequence of union operations ever merges two specific groups. Recognizing "this is fundamentally a connectivity question, asked repeatedly" is the signal to reach for Union-Find instead of re-traversing from scratch each time.

Check your recall

1. What question does Union-Find answer without running a traversal?

Union-Find tracks group membership directly, so this check doesn't require walking the graph at all.

2. In this problem, how is the redundant edge identified?

If both endpoints are already connected before this edge is added, this edge is the one creating the cycle.

3. What does path compression accomplish inside find?

By repointing visited nodes straight at the root, later lookups skip the intermediate steps entirely.

4. Fill in the blank: two nodes are in the same group exactly when find returns the same ___ for both.

Every node in a group eventually points, directly or indirectly, to this single shared node.

5. Fill in the blank: path ___ is the optimization that keeps Union-Find's operations close to constant time.

Without it, parent chains could grow long and each find would cost more than nearly-constant time.
