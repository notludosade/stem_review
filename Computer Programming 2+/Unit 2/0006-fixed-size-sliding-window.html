Fixed-Size Sliding Window

Recomputing a sum over every possible window of size k is wasted work — sliding the window reuses almost all of the previous computation.

← Lesson 5 Lesson 7 → Contents Glossary →

Problem: given an array and a fixed size k, find the maximum sum of any k consecutive elements. Brute force: for every starting index, sum the next k elements. With n starting positions and k elements summed each time, that's O(n·k) — and the bottleneck is obvious once you look for it: adjacent windows share k − 1 elements, and the brute force re-adds every one of them from scratch.

The idea Compute the first window's sum once. To slide the window forward by one position, subtract the element leaving on the left and add the element entering on the right — O(1) per slide instead of O(k).
Python 
def max_window_sum(nums, k):
    window_sum = sum(nums[:k])
    best = window_sum
    for i in range(k, len(nums)):
        window_sum += nums[i] - nums[i - k]
        best = max(best, window_sum)
    return best
Java 
int maxWindowSum(int[] nums, int k) {
    int windowSum = 0;
    for (int i = 0; i < k; i++) windowSum += nums[i];
    int best = windowSum;
    for (int i = k; i < nums.length; i++) {
        windowSum += nums[i] - nums[i - k];
        best = Math.max(best, windowSum);
    }
    return best;
}
JavaScript

C++ 
int maxWindowSum(std::vector<int>& nums, int k) {
    int windowSum = 0;
    for (int i = 0; i < k; i++) windowSum += nums[i];
    int best = windowSum;
    for (int i = k; i < nums.size(); i++) {
        windowSum += nums[i] - nums[i - k];
        best = std::max(best, windowSum);
    }
    return best;
}

This drops the total cost from O(n·k) to O(n) — each element is added exactly once and subtracted exactly once, no matter how large k is. The general shape — maintain a running aggregate over a window, and update it incrementally as the window moves — extends to more than just sums: max/min over a window, counts of characters, or any total that can be adjusted by "remove the outgoing element's effect, add the incoming element's effect."

Why it matters here Fixed-size sliding window is the simplest version of a pattern that recurs constantly: whenever a problem asks about every contiguous sub-range of a fixed length, recomputing from scratch is almost always the bottleneck, and incremental updates almost always fix it. Lesson 7 removes the "fixed length" restriction — the harder and far more common real-world case.

Check your recall

1. What is the time complexity of brute-force recomputing the sum of every window of size k?

Both the number of windows (n) and the cost per window (k) contribute, multiplying together.

2. What two operations does sliding the window forward by one position require?

Only the element leaving and the element entering actually change — everything else is shared with the previous window.

3. Why do adjacent windows of size k share most of their elements?

k − 1 elements are shared between any two windows that are one position apart — only one element differs on each end.

4. Fill in the blank: a contiguous, fixed-length range of elements that slides across an array one position at a time is called a ___.

This is the structure the entire technique is named after.

5. Fill in the blank: updating a running total by adjusting only for what entered and left, instead of recomputing from scratch, is called an ___ update.

This is what turns an O(k)-per-window cost into O(1) per slide.
