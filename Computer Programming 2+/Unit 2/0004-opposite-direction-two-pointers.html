Opposite-Direction Two Pointers

On a sorted array, two indices walking toward each other can replace a nested loop entirely.

← Lesson 3 Lesson 5 → Contents Glossary →

Take Two Sum again, but with one new fact: the array is already sorted. That single fact changes the best approach entirely. Instead of a hash map, place one pointer at the start and one at the end, and move them based on how the current sum compares to the target.

The idea If nums[left] + nums[right] is too small, the array being sorted guarantees moving left rightward is the only way to increase the sum. If it's too large, move right leftward. If it matches, you're done.
Python 
def two_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return [left, right]
        elif total < target:
            left += 1
        else:
            right -= 1
Java 
int[] twoSumSorted(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int total = nums[left] + nums[right];
        if (total == target) return new int[] { left, right };
        else if (total < target) left++;
        else right--;
    }
    return null;
}
JavaScript 
function twoSumSorted(nums, target) {
  let left = 0, right = nums.length - 1;
  while (left < right) {
    const total = nums[left] + nums[right];
    if (total === target) return [left, right];
    else if (total < target) left++;
    else right--;
  }
}
C++ 
std::vector<int> twoSumSorted(std::vector<int>& nums, int target) {
    int left = 0, right = nums.size() - 1;
    while (left < right) {
        int total = nums[left] + nums[right];
        if (total == target) return {left, right};
        else if (total < target) left++;
        else right--;
    }
    return {};
}

No hash map needed: O(n) time, O(1) extra space — strictly better than Lesson 1's solution, purely because sortedness is guaranteed here. That trade-off is the lesson: a hash map buys speed when the data has no usable order; two pointers buy speed for free when it does. Recognizing which situation you're in is the actual skill — not the code itself, which is short either way.

The same shape solves a very different-looking problem: checking whether a string reads the same forwards and backwards. Walk from both ends inward, comparing characters, stopping the moment they disagree (skipping non-alphanumeric characters and case differences, depending on the exact problem statement).

Why it matters here "Opposite-direction two pointers" is the single most common shape for problems on sorted arrays or symmetric structures like palindromes — the pattern shows up again in Unit 3's binary search boundaries and Unit 9's interval merging. Once it's recognized as its own tool, "the array is sorted" becomes an instant signal to reach for it before anything else.

Check your recall

1. What fact about the input makes the opposite-direction two-pointer approach to Two Sum work?

Sortedness guarantees which direction to move a pointer when the current sum is too high or too low.

2. If nums[left] + nums[right] is smaller than the target on a sorted array, which pointer should move, and why?

Moving right leftward would only decrease the sum further — the wrong direction when the sum needs to grow.

3. What is the space complexity of the two-pointer solution, compared to Lesson 1's hash-map solution?

Two pointers need only two integer variables — no hash map or other structure is required.

4. Fill in the blank: opposite-direction two pointers require the input to already be ___, or the direction to move each pointer can't be guaranteed correct.

Without a guaranteed order, moving a pointer could move away from the answer instead of toward it.

5. Fill in the blank: a string that reads the same forwards and backwards, checkable by walking two pointers inward from both ends, is called a ___.

Comparing characters from both ends inward stops the moment a mismatch is found.
