Fast & Slow Pointers

Two pointers moving at different speeds through a linked list can detect a loop no amount of scanning could otherwise find without extra memory.

← Lesson 4 Lesson 6 → Contents Glossary →

CP2's linked-list lesson assumed lists are finite chains ending in null. But a corrupted or intentionally malformed list can have its tail point back into itself, forming a cycle — and a naive traversal of that list never terminates.

The brute-force fix is a hash set: store every node visited, and if a node is ever seen twice, a cycle exists. That works, but costs O(n) space. Floyd's cycle detection (the "tortoise and hare") gets the same answer in O(1) space: run one pointer one step at a time, and a second pointer two steps at a time. If there's no cycle, the fast pointer reaches the end first. If there is one, the fast pointer eventually laps the slow one and they meet.

Python 
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
Java 
boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}
JavaScript 
function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}
C++ 
bool hasCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}

Why do they always meet, and not just repeatedly pass each other? Once both pointers are inside the cycle, the fast pointer gains exactly one node on the slow pointer every step — so the gap between them shrinks by one each time, and a shrinking integer gap must eventually hit zero. That's the whole proof, and it generalizes: whenever "two things moving at different, fixed rates around a loop" describes a problem, expect them to eventually align.

Why it matters here Fast/slow pointers are the standard O(1)-space answer to cycle-detection and "find the middle of a linked list in one pass" — both frequent as sub-steps inside larger problems (a common one: find the middle, then reverse the second half). They're also a clean example of trading a slightly less obvious proof for real space savings, the same trade Lesson 2 named directly.

Check your recall

1. What does the brute-force hash-set approach to cycle detection cost that Floyd's algorithm avoids?

Storing every visited node in a hash set costs O(n) space; Floyd's algorithm uses only two pointers.

2. If there is no cycle in the list, what happens to the fast pointer?

Moving twice as fast, it simply runs out of list first when there's no cycle to trap it in.

3. Why must the fast and slow pointers eventually meet once both are inside a cycle?

A gap that shrinks by exactly one integer step each iteration must eventually reach zero.

4. Fill in the blank: when a linked list's tail points back into an earlier node instead of ending in null, the list contains a ___.

A naive traversal of such a list never terminates, since it never reaches null.

5. Fill in the blank: Floyd's cycle detection algorithm is commonly nicknamed the "___ and hare" algorithm, after its slow and fast pointers.

The slow pointer is the "tortoise"; the fast pointer is the "hare."
