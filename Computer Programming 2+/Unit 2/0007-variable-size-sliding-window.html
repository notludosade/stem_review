Variable-Size Sliding Window

Most real sliding-window problems don't hand you a fixed k — the window has to grow and shrink on its own, based on a rule.

← Lesson 6 Contents Glossary →

Problem: find the length of the longest substring with no repeated characters. There's no fixed window size given up front — the window has to expand while characters stay unique, and shrink the moment a repeat appears.

The idea Keep two pointers, left and right, both starting at 0, plus a set of characters currently inside the window. Expand right one step at a time; whenever the incoming character is already in the set, shrink from left — removing characters from the set — until it isn't anymore.
Python 
def length_of_longest_substring(s):
    seen = set()
    left = 0
    best = 0
    for right in range(len(s)):
        while s[right] in seen:
            seen.remove(s[left])
            left += 1
        seen.add(s[right])
        best = max(best, right - left + 1)
    return best
Java 
int lengthOfLongestSubstring(String s) {
    Set<Character> seen = new HashSet<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        while (seen.contains(s.charAt(right))) {
            seen.remove(s.charAt(left));
            left++;
        }
        seen.add(s.charAt(right));
        best = Math.max(best, right - left + 1);
    }
    return best;
}
JavaScript 
function lengthOfLongestSubstring(s) {
  const seen = new Set();
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    while (seen.has(s[right])) {
      seen.delete(s[left]);
      left++;
    }
    seen.add(s[right]);
    best = Math.max(best, right - left + 1);
  }
  return best;
}
C++ 
int lengthOfLongestSubstring(std::string s) {
    std::unordered_set<char> seen;
    int left = 0, best = 0;
    for (int right = 0; right < s.size(); right++) {
        while (seen.count(s[right])) {
            seen.erase(s[left]);
            left++;
        }
        seen.insert(s[right]);
        best = std::max(best, right - left + 1);
    }
    return best;
}

It looks like a nested loop — a while loop inside a for loop — which would suggest O(n²). But left only ever moves forward, never resets, and can move at most n times total across the entire run of the outer loop, not n times per iteration. Each pointer independently makes at most n moves in total, so the real cost is O(n) + O(n) = O(n) — this is exactly Rule 1 from Lesson 2, just harder to see because the two loops are nested in the code rather than sequential.

Why it matters here This "looks nested, is actually linear" shape is one of the most commonly misjudged complexities in interviews — correctly explaining why it's O(n) and not O(n²) is often worth more to an interviewer than the code itself. The general recipe — expand right to grow the window, shrink left while some condition is violated, track the best result along the way — solves a large share of substring and subarray problems, whatever the specific condition is.

Check your recall

1. What condition causes the window to shrink from the left in this problem?

A repeated character is exactly what breaks the "no repeats" rule the window must maintain.

2. Despite the nested loop structure in the code, what is the actual time complexity, and why?

Both pointers make at most n total moves across the entire run, not per outer-loop iteration — the key exception to "nested loops multiply."

3. What is the general recipe this pattern follows, regardless of the specific window condition?

This shape generalizes across many different specific conditions — only what triggers a shrink changes.
