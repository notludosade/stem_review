From Brute Force to Optimal

Start with Two Sum: given an array of integers and a target, return the indices of the two numbers that add up to the target. Assume exactly one valid answer exists.

Problem Given nums = [2, 7, 11, 15] and target = 9, return [0, 1], because nums[0] + nums[1] == 9.

The obvious approach: for every number, check every other number, looking for a pair that sums to the target. This is brute force — correct, and the natural first thing to reach for, but worth timing precisely before assuming it's good enough.

Python · Brute force 
def two_sum(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
Java · Brute force 
int[] twoSum(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) {
        for (int j = i + 1; j < nums.length; j++) {
            if (nums[i] + nums[j] == target) {
                return new int[] { i, j };
            }
        }
    }
    return null;
}
JavaScript · Brute force 
function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) {
        return [i, j];
      }
    }
  }
}
C++ · Brute force 
std::vector<int> twoSum(std::vector<int>& nums, int target) {
    for (int i = 0; i < nums.size(); i++) {
        for (int j = i + 1; j < nums.size(); j++) {
            if (nums[i] + nums[j] == target) {
                return {i, j};
            }
        }
    }
    return {};
}

Two nested loops over n elements means roughly n² comparisons in the worst case — fine for a handful of numbers, but with 100,000 numbers that's on the order of 10 billion checks. That's the bottleneck: repeatedly re-scanning the array to ask "have I seen the number I need?"

A hash map answers that exact question in roughly one step. Instead of searching, walk the array once, and for each number ask "have I already stored the complement I need?" — checking and inserting as you go.

Python · Optimized 
def two_sum(nums, target):
    seen = {}  # value -> index
    for i, n in enumerate(nums):
        complement = target - n
        if complement in seen:
            return [seen[complement], i]
        seen[n] = i
Java · Optimized 
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (seen.containsKey(complement)) {
            return new int[] { seen.get(complement), i };
        }
        seen.put(nums[i], i);
    }
    return null;
}
JavaScript · Optimized 
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) {
      return [seen.get(complement), i];
    }
    seen.set(nums[i], i);
  }
}
C++ · Optimized 
std::vector<int> twoSum(std::vector<int>& nums, int target) {
    std::unordered_map<int, int> seen;
    for (int i = 0; i < nums.size(); i++) {
        int complement = target - nums[i];
        if (seen.count(complement)) {
            return {seen[complement], i};
        }
        seen[nums[i]] = i;
    }
    return {};
}

One pass, one hash map — average O(n) time instead of O(n²), at the cost of O(n) extra space to store what's been seen. That trade is the recurring theme of this entire course: optimal usually means spending memory to avoid repeated work.

Why it matters here Whether the goal is a technical interview or a timed contest, nobody wants to watch you write the nested loop and stop there. The move that actually gets noticed — by an interviewer or a judge's time limit — is naming the bottleneck out loud and reaching for the structure that removes it. Two Sum is the smallest possible example of a habit this whole course is built to install.

Check your recall

1. What is the time complexity of the brute-force Two Sum solution?

Every element is compared against every other element, giving roughly n × n comparisons in the worst case.

2. What question does the hash map answer in roughly one step, replacing repeated scanning?

Storing each value as it's seen turns "search the rest of the array" into "look it up."

3. What does the optimized solution trade to bring the time complexity down?

The hash map costs O(n) extra memory, in exchange for average O(n) instead of O(n²) time.

4. Fill in the blank: the repeated, avoidable work a brute-force solution does — the thing an optimization removes — is called the ___.

Naming the bottleneck precisely is what points you toward the right structure to remove it.

5. Fill in the blank: for a number n and a target t, the value t − n that Two Sum looks up in the hash map is called the ___.

It's the value that would complete the pair, which is exactly what gets checked against "seen" values.
