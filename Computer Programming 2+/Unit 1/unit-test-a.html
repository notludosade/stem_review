1. A brute-force Two Sum solution checks every pair of numbers using two nested loops over an array of n elements. What is its worst-case time complexity?

Every element gets compared against every other element, giving roughly n × n comparisons in the worst case.

2. The hash-map version of Two Sum runs in average O(n) time instead of O(n²). What does it spend to achieve that speedup?

The hash map costs O(n) extra memory, in exchange for average O(n) instead of O(n²) time — the recurring trade of this whole course.

3. Fill in the blank: the specific repeated or wasted work that a brute-force solution performs — the thing an optimization is designed to remove — is called the ___.

Naming the bottleneck precisely is what points toward the right structure to remove it.

4. A function runs one loop over n elements, and then, after that loop finishes, runs a second, separate loop over the same n elements. What is the combined time complexity?

O(n) + O(n) simplifies to O(n) — only nested loops multiply, sequential loops add.

5. Fill in the blank: appending to a dynamic array is usually O(1), but occasionally costs O(n) when a resize is triggered. Averaged over many appends, the cost still works out to O(1) — this kind of averaged analysis is called ___ analysis.

This is why dynamic-array append is treated as O(1) even though any single call might occasionally be O(n).

6. Trace the hash-map Two Sum algorithm on nums = [3, 2, 4] with target = 6, walking left to right. Answer both parts:

(a) After processing index 0 (the number 3), what does the seen map contain, and has a match been found yet?

(b) Fill in the blank: the value looked up in the hash map at each step — computed as target minus the current number — is called the ___.

(a) At index 0, complement = 6 − 3 = 3, which isn't in the empty map yet, so 3 gets stored with no match — only at index 2 (value 4, complement 2) does a match occur, returning [1, 2]. (b) "Complement" is the term for target minus the current number, the value being looked up each step.

7. Consider the recursive function sum_to(n): if n == 0, return 0; else return n + sum_to(n − 1). Answer both parts:

(a) What is this function's space complexity, and why?

(b) Fill in the blank: rewriting the same function as a loop keeps its time complexity at O(n) but drops its space complexity to O(___).

(a) Each pending call remains on the stack awaiting its recursive return; n pending calls means O(n) stack space, even with no other data structure in sight. (b) A loop needs only one running total, not a growing call stack, so space drops to O(1).

8. A contest problem gives two different versions of the same task. Answer both parts:

(a) If the first version states n ≤ 20, what does that most strongly suggest?

(b) If the second version instead states n ≤ 10⁹, what does that most strongly suggest?

(a) With n this small, exponential subsets or orderings are computationally feasible and may be exactly what's intended. (b) At n = 10⁹, even one full O(n) pass can exceed typical time limits, so something logarithmic or constant is expected instead.

9. The five-step framework runs, in order: Clarify, Brute force, Find the bottleneck, Pattern-match, Verify. Answer both parts:

(a) Which step comes immediately after stating the brute-force solution?

(b) Fill in the blank: the very first step of the framework — restating the problem and checking constraints and edge cases before writing anything — is to ___.

(a) After stating a correct-but-slow brute force, the immediate next move is naming the specific repeated work it does. (b) "Clarify" is the framework's first step, before any code is written.

10. Answer both parts about why steps 2 and 5 of the framework matter:

(a) Why does the framework ask you to state a brute-force solution out loud in step 2, even when it obviously won't be fast enough?

(b) Fill in the blank: step 5 — tracing the optimized solution against the original example and edge cases before considering the work done — is called ___.

(a) A stated brute force demonstrates understanding and gives something later work can be checked against. (b) "Verify" is the final step, catching subtle bugs a "clever" optimization can introduce before submission.
