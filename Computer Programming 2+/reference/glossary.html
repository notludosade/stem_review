Every term introduced in this course, defined once and kept consistent everywhere it's used.

Thinking Like a Problem Solver

Brute force

The most direct solution to a problem, usually found first, often not the most efficient one possible.

Bottleneck

The specific piece of repeated or wasted work inside a brute-force solution that an optimization targets.

Time-space tradeoff

Spending extra memory (like a hash map) to reduce the number of operations needed.

Space complexity

How much extra memory an algorithm uses as input size grows, including call-stack frames from recursion.

Amortized analysis

Averaging an occasionally expensive operation (like resizing an array) over many cheap ones, to get its true per-operation cost.

Pattern-matching (problem solving)

Recognizing that a new problem's shape matches a known technique, rather than solving it from first principles each time.

Two Pointers & Sliding Window

Two pointers

Tracking two positions in a structure at once, moved according to rules that avoid redundant work a nested loop would repeat.

Opposite-direction two pointers

One pointer starting at each end of a sorted structure, closing inward based on a comparison at each step.

Fast and slow pointers

Two pointers moving through the same structure at different speeds — the fast one two steps at a time, the slow one one step.

Floyd's cycle detection

Using fast and slow pointers to detect a cycle in a linked list: if one exists, the two pointers are guaranteed to meet.

Sliding window

A contiguous range of elements that moves across a sequence one step at a time, reusing overlap with the previous range.

Fixed-size window

A sliding window whose length is set in advance and never changes as it moves.

Variable-size window

A sliding window whose length grows and shrinks dynamically based on whether some condition currently holds.

Incremental update

Adjusting a running total for only what entered or left a window, instead of recomputing it from scratch.

Binary Search Beyond Sorted Arrays

Rotated sorted array

An array that was sorted once, then had some prefix moved to the end — no longer sorted overall, but at least one half around any midpoint still is.

Monotonic condition

A condition that is false for every value on one side of some threshold and true for every value on the other — the true requirement binary search runs on.

Binary search on the answer

Binary-searching directly over a range of candidate answers using a monotonic check, rather than over an actual sorted array.

Boundary search

A binary search modified to keep narrowing toward the first or last matching index, instead of stopping at any match.

Trees

Binary tree

A node holding a value plus references to at most two children, conventionally named left and right.

Traversal

Visiting every node in a tree according to some defined order.

Pre-order / in-order / post-order

The three depth-first traversal orders, distinguished only by when the current node is visited relative to its two recursive calls.

Level-order (breadth-first) traversal

Visiting nodes level by level using a queue, rather than plunging depth-first with recursion.

Height

The length of the longest root-to-leaf path in a tree; determines the O(h) cost of most tree operations.

Binary search tree (BST)

A binary tree where every node's entire left subtree is smaller than it, and entire right subtree is larger.

Self-balancing tree

A BST variant (AVL tree, red-black tree) that automatically restructures itself to keep height at O(log n) regardless of insertion order.

Lowest common ancestor (LCA)

The deepest node in a tree that has both of two given nodes somewhere in its subtrees.

Heaps & Priority Queues

Heap

A binary tree where every parent is smaller (min-heap) or larger (max-heap) than both of its children, stored as a plain array.

Min-heap / max-heap

A heap ordered so the smallest (min-heap) or largest (max-heap) value is always at the root, retrievable in O(1).

Heapify

Building a valid heap from an existing unsorted collection in O(n), faster than a full O(n log n) sort.

Priority queue

The abstract structure a heap is typically used to implement: always retrieve the highest-priority (smallest or largest) element next.

Bounded heap

A heap deliberately capped at size k, used to track only the k largest or smallest (or most frequent) values seen so far.

Quickselect

A partition-based alternative to a heap for finding the kth largest/smallest value, averaging O(n) with a worse worst case.

Graphs

Graph

A set of nodes connected by edges, with no restriction on the number of connections or whether following edges can cycle back.

Adjacency list

A mapping from each node to the list of nodes it directly connects to — the most common way to represent a graph in code.

Multi-source BFS

A breadth-first search whose queue is seeded with more than one starting node at once, rather than a single root.

Topological sort

An ordering of a directed graph's nodes where every edge points from earlier to later in the order; exists only if no cycle exists.

In-degree

The number of edges pointing into a node — the count Kahn's algorithm decrements to discover newly unblocked nodes.

Union-Find (Disjoint Set Union)

A structure that tracks which nodes belong to the same group, answering "are these connected?" without a traversal.

Path compression

Repointing every node visited during a find call directly at the group's root, keeping future lookups nearly constant time.

Dijkstra's algorithm

A shortest-path algorithm for weighted graphs — BFS with its queue replaced by a min-heap ordered by distance so far.

Backtracking

Backtracking

DFS over a tree of choices: choose an option, recurse to explore it, then undo the choice before trying the next.

Choose / explore / unchoose

The three-step template underlying every backtracking solution — the unchoose step is what lets one shared path variable be reused across branches.

Pruning

Abandoning a branch of a backtracking search as soon as it's known that branch cannot lead to a valid answer.

Dynamic Programming

Overlapping subproblems

The same smaller subproblem gets solved repeatedly across a recursion's call tree, making caching worthwhile.

Optimal substructure

A problem's answer can be built directly from the answers to its smaller pieces.

Memoization

Top-down DP: the natural recursion, with each result cached the first time it's computed.

Tabulation

Bottom-up DP: an array of answers built iteratively from the base cases upward, with no recursion.

Kadane's algorithm

Tracking the best subarray sum ending at the current position, deciding at each step whether to extend it or restart.

0/1 knapsack

Choosing whether to include each item at most once toward some capacity, maximizing or checking reachability of a target.

Greedy Algorithms & Bit Manipulation

Greedy algorithm

Committing to one locally-best choice per step with no backtracking, safe only when a proof shows it's never worse than any alternative.

Exchange argument

The standard proof technique for a greedy algorithm: showing that swapping its choice for any other choice never produces a better result.

XOR cancellation

The property a ^ a = 0 and a ^ 0 = a, used to cancel out paired values and isolate an unpaired one in a single pass.

Bit trick

A narrow but powerful idiom (set, clear, toggle, check a bit; test a power of two) that trades a data structure for a property of a bitwise operator.

Prefix sum

A running total kept alongside a traversal, letting any subarray's sum be found by subtracting two earlier totals instead of resumming.
