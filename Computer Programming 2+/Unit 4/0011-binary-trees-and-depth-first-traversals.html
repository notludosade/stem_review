Binary Trees & Depth-First Traversals

A tree is recursion's natural habitat — every subtree is itself a smaller tree, base case and all.

← Lesson 10 Lesson 12 → Contents Glossary →

A binary tree is a node holding a value plus references to at most two children, left and right. Visiting every node in a specific order is called a traversal. This maps directly onto the recursion vocabulary from Computer Programming 2's Unit 4: the base case is an empty (null) node, and the recursive case processes the current node's value plus whatever its two children's own traversals produce.

The idea A depth-first traversal visits a node, its left subtree, and its right subtree — but when it visits the node relative to the two subtrees defines three variants: visit-left-right ("in-order"), visit-then-left-right ("pre-order"), or left-right-then-visit ("post-order"). All three are the same three lines of code, just reordered.
Python 
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(root):
    if root is None:
        return []
    return inorder(root.left) + [root.val] + inorder(root.right)
Java 
class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int val) { this.val = val; }
}

void inorder(TreeNode root, List<Integer> result) {
    if (root == null) return;
    inorder(root.left, result);
    result.add(root.val);
    inorder(root.right, result);
}
JavaScript 
class TreeNode {
  constructor(val, left = null, right = null) {
    this.val = val;
    this.left = left;
    this.right = right;
  }
}

function inorder(root, result = []) {
  if (root === null) return result;
  inorder(root.left, result);
  result.push(root.val);
  inorder(root.right, result);
  return result;
}
C++ 
struct TreeNode {
    int val;
    TreeNode *left, *right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

void inorder(TreeNode* root, std::vector<int>& result) {
    if (root == nullptr) return;
    inorder(root->left, result);
    result.push_back(root->val);
    inorder(root->right, result);
}

This is in-order traversal: left subtree, then this node, then right subtree. Move the result.add(root.val) line above both recursive calls and it becomes pre-order (node, left, right); move it below both and it becomes post-order (left, right, node). Same recursion, same base case, three different places to do the work.

Time complexity is O(n) — every node is visited exactly once. Space complexity is O(h), where h is the tree's height, because that's how deep the call stack goes (this is Unit 1 Lesson 2's "recursive call-stack space" rule, applied directly). For a balanced tree, h is O(log n); for a completely unbalanced tree — a straight line of left children, say — h degrades to O(n).

Why it matters here Every recursive call here is doing exactly what CP2's call-stack lesson described: pushing a frame, waiting on two smaller subproblems, then returning. There's also an iterative version of each traversal that replaces the implicit call stack with an explicit one you manage by hand — same idea as CP2's debugging lesson, which bisected a bug instead of a tree. Recognizing traversal order as "just where one line goes" — not three separate things to memorize — is most of what this lesson is trying to build.

Check your recall

1. What distinguishes pre-order, in-order, and post-order traversal from one another?

All three visit every node; only the placement of the "visit" step relative to the two recursive calls changes.

2. What is the base case for a recursive tree traversal?

Recursing past the last real node reaches null, where there's nothing left to visit and the recursion stops.

3. Why is the space complexity of a recursive traversal O(h) rather than O(n)?

At any moment, only the frames along one root-to-node path are active — not all n nodes at once.

4. Fill in the blank: the space complexity of a recursive traversal is O(h), where h is the tree's ___.

This ranges from O(log n) for a balanced tree up to O(n) for a completely unbalanced one.

5. Fill in the blank: visiting every node in a tree according to some defined order is called a ___.

Pre-order, in-order, and post-order are the three depth-first variants of this.
