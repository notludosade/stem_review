Binary Search Trees: Properties and Validation

One ordering rule turns a plain binary tree into a structure that supports Lesson 8's O(log n) search — if every node actually obeys it.

← Lesson 12 Lesson 14 → Contents Glossary →

A binary search tree (BST) is a binary tree where, for every node, everything in its left subtree is smaller than the node's value, and everything in its right subtree is larger. Note the word every: it's not enough for a node's immediate children to satisfy this — the entire left subtree, however deep, must stay below the node's value, and the entire right subtree must stay above it.

The idea A common mistake is checking only node.left.val < node.val < node.right.val at each node. That misses violations further down. Instead, carry a valid (min, max) range down through the recursion: each node must fall strictly inside its inherited range, and it narrows that range differently for its left child (new max) versus its right child (new min).
Python 
def is_valid_bst(root, low=float('-inf'), high=float('inf')):
    if root is None:
        return True
    if not (low < root.val < high):
        return False
    return (is_valid_bst(root.left, low, root.val) and
            is_valid_bst(root.right, root.val, high))
Java 
boolean isValidBST(TreeNode root) {
    return validate(root, Long.MIN_VALUE, Long.MAX_VALUE);
}

boolean validate(TreeNode node, long low, long high) {
    if (node == null) return true;
    if (!(low < node.val && node.val < high)) return false;
    return validate(node.left, low, node.val) && validate(node.right, node.val, high);
}
JavaScript 
function isValidBST(root, low = -Infinity, high = Infinity) {
  if (root === null) return true;
  if (!(low < root.val && root.val < high)) return false;
  return isValidBST(root.left, low, root.val) &&
         isValidBST(root.right, root.val, high);
}
C++ 
bool validate(TreeNode* node, long low, long high) {
    if (node == nullptr) return true;
    if (!(low < node->val && node->val < high)) return false;
    return validate(node->left, low, node->val) &&
           validate(node->right, node->val, high);
}

bool isValidBST(TreeNode* root) {
    return validate(root, LONG_MIN, LONG_MAX);
}

This is O(n) time — every node is visited once — and O(h) space, the same call-stack rule from Lesson 11. An equivalent alternative: an in-order traversal of a valid BST always produces values in strictly increasing order, so running Lesson 11's in-order traversal and checking the result is sorted also validates a BST, at the cost of O(n) extra space to store the values.

Why it matters here A valid BST is what makes Lesson 8 and Lesson 10's binary search ideas apply to a tree instead of an array: search, minimum, and maximum are all O(h). But an unbalanced BST — built by inserting already-sorted data, for instance — degenerates into a straight line, making every operation O(n). Self-balancing variants like AVL trees and red-black trees exist specifically to guarantee h stays O(log n) no matter the insertion order, by automatically restructuring the tree after insertions and deletions. That guarantee is genuinely useful to know exists — but implementing one from scratch is deliberately out of scope for this course; production code always reaches for a language's built-in balanced structure instead (Java's TreeMap, C++'s std::map) rather than hand-rolling one.

Check your recall

1. Why is checking only a node's immediate children insufficient to validate a BST?

A node deep in a left subtree could be locally fine with its own parent, yet still exceed a value far above it in the tree.

2. When recursing into a node's right child, how does the valid range change?

Everything in the right subtree must be greater than the current node, so the current node's value becomes the new floor.

3. What happens to a BST's operations if it becomes completely unbalanced, such as by inserting already-sorted data?

The height h grows to n in the worst case, and BST operation cost is O(h).

4. Fill in the blank: an in-order traversal of a valid BST always produces values in strictly ___ order.

This gives an equivalent way to validate a BST: traverse it in-order and check the result is sorted.

5. Fill in the blank: AVL trees and red-black trees are both examples of self-___ trees, which restructure themselves to keep height at O(log n).

This course doesn't implement one from scratch, but knowing why they exist explains a lot about production data structure choices.
