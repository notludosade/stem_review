1. Pre-order, in-order, and post-order traversal all visit the exact same set of nodes in a binary tree. What actually distinguishes them from one another?

Moving one line — where the node's own value is recorded — above, between, or below the two recursive calls is the entire difference between the three orders.

2. Fill in the blank: visiting every node in a tree according to a defined order is called a ___.

Pre-order, in-order, and post-order are the three depth-first variants of this.

3. Why does level-order traversal need a queue instead of relying on recursion the way depth-first traversal does?

FIFO order is what lets all of one depth get processed before any of the next depth begins.

4. Fill in the blank: capturing the queue's size before each round's inner loop begins draws a boundary between the current level and the next one, both living in the same ___.

Without capturing that count first, newly-pushed children would get processed as part of the current level by mistake.

5. Why is checking only a node's immediate children — left.val < node.val < right.val — insufficient to validate a binary search tree?

A node deep in a subtree could be locally fine with its own parent, yet still violate a bound set far above it in the tree.

6. Consider the tree with root 5 (left child 3, right child 8), where 3 has left child 1 and right child 4. Answer both parts:

(a) What is the pre-order traversal of this tree?

(b) Fill in the blank: the in-order traversal of this same tree is 1, 3, 4, 5, ___.

(a) Pre-order visits the node before its subtrees: 5, then the entire left subtree in pre-order (3, 1, 4), then the right subtree (8). (b) In-order visits left subtree, node, then right subtree: 1, 3, 4, 5, 8 — the tree's values in increasing order, since this tree also happens to be a valid BST.

7. Using the same tree (root 5; left child 3 with children 1 and 4; right child 8, a leaf), answer both parts:

(a) What does level-order traversal return?

(b) Fill in the blank: during the second round (level 1), the queue's captured levelSize is ___, since exactly two nodes (3 and 8) are processed that round.

(a) Level 0 holds just the root (5); level 1 holds its two children (3, 8) in the order they were enqueued; level 2 holds only node 3's two children (1, 4), since node 8 is a leaf. (b) levelSize is captured as the queue's length before the round's loop starts — with exactly 3 and 8 in the queue at that point, levelSize is 2.

8. Consider the tree root=10 (left child 5, right child 15), where 15 has left child 6 and right child 20. Answer both parts:

(a) What happens when checking node 15's left child (6) using the (min, max) range approach?

(b) Fill in the blank: a naive check that compares each node only to its immediate children would wrongly call this tree ___, because 6 < 15 < 20 looks fine locally.

(a) Node 15 inherits the range (10, ∞) from being root 10's right child; passing that down, node 6 must satisfy 10 < 6, which is false, so the recursive range check correctly rejects the tree. (b) The naive immediate-children check only sees node.left(6) < node(15) < node.right(20), which holds, so it would incorrectly call the tree valid — exactly the bug Lesson 13 warns against.

9. Consider the tree root=3 (left child 5, right child 1), where 5's children are 6 and 2, and 2's children are 7 and 4. Trace the LCA algorithm for p=7, q=4. Answer both parts:

(a) What does the recursive call at node 2 return, and why?

(b) Fill in the blank: propagating this result upward through node 5 (whose left child, 6, returns null) and then through the root (whose right child, node 1, also returns null) means the final lowest common ancestor of 7 and 4 is node ___.

(a) At node 2, the recursive calls into its own left child (7) and right child (4) both return non-null, which is exactly the signal that node 2 is where p and q's paths diverge — making it their LCA. (b) That result (node 2) is the only non-null value passed upward at every level above it, so it survives all the way up to become the final answer.

10. For the path 5 → 4 → 11 → 2 (each step a parent-to-child edge) with target sum 22, answer both parts:

(a) Trace the running "remaining target" as the path descends. What is the remaining target upon reaching leaf node 2, and does this path sum to the target?

(b) Fill in the blank: this problem and lowest common ancestor share the same recursive shape — a base case, a recursive call into each child, and a ___ step that merges what both children returned.

(a) Subtracting each node's value from the remaining target as the path descends (22→17→13→2→0) reaches exactly 0 at the leaf, confirming this path sums to 22. (b) "Combining" is the exact term Lesson 14 uses for the step that turns two child results into one answer at the current node — the one piece that actually changes between different tree problems using this shape.
