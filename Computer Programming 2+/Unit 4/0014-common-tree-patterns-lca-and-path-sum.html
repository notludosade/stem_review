Common Tree Patterns: Lowest Common Ancestor & Path Sum

Two problems that look unrelated turn out to share the same shape: return something from a recursive call, and combine what comes back from both children.

← Lesson 13 Contents Glossary →

Problem one: given a binary tree and two nodes p and q, find their lowest common ancestor (LCA) — the deepest node that has both p and q somewhere in its subtrees. Problem two: given a binary tree and a target sum, determine whether any root-to-leaf path adds up to exactly that target. Both are solved by a recursive function that returns information upward and combines results from its two children.

The idea For LCA: at each node, recurse into both children. If both recursive calls find something (one found p, the other found q), the current node is the answer. If only one side found something, pass that result upward unchanged. For path sum: subtract the current node's value from the remaining target as you recurse down, and check at each leaf whether the remaining target has reached exactly zero.
Python 
def lowest_common_ancestor(root, p, q):
    if root is None or root is p or root is q:
        return root
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    if left and right:
        return root          # p and q found on different sides
    return left if left else right
Java 
TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;
    TreeNode left = lowestCommonAncestor(root.left, p, q);
    TreeNode right = lowestCommonAncestor(root.right, p, q);
    if (left != null && right != null) return root;   // found on different sides
    return left != null ? left : right;
}
JavaScript 
function lowestCommonAncestor(root, p, q) {
  if (root === null || root === p || root === q) return root;
  const left = lowestCommonAncestor(root.left, p, q);
  const right = lowestCommonAncestor(root.right, p, q);
  if (left && right) return root;   // found on different sides
  return left ? left : right;
}
C++ 
TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (root == nullptr || root == p || root == q) return root;
    TreeNode* left = lowestCommonAncestor(root->left, p, q);
    TreeNode* right = lowestCommonAncestor(root->right, p, q);
    if (left != nullptr && right != nullptr) return root;   // found on different sides
    return left != nullptr ? left : right;
}

Both problems share the same recursive shape: a base case at null (or a leaf), a recursive call into each child, and a combining step that decides what to return based on what came back from both sides. That combining step is the actual pattern — for LCA it's "did both sides find something," for path sum it's "did the remaining target reach zero exactly at a leaf." Each is O(n) time, since every node is visited at most once, and O(h) space for the call stack, same as every traversal in this unit.

Why it matters here A large share of tree interview questions are variations on "recurse into both children, then combine their results" — diameter, balanced-tree checking, maximum path sum, and subtree-matching problems all reuse this exact shape with a different combining rule. Once this pattern is recognized as one idea rather than a list of unrelated problems, most new tree questions become "what do I return, and how do I combine two of them" instead of "where do I even start."

Check your recall

1. In the LCA solution, what does it mean when both the left and right recursive calls return a non-null result?

If p and q were on the same side, that side's recursive call alone would already return their ancestor.

2. How does the path sum problem track progress as it recurses toward a leaf?

Checking whether the remaining target hits exactly zero at a leaf avoids having to sum a whole path after the fact.

3. What shared recursive shape do LCA and path sum both follow?

This combining-results shape generalizes to many other tree problems beyond just these two.
