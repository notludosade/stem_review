Backtracking Fundamentals: Subsets & Permutations

A recursive tree that explores every choice, undoing each one before trying the next — the template behind an entire family of "generate all ___" problems.

← Lesson 22 Lesson 24 → Contents Glossary →

Problem: given an array of distinct integers, return every possible subset (the power set). Backtracking is DFS (Unit 6) on an implicit decision tree: at each step, choose an option, explore deeper by recursing, then unchoose that option before trying the next one. That third step — undoing the choice — is the one genuinely new idea; everything else is the recursive DFS already familiar from Unit 4 and Unit 6.

The idea Build subsets one decision at a time: for each number, decide whether to include it, moving to the next number either way. A running path holds the subset built so far. Every time a number is added to path, the current path is recorded as one complete subset, then recursion continues; after returning, that number is removed from path again — the backtrack — so the next number can be tried in its place.
Python 
def subsets(nums):
    result = []
    path = []

    def backtrack(start):
        result.append(path[:])          # record the current subset (a copy)
        for i in range(start, len(nums)):
            path.append(nums[i])        # choose
            backtrack(i + 1)            # explore
            path.pop()                  # unchoose

    backtrack(0)
    return result
Java 
List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    List<Integer> path = new ArrayList<>();
    backtrack(nums, 0, path, result);
    return result;
}

void backtrack(int[] nums, int start, List<Integer> path, List<List<Integer>> result) {
    result.add(new ArrayList<>(path));   // record the current subset (a copy)
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                // choose
        backtrack(nums, i + 1, path, result);   // explore
        path.remove(path.size() - 1);     // unchoose
    }
}
JavaScript 
function subsets(nums) {
  const result = [];
  const path = [];

  function backtrack(start) {
    result.push([...path]);        // record the current subset (a copy)
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);          // choose
      backtrack(i + 1);            // explore
      path.pop();                  // unchoose
    }
  }

  backtrack(0);
  return result;
}
C++ 
void backtrack(std::vector<int>& nums, int start, std::vector<int>& path,
               std::vector<std::vector<int>>& result) {
    result.push_back(path);            // record the current subset (a copy)
    for (int i = start; i < (int)nums.size(); i++) {
        path.push_back(nums[i]);       // choose
        backtrack(nums, i + 1, path, result);   // explore
        path.pop_back();               // unchoose
    }
}

std::vector<std::vector<int>> subsets(std::vector<int>& nums) {
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack(nums, 0, path, result);
    return result;
}

There are 2ⁿ possible subsets, and building each one costs up to O(n) to copy, giving O(n · 2ⁿ) time — exponential, but unavoidable since the answer itself has that many entries. A closely related problem, permutations (every possible ordering of all n numbers, LeetCode #46), uses the identical choose-explore-unchoose template with one change: instead of a start index that only moves forward, a used tracker marks which numbers are already placed in path, since any unused number can go next regardless of order. That single change is the whole difference — subsets asks "include or skip," permutations asks "which unused number goes here next," and both explore n! or 2ⁿ leaves of the same kind of recursive tree.

Why it matters here Backtracking is DFS from Unit 6, applied to a tree of choices instead of a tree of physical nodes — the recursion, the base case, and the traversal shape are all already familiar. The one addition is undoing a choice after exploring it, so the same path variable can be reused across every branch instead of being copied fresh each time. Nearly every "generate all ___" or "find every way to ___" problem — subsets, permutations, combinations, valid arrangements — is this exact template with a different rule for what counts as a valid choice.

Check your recall

1. What are the three steps of the backtracking template?

Undoing the choice after exploring it is what lets one shared path variable be reused across every branch.

2. Why must path.pop() (or its equivalent) run after each recursive call returns?

Without undoing the choice, path would keep growing with leftover choices from earlier branches.

3. What is the one change that turns the subsets template into a permutations solution?

Since order matters for permutations, any unused number can go next — not only ones after the current index.

4. Fill in the blank: the step that removes the most recent choice after exploring it is called the ___ step.

This is the one genuinely new idea beyond ordinary DFS.

5. Fill in the blank: generating all 2ⁿ subsets takes ___ time, which is unavoidable since the answer itself has that many entries.

No algorithm can list 2ⁿ results any faster than roughly 2ⁿ time.
