Combination Sum & Combinations Under Constraints

A constraint isn't just something to check at the end — it's a reason to stop exploring a branch immediately.

← Lesson 23 Lesson 25 → Contents Glossary →

Problem: given an array of distinct positive integers and a target, return every combination of numbers (each number reusable any number of times) that sums exactly to the target. This is Lesson 23's exact backtracking template, but now every branch carries a running sum, and the moment that sum exceeds the target, there is no reason to keep exploring deeper — the branch can be abandoned immediately. This early abandonment is called pruning.

The idea Choose, explore, unchoose — identical to Lesson 23 — with one addition: before recursing, check whether the current choice has already pushed the running sum past the target. If so, stop; nothing deeper down that branch can possibly work, since every number is positive. Because the same number can be reused, the recursive call passes the same start index rather than advancing it, while still moving forward through the array for numbers not being reused.
Python 
def combination_sum(candidates, target):
    result = []
    path = []

    def backtrack(start, remaining):
        if remaining == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:
                continue                     # prune: too large, and the rest are sorted larger still
            path.append(candidates[i])       # choose
            backtrack(i, remaining - candidates[i])   # explore (same i: reuse allowed)
            path.pop()                        # unchoose

    candidates.sort()
    backtrack(0, target)
    return result
Java 
List<List<Integer>> combinationSum(int[] candidates, int target) {
    List<List<Integer>> result = new ArrayList<>();
    Arrays.sort(candidates);
    backtrack(candidates, 0, target, new ArrayList<>(), result);
    return result;
}

void backtrack(int[] candidates, int start, int remaining, List<Integer> path, List<List<Integer>> result) {
    if (remaining == 0) {
        result.add(new ArrayList<>(path));
        return;
    }
    for (int i = start; i < candidates.length; i++) {
        if (candidates[i] > remaining) break;   // prune: too large, and the rest are sorted larger still
        path.add(candidates[i]);                 // choose
        backtrack(candidates, i, remaining - candidates[i], path, result);   // explore (same i: reuse allowed)
        path.remove(path.size() - 1);            // unchoose
    }
}
JavaScript 
function combinationSum(candidates, target) {
  const result = [];
  const path = [];
  candidates.sort((a, b) => a - b);

  function backtrack(start, remaining) {
    if (remaining === 0) {
      result.push([...path]);
      return;
    }
    for (let i = start; i < candidates.length; i++) {
      if (candidates[i] > remaining) break;   // prune: too large, and the rest are sorted larger still
      path.push(candidates[i]);                // choose
      backtrack(i, remaining - candidates[i]); // explore (same i: reuse allowed)
      path.pop();                               // unchoose
    }
  }

  backtrack(0, target);
  return result;
}
C++ 
void backtrack(std::vector<int>& candidates, int start, int remaining,
               std::vector<int>& path, std::vector<std::vector<int>>& result) {
    if (remaining == 0) {
        result.push_back(path);
        return;
    }
    for (int i = start; i < (int)candidates.size(); i++) {
        if (candidates[i] > remaining) break;   // prune: too large, and the rest are sorted larger still
        path.push_back(candidates[i]);           // choose
        backtrack(candidates, i, remaining - candidates[i], path, result);   // explore (same i: reuse allowed)
        path.pop_back();                          // unchoose
    }
}

std::vector<std::vector<int>> combinationSum(std::vector<int>& candidates, int target) {
    std::sort(candidates.begin(), candidates.end());
    std::vector<std::vector<int>> result;
    std::vector<int> path;
    backtrack(candidates, 0, target, path, result);
    return result;
}

Sorting first (O(n log n)) makes the prune correct as a break rather than a continue — once one candidate is too large, every candidate after it is too, since the array is sorted ascending. The exact worst-case time complexity is hard to state cleanly since it depends on the target and candidate values, but pruning is what keeps the search from wasting time on branches whose sum has already overshot, rather than only discovering the failure at a much deeper leaf.

Why it matters here Pruning is the difference between backtracking that merely works and backtracking that runs fast enough to pass — the constraint isn't only a filter applied to finished results, it's a signal to stop early. This is the same principle as Unit 3's binary search on the answer: a condition that can rule out an entire remaining range should be checked as early as possible, not after fully computing something doomed to fail. Any backtracking problem with a numeric constraint (sum, count, capacity) should be scanned for a prune the moment that constraint is violated.

Check your recall

1. What does "pruning" mean in the context of backtracking?

Pruning stops wasted work by recognizing failure before fully exploring a doomed branch.

2. Why does the recursive call pass the same index i instead of i + 1?

Advancing to i + 1 would forbid reusing a candidate, which this problem explicitly allows.

3. Why does sorting the candidates first make the prune correct as an early break?

Without sorting, a break could skip over a smaller, still-valid candidate further along in the array.
