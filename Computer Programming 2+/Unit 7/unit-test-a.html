1. What are the three steps of the backtracking template introduced for generating subsets?

Undoing the choice after exploring it is what lets one shared path variable be reused across every branch instead of being copied fresh each time.

2. Trace subsets([1, 2]) using the backtracking algorithm from Lesson 23. Answer both parts:

(a) In what order are subsets appended to result?

(b) Fill in the blank: this process produces 2ⁿ subsets total, an amount of work described as ___ growth in n.

(a) result.append(path[:]) records the subset before every new number is added, so the empty set is recorded first, then [1], then [1, 2] once 2 joins it, then finally [2] once the recursion backtracks and moves on from 1 entirely. (b) 2ⁿ is exponential, though unavoidable since that's exactly how many subsets exist to list.

3. What is the one change that turns the subsets backtracking template into a permutations solution?

Since order matters for permutations, any unused number can go next — not only ones after the current index, which is all a forward-only start index would allow.

4. Fill in the blank: stopping a backtracking branch early once it can no longer succeed is called ___.

This is the one addition Combination Sum makes to the plain choose-explore-unchoose backtracking template.

5. Trace combination_sum([2, 3, 6, 7], target=7). Answer both parts:

(a) Which combinations appear in the result?

(b) Fill in the blank: recursing with the same index i (rather than i + 1) is valid here because each candidate may be ___ any number of times.

(a) 2 + 2 + 3 = 7 and 7 alone = 7 are the only two ways to reach the target using non-decreasing picks from {2, 3, 6, 7}; missing [7] is a common trap since it's easy to stop tracing after the first combination found. (b) Combination Sum explicitly allows reusing a candidate, which is exactly why the same index is passed forward instead of i + 1.

6. Why does sorting the candidates first make the prune correct as an early break?

Without sorting, a break could skip over a smaller, still-valid candidate further along in the array — break only becomes safe once ascending order guarantees nothing smaller remains.

7. Word Search's recursion marks a cell visited by temporarily overwriting it with '#'. Answer both parts:

(a) Why must a visited cell be un-marked after backtracking, unlike Lesson 18's sunk land cells?

(b) Fill in the blank: restoring a cell's original letter after exploring its neighbors is the ___ step from Lesson 23's template.

(a) Lesson 18 counted every reachable region once; Word Search searches for one specific path per starting attempt, so a failed attempt must not affect a later, unrelated attempt. (b) This is the same unchoose idea from subsets and permutations, applied here to a grid cell instead of a path array.

8. In exist(board, word), consider the recursive helper backtrack(r, c, i). Answer both parts:

(a) What does the index i track during the recursion?

(b) What causes a branch of this search to fail immediately?

(a) Reaching i equal to the word's length means every letter has already been matched in order, so the search succeeds. (b) Any one of these conditions means this path cannot possibly complete the word, so recursion returns false immediately rather than exploring further.

9. In the worst case, Word Search's runtime is described by which expression, where L is the word's length and the grid has rows·cols cells?

Every one of the grid's rows·cols cells could be tried as a starting point, and each attempt explores up to 4 directions at each of the word's L letters — 4^L work per start, though pruning keeps this far from reached in practice.

10. Consider the remaining parameter in combination_sum's recursion. Answer both parts:

(a) Fill in the blank: each recursive call tracks how much of the target sum is still ___, checking whether it hits exactly zero.

(b) What does reaching remaining == 0 signal?

(a) Tracking what's left rather than a running total mirrors Lesson 14's path-sum trick. (b) remaining == 0 is exactly the base case that appends a copy of path to result — the path built so far already hits the target exactly.
