Finding Boundaries

Standard binary search stops the moment it finds a match. Finding the first or last occurrence means teaching it to keep searching on purpose.

← Lesson 9 Contents Glossary →

Problem: given a sorted array that may contain duplicates, find the first and last index of a given target. Standard binary search finds a matching index, but gives no guarantee it's the first or last one among duplicates.

The idea Run two separate binary searches. For the first occurrence: whenever the midpoint matches, record it, but keep searching the left half anyway, in case an earlier match exists. For the last occurrence: on a match, record it and keep searching the right half instead.
Python 
def search_range(nums, target):
    def find_bound(find_first):
        left, right = 0, len(nums) - 1
        result = -1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                result = mid
                if find_first:
                    right = mid - 1   # keep looking left
                else:
                    left = mid + 1    # keep looking right
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
        return result

    return [find_bound(True), find_bound(False)]
Java 
int[] searchRange(int[] nums, int target) {
    return new int[] { findBound(nums, target, true), findBound(nums, target, false) };
}

int findBound(int[] nums, int target, boolean findFirst) {
    int left = 0, right = nums.length - 1, result = -1;
    while (left <= right) {
        int mid = (left + right) / 2;
        if (nums[mid] == target) {
            result = mid;
            if (findFirst) right = mid - 1;   // keep looking left
            else left = mid + 1;                // keep looking right
        } else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return result;
}

int findBound(std::vector<int>& nums, int target, bool findFirst) {
    int left = 0, right = nums.size() - 1, result = -1;
    while (left <= right) {
        int mid = (left + right) / 2;
        if (nums[mid] == target) {
            result = mid;
            if (findFirst) right = mid - 1;   // keep looking left
            else left = mid + 1;                // keep looking right
        } else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return result;
}

std::vector<int> searchRange(std::vector<int>& nums, int target) {
    return { findBound(nums, target, true), findBound(nums, target, false) };
}

Both searches are still O(log n), so finding the full range costs O(log n) total — dramatically better than finding one match with binary search and then scanning outward linearly in both directions, which degrades to O(n) whenever a value is repeated many times (imagine a target that appears in half the array).

Why it matters here This closes Unit 3's real point: binary search is not one formula but a small family of variations — search for existence, search for a boundary, search over an abstract answer space — all sharing the same "eliminate half using a decidable rule" core from Lesson 8. Recognizing which variation a problem needs, rather than reaching for the one memorized template, is what separates fluency here from rote recall.

Check your recall

1. When searching for the first occurrence and the midpoint matches the target, what should happen next?

An earlier match might still exist further left — stopping immediately could miss it.

2. Why is finding both boundaries with two binary searches better than one binary search plus a linear scan outward?

If a target appears across half the array, scanning outward from one match is effectively linear.

3. What is the overall time complexity of finding both the first and last index of a target?

Two O(log n) searches run one after another still total O(log n).

4. Fill in the blank: modifying binary search to keep narrowing toward the first or last matching index, instead of stopping at any match, is called finding a ___.

This is the name for this whole lesson's variation on the standard search.

5. Fill in the blank: the reason a single match isn't enough information in this problem is that the array may contain ___ of the target value.

With no duplicates, standard binary search would already return the unique correct index.
