The Pattern Recognition Cheat Sheet

No new algorithm this time — just every signal from this course's 32 lessons, organized into one lookup table for the moment a new problem needs a starting move.

← Lesson 32 Lesson 34 → Contents Glossary →

The single hardest part of a new LeetCode problem is rarely writing the code — it's recognizing which of the patterns already learned actually applies. Lesson 3's five-step framework named this "pattern-match," but by now there are far more patterns to match against than there were in Unit 1. This lesson is a single reference: read the problem, look for its signal below, and jump straight to the technique.

Pair or triplet with a target sum, sorted input

Opposite-direction two pointers, O(n). Unsorted input instead means a hash map — trade space for one linear pass (Lessons 1, 4).

Cycle detection in a linked list

Fast and slow pointers — Floyd's cycle detection guarantees the two meet if a cycle exists (Lesson 5).

Longest/shortest contiguous subarray or substring meeting a condition

Sliding window — fixed-size if the length is given, variable-size if it grows and shrinks on a rule (Lessons 6, 7).

Sorted array that's been rotated, or "sorted" with a twist

Binary search, modified: check which half is still sorted around the midpoint (Lesson 8).

"Minimize the maximum" / "maximize the minimum" over a range of possible answers

Binary search on the answer space, driven by a monotonic true/false check rather than a sorted array (Lesson 9).

First or last occurrence of a value

Boundary search — binary search that keeps narrowing past the first match found (Lesson 10).

Any problem on a binary tree

Depth-first recursion (pre/in/post-order) for most tree shapes; level-order BFS with a queue specifically when the problem cares about depth or rows (Lessons 11, 12).

Validate or exploit a binary search tree's ordering

DFS with a shrinking (min, max) valid range, or an in-order traversal that must come out sorted (Lesson 13).

Path sum, lowest common ancestor, or "combine two subtree results"

Recurse on both children, then combine their two results at the current node (Lesson 14).

"Kth largest/smallest," "top K," or "K closest"

A heap bounded at size k, O(n log k) — no full sort needed (Lessons 15, 16, 17).

Grid or graph: count islands, flood-fill, or reach every connected cell/node

DFS or BFS with a visited set, so no cell or node is processed twice (Lesson 18).

Shortest path, unweighted graph, or "spreads outward from multiple sources at once"

Multi-source BFS — seed the queue with every starting point before the first level (Lesson 19).

"Must happen before," prerequisites, or build order

Topological sort via Kahn's algorithm — count in-degrees, process nodes as they hit zero (Lesson 20).

"Are these already connected?" repeated many times, or detect a cycle while building a graph

Union-Find with path compression, no traversal needed per query (Lesson 21).

Shortest path, weighted graph

Dijkstra's algorithm — BFS with a min-heap ordered by distance so far (Lesson 22).

Generate all subsets, permutations, or combinations

Backtracking: choose, explore (recurse), unchoose (Lesson 23).

Combinations under a numeric constraint (target sum, capacity)

Backtracking with pruning — sort first, then break out of a branch as soon as the constraint is violated (Lesson 24).

Search a grid for a path spelling out a specific sequence

Backtracking DFS with a visited marker that gets restored after exploring each direction (Lesson 25).

Recursion that recomputes the same subproblem repeatedly

Memoization (cache the recursion) or tabulation (build the array bottom-up) — the two faces of dynamic programming (Lesson 26).

"Maximize/minimize this, but adjacent choices conflict"

1D DP where dp[i] depends only on the one or two states right before it, often compressible to O(1) space (Lesson 27).

Two strings or a grid, comparing or counting paths position by position

2D DP — the state needs two indices, not one (Lesson 28).

Choose a subset of items to hit or stay under some capacity

Knapsack-style DP — a capacity dimension, with iteration direction controlling whether items can repeat (Lesson 29).

Longest subsequence obeying an ordering rule, not necessarily contiguous

Sequence DP where dp[i] can depend on any earlier index, not just the one right before (Lesson 30).

Intervals: scheduling, overlap counting, or merging

Sort by start or end time, then a single greedy pass — no DP table required if an exchange argument proves it safe (Lesson 31).

"Every element appears twice except one," or O(1) space is explicitly required on integers

A bit trick — XOR cancellation, or a set/clear/toggle-bit idiom (Lesson 32).

How to use this table under time pressure Constraints are a signal in themselves before a single pattern is even considered: n up to 10⁵–10⁶ usually rules out anything O(n²), which rules out plain backtracking or nested-loop DP without pruning; n up to 15–20 is often a hint that a brute-force or bitmask approach over all subsets is actually intended. Reading the constraints first narrows this whole table down to two or three real candidates before the problem's wording is even re-read a second time.

Check your recall

1. A problem asks for the length of the longest substring with no repeating characters. Which pattern does that signal?

"Substring" plus "longest ... meeting a condition" is exactly the sliding window signal from Lessons 6 and 7.

2. A problem gives course prerequisites and asks if it's possible to finish every course. Which pattern does that signal?

Prerequisites are a direct match for Lesson 20's in-degree counting approach.

3. Why is checking a problem's constraints (like n up to 10⁵) useful before choosing a pattern?

A large n effectively bans slower approaches before any other analysis, narrowing the candidate list fast.

4. Fill in the blank: reading a problem's ___ first (like the bound on n) can rule out entire categories of pattern before rereading the problem itself.

This is the fastest possible narrowing step available before analyzing the problem's actual logic.

5. Fill in the blank: this lesson organizes every pattern in the course by the ___ in a problem's description that points to it.

Recognizing the signal, not memorizing every problem individually, is the actual transferable skill.
