Greedy Algorithms & Interval Scheduling

Sometimes the locally best choice at each step turns out to always be globally correct — no backtracking, no DP table, no exploration required.

← Lesson 30 Lesson 32 → Contents Glossary →

Problem: given a list of intervals, find the minimum number that must be removed so none of the remaining ones overlap. Unlike Unit 8's DP problems, no table of subproblem answers is needed here — a greedy algorithm makes one clearly-best choice at each step and never looks back, and for this specific problem, that greedy choice is provably always correct.

The idea Sort intervals by end time. Walk through them in that order, greedily keeping any interval that starts at or after the end of the last interval kept. Whenever the next interval overlaps the last one kept, it must be the one removed — keeping the interval that ends earliest always leaves the most room for everything still to come, so this choice is never worse than any alternative.
Python 
def erase_overlap_intervals(intervals):
    intervals.sort(key=lambda interval: interval[1])   # sort by end time
    removed = 0
    prev_end = float('-inf')
    for start, end in intervals:
        if start >= prev_end:
            prev_end = end          # keep this interval: it doesn't overlap
        else:
            removed += 1             # overlaps the last kept interval: remove this one
    return removed

}

C++ 
int eraseOverlapIntervals(std::vector<std::vector<int>>& intervals) {
    std::sort(intervals.begin(), intervals.end(),
              [](const auto& a, const auto& b) { return a[1] < b[1]; });   // sort by end time
    int removed = 0;
    int prevEnd = INT_MIN;
    for (auto& interval : intervals) {
        if (interval[0] >= prevEnd) {
            prevEnd = interval[1];    // keep this interval: it doesn't overlap
        } else {
            removed++;                // overlaps the last kept interval: remove this one
        }
    }
    return removed;
}

Sorting costs O(n log n); the single pass afterward is O(n), so the whole algorithm is O(n log n) — no DP table, no exponential search, just one sort and one linear scan. A closely related problem, Merge Intervals (LeetCode #56), uses the same "sort by start (or end, since they tie at the boundary) then walk through once" shape: sort by start time, and merge the current interval into the previous one whenever they overlap (current start ≤ previous end), extending the previous interval's end to the larger of the two; otherwise, start a new merged interval. Both problems reduce to the same first move — sort the intervals — before a single greedy pass does the rest.

Why it matters here Greedy algorithms look deceptively similar to DP: both make a sequence of choices toward an optimal answer. The difference is provability — DP is needed when a locally good choice can turn out to be globally wrong (so every option must be tracked), while greedy is usable only when a proof (often an exchange argument: "swapping the greedy choice for any other choice never does better") shows the locally best choice is always safe. Interval problems are the most common place greedy shows up, precisely because sorting by start or end time so often makes that safety argument straightforward.

Check your recall

1. Why does this algorithm sort intervals by end time rather than start time?

An interval ending earlier can never block more future intervals than one ending later would.

2. What fundamentally distinguishes a greedy algorithm from a dynamic programming one?

Greedy only works when a proof shows the locally best choice is never worse than any alternative.

3. What do Non-overlapping Intervals and Merge Intervals have in common as a first step?

Sorting first is what makes a single greedy pass sufficient for either problem.
