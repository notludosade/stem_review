Problem (LeetCode #560, Subarray Sum Equals K): given an array of integers and an integer k, return the number of contiguous subarrays whose elements sum to exactly k. This lesson doesn't introduce a new technique — it works this problem the way an actual interview or contest attempt should go, one framework step at a time.

Step 1: Clarify Can the array contain negative numbers? Yes — nothing here restricts it to positives. Can k be negative or zero? Also yes. This single clarification already matters: it rules out any two-pointer window approach, since Lesson 7's sliding window logic depends on adding an element only ever increasing the running sum, which negative numbers break.
Step 2: Brute force The direct approach: for every pair of start and end indices, sum that subarray and check if it equals k. That's an O(n²) pair of nested loops (or O(n³) if each subarray sum is recomputed from scratch instead of extended from the previous end index). It works, but on the constraint n up to 2 × 10⁴ typically listed for this problem, O(n²) is right at the edge of too slow.
Step 3: Find the bottleneck The repeated work is recomputing overlapping subarray sums from scratch. A running prefix sum fixes that part in O(1) per index — but checking every earlier prefix sum for a match is still an O(n) inner step, leaving O(n²) overall. That inner "check every earlier value" step is the actual bottleneck, and it's a familiar shape.
Step 4: Pattern-match A subarray from index i+1 to j sums to k exactly when prefixSum[j] - prefixSum[i] = k, which rearranges to prefixSum[i] = prefixSum[j] - k. That's Lesson 1's Two Sum complement trick wearing a prefix-sum costume: instead of asking "have I seen target − num before?", this asks "have I seen prefixSum − k before?" A hash map counting how many times each prefix sum has occurred turns the inner check into O(1), and the whole solution into one O(n) pass.
Python 
def subarray_sum(nums, k):
    count = 0
    prefix_sum = 0
    sum_counts = {0: 1}       # empty prefix (sum 0) has occurred once, before any element
    for num in nums:
        prefix_sum += num
        count += sum_counts.get(prefix_sum - k, 0)   # how many earlier prefixes make a subarray = k
        sum_counts[prefix_sum] = sum_counts.get(prefix_sum, 0) + 1
    return count
Java 
int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> sumCounts = new HashMap<>();
    sumCounts.put(0, 1);      // empty prefix (sum 0) has occurred once, before any element
    int count = 0;
    int prefixSum = 0;
    for (int num : nums) {
        prefixSum += num;
        count += sumCounts.getOrDefault(prefixSum - k, 0);   // earlier prefixes making a subarray = k
        sumCounts.put(prefixSum, sumCounts.getOrDefault(prefixSum, 0) + 1);
    }
    return count;
}
JavaScript 
function subarraySum(nums, k) {
  const sumCounts = new Map([[0, 1]]);   // empty prefix (sum 0) has occurred once, before any element
  let count = 0;
  let prefixSum = 0;
  for (const num of nums) {
    prefixSum += num;
    count += sumCounts.get(prefixSum - k) || 0;   // earlier prefixes making a subarray = k
    sumCounts.set(prefixSum, (sumCounts.get(prefixSum) || 0) + 1);
  }
  return count;
}
C++ 
int subarraySum(std::vector<int>& nums, int k) {
    std::unordered_map<int, int> sumCounts;
    sumCounts[0] = 1;         // empty prefix (sum 0) has occurred once, before any element
    int count = 0;
    int prefixSum = 0;
    for (int num : nums) {
        prefixSum += num;
        auto it = sumCounts.find(prefixSum - k);
        if (it != sumCounts.end()) {
            count += it->second;   // earlier prefixes making a subarray = k
        }
        sumCounts[prefixSum]++;
    }
    return count;
}
Step 5: Verify Trace nums = [1, 2, 3], k = 3 by hand: prefix sums after each element are 1, 3, 6. At prefix 1, look for 1 − 3 = −2 (not seen, count stays 0). At prefix 3, look for 3 − 3 = 0 (seen once, from the empty prefix — count becomes 1, correctly matching subarray [1, 2]). At prefix 6, look for 6 − 3 = 3 (seen once — count becomes 2, correctly matching subarray [3]). Final answer 2, which matches both subarrays summing to 3 by inspection. Edge case worth checking separately: an all-zero array with k = 0, which relies on that initial sum_counts = {0: 1} entry to count the empty-prefix match correctly.

Check your recall

1. Why does this problem rule out a sliding window approach during the clarify step?

Sliding window correctness in Lessons 6 and 7 depends on sums moving monotonically as the window grows, which negative numbers break.

2. What earlier lesson's pattern does the prefix-sum hash map trick directly reuse?

Both check "has target − current already been seen," just applied to a running prefix sum instead of a single array value.

3. Why does sumCounts start with the entry {0: 1} before any element is processed?

Without it, a subarray starting at index 0 that already equals k would never be counted.

4. Fill in the blank: this solution tracks a running ___ sum, turning a subarray-sum check into a single hash map lookup.

The running total up to each index is what makes any subarray's sum a simple subtraction.

5. Fill in the blank: Lesson 3's framework names the repeated, avoidable work inside a brute-force solution the ___.

Finding this is exactly what turned an O(n²) scan into an O(n) hash map lookup here.
