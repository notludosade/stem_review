Bit Manipulation Essentials: Single Number

A completely different kind of efficiency trick — working directly with a number's binary representation instead of its value.

← Lesson 31 Lesson 33 → Contents Glossary →

Problem: given an array where every number appears exactly twice except for one, find that single number — in O(n) time and O(1) space, meaning no hash set counting occurrences is allowed. The trick relies entirely on one property of the XOR (exclusive or) operator: a ^ a = 0, and a ^ 0 = a. XOR every number in the array together, and every pair cancels itself out to zero, leaving only the number with no partner.

The idea XOR is both commutative and associative, so the order numbers are combined in doesn't matter. Starting an accumulator at 0 and XOR-ing every element into it means every number that appears twice contributes x ^ x = 0 (no effect), while the lone unpaired number survives untouched since it's only XOR-ed with 0 overall.
Python 
def single_number(nums):
    result = 0
    for num in nums:
        result ^= num       # pairs cancel to 0; the lone number survives
    return result
Java 
int singleNumber(int[] nums) {
    int result = 0;
    for (int num : nums) {
        result ^= num;       // pairs cancel to 0; the lone number survives
    }
    return result;
}
JavaScript 
function singleNumber(nums) {
  let result = 0;
  for (const num of nums) {
    result ^= num;        // pairs cancel to 0; the lone number survives
  }
  return result;
}
C++ 
int singleNumber(std::vector<int>& nums) {
    int result = 0;
    for (int num : nums) {
        result ^= num;        // pairs cancel to 0; the lone number survives
    }
    return result;
}

One pass, one integer accumulator: O(n) time, O(1) space, no hash set required at all. This is one example from a small set of bit tricks worth having memorized:

Reference: common bit tricks n & 1 checks whether n is odd (the lowest bit is 1). n >> 1 and n << 1 divide or multiply by 2, discarding any remainder on the way down. n & (n - 1) clears the lowest set bit — if the result is 0, n was a power of two to begin with. n | (1 << k) sets bit k; n & ~(1 << k) clears bit k; n ^ (1 << k) toggles bit k.
Why it matters here Bit tricks trade a data structure (a hash set, here) for a mathematical property of an operator, which is what makes them valuable specifically when a problem's constraints explicitly forbid extra space. They rarely apply broadly — each trick solves a narrow shape of problem — but recognizing "this problem is really about parity, powers of two, or toggling a flag" is the signal that a bitwise operator might replace an entire data structure with a single expression.

Check your recall

1. What XOR property makes the Single Number solution work?

Since every duplicate contributes x ^ x = 0, only the unpaired number is left after all cancellations.

2. Why doesn't the order in which numbers are XOR-ed together matter?

These two properties are what let a single running accumulator replace tracking every number's pair explicitly.

3. What does the expression n & (n - 1) accomplish?

If clearing the lowest set bit results in exactly 0, n had only one set bit to begin with, meaning it's a power of two.

4. Fill in the blank: the operator with the property a ^ a = 0 and a ^ 0 = a is ___.

Short for exclusive or, this is the operator this entire lesson's solution depends on.

5. Fill in the blank: the XOR approach solves Single Number in O(1) extra ___, unlike a hash-set approach.

Only a single integer accumulator is needed, regardless of how large the input array grows.
