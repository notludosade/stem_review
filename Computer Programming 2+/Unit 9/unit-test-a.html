1. Why does the interval-scheduling greedy algorithm sort intervals by end time rather than start time?

An interval ending earlier can never block more future intervals than one ending later would.

2. Fill in the blank: an algorithm that makes one locally best choice at each step, with no backtracking, is called a ___ algorithm.

This is the term for the entire category of algorithm Lesson 31 introduces.

3. What XOR property makes the Single Number solution work?

Since every duplicate contributes x ^ x = 0, only the unpaired number is left after all cancellations.

4. Fill in the blank: the operator with the property a ^ a = 0 and a ^ 0 = a is ___.

Short for exclusive or, this is the operator the Single Number solution depends on.

5. A problem states n ≤ 10⁵–10⁶. What does that constraint most strongly rule out before the problem's wording is even fully re-read?

A large n effectively bans slower approaches before any other analysis, narrowing the candidate list fast.

6. For intervals = [[1,2],[2,3],[3,4],[1,3]], sorted by end time this becomes [[1,2],[2,3],[1,3],[3,4]]. Answer both parts:

(a) After keeping [1,2] (prev_end=2) and [2,3] (prev_end=3), what happens when [1,3] is checked?

(b) Fill in the blank: after also keeping [3,4] (start 3 ≥ prev_end 3), the total number of intervals removed is ___.

(a) [1,3] starts at 1, which is before prev_end=3 (the end of the last kept interval, [2,3]), so it overlaps and must be removed rather than kept. (b) [3,4] starts exactly at prev_end=3, which counts as non-overlapping, so it's kept — leaving exactly 1 interval ([1,3]) removed overall.

7. Trace result = 0; for each num in [4, 1, 2, 1, 2]: result ^= num. Answer both parts:

(a) What is the value of result immediately after processing the third element (2)?

(b) Fill in the blank: continuing through the remaining elements (1 and 2), the final value of result — the single non-duplicated number — is ___.

(a) 0^4=4, 4^1=5, 5^2=7 — after three elements, result is 7. (b) Continuing: 7^1=6, then 6^2=4; the two 1's and two 2's each fully cancel via a^a=0, leaving only 4, the number with no pair.

8. A problem gives a graph of tasks with dependency edges and asks for one valid order to complete all tasks (not just whether it's possible). Answer both parts:

(a) Which pattern from this course applies, and which lesson's algorithm produces the order directly?

(b) Fill in the blank: reading a problem's ___ first (such as a bound on n) can rule out entire categories of pattern before the problem's wording is even reread.

(a) "Dependencies" plus "produce a valid order" is exactly Lesson 20's signal — Kahn's algorithm already visits nodes in valid dependency order, so recording that order instead of just counting it solves this directly. (b) Checking constraints first is the fastest narrowing step Lesson 33 recommends, before analyzing a problem's logic in depth.

9. For nums = [1, -1, 0], k = 0, trace the prefix-sum algorithm. sumCounts starts as {0: 1}. Answer both parts:

(a) After processing the second element (-1, prefix sum = 0), what is count, and what does sumCounts contain?

(b) Fill in the blank: after processing the third element (0, prefix sum still 0), the final count of subarrays summing to 0 is ___.

(a) At the second element, prefix sum is 1 + (−1) = 0; looking up prefix − k = 0 − 0 = 0 finds the initial {0: 1} entry once, so count becomes 1, and sumCounts is updated to {0: 2, 1: 1}. (b) At the third element, prefix sum stays 0; looking up 0 again now finds 2 prior occurrences, adding 2 more to reach a final count of 3 — matching the three subarrays [1,-1], [1,-1,0], and [0] that each sum to 0.

10. The five-step framework's final step, "verify," traces the optimized solution against edge cases before considering the work finished. Answer both parts about Subarray Sum Equals K:

(a) What specific edge case does the lesson highlight as worth checking separately?

(b) Fill in the blank: this initial entry, sumCounts = {0: ___}, represents the empty prefix — the state before any element has been processed — and is needed to correctly count subarrays starting at index 0 that already equal k.

(a) An all-zero array with k=0 is the edge case Lesson 34 calls out specifically, since every subarray in it sums to 0, and getting the count right depends entirely on that initial empty-prefix entry being counted correctly. (b) Without sum_counts starting at {0: 1}, a subarray starting at index 0 that already equals k would never be counted, since there'd be no "earlier" prefix sum of 0 to match against.
