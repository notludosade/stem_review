Merging with a Heap: Top K Frequent Elements

Closing this unit by merging two separate techniques — CP2's hash map and Lesson 16's bounded heap — into one solution.

← Lesson 16 Contents Glossary →

Problem: given an array of integers, return the k most frequent values. This isn't a new pattern so much as two already-known ones merged together: count each value's frequency with a hash map (Computer Programming 2's Unit 3), then apply Lesson 16's exact bounded-heap trick — except keyed by frequency instead of by raw value.

The idea Build a hash map from value to frequency in one O(n) pass. Then maintain a min-heap capped at size k, holding (value, frequency) pairs ordered by frequency — pushing every pair in, and popping the lowest-frequency pair whenever the heap exceeds size k. What remains is exactly the k most frequent values.
Python 
import heapq
from collections import Counter

def top_k_frequent(nums, k):
    counts = Counter(nums)
    heap = []
    for num, freq in counts.items():
        heapq.heappush(heap, (freq, num))   # ordered by frequency first
        if len(heap) > k:
            heapq.heappop(heap)               # discard the lowest-frequency pair
    return [num for freq, num in heap]
Java 
List<Integer> topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> counts = new HashMap<>();
    for (int num : nums) counts.merge(num, 1, Integer::sum);

    PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[1] - b[1]);   // min-heap by frequency
    for (Map.Entry<Integer, Integer> entry : counts.entrySet()) {
        heap.offer(new int[] { entry.getKey(), entry.getValue() });
        if (heap.size() > k) heap.poll();   // discard the lowest-frequency pair
    }
    List<Integer> result = new ArrayList<>();
    for (int[] pair : heap) result.add(pair[0]);
    return result;
}
JavaScript 
// Lesson 15's MinHeap, extended with a comparator so it can be keyed by frequency
class MinHeap {
  constructor(compare) { this.data = []; this.compare = compare; }
  push(val) {
    this.data.push(val);
    let i = this.data.length - 1;
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.compare(this.data[parent], this.data[i]) <= 0) break;
      [this.data[parent], this.data[i]] = [this.data[i], this.data[parent]];
      i = parent;
    }
  }
  pop() {
    const top = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let smallest = i;
        if (l < this.data.length && this.compare(this.data[l], this.data[smallest]) < 0) smallest = l;
        if (r < this.data.length && this.compare(this.data[r], this.data[smallest]) < 0) smallest = r;
        if (smallest === i) break;
        [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
        i = smallest;
      }
    }
    return top;
  }
}

function topKFrequent(nums, k) {
  const counts = new Map();
  for (const num of nums) counts.set(num, (counts.get(num) || 0) + 1);

  const heap = new MinHeap((a, b) => a[1] - b[1]);   // compare by frequency
  for (const pair of counts) {
    heap.push(pair);
    if (heap.data.length > k) heap.pop();
  }
  return heap.data.map(([num]) => num);
}
C++ 
std::vector<int> topKFrequent(std::vector<int>& nums, int k) {
    std::unordered_map<int, int> counts;
    for (int num : nums) counts[num]++;

    auto compare = [](const std::pair<int,int>& a, const std::pair<int,int>& b) {
        return a.second > b.second;   // min-heap by frequency
    };
    std::priority_queue<std::pair<int,int>, std::vector<std::pair<int,int>>, decltype(compare)> heap(compare);

    for (const auto& entry : counts) {
        heap.push(entry);
        if (heap.size() > k) heap.pop();   // discard the lowest-frequency pair
    }
    std::vector<int> result;
    while (!heap.empty()) {
        result.push_back(heap.top().first);
        heap.pop();
    }
    return result;
}

Counting takes O(n). With u unique values, maintaining the bounded heap costs O(u log k), for a total of O(n + u log k) — and since u ≤ n, this is never worse than O(n log k). A completely different approach, bucket sort by frequency, reaches O(n) overall by exploiting the fact that frequency can never exceed the array's length — worth knowing exists, though the heap approach here generalizes to far more problems than this one specific trick does.

Why it matters here Almost no real interview or contest problem arrives as a single clean pattern — it's usually two or three earlier ideas, applied together, in a shape not seen exactly before. This lesson deliberately closes Unit 5 on that note: the hash map wasn't reinvented, and the bounded heap wasn't reinvented — recognizing where each one still applies, and combining them, is the actual skill being built across this entire course.

Check your recall

1. What two previously learned techniques does this lesson's solution combine?

Counting frequencies is a plain hash map problem; keeping only the top k by that count is exactly Lesson 16's pattern, keyed differently.

2. In this problem, what is the heap ordered by, instead of the raw value itself?

The heap tracks which values occur most often, not which values are numerically largest.

3. What is the overall time complexity of the hash map plus bounded heap approach?

Counting costs O(n); maintaining the heap costs O(log k) per unique value, of which there are at most n.

4. Fill in the blank: in this lesson's heap, pairs are ordered by ___ rather than by the raw value.

This is the one change from Lesson 16's kth-largest pattern — everything else about the bounded-heap trick stays the same.

5. Fill in the blank: an alternative O(n) approach exploits the fact that frequency is bounded by array length, using ___ sort.

This groups values into buckets indexed by their frequency count, avoiding the heap entirely.
