Heap Fundamentals

A structure that keeps "the smallest so far" instantly available, without ever fully sorting anything.

← Lesson 14 Lesson 16 → Contents Glossary →

A heap is a binary tree with one relaxed rule: every parent is smaller than (or equal to) both of its children — a min-heap — or larger than both, a max-heap. Unlike a BST from Lesson 13, there's no ordering between siblings or between a node and the rest of its subtree beyond its own children — only the parent-child relationship matters. That looser rule is exactly what makes inserting and removing the minimum (or maximum) cost only O(log n), while still being far cheaper to build than a fully sorted structure.

The idea A heap is stored as a plain array, not as linked nodes — the tree structure is implicit: the children of index i live at 2i + 1 and 2i + 2. Every language here provides (or nearly provides) a built-in heap; using it directly is almost always the right call over implementing one from scratch.
Python 
import heapq

def three_smallest(nums):
    heapq.heapify(nums)                 # O(n), turns the list into a min-heap in place
    return [heapq.heappop(nums) for _ in range(3)]   # each pop is O(log n)
Java 
List<Integer> threeSmallest(List<Integer> nums) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(nums);   // min-heap by default
    List<Integer> result = new ArrayList<>();
    for (int i = 0; i < 3; i++) result.add(heap.poll());        // each poll is O(log n)
    return result;
}
JavaScript 
class MinHeap {
  constructor() { this.data = []; }
  push(val) {
    this.data.push(val);
    let i = this.data.length - 1;
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.data[parent] <= this.data[i]) break;
      [this.data[parent], this.data[i]] = [this.data[i], this.data[parent]];
      i = parent;
    }
  }
  pop() {                                // O(log n): swap last leaf to root, sink it down
    const top = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let smallest = i;
        if (l < this.data.length && this.data[l] < this.data[smallest]) smallest = l;
        if (r < this.data.length && this.data[r] < this.data[smallest]) smallest = r;
        if (smallest === i) break;
        [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
        i = smallest;
      }
    }
    return top;
  }
}
C++ 
std::vector<int> threeSmallest(std::vector<int> nums) {
    std::priority_queue<int, std::vector<int>, std::greater<int>> heap(nums.begin(), nums.end());
    std::vector<int> result;
    for (int i = 0; i < 3; i++) {
        result.push_back(heap.top());   // O(1) peek
        heap.pop();                       // O(log n)
    }
    return result;
}

Python's heapq and C++'s std::priority_queue default to a max-heap and min-heap respectively in the opposite way you might expect — heapq is min-heap-only, and priority_queue is max-heap unless given std::greater explicitly, as above. JavaScript alone has no built-in heap at all — implementing one by hand, as shown, is the normal, expected solution, not a workaround.

Why it matters here Building a heap from an existing collection (heapify) costs O(n), not O(n log n) — it's cheaper than it looks, because most nodes are near the bottom and need very few swaps to settle. Every individual push or pop afterward is O(log n), and peeking at the min or max is O(1). Whenever a problem repeatedly needs "the current smallest (or largest) of a changing collection," a heap is almost always the answer — Lessons 16 and 17 are both this exact instinct applied to specific problems.

Check your recall

1. What is the one ordering rule a min-heap actually enforces?

Unlike a BST, there's no rule relating a node to its whole subtree or to its siblings — only to its direct children.

2. How is a heap typically stored in memory?

The tree shape is implicit in the array's indices — index i's children live at 2i+1 and 2i+2 — with no pointers needed.

3. What is the time complexity of building a heap from an existing unsorted collection (heapify)?

This is a common surprise — heapify is asymptotically cheaper than a full sort, even though extracting all elements one at a time afterward is not.

4. Fill in the blank: a binary tree where every parent is smaller (or larger) than both of its children is called a ___.

This is the name for the entire structure this lesson introduces.
