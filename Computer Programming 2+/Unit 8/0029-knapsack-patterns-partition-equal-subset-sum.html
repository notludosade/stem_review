Knapsack Patterns: Partition Equal Subset Sum

A second dimension that isn't a position at all, but a running capacity — and a direction of iteration that decides whether an item can be reused.

← Lesson 28 Lesson 30 → Contents Glossary →

Problem: given an array of positive integers, determine whether it can be split into two subsets with equal sum. If the total sum is odd, it's immediately impossible — an odd number can't split into two equal halves. Otherwise, the question becomes: can some subset of the array sum to exactly total / 2? That's the classic 0/1 knapsack question — each number is an item that can either be included or excluded, and it can be used at most once.

The idea Build a boolean array dp of size target + 1, where dp[s] means "some subset of the numbers processed so far sums to exactly s." Start with only dp[0] = True (an empty subset sums to zero). For each number, update the array by iterating sums from target down to that number — going backward guarantees each number is only used once per subset, since a lower value hasn't been updated by the current number yet when a higher one reads from it.
Python 
def can_partition(nums):
    total = sum(nums)
    if total % 2 != 0:
        return False               # an odd total can never split evenly
    target = total // 2

    dp = [False] * (target + 1)
    dp[0] = True                    # an empty subset always sums to zero
    for num in nums:
        for s in range(target, num - 1, -1):    # backward: use each number at most once
            dp[s] = dp[s] or dp[s - num]
    return dp[target]
Java 
boolean canPartition(int[] nums) {
    int total = 0;
    for (int num : nums) total += num;
    if (total % 2 != 0) return false;   // an odd total can never split evenly
    int target = total / 2;

    boolean[] dp = new boolean[target + 1];
    dp[0] = true;                        // an empty subset always sums to zero
    for (int num : nums) {
        for (int s = target; s >= num; s--) {   // backward: use each number at most once
            dp[s] = dp[s] || dp[s - num];
        }
    }
    return dp[target];
}
JavaScript 
function canPartition(nums) {
  const total = nums.reduce((a, b) => a + b, 0);
  if (total % 2 !== 0) return false;   // an odd total can never split evenly
  const target = total / 2;

  const dp = new Array(target + 1).fill(false);
  dp[0] = true;                          // an empty subset always sums to zero
  for (const num of nums) {
    for (let s = target; s >= num; s--) {   // backward: use each number at most once
      dp[s] = dp[s] || dp[s - num];
    }
  }
  return dp[target];
}
C++ 
bool canPartition(std::vector<int>& nums) {
    int total = 0;
    for (int num : nums) total += num;
    if (total % 2 != 0) return false;   // an odd total can never split evenly
    int target = total / 2;

    std::vector<bool> dp(target + 1, false);
    dp[0] = true;                         // an empty subset always sums to zero
    for (int num : nums) {
        for (int s = target; s >= num; s--) {   // backward: use each number at most once
            dp[s] = dp[s] || dp[s - num];
        }
    }
    return dp[target];
}

With n numbers and a target sum of T, this runs in O(n · T) time and O(T) space — pseudo-polynomial, since T is a value, not a count of items, and can be large even for a small array. Iterating backward is the entire trick: Lesson 24's Combination Sum iterated forward because reuse was allowed there; here, iterating backward through each number's own pass ensures a number can't be picked twice within the same subset.

Why it matters here This is Lesson 28's 2D DP in disguise — a full table would be dp[i][s] (using the first i numbers, can s be reached), but since row i only ever depends on row i − 1, it collapses to a single 1D array updated carefully in place, the same space-compression idea from Lessons 26 and 28. The knapsack family (0/1 knapsack, unbounded knapsack, subset sum) is really one recurrence with a rule about reuse — and that rule is controlled entirely by which direction the inner loop iterates.

Check your recall

1. Why does an odd total sum immediately rule out a valid partition?

Two equal integer subset sums must add to an even total by definition.

2. Why does the inner loop iterate from target down to num, rather than from num up to target?

Forward iteration would let a number's own update be read again later in the same pass, effectively reusing it.

3. What does dp[s] represent at any point during the algorithm?

This is exactly the 0/1 knapsack question, asked for every possible sum up to the target at once.

4. Fill in the blank: choosing whether to include each item at most once toward a capacity is the classic 0/1 ___ problem.

The 0 and 1 refer to excluding or including each item exactly zero or one times.

5. Fill in the blank: iterating the sums ___, from target down to the current number, is what enforces the 0/1 (use-once) rule.

This is the single detail that separates 0/1 knapsack from the reuse-allowed pattern in Lesson 24.
