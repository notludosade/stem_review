1. A direct recursive solution recomputes ways(5) dozens of times across different branches of its call tree. Which DP property does this illustrate?

The same smaller input being solved again and again across the call tree is exactly what overlapping subproblems means — the signal that caching will help.

2. Which statement correctly distinguishes the two DP implementation strategies?

They compute identical answers, differing only in direction and mechanism — one is recursion plus a cache, the other is an iterative array built from the base cases up.

3. Trace the tabulated climb_stairs_tab(6). Answer both parts:

(a) What is dp[6]?

(b) Fill in the blank: this space-compression trick — replacing the whole dp array with two running variables — drops space from O(n) down to O(___).

(a) dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5, dp[5]=8, dp[6]=13 — each value sums the two before it. (b) Since only the previous two entries are ever read, two variables fully replace the array, giving O(1) space.

4. Given nums = [2, 7, 9, 3, 1], what does rob(2) (0-indexed, using only houses 0 through 2) equal under rob(i) = max(rob(i - 1), rob(i - 2) + nums[i])?

rob(0) = 2, rob(1) = max(2, 7) = 7, so rob(2) = max(7, 2 + 9) = max(7, 11) = 11 — taking house 2 alongside house 0 beats skipping it.

5. Trace Kadane's algorithm on nums = [5, 4, -1, 7, 8]. Answer both parts:

(a) What is the maximum subarray sum?

(b) Fill in the blank: since every running total after the first element stays higher than starting fresh, the maximum subarray here is the entire array, summing to ___.

(a) current never needs to restart, climbing 5, 9, 8, 15, 23, so the best sum is 23. (b) 5 + 4 - 1 + 7 + 8 = 23, the whole array — extending always beat restarting here since there's no dip large enough to make restarting better.

6. For a 3×3 grid (m = 3, n = 3), what is dp[2][2] (0-indexed), the number of distinct paths to the bottom-right corner?

Filling row by row: dp[1][1] = 2, dp[1][2] = 3, dp[2][1] = 3, so dp[2][2] = dp[1][2] + dp[2][1] = 3 + 3 = 6.

7. Find the edit distance between word1 = "horse" and word2 = "ros" (LeetCode's own example). Answer both parts:

(a) What is the edit distance between "horse" and "ros"?

(b) Which sequence of edits achieves this minimum?

(a) Filling the full dp table for these two words gives dp[5][3] = 3. (b) horse → rorse (substitute h→r) → rose (delete the extra r) → ros (delete the trailing e) is one valid 3-edit path.

8. Consider can_partition([1, 2, 3, 5]). Answer both parts:

(a) What does can_partition immediately return, and why?

(b) Fill in the blank: iterating the inner loop backward (from target down to num) ensures each number is used at most once, rather than being ___ within the same subset.

(a) 1+2+3+5 = 11, which is odd, so the dp array isn't even built — the odd-total check short-circuits immediately. Note {1,2,3} sums to 6, not 5, so it isn't actually an equal partition either. (b) Backward iteration is exactly what stops a number's own update from being read again later in the same pass.

9. Fill in the blank: with n numbers and a target sum T, this algorithm's O(n · T) runtime is called pseudo-___, since T is a value rather than a count of items and can be large even for a small array.

The runtime scales with the numeric magnitude of the target, not just the number of items — that's exactly what makes it pseudo-polynomial rather than truly polynomial in the input size.

10. Trace length_of_lis([0, 1, 0, 3, 2, 3]). Answer both parts:

(a) What is the length of the longest increasing subsequence?

(b) Fill in the blank: checking every pair (i, j) in this straightforward approach gives a ___ time complexity of O(n²).

(a) The chain 0, 1, 2, 3 (using indices 0, 1, 4, 5) is a longest increasing subsequence of length 4. (b) A nested loop over the same array of size n produces n² total comparisons — quadratic growth.
