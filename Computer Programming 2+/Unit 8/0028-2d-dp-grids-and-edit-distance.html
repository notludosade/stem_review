2D DP: Grids & Edit Distance

When the answer at one position depends on two directions of "previous" instead of one, the dp array grows a second dimension.

← Lesson 27 Lesson 29 → Contents Glossary →

Problem: a robot sits at the top-left corner of an m×n grid and can only move right or down. How many distinct paths reach the bottom-right corner? Each cell can only be reached from the cell directly above it or the cell directly to its left, so paths(r, c) = paths(r - 1, c) + paths(r, c - 1) — Lesson 26's Climbing Stairs recurrence, just indexed by two coordinates instead of one.

The idea Build a 2D dp table the same size as the grid. The entire first row and first column are base cases equal to 1 — there's exactly one way to reach any cell along the top or left edge (a straight line of moves). Every other cell is the sum of the cell above and the cell to its left, filled in row by row.
Python 
def unique_paths(m, n):
    dp = [[1] * n for _ in range(m)]    # top row and left column are all base cases: 1
    for r in range(1, m):
        for c in range(1, n):
            dp[r][c] = dp[r - 1][c] + dp[r][c - 1]   # from above, or from the left
    return dp[m - 1][n - 1]
Java 
int uniquePaths(int m, int n) {
    int[][] dp = new int[m][n];
    for (int r = 0; r < m; r++) dp[r][0] = 1;   // left column: one straight-down path
    for (int c = 0; c < n; c++) dp[0][c] = 1;   // top row: one straight-right path
    for (int r = 1; r < m; r++) {
        for (int c = 1; c < n; c++) {
            dp[r][c] = dp[r - 1][c] + dp[r][c - 1];   // from above, or from the left
        }
    }
    return dp[m - 1][n - 1];
}

C++

Filling every one of the m×n cells costs O(1) work each, for O(m · n) time and space overall — and since each row only ever reads the row directly above it, this can be compressed to a single 1D array of length n, updated in place, the same space-compression idea from Lesson 26 applied to a second dimension.

Edit Distance (LeetCode #72) extends this same grid shape to two strings instead of one grid: given words word1 and word2, find the minimum number of insertions, deletions, or substitutions to turn one into the other. Build a dp table where dp[i][j] is the edit distance between the first i characters of word1 and the first j characters of word2. When the characters at positions i and j match, no edit is needed there: dp[i][j] = dp[i - 1][j - 1]. When they don't match, the answer is 1 plus the best of the three possible edits: dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) — deleting from word1, inserting into word1, or substituting — each corresponding to moving through the grid from a different neighboring cell. The base cases along row 0 and column 0 are simply the number of insertions or deletions needed to build up from nothing.

Why it matters here Both problems fill a 2D table where each cell depends only on cells directly above, to the left, or diagonally above-left — the same "look at a small fixed set of neighbors" idea from Unique Paths, just with a three-way minimum instead of a two-way sum. Once a problem's state naturally needs two indices to describe (a position in a grid, or a pair of positions in two different strings), the recurrence almost always reduces to "this cell from a small set of neighboring cells," and the table can be filled in the same row-by-row order every time.

Check your recall

1. Why are the entire top row and left column of the Unique Paths table set to 1?

An edge cell can only be reached by moving entirely in one direction, since the other direction would go off the grid.

2. In Edit Distance, what happens when the characters at the current positions in both words already match?

Matching characters carry no cost, so the value simply comes from having already solved the smaller prefix pair.

3. What do the three neighboring cells (up, left, diagonal) represent when characters don't match in Edit Distance?

Each direction in the table corresponds to one specific type of edit operation.

4. Fill in the blank: 2D DP is used when a problem's state naturally needs ___ indices to describe, rather than just one.

A grid position or a pair of string prefixes are both naturally described by two coordinates.

5. Fill in the blank: since each row of the Unique Paths table only reads the row directly above it, the table can be space-___ down to a single 1D array.

This is the same idea introduced in Lesson 26 for 1D DP, applied to a second dimension here.
