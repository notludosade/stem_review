Memoization vs. Tabulation: Climbing Stairs

Recursion that stops repeating itself, by remembering answers it's already computed — the entire idea behind dynamic programming.

← Lesson 25 Lesson 27 → Contents Glossary →

Problem: climbing a staircase of n steps, taking either 1 or 2 steps at a time, how many distinct ways are there to reach the top? Writing the direct recursion — ways(n) = ways(n - 1) + ways(n - 2), since the last move was either a 1-step or a 2-step — gives a correct but painfully slow solution: it recomputes ways(5), say, dozens of times across different branches of the same call tree. Dynamic programming is exactly this: recursion with overlapping subproblems, solved once and remembered instead of recomputed.

The idea A problem qualifies for DP when it has overlapping subproblems (the same smaller inputs get solved repeatedly) and optimal substructure (the answer to the whole problem can be built directly from answers to its smaller pieces). Two equivalent ways to exploit this: memoization (top-down) keeps the natural recursion but caches each result the first time it's computed; tabulation (bottom-up) builds an array of answers iteratively, starting from the base cases and working up to n, with no recursion or call stack at all.
Python 
# Top-down: memoization
def climb_stairs_memo(n, cache={}):
    if n <= 2:
        return n
    if n in cache:
        return cache[n]                 # already solved this subproblem
    cache[n] = climb_stairs_memo(n - 1, cache) + climb_stairs_memo(n - 2, cache)
    return cache[n]

# Bottom-up: tabulation
def climb_stairs_tab(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]   # build upward from the base cases
    return dp[n]
Java 
// Top-down: memoization
Map<Integer, Integer> cache = new HashMap<>();

int climbStairsMemo(int n) {
    if (n <= 2) return n;
    if (cache.containsKey(n)) return cache.get(n);   // already solved this subproblem
    int result = climbStairsMemo(n - 1) + climbStairsMemo(n - 2);
    cache.put(n, result);
    return result;
}

// Bottom-up: tabulation
int climbStairsTab(int n) {
    if (n <= 2) return n;
    int[] dp = new int[n + 1];
    dp[1] = 1;
    dp[2] = 2;
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];   // build upward from the base cases
    }
    return dp[n];
}
JavaScript 
// Top-down: memoization
function climbStairsMemo(n, cache = new Map()) {
  if (n <= 2) return n;
  if (cache.has(n)) return cache.get(n);   // already solved this subproblem
  const result = climbStairsMemo(n - 1, cache) + climbStairsMemo(n - 2, cache);
  cache.set(n, result);
  return result;
}

// Bottom-up: tabulation
function climbStairsTab(n) {
  if (n <= 2) return n;
  const dp = new Array(n + 1).fill(0);
  dp[1] = 1;
  dp[2] = 2;
  for (let i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];   // build upward from the base cases
  }
  return dp[n];
}
C++ 
// Top-down: memoization
std::unordered_map<int, int> cache;

int climbStairsMemo(int n) {
    if (n <= 2) return n;
    if (cache.count(n)) return cache[n];   // already solved this subproblem
    int result = climbStairsMemo(n - 1) + climbStairsMemo(n - 2);
    cache[n] = result;
    return result;
}

// Bottom-up: tabulation
int climbStairsTab(int n) {
    if (n <= 2) return n;
    std::vector<int> dp(n + 1);
    dp[1] = 1;
    dp[2] = 2;
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];   // build upward from the base cases
    }
    return dp[n];
}

Both versions run in O(n) time and O(n) space — a dramatic improvement over the uncached recursion's O(2ⁿ), since each of the n subproblems is now solved exactly once instead of exponentially many times. Tabulation here can go further: since dp[i] only ever depends on the previous two values, the entire array can be replaced with two variables, dropping space to O(1) — an optimization worth knowing exists, though the full array is usually written first for clarity.

Why it matters here Climbing Stairs is secretly the Fibonacci sequence, and Fibonacci is the smallest possible example of what every DP problem in this unit will look like: a recurrence relating the answer for n to answers for smaller values, with those smaller answers reused often enough that caching them changes the runtime class entirely. Recognizing "this recursion keeps solving the same smaller input" is the signal to reach for memoization or tabulation — the same signal that will apply to every remaining lesson in this unit.

Check your recall

1. What makes a problem a good candidate for dynamic programming?

Overlapping subproblems means caching pays off; optimal substructure means the full answer can be built from smaller ones.

2. What is the key difference between memoization and tabulation?

Both compute the same answers, just in the opposite order and with different mechanisms for reuse.

3. Why is the uncached recursive version of Climbing Stairs so much slower?

Without caching, the call tree branches into roughly 2ⁿ calls, most of them solving inputs already solved elsewhere.

4. Fill in the blank: subproblems that get solved more than once across a recursion's call tree are called ___ subproblems.

This is one of the two properties (along with optimal substructure) that make a problem suitable for DP.

5. Fill in the blank: building an array of answers iteratively from the base cases upward, with no recursion, is called ___.

This is the bottom-up counterpart to top-down memoization.
