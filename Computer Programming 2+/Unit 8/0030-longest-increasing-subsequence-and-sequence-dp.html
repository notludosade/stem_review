Longest Increasing Subsequence & Sequence DP

Closing this unit with a recurrence that looks back at every earlier index, not just the one or two right before it.

← Lesson 29 Contents Glossary →

Problem: given an array of integers, find the length of the longest strictly increasing subsequence (elements don't need to be contiguous, just in increasing order and in their original relative order). Unlike Lesson 27's House Robber, where each position only depended on the one or two immediately before it, here dp[i] — the length of the longest increasing subsequence ending exactly at index i — depends on every earlier index j where nums[j] < nums[i].

The idea For each index i, look back at every earlier index j. If nums[j] < nums[i], then index i could extend that subsequence: dp[i] = max(dp[i], dp[j] + 1). Every index starts with dp[i] = 1 (itself alone is a valid subsequence of length 1). The final answer is the largest value anywhere in dp, since the longest subsequence overall could end at any index.
Python 
def length_of_lis(nums):
    dp = [1] * len(nums)         # every element alone is a subsequence of length 1
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)   # extend the subsequence ending at j
    return max(dp)
Java 
int lengthOfLIS(int[] nums) {
    int[] dp = new int[nums.length];
    Arrays.fill(dp, 1);           // every element alone is a subsequence of length 1
    int best = 1;
    for (int i = 0; i < nums.length; i++) {
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {
                dp[i] = Math.max(dp[i], dp[j] + 1);   // extend the subsequence ending at j
            }
        }
        best = Math.max(best, dp[i]);
    }
    return best;
}
JavaScript 
function lengthOfLIS(nums) {
  const dp = new Array(nums.length).fill(1);   // every element alone is a subsequence of length 1
  for (let i = 0; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);   // extend the subsequence ending at j
      }
    }
  }
  return Math.max(...dp);
}
C++ 
int lengthOfLIS(std::vector<int>& nums) {
    std::vector<int> dp(nums.size(), 1);   // every element alone is a subsequence of length 1
    int best = 1;
    for (int i = 0; i < (int)nums.size(); i++) {
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {
                dp[i] = std::max(dp[i], dp[j] + 1);   // extend the subsequence ending at j
            }
        }
        best = std::max(best, dp[i]);
    }
    return best;
}

With a nested loop checking every pair (i, j), this runs in O(n²) time and O(n) space. A faster O(n log n) approach exists: maintain an array of the smallest possible "tail" value for an increasing subsequence of each length, and use Unit 3's binary search to find where the current number belongs in that array in O(log n) instead of scanning every earlier index — trading the straightforward O(n²) recurrence for a cleverer O(n log n) one when the input is large enough to need it.

Why it matters here LIS closes this unit by showing that "previous" in a DP recurrence doesn't have to mean "immediately before" — it can mean "any earlier index satisfying some condition," at the cost of an extra inner loop. Across this entire unit, the same skeleton kept reappearing: identify what a state needs to remember (one index, two indices, a capacity, or here, every earlier ending point), write the recurrence connecting a state to the smaller states it depends on, and decide whether to compute it top-down with memoization or bottom-up with tabulation. That skeleton, not any single problem, is the actual thing this unit was teaching.
