Encapsulation — How One Message Becomes Many Envelopes

Lesson 5 said each layer only talks to its neighbors. This lesson is the mechanism that makes that true: every layer wraps the data it's handed in its own envelope before passing it down.

← Lesson 5 Unit 3, Lesson 7 → Contents Glossary →

Your browser wants to send one HTTP request. By the time it actually leaves your computer as electrical signals on a wire, that single request has been wrapped in three separate layers of extra information, one from each layer below Application. This lesson watches that wrapping happen step by step, then watches it get undone in reverse order when it arrives.

Headers, payloads, and PDUs

Definitions A header is a small block of structured metadata that a layer adds to the front of the data it's given — things like addresses, sizes, and sequence information, whose exact format is defined by that layer's protocol. The payload is the data being carried — from any given layer's point of view, everything handed to it by the layer above, including that layer's own header, counts as an opaque payload it doesn't need to understand. The combination of a layer's own header plus its payload is called a PDU (Protocol Data Unit) — each layer has its own name for its PDU (a Transport-layer PDU is called a segment, an Internet-layer PDU is called a packet, and a Link-layer PDU is called a frame).
Definition Encapsulation is the process of each layer wrapping the data from the layer above inside its own header (and, at the Link layer, sometimes a trailer at the end too) as the data travels down the stack on its way out. Decapsulation is the reverse: each layer on the receiving end strips off its own header, reading just enough of it to know what to do next, then hands the remaining payload up to the next layer.

Following the trip out, layer by layer Application layer builds the raw HTTP request (the innermost payload). Transport layer (Lesson 15) wraps it in a TCP header carrying source and destination port numbers — the result is called a segment. Internet layer (Unit 3) wraps that segment in an IP header carrying source and destination IP addresses — the result is called a packet. Link layer (Lesson 7) wraps that packet in an Ethernet (or Wi-Fi) header carrying source and destination MAC addresses, plus a trailer at the very end — the result is called a frame, and it's the frame that actually goes out over the wire as electrical signals.
Why each layer only reads its own header When a frame arrives at a router, the router only needs to read the Link-layer header (enough to know it arrived, and sometimes not even fully decapsulate it if just forwarding) and the Internet-layer header underneath (to know where the packet is ultimately headed) to do its job — it has no need to open the TCP header or look at the HTTP request inside. This is Lesson 5's layer isolation in action: a router operates entirely at the Internet layer and below, is completely indifferent to what protocol or application generated the payload, and can forward IP packets belonging to HTTP, DNS, or literally any other application equally well, because it never looks past its own layer's header.

Decapsulation: the exact reverse, on the way in

At the destination, the process runs backward. The Link layer receives the frame, strips its Ethernet header and trailer, and hands the packet up. The Internet layer strips the IP header and hands the segment up. The Transport layer strips the TCP header, using the port number inside to figure out which specific program on the destination machine should receive it, and hands the original HTTP request up to that program's Application layer — arriving as the exact same request your browser built, unwrapped one envelope at a time in the opposite order it was wrapped.

The nesting-doll analogy Encapsulation is a set of Russian nesting dolls being assembled from the inside out — smallest doll (the HTTP request) placed inside a slightly bigger one (TCP segment), placed inside a bigger one still (IP packet), placed inside the biggest, outermost one (Ethernet frame). Decapsulation is simply opening that assembled doll from the outside in, removing exactly one shell at a time, until only the original smallest doll is left.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a header, in the encapsulation sense?

Every layer that participates adds its own header, formatted according to its own protocol's rules.

2. What does a router need to look at to forward a packet, and what does that reveal about layering?

A router operates at the Internet layer and below and is indifferent to whatever application or protocol produced the payload it's carrying.

3. In what order does decapsulation strip headers, relative to the order they were added during encapsulation?

Like opening nesting dolls from the outside in, decapsulation removes the outermost (most recently added) envelope first.

4. Fill in the blank: the general name for "a layer's own header plus its payload," which gets a more specific name at each layer (segment, packet, frame), is a ___.

PDU is the umbrella term; segment, packet, and frame are the layer-specific names for a PDU at the Transport, Internet, and Link layers respectively.
