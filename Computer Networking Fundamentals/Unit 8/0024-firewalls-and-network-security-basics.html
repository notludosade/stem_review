Firewalls and Network Security Basics

Every concept in this course — ports, addresses, protocols — is also exactly what a firewall inspects to decide what traffic gets to exist at all.

← Lesson 23 Lesson 25 → Contents Glossary →

Everything so far in this course has been about getting traffic through a network reliably. This final unit flips the question: how does a network decide which traffic shouldn't get through at all, and how does it recognize when something has gone wrong along the way? A firewall is where that first question gets answered, sitting at nearly every network boundary this course has described.

What a firewall does

Definition A firewall is a system that inspects network traffic crossing a boundary (often between a private network and the internet) and decides, based on a configured set of rules, whether to allow or block it. Packet filtering is the most basic firewall technique: examining each packet's header fields — source and destination IP address (Unit 3), source and destination port (Lesson 14), and protocol — against a rule set, without inspecting the actual payload at all.
Worked example: a home router's default firewall rules A typical home router's firewall allows outbound connections initiated from inside the network (you visiting a website) and allows the corresponding inbound replies, but blocks unsolicited inbound connection attempts from the outside internet by default — nobody on the internet can just reach out and connect directly to a random port on your laptop. This single rule, largely invisible to most users, is a major reason home devices aren't constantly probed and attacked directly by anyone who happens to know their public IP address (which, recall from Lesson 12, they usually share via NAT anyway).

Allowlists and denylists

Definitions An allowlist (default-deny) approach blocks all traffic except what's explicitly permitted — the most restrictive, and generally most secure, starting point. A denylist (default-allow) approach permits all traffic except what's explicitly blocked — more permissive, and only as good as how complete the list of known-bad traffic is kept.
Why default-deny is the stronger security posture A denylist can only block threats someone already thought to add to the list — it does nothing against something new. An allowlist flips the burden entirely: nothing gets through unless it was specifically planned for, so an unanticipated threat that was never on anyone's radar still gets blocked by default, simply because it wasn't explicitly permitted. The trade-off is inconvenience: a legitimate new use of the network also needs an explicit rule added before it works, which is real ongoing maintenance work — but for anything genuinely security-critical, that cost is usually judged worth paying.

Where firewalls sit, connected back to this course

A firewall's packet-filtering rules operate directly on concepts from earlier units: blocking by IP address uses Unit 3's addressing; blocking by port (say, blocking all inbound traffic to port 23, an old and insecure remote-login protocol) uses Lesson 14's port numbers directly; and more advanced firewalls can inspect further up the stack, even reading Application-layer content (Unit 6) to block specific kinds of HTTP requests. A firewall isn't a separate, unrelated piece of networking — it's this course's entire vocabulary, reused as the basis for a decision: let it through, or don't.
