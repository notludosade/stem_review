Common Attacks — Spoofing, Sniffing, and Man-in-the-Middle

Every one of these attacks works by exploiting a trust assumption this course made along the way — mostly the assumption that headers and network positions can be taken at face value.

← Lesson 24 Lesson 26 → Contents Glossary →

Nearly everything this course has covered assumes good faith: that a packet's source address is honest, that nobody's quietly reading traffic that isn't addressed to them, and that a server presenting a valid-looking certificate really is who it claims. Those assumptions mostly hold — but every one of them can be deliberately broken, and this lesson names the three most common ways that happens.

Spoofing

Definition Spoofing is forging the source information in a packet — most commonly the source IP address — to make traffic appear to come from somewhere (or someone) it didn't actually come from. Nothing in the basic IP protocol from Unit 3 requires the source address field to be truthful; a sender can simply write a different address into that field, and, absent additional verification, the network will forward it as if it were genuine.
Why spoofing works at all Recall Lesson 11: a router forwards based on the destination address, and generally has no built-in way to verify the source address is honest — checking that would mean confirming a packet actually originated from where it claims, which the basic protocol was never designed to do. Spoofing exploits exactly this gap. It's used both to hide an attacker's real identity, and in some denial-of-service attacks, to make it look like an attack is coming from many different (fake) sources at once, complicating any attempt to simply block "the" attacker's address.

Sniffing

Definition Sniffing (packet sniffing) is capturing and reading network traffic that isn't addressed to the reader, using a packet sniffer — software that puts a network interface into a mode where it captures traffic on the local network segment rather than only what's addressed to that specific device. On an unencrypted connection, anyone in a position to sniff traffic can read it in plain text — exactly the vulnerability Lesson 19's HTTPS/TLS exists to close.
Worked example: a public Wi-Fi network On a shared public Wi-Fi network, traffic between other users' devices and the router can, depending on the network's configuration, be visible to a sniffer running on any other device connected to that same network. If a website is loaded over plain HTTP instead of HTTPS, anything sent — a password, a search, a message — can be captured and read in plain text by anyone sniffing that network segment. This is precisely why every lesson in Unit 6 emphasized HTTPS: encryption means a sniffer can still capture the traffic, but what they capture is unreadable scrambled bytes instead of your actual data.

Man-in-the-middle

Definition A man-in-the-middle attack (MITM) is when an attacker secretly positions themselves between two communicating parties, intercepting (and potentially altering) traffic passing between them, while both original parties believe they're communicating directly with each other. It's a step beyond passive sniffing: instead of only reading traffic that happens to pass by, the attacker actively inserts themselves into the path the traffic takes.
Why this is exactly the scenario Lesson 19's certificate check defends against Recall the man-in-the-middle scenario Lesson 19 described directly: an attacker intercepts a connection and presents themselves as the real server, potentially having a perfectly encrypted — but entirely compromised — conversation with an unsuspecting victim, reading everything before forwarding it (or not) to the real destination. TLS's certificate verification is the specific countermeasure: your browser checks that the certificate presented actually belongs to the domain you're trying to reach, issued by a trusted third party, and refuses to proceed silently if it doesn't check out. This is why a browser's certificate warning should never be casually clicked through — it exists specifically to catch this attack in progress.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does IP spoofing exploit?

Nothing in basic IP forwarding verifies the source address is honest — routers forward based on destination, not source truthfulness.

2. Why does HTTPS meaningfully limit what a packet sniffer on a shared network can actually learn?

Encryption doesn't stop capture — it makes what's captured unreadable without the key, unlike plain-text HTTP.

3. What specifically distinguishes a man-in-the-middle attack from simple passive sniffing?

MITM is active positioning within the traffic's path, beyond just passively reading traffic that happens to be visible.

4. Fill in the blank: TLS's specific countermeasure against a man-in-the-middle attacker impersonating a real server is verifying that server's ___, refusing to proceed if it doesn't check out.

Certificate verification, from Lesson 19, is exactly the defense against this attack.
