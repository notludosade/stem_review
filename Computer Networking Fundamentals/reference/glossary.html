Unit 1 — What Networks Actually Are

Network / node / link

A network is a collection of devices (nodes) connected by communication pathways (links) that allow them to exchange data. A node just needs an address and the ability to send or receive data — it doesn't have to be a general-purpose computer.

Protocol

An agreed-upon set of rules specifying how data is formatted, sent, and interpreted, so two independently built pieces of software can understand each other.

LAN / WAN

A LAN (Local Area Network) is confined to a small physical area, typically under one owner's control. A WAN (Wide Area Network) spans a large geographic area, usually relying on infrastructure the owner doesn't fully control.

The internet / ISP

The internet is a decentralized collection of independently owned networks that agree to forward each other's traffic — not one giant, centrally-owned network. An ISP (internet service provider) is the company connecting a smaller local network to the wider internet.

Bandwidth / latency / throughput

Bandwidth is the maximum theoretical rate a link could carry data at. Latency is the delay before a single piece of data arrives, dominated by distance and hop count. Throughput is the rate actually achieved in practice, always at or below bandwidth.

Unit 2 — How Data Travels — Packets & Layers

Circuit switching / packet switching

Circuit switching reserves a dedicated path for a conversation's full duration, even during silence. Packet switching breaks data into small, independently addressed packets sent with no dedicated path reserved in advance — what the internet is built on.

Layer

A self-contained slice of the networking problem, with a defined job and a defined interface to the layers immediately above and below it.

OSI model / TCP/IP model

OSI is a seven-layer reference model, widely used for vocabulary. TCP/IP is the simpler, four-layer model (Link, Internet, Transport, Application) that real, deployed internet protocols actually follow.

Header / payload / PDU

A header is structured metadata a layer adds to the front of its data. The payload is the data being carried. A PDU (Protocol Data Unit) is a layer's header plus payload — called a segment (Transport), packet (Internet), or frame (Link).

Encapsulation / decapsulation

Encapsulation is each layer wrapping data from the layer above in its own header on the way out. Decapsulation is the reverse — each layer stripping its own header on arrival, in the opposite order.

Unit 3 — Addressing the Network

MAC address

A 48-bit identifier permanently assigned by a device's manufacturer to its NIC (Network Interface Card), meaningful only on its local network segment — replaced with a new one at every router hop.

IPv4 address / octet

A 32-bit address, usually written in dotted-decimal notation as four octets (8-bit segments, 0-255) separated by dots, like 192.168.1.14.

Public IP address / private IP address

A public address is globally unique and routable across the open internet. A private address (like 192.168.x.x) is only meaningful inside one local network and is reused across countless separate networks.

Subnet / subnet mask / CIDR notation

A subnet is a subdivision of a larger network. A subnet mask marks the network/host bit split. CIDR notation writes that split compactly as a slash and a bit count, like /24.

Network address / broadcast address / usable hosts

The network address (all host bits 0) identifies the subnet itself; the broadcast address (all host bits 1) reaches every device on it — neither is assignable to one device. Usable hosts = 2^h − 2, where h is the number of host bits.

Address exhaustion

The depletion of the pool of available IPv4 addresses, forcing reliance on smaller reclaimed blocks and address-sharing techniques like NAT.

IPv6 / hextet

The successor address system using 128-bit addresses (roughly 340 undecillion possible addresses), written as eight colon-separated hextets (16-bit groups) instead of IPv4's four octets.

Unit 4 — Getting Packets Where They're Going

Switch / router

A switch operates at the Link layer, forwarding frames within one network using MAC addresses. A router operates at the Internet layer, forwarding packets between separate networks using IP addresses and a routing table.

Default gateway

The specific router a device sends a packet to whenever the destination isn't on its own local network — the exit door to everywhere else.

TTL (Time to Live)

A counter in every IP packet's header, decreased by 1 at every router hop; a router discards a packet whose TTL reaches 0, preventing infinite routing loops.

NAT (Network Address Translation)

A technique, usually performed by a router, that rewrites a private device's source address to the router's shared public address for outgoing traffic, and reverses it for the matching reply.

Domain name / DNS

A domain name is a human-readable name identifying an internet resource. DNS (Domain Name System) is the distributed system that translates domain names into IP addresses.

Resolver / root, TLD, and authoritative servers

A resolver performs a DNS lookup on a device's behalf, querying a root server, then a TLD server, then an authoritative server, each more specific than the last, to find the final answer.

A record / DNS caching

An A record is the DNS record type mapping a domain name to an IPv4 address. Caching is a resolver temporarily storing an answer so a repeated lookup doesn't require repeating the full lookup chain.

Unit 5 — The Transport Layer

Port / well-known ports

A port is a 16-bit number identifying a specific program on a device, used alongside an IP address. Well-known ports (0-1023) are reserved by convention for common services, like 80 for HTTP and 443 for HTTPS.

Multiplexing / demultiplexing

Multiplexing combines multiple conversations onto one shared IP address; demultiplexing sorts incoming traffic back out to the correct program based on its destination port.

TCP / connection-oriented

TCP (Transmission Control Protocol) is connection-oriented and provides reliable, ordered delivery using sequence numbers, acknowledgments, and retransmission of lost data.

Three-way handshake

The fixed SYN / SYN-ACK / ACK message exchange TCP uses to establish a connection and synchronize starting sequence numbers before any data is sent.

UDP / connectionless / datagram

UDP (User Datagram Protocol) is connectionless, with no handshake and no delivery guarantee. Each independently sent chunk of UDP data is called a datagram.

Unit 6 — The Web, Built on Top

HTTP / request-response

HTTP (HyperText Transfer Protocol) follows a strict request-response pattern: the client sends one request (with a method and URL) over an established TCP connection, and the server sends back one response.

HTTP message structure

Every HTTP message has a start line (request line or status line), one or more headers, a required blank line, and an optional body — in that order.

Status code

The three-digit number in a response's status line: 2xx success, 3xx redirection, 4xx client error, 5xx server error.

Stateless / cookie

HTTP is stateless — the server doesn't automatically remember previous requests. A cookie is a workaround: a small piece of data the browser automatically re-sends on every later request to re-prove identity.

HTTPS / TLS / certificate

HTTPS is ordinary HTTP sent over an encrypted connection. TLS (Transport Layer Security) is the protocol performing that encryption, and it verifies the server's identity using a certificate issued by a trusted third party.

API / REST API / endpoint / resource

An API is a defined way for one program to interact with another. A REST API is built on standard HTTP, treating each URL (endpoint) as a resource acted on via HTTP methods (GET, POST, PUT, DELETE).

Unit 7 — Writing Networked Programs

Socket

The operating system's programming interface for network communication — an object code uses to send and receive data, hiding lower-layer details behind simple function calls.

Bind / listen / connect

Bind associates a socket with a local port. Listen (server-only) waits for incoming connections. Connect (client-only) initiates a connection, triggering TCP's handshake for a TCP socket.

Client-server model

A model with fixed, asymmetric roles: a server runs continuously and listens for connections; a client initiates connections and makes requests.

Peer-to-peer (P2P) / peer

A model with no fixed client/server asymmetry — every peer can act as both client and server simultaneously, initiating and accepting connections with other peers.

Unit 8 — Keeping Networks Working & Safe

Firewall / packet filtering

A firewall inspects traffic crossing a network boundary and decides, by rule, whether to allow or block it. Packet filtering is the basic technique of checking header fields (IP address, port, protocol) against those rules.

Allowlist / denylist

An allowlist (default-deny) blocks all traffic except what's explicitly permitted. A denylist (default-allow) permits all traffic except what's explicitly blocked.

Spoofing

Forging a packet's source information, most commonly the source IP address, to make traffic appear to come from somewhere it didn't actually come from.

Sniffing / packet sniffer

Capturing and reading network traffic that isn't addressed to the reader, using a packet sniffer — readable in plain text unless the traffic is encrypted (HTTPS).

Man-in-the-middle attack

An attacker secretly positions themselves between two communicating parties, intercepting (and potentially altering) traffic while both parties believe they're communicating directly.

ping / ICMP

Ping sends a small message to a target and measures whether/how quickly a reply comes back, using ICMP (Internet Control Message Protocol), a diagnostics-focused Internet-layer protocol.

traceroute

A diagnostic tool revealing every router hop to a destination by sending packets with increasing TTL values and reading the ICMP "expired" replies each discarding router sends back.
