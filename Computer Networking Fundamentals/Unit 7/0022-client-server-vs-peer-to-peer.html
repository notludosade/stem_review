Client-Server vs. Peer-to-Peer

Every example so far had one obvious client and one obvious server. That's a design choice, not a law of networking — and the alternative shows up more often than you'd expect.

← Lesson 21 Lesson 23 → Contents Glossary →

Lesson 21's example had a clear asymmetry: one program called listen() and accept() and waited; the other called connect() and initiated. That asymmetry has a name — client-server — and it's been the assumed shape of nearly every example in this entire course. It's worth pausing to name it explicitly, and to meet the alternative model that doesn't share that asymmetry at all.

The client-server model

Definition In the client-server model, roles are fixed and asymmetric: a server runs continuously, listens for connections, and responds to requests; a client initiates connections and makes requests. A web server (Units 6) is a server in this exact sense — always running, always listening on port 80/443, waiting for browsers (clients) to connect. This is the model nearly every example in this course has quietly assumed, because it's also, by far, the most common real-world arrangement.
Why client-server is the default choice Centralizing the server side has real practical advantages: one place to update the software, one place to enforce access rules, one place to keep data consistent and backed up, and a predictable address (that DNS name from Lesson 13) that never changes even as clients come and go constantly. The trade-off is equally real: the server becomes a single point that every client depends on — if it goes down, every client relying on it loses service simultaneously, and its owner bears the full cost of enough capacity to serve every client at once.

The peer-to-peer model

Definition In the peer-to-peer model (P2P), there's no fixed client/server asymmetry — every participating device (a peer) can act as both a client and a server simultaneously, initiating connections to other peers while also accepting connections from them. File-sharing protocols are the classic example: instead of one central server storing an entire file and serving it to every downloader, peers who already have pieces of the file serve those pieces directly to other peers who don't, while simultaneously downloading pieces they're still missing from others.
Worked example: downloading the same file two ways Client-server: 10,000 people download a large file from one company's server. That server's single connection to the internet must supply the full file, potentially 10,000 separate times, and if that server goes offline, nobody can download it anymore, regardless of how many of the 10,000 people already have a full copy sitting on their own machine. Peer-to-peer: those same 10,000 people, once they've downloaded pieces of the file, start serving those pieces to each other directly — the "load" of distributing the file spreads out across many peers instead of concentrating on one server, and the file remains available as long as at least one peer with a complete copy is still online, even if the original source disappears entirely.
Why P2P isn't simply "the better option" P2P trades away exactly the advantages client-server offered: there's no single place to guarantee data is accurate or up to date, no central authority enforcing who can access what, and coordinating "who has which piece of what" across potentially thousands of independent, unreliable peers is a genuinely harder engineering problem than a server just answering requests directly from its own data. P2P shines specifically when the goal is distributing the same content to many participants resiliently and cheaply; it's a poor fit for something like a bank's account balances, where a single, centrally controlled, always-consistent source of truth is exactly what you want.

Check your recall

No peeking back up — answer from memory first, then check.

1. What's the defining asymmetry of the client-server model?

The server listens and waits; the client connects and requests — a fixed, asymmetric relationship.

2. What's the key structural difference in a peer-to-peer network, compared to client-server?

P2P removes the fixed client/server asymmetry — every peer can initiate and accept connections.

3. Why would a bank's account-balance system be a poor fit for a peer-to-peer design?

Centralized consistency and access control are exactly what client-server offers and P2P sacrifices.

4. Fill in the blank: in a peer-to-peer network, each participating device that can act as both client and server is called a ___.

A peer plays both roles at once, unlike the fixed client/server split.
