DNS — Turning Names into Addresses

Nobody types an IP address into a browser. DNS is the system quietly translating the name you typed into the address every earlier lesson in this unit has actually needed.

← Lesson 12 Unit 5, Lesson 14 → Contents Glossary →

Every lesson in this unit has assumed you already know the destination's IP address. In reality, you almost never do — you type a domain name, and something else figures out the address for you, invisibly, in a fraction of a second. That something is DNS, and understanding it means understanding that "typing a website name" is actually two separate network operations stacked on top of each other, not one.

Domain names and the DNS

Definition A domain name is a human-readable name — like example.com — that identifies a resource on the internet without requiring anyone to memorize its numeric IP address. DNS (Domain Name System) is the distributed system that translates domain names into IP addresses on request, functioning as the internet's phone book: you look up a name, and DNS hands back the number to actually dial.

How a lookup actually works

Definition A resolver is the piece of software (usually run by your ISP or a public service like a company's own DNS server) that performs the actual lookup on your behalf. A domain name isn't stored in one single place — DNS is organized hierarchically, and a resolver typically queries a chain of servers, each more specific than the last: a root server (knows only which server handles each top-level domain, like .com or .org), a TLD server (knows which server is authoritative for a specific domain within that top-level domain), and finally an authoritative server for that exact domain, which holds the actual answer.
Worked example: resolving example.com Your device asks its resolver for example.com's IP address. The resolver first asks a root server, which doesn't know the answer but knows which server handles .com domains, and points the resolver there. The resolver then asks that .com TLD server, which doesn't know the exact IP address either, but knows which server is authoritative for example.com specifically, and points the resolver there. Finally, the resolver asks that authoritative server directly, which holds an A record (the specific DNS record type mapping a domain name to an IPv4 address) for example.com, and returns the actual IP address. The resolver hands that address back to your device, and only then does your device have what it needs to actually connect — everything this unit's earlier lessons covered (routing, addressing) happens only after this lookup finishes.
Why DNS is hierarchical instead of one giant lookup table No single server could realistically hold the authoritative answer for every domain name that exists — the internet has hundreds of millions of registered domains, updated constantly. Splitting the responsibility hierarchically means each server only needs to know a small, manageable slice: a root server needs to know only a few hundred top-level domains, not hundreds of millions of individual sites. This is the same "each hop only needs local knowledge" idea Lesson 11 introduced for routing, applied to name lookups instead of packet forwarding.

In practice, this whole multi-step lookup usually takes a few milliseconds, and it's rarely even repeated for the same domain: resolvers cache (temporarily store) answers they've already looked up, for a length of time the authoritative server specifies, so that visiting the same site again shortly after doesn't require repeating the full root-to-authoritative chain.

Check your recall

No peeking back up — answer from memory first, then check.

1. What problem does DNS solve?

DNS is purely a name-to-address translation system, functioning as the internet's phone book.

2. Why is DNS organized hierarchically (root, then TLD, then authoritative server) instead of one giant central lookup table?

Hierarchical delegation lets each server hold only a manageable slice of the total mapping, mirroring how routers only need local, next-hop knowledge.

3. What does a resolver do when it caches a DNS answer?

Caching avoids repeating the multi-step lookup for domains that were already resolved recently.

4. Fill in the blank: the specific DNS record type that maps a domain name to an IPv4 address is called an ___.

An A record is the DNS record type held by the authoritative server, returned at the end of a successful lookup.
