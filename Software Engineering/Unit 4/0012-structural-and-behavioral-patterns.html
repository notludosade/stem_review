Structural and Behavioral Patterns: Adapter, Observer, Strategy

Making incompatible interfaces work together, reacting to change, and swapping behavior without rewriting callers.

← Lesson 11 Lesson 13 → Contents Glossary →

Lesson 11 covered patterns about creating objects. This lesson covers one structural pattern (about how objects are composed together) and two behavioral patterns (about how objects communicate and share responsibility).

Adapter: making incompatible interfaces work together

Why Adapter exists An Adapter wraps an existing class with a different interface, translating calls so it can be used where a specific, different interface is expected — without modifying the original class. It's the same idea as a physical power adapter: it doesn't change what's on either end, it just translates between two incompatible shapes.
Example 
class LegacyLogger:
    def write_log(self, msg):
        print(f"LOG: {msg}")

class LoggerAdapter:
    def __init__(self, legacy_logger):
        self._legacy = legacy_logger
    def log(self, message):  # the interface new code expects
        self._legacy.write_log(message)
New code calls .log(message), the interface it expects, without ever needing to know the underlying logger only understands .write_log(msg). The old class is used entirely unmodified.

Observer: reacting automatically to change

One subject, many automatically-notified observers The Observer pattern lets a "subject" object maintain a list of dependent "observers," and automatically notify all of them whenever its own state changes — without the subject needing to know any specifics about what each observer actually does in response.
Example A StockPrice object changes value, and three unrelated observers registered to it — a chart that redraws, a mobile push notification, and a logging service — each get notified automatically. StockPrice doesn't know or care that three specific things happen in response; it just announces "I changed," and each observer decides its own reaction independently.

Strategy: swapping behavior without rewriting callers

Making an algorithm swappable The Strategy pattern defines a family of interchangeable algorithms behind one shared interface, so the code that uses one can switch between them without any changes to itself.
Hardcoded branching 
def calculate_shipping(order, method):
    if method == "standard":
        return order.weight * 0.5
    elif method == "express":
        return order.weight * 1.5 + 10
    elif method == "overnight":
        return order.weight * 3 + 25
Strategy pattern 
class StandardShipping:
    def calculate(self, order):
        return order.weight * 0.5

class ExpressShipping:
    def calculate(self, order):
        return order.weight * 1.5 + 10

def calculate_shipping(order, strategy):
    return strategy.calculate(order)  # any strategy works here
Why this is better than a branching function Adding a new shipping method with the branching version means editing a growing function and risking every existing branch. With Strategy, adding a new method means adding a new small class — the calling code, calculate_shipping(), never has to change at all.

1. What does an Adapter pattern do?

Adapter is specifically about translating between two incompatible interfaces without changing the original class.

2. In the Observer pattern, what does the subject need to know about its observers?

Observer decouples the subject entirely from what each observer actually does in response to a notification.

3. Why is the Strategy pattern preferable to a large if/elif chain for interchangeable algorithms?

Strategy isolates each algorithm into its own class, so the calling code and other algorithms stay untouched when one is added.

4. Fill in the blank: an ___ wraps an existing class so it matches an interface different calling code expects, without modifying the original.

Adapter is the pattern named for exactly this translation role, like a physical power adapter.

5. Fill in the blank: the ___ pattern lets a subject automatically notify a list of registered dependents whenever its own state changes.

Observer is the behavioral pattern built around one subject broadcasting change to many independent observers.
