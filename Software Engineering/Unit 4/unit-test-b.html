Unit 4 Test — Version B

Design Patterns. 10 points across every lesson in this unit — 5 questions worth 1 point, 5 worth 1 point split across two parts. Score 90% or higher to clear this unit.

1. What does a design pattern actually provide to an engineer, according to Lesson 10?

Patterns name a general shape of solution — the specific implementation still has to be adapted to your language and context.

2. Why do design patterns feel instantly recognizable once you learn them, even before you knew their names?

Patterns are discovered, not invented — they're recognizable because they reflect designs engineers keep independently reaching on their own.

3. A new payment type needs to be added to a system. With a Factory in place, what does adding it actually require?

Centralizing the creation decision in one Factory is exactly what turns "update five copies" into "update one function."

4. Fill in the blank: a Singleton provides one ___ point of access to its single instance, commonly used for things like a shared configuration object or connection pool.

A single, globally accessible point of entry is exactly what makes a Singleton both convenient and, in Lesson 11's warning, risky.

5. Fill in the blank: LoggerAdapter translates calls to .log(message) into the old logger's .write_log(msg), leaving the original LegacyLogger class entirely ___.

Adapter wraps and translates without ever modifying the class being adapted, like a physical power adapter.

6. A team reaches for Singleton any time a class "should probably only exist once" in the program. Answer both parts:

(a) What real cost does this pattern introduce, beyond guaranteeing one instance?

(b) Fill in the blank: dependency injection instead passes the shared instance explicitly as a ___, avoiding the hidden global access point.

Singleton's hidden global access is the exact problem dependency injection avoids by making the shared instance an explicit, visible parameter.

7. A subject object maintains a list of dependent observers and automatically notifies all of them whenever its own state changes. Answer both parts:

(a) What is this pattern called?

(b) Fill in the blank: the subject doesn't know or care what each observer specifically does in response — it just announces the change, and each observer reacts ___.

Observer decouples the subject completely from its observers' individual reactions — it only broadcasts that a change happened.

8. calculate_shipping(order, strategy) calls strategy.calculate(order), where any interchangeable shipping-method class can be passed in as strategy. Answer both parts:

(a) What pattern is this?

(b) Fill in the blank: with this pattern, adding a new shipping method means adding a new small class — the calling code, ___(), never has to change at all.

Strategy defines a family of interchangeable algorithms behind one shared interface, so the caller never needs to change when a new algorithm is added.

9. A math constant like PI = 3.14159 gets wrapped in a full Singleton class, even though it's neither shared mutable state nor expensive to create. Answer both parts:

(a) Why does the plain constant win over the Singleton version here?

(b) Fill in the blank: experienced engineers start from a real, current ___ and only then ask which pattern fits — never the reverse.

Starting from the pattern and searching for a place to use it is the exact overengineering mistake this lesson warns against.

10. This unit covers Factory and Singleton as one category, Adapter as a second, and Observer and Strategy as a third. Answer both parts:

(a) What category does Adapter alone belong to?

(b) Fill in the blank: Factory and Singleton are ___ patterns, since both are about controlling how objects get created.

Creational patterns govern object creation, structural patterns govern composition, and behavioral patterns govern communication between objects.
