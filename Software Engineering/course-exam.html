1. A script that produces the correct output today, but that no one besides its author can safely modify six months from now, is missing what software engineering adds on top of programming?

Engineering adds the dimensions of scale and lifetime — code that only one person will ever read, for one moment in time, doesn't need them; almost no real code stays that way.

2. Fill in the blank: across the software development lifecycle, the phase that consumes the most total time and cost over a system's life is ___, not initial development.

Most of a system's lifetime is spent fixing, extending, and adapting code that already shipped — maintenance dwarfs initial development in aggregate cost.

3. Two engineers each edit a shared file and save their copies back to a plain shared drive, one after the other, with no version control in place. What specifically goes wrong?

Without a system tracking changes, a plain file save has no concept of "someone else changed this since I opened it" — it just overwrites.

4. Fill in the blank: a lightweight, movable pointer to a line of commits, letting work happen in isolation before it's combined with other work, is called a ___.

A branch is just a pointer that moves forward as new commits are made on it — cheap to create, cheap to abandon.

5. A codebase has hundreds of functions touched by dozens of engineers over several years. Why does manually re-checking every existing feature after each change stop being feasible at this scale?

Scale is exactly what breaks manual verification — the number of interactions to re-check grows far faster than the number of engineers available to check them.

6. Fill in the blank: writing a failing test before writing the code that makes it pass, then cleaning up, is a practice called ___ development.

Test-driven development's red-green-refactor cycle starts with a failing test on purpose, before any implementation exists.

7. Where did the Gang of Four's cataloged design patterns actually come from?

Design patterns were catalogued, not invented — they name recurring shapes of solution that kept appearing independently across the industry.

8. Fill in the blank: a design pattern that restricts a class to exactly one instance, with a single global point of access to it, is called ___.

Singleton is the pattern named for exactly that guarantee — only one instance ever exists.

9. A team debates renaming a local variable versus whether two services should share one database or each own their own. Which is the architectural decision, and why?

The reversal test is the distinguishing question: how expensive would it be to undo this decision later? Database ownership is expensive to reverse; a variable rename is not.

10. Fill in the blank: the degree to which one component depends on another component's internal details, such that a change to one forces a change to the other, is called ___.

High coupling means components can't change independently — a core cost architecture tries to minimize.

11. An engineer who is the only person who understands a critical module goes on vacation, and no one else can safely modify it. Which job of code review exists specifically to prevent this kind of situation?

Review's knowledge-spreading effect is a direct antidote to single points of failure like one person being the only one who understands a module.

12. Fill in the blank: prefixing a minor, optional code review comment with "___:" signals to the author that it's not blocking and can be safely ignored or addressed at their discretion.

The "nit:" convention exists to separate small, optional style preferences from comments that must be resolved before merging.

13. The Agile Manifesto favors working software over exhaustive documentation and responding to change over following a rigid upfront plan. What do Scrum and Kanban represent relative to those values?

Agile is a set of values and principles; Scrum and Kanban are two different concrete ways teams choose to put those values into practice.

14. Fill in the blank: in Scrum, work is organized into fixed-length iterations called ___, commonly one or two weeks long, where the team commits to a specific set of backlog work upfront.

The sprint is Scrum's core time-boxed unit of planning and delivery.
