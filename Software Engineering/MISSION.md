# Mission

## Why this course exists

Computer Programming 1 and 2 teach how to write correct code in four languages. Neither course teaches how software actually gets built at scale, by teams, over years — the difference between a program that works once on one machine and a system that stays correct, maintainable, and collaboratively buildable as it grows. That gap is what this course fills: the practices, tools, and vocabulary of professional software engineering, as distinct from programming itself.

## Success criteria

By the end of this course, the learner should be able to:
- Describe the software development lifecycle and explain what each phase is actually for, not just name it
- Use Git confidently: commits, branches, merges, conflict resolution, and pull requests
- Explain why automated testing exists, distinguish unit from integration tests, and write testable code
- Recognize and correctly apply at least a handful of the most common design patterns — and recognize when a pattern is overkill
- Explain the trade-offs between major architectural choices (monolith vs. microservices, coupling and cohesion) and what technical debt actually is
- Participate meaningfully in code review, both giving and receiving feedback
- Explain how Scrum and Kanban structure real team workflows, and trace a single feature from a ticket to production

## Constraints

- Assumes Computer Programming 1 and Computer Programming 2 (syntax, OOP, and core language fluency) as prerequisites — this course does not re-teach language basics.
- Illustrative code examples use a single representative language per example (usually JavaScript or Python) rather than the four-language side-by-side format CP1/CP2 use, since the subject here is engineering practice, not language syntax.
- US/industry-general conventions (Git, GitHub-style pull requests, Scrum terminology) — not tied to any one company's internal process.

## Out of scope

- Deep dives into every Gang-of-Four design pattern — a representative handful, not an exhaustive catalog.
- Specific cloud infrastructure or DevOps tooling (CI/CD pipeline configuration, container orchestration) — this course covers the engineering practices around building software, not deployment infrastructure itself.
- Formal software architecture certification-level depth (e.g., full enterprise architecture frameworks) — this stays at the level a working engineer needs day to day.
