Unit 6 Test — Version B

Code Review and Collaboration. 10 points across every lesson in this unit — 5 questions worth 1 point, 5 worth 1 point split across two parts. Score 90% or higher to clear this unit.

1. A pull request passes every automated test, yet a reviewer still flags that a specific input the ticket describes was never actually handled. What does this illustrate?

A reviewer not anchored to the author's assumptions is more likely to catch a misunderstood requirement no test checks for.

2. A payments module has only ever been touched by one engineer, and no one else on the team can confidently explain how it works. Which job of code review is specifically meant to prevent this?

Without review, understanding of a given part of the codebase concentrates in whoever originally wrote it.

3. Despite having thirty different contributors over several years, a codebase still reads like it follows one coherent set of conventions. What does the lesson credit this to?

Review is where shared conventions get enforced in day-to-day practice, keeping a codebase consistent even with many contributors.

4. Fill in the blank: reasoning "we can skip review this time, the ___ will catch anything important" ignores that review's other two jobs — spreading knowledge and enforcing consistency — don't get covered by that at all.

This reasoning treats review as pure bug-catching, missing its other two jobs entirely.

5. Fill in the blank: a reviewer who wants to flag a minor, optional style preference without blocking the merge will often literally write "___:" at the start of the comment.

"Nit:" is the common convention marking a comment as a minor, optional suggestion.

6. A reviewer's comments on a pull request read: "This SQL query is vulnerable to injection — must be parameterized before merging," and separately, "nit: this file might read a little cleaner with the helper functions moved above the class." Answer both parts:

(a) Which comment is a blocking issue?

(b) Fill in the blank: a reviewer who marks a comment clearly as a nit lets the author use ___ about whether to act on it, without stalling the whole change.

Clearly marking a comment as a nit signals it's the author's judgment call, unlike a blocking issue.

7. One reviewer writes: "You clearly rushed this and didn't test it properly." Another reviewer instead writes: "This loop doesn't handle an empty input list and will throw an IndexError — worth adding a check, or is empty input already handled somewhere upstream?" Answer both parts:

(a) Why is the second comment more effective?

(b) Fill in the blank: the first comment is ___-directed, judging the author instead of describing the code's specific behavior.

Naming a specific behavior and asking rather than asserting makes work-directed feedback more effective.

8. An author gets a comment questioning whether their approach handles a particular edge case correctly. Answer both parts:

(a) What should the author understand this comment to be, per the lesson?

(b) Fill in the blank: neither treating a comment as a personal attack nor as a command to obey blindly serves review's actual goal of correct, ___ code.

A review comment is a check on the code itself, not a judgment of the author's skill.

9. One engineer changes anything a reviewer suggests immediately, without ever asking why. Another engineer reads every comment as an accusation about their ability. Answer both parts:

(a) What does the lesson call these two reactions to feedback?

(b) Fill in the blank: the lesson names ___ — reacting to a code comment as if it were a judgment on you personally — as the biggest failure mode in receiving feedback.

Blind compliance and defensiveness are the two named failure modes; defensiveness is called out as the biggest one.

10. A reviewer suggests restructuring a function the author deliberately wrote a certain way, for a reason the reviewer may not know about. Answer both parts:

(a) What's the recommended way to respond if the author disagrees with the suggestion?

(b) Fill in the blank: silently complying with feedback you believe is wrong doesn't actually serve review's goal of correct, ___ code.

Neither blind compliance nor defensiveness serves review's goal — engaged, reasoned disagreement does.
