Unit 6 Test — Version A

Code Review and Collaboration. 10 points across every lesson in this unit — 5 questions worth 1 point, 5 worth 1 point split across two parts. Score 90% or higher to clear this unit.

1. A reviewer who didn't write a given pull request notices an edge case the author missed, even though every automated test still passes. What does this illustrate about code review's first job?

A reviewer not anchored to the author's assumptions is more likely to catch an edge case or misunderstood requirement no test checks for.

2. An engineer who's the only person who understands a critical module goes on vacation, and no one else can safely modify it. Which job of code review exists specifically to prevent this kind of situation?

Without review, understanding of a given part of the codebase concentrates in whoever wrote it — review continuously spreads that understanding instead.

3. Over time, a codebase reviewed consistently by the same team tends to read as if it were written by one disciplined author, despite having dozens of contributors. Which job of review does this reflect?

Review is where a team's shared conventions get enforced in day-to-day practice, rather than existing only as an unread document.

4. Fill in the blank: a team that treats review purely as bug-catching often skips it under deadline pressure, reasoning "the ___ will catch anything important" — missing that review's other two jobs don't get covered by that reasoning at all.

This reasoning ignores that knowledge-spreading and consistency-enforcement are jobs tests can't do at all.

5. Fill in the blank: many teams prefix an optional, non-blocking review comment with "___:" so the author immediately knows it isn't mandatory before merging.

"Nit:" is the common convention marking a comment as a minor, optional suggestion.

6. A reviewer leaves two comments on a pull request: one says "this will crash on an empty list — needs a null check before merging," and the other says "nit: I'd probably call this variable total instead of sum, but up to you." Answer both parts:

(a) Which comment is the blocking issue?

(b) Fill in the blank: treating every comment as equally mandatory — insisting the variable name change with the same urgency as the crash fix — trains authors to dread or ___ review entirely.

Distinguishing blocking issues from nits keeps review fast and meaningful, rather than paralyzing or being ignored.

7. One reviewer writes: "You clearly didn't think about concurrent access here." A different reviewer instead writes: "This increments the counter without a lock — two concurrent requests could both read the same value before either writes it back. Worth adding a lock, or is there a reason concurrency isn't a concern here?" Answer both parts:

(a) Why is the second version more effective, not just more polite?

(b) Fill in the blank: the first comment is ___-directed, judging the author rather than the code's specific, observable behavior.

Naming the specific behavior and asking rather than asserting is what makes work-directed feedback more effective than person-directed feedback.

8. An author receives a comment questioning a design choice in their pull request. Answer both parts:

(a) According to the lesson, what should the author understand a review comment to be?

(b) Fill in the blank: treating a comment as a personal attack, or as an unquestionable command to blindly obey, both work against review's actual goal — producing correct, ___ code.

A review comment is a check on the code itself, not a judgment of the author's skill.

9. One author reacts to every review comment by silently making the exact change requested without ever asking why. Another author reacts to every comment as if their competence were being attacked. Answer both parts:

(a) What does the lesson call these two reactions?

(b) Fill in the blank: the biggest failure mode this lesson names in receiving feedback is ___ — treating a comment on the code as a judgment on the author.

Blind compliance and defensiveness are the two named failure modes; defensiveness is called out as the biggest one.

10. A reviewer leaves a comment suggesting a different variable name than the one an author chose to match an API response field. Answer both parts:

(a) What's the recommended way for the author to respond, if they disagree with the suggestion?

(b) Fill in the blank: silently complying with a suggestion you think is wrong helps nobody — engaging with reasoning is what actually serves review's goal of producing correct, ___ code.

Neither blind compliance nor defensiveness serves review's goal — engaged, reasoned disagreement does.
