Finding and Reading a Game's Configuration Files

Of everything an unpacked archive contains, config files are the easiest and safest place to start modding — no repacking, no recompiling, just a text editor and a value that already means something to the game.

← Lesson 5 Unit 3, Lesson 7 → Contents Glossary →

Alongside binary textures, models, and audio, most unpacked archives also contain config files — plain, human-readable text in formats like .ini, .cfg, .json, or .xml. These hold exactly the kind of values Lesson 1 called "config tweaks": weapon damage, enemy spawn rates, key bindings, difficulty curves — numbers and settings the game reads at startup or during play, rather than values baked into compiled code.

Definition A human-readable format is one a person can open in a plain text editor and understand directly, as opposed to a binary format, which requires a specialized tool or parser to make sense of — most config files are human-readable by design.

Why config files are the easy on-ramp

This is data-driven design: instead of hardcoding "the sword does 10 damage" directly into compiled game logic, the logic instead reads a variable — damage — from a config file, and that same logic works no matter what number the file holds. Studios build games this way for their own convenience: it lets a designer balance the game by editing numbers instead of asking a programmer to recompile the engine every time a value needs tuning. That same convenience is exactly what makes config files the lowest-risk entry point for a modder — editing a number in a text file can't corrupt a binary format, break a mesh's vertex count, or require any programming knowledge at all. It's also usually the most legally uncomplicated kind of mod, since it changes no copyrighted assets or code, only values.

Why it matters here Unit 4's entire final lesson — balancing and data-driven mods — is built on exactly this technique, scaled up. Learning to recognize a config value and what it controls here is the whole skill; everything later just applies it to bigger, more interesting numbers.

1. Why are config files generally the safest entry point for a new modder?

A plain-text value is edited with nothing but a text editor and can't break a binary format the way a mismatched asset can.

2. What does "data-driven design" mean in the context of a game's damage value?

Data-driven design separates the logic ("read the damage variable") from the specific value, which is exactly what makes that value editable without recompiling.

3. Why do studios build games with data-driven config values in the first place, even before modders get involved?

Data-driven design is primarily a development convenience — modders benefit from it, but studios build this way for their own designers' sake.
