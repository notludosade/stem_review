1. Why does a use-after-free bug (Lesson 9) only sometimes trigger a segmentation fault instead of every single time?

Whether the freed address is still mapped at all decides "garbage value" versus "segfault" — not consistency of the bug itself.

2. Fill in the blank: capturing a crashed process's full memory and register state to a file for later inspection is called writing a ___.

A core dump is that saved snapshot, taken at the exact moment of the crash.

3. What does a breakpoint actually do when a debugger reaches it?

A breakpoint's entire job is pausing execution so real state can be inspected instead of guessed at.

4. Fill in the blank: because ___ places no requirement on a program's result, an optimizing compiler is free to assume it never happens at all.

Undefined behavior's total lack of requirements is exactly what licenses compilers to optimize as if it never occurs.

5. The exact number of bytes a C int occupies varies between compilers, but any one compiler always answers consistently and documents its choice. What category of behavior is this?

A consistent, documented, per-compiler answer without a standard-mandated value is exactly what implementation-defined means.

6. Two loop counters overflow past their maximum value — one is signed, one is unsigned. Answer both parts:

(a) Which one is guaranteed by the C standard to wrap around to a specific, predictable value?

(b) What category of behavior governs the signed counter's overflow instead?

Unsigned overflow wraps predictably by standard guarantee; signed overflow falls into undefined behavior instead, with no such guarantee.

7. An optimizing compiler encounters code whose correctness depends on signed integer overflow actually wrapping around. Answer both parts:

(a) Is the compiler required to preserve wraparound behavior for the programmer's benefit?

(b) What can result from this mismatch between programmer assumption and compiler assumption?

Assuming UB never happens is exactly why an optimizer can produce a program that no longer matches a programmer's wraparound assumption.

8. Rust and Python sit on opposite ends of the systems-vs-managed spectrum in different ways. Answer both parts:

(a) Which language category typically requires the programmer to manage memory lifetime manually?

(b) Which category trades some performance for automatically eliminating whole classes of memory bugs?

Manual lifetime control versus automatic, runtime-enforced safety is the exact axis separating the two categories.

9. Because a managed language automatically reclaims unreachable heap memory, answer both parts:

(a) Can that language still produce a double-free bug the way C can?

(b) What must the garbage collector spend to provide this guarantee?

Removing the explicit free() call removes double-free by construction, but the collector's own work is a real, ongoing cost.

10. A company needs a one-off internal script to reformat a CSV file once a week. Answer both parts:

(a) Which category of language is the better practical fit?

(b) Why?

Low-stakes, non-performance-critical tasks are exactly where a managed language's tradeoffs pay off instead of costing anything.
