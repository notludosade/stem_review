Unit 1 — From Source Code to Running Program

Source code / Machine code

Source code is the human-readable text a program is written in; machine code is the raw binary instructions a processor executes directly. Every language's source must eventually become machine code before a processor can run it.

Compiling vs. interpreting

Compiling translates an entire program into machine code once, ahead of time, producing a standalone executable; interpreting translates and executes source code piece by piece, every single time the program runs.

Compiler

A program that translates source code into machine code (like gcc). In the compilation pipeline's narrower sense, "the compiler" is specifically the stage that turns preprocessed C source into assembly language.

Interpreter

A program — itself already compiled into machine code — that reads and executes another program's source code, or a lightweight intermediate form of it, one piece at a time as it runs.

Executable

A standalone file of machine code, produced by a compiler and linker, that a processor can run directly with no further translation step and no toolchain present.

Preprocessor

The pipeline stage that performs purely textual substitution on source code before any real compiling happens — expanding #include and #define, and resolving #if/#ifdef blocks.

Assembler / Object file

The assembler translates human-readable assembly language into an object file: actual binary machine code that may still reference functions or variables (like printf) defined somewhere else entirely.

Linker

Takes one or more object files, plus any needed libraries, and resolves every outside reference by finding where it's defined and patching in its real address, producing one final executable.

Static library / Dynamic library

A static library is copied directly into the executable at link time; a dynamic library stays a separate file on disk, loaded and linked in only when the program actually runs.

Unit 2 — Memory: Stack and Heap

Process / Address space

A process is a running instance of a program, given its own address space — a range of memory addresses only it can see, laid out into distinct regions by the operating system.

Text segment / Data segment

The text (code) segment holds a program's compiled instructions and is normally read-only; the data segment holds global and static variables with an initial value baked into the executable.

Heap

The address-space region holding memory a program requests dynamically while running, growing upward as more is allocated.

Stack

The address-space region holding local variables and function-call bookkeeping, growing downward as functions call other functions.

Stack frame / Return address

A stack frame (activation record) is a block pushed onto the stack for each function call, holding its locals, parameters, and return address — where execution resumes in the caller once the call finishes.

Stack overflow

Happens when the stack grows past the space reserved for it, most commonly from recursion with no base case; the OS detects it and terminates the program immediately.

Dynamic memory allocation

Requesting a block of memory from the heap while the program is running, of a size decided at run time rather than baked in at compile time — in C, via malloc.

Memory leak

Happens when a program loses every pointer to a heap block without ever calling free on it — the block stays fully reserved, but nothing in the program can reach it to free it later.

Garbage collection

A managed language's background runtime system that periodically scans for heap objects nothing can reach anymore and reclaims them automatically — no explicit free() call, and as a result, no double free or use-after-free — at the cost of real CPU time and occasional pauses.

Unit 3 — Pointers and Addresses

Pointer

A variable whose value is a memory address, declared with an asterisk: int *p declares p as "a pointer to an int."

Address-of operator (&) / Dereference operator (*)

The address-of operator takes an ordinary variable and produces its address; the dereference operator, applied to a pointer, reads (or writes) the value stored at the address it holds.

Pointer arithmetic

Adding or subtracting an integer from a pointer moves the result by that many elements, not bytes — the compiler automatically multiplies by sizeof the pointer's type.

Dangling pointer

A pointer that still holds an address, but the memory at that address is no longer valid to use — because its stack frame was popped, or its heap memory has already been freed. C never clears the pointer's value, so it looks exactly like a valid one.

Use-after-free

Dereferencing a dangling pointer whose memory has already been freed — the result may print stale data, print something else entirely, or crash, unpredictably from run to run.

Double free

Calling free() twice on the same pointer, corrupting the allocator's internal bookkeeping — the result can crash immediately or silently corrupt an unrelated future allocation.

Unit 4 — Data Representation

Unsigned integer

Stores only non-negative values, interpreting its bits directly as a plain binary number.

Two's complement

The representation essentially every modern processor uses for signed integers — the leading bit is weighted negative, and one adder circuit handles both signed and unsigned addition identically.

Integer overflow

Happens when the true mathematical result of an operation needs more bits than the type has, so the result silently wraps around within the fixed bit width available.

Floating-point number (sign / mantissa / exponent)

Stored as three parts mirroring scientific notation: a sign bit, a mantissa (or significand — the significant digits), and an exponent (how far to shift the binary point).

Memory alignment

A hardware requirement, or strong performance preference, that a value of a given size start at an address that's a multiple of its own size.

Padding

Unused filler bytes the compiler silently inserts between struct fields, purely to keep every field's starting address at the correct alignment multiple.

Unit 5 — Processes and the Operating System

Operating system (OS)

The software that manages a computer's hardware resources — CPU, memory, storage, peripherals — and provides a controlled, consistent way for programs to use them.

Kernel

The operating system's core, running with full, privileged hardware access and making the actual resource-allocation decisions; everything else commonly thought of as "the OS" runs on top of it with the same restricted access as any other program.

Program

A static executable file sitting on disk, doing nothing until something runs it — as opposed to a process, its running instance (Unit 2).

Process states (new / ready / running / waiting / terminated)

A process's life cycle: created (new), able to run but waiting for CPU time (ready), actually executing (running), waiting on something slow like disk I/O with the CPU freed for other work (waiting), and finished (terminated).

User mode / Kernel mode

User mode is the restricted privilege level ordinary program code runs in, unable to directly touch hardware; kernel mode is the OS kernel's full, unrestricted privilege level.

System call

A controlled, deliberate request that switches the CPU from user mode into kernel mode for a moment, lets trusted kernel code perform a privileged operation on the program's behalf, then switches back.

System call categories (file I/O / process control / memory management)

File I/O covers open/read/write/close; process control covers fork (create a process) and exit (terminate one); memory management covers requesting more address space from the OS, what malloc ultimately relies on.

Unit 6 — Concurrency

Thread

An independent sequence of instructions the CPU can schedule and run, existing inside a process; every process has at least one.

Multithreaded

Describes a process with more than one thread running inside it, each with its own stack and registers, but sharing the process's heap, data segment, and open files.

Race condition

A bug where a program's correctness depends on the precise timing or interleaving of operations across multiple threads, so the outcome differs depending on uncontrolled execution order.

Mutex

A mutual exclusion lock: an object one thread can lock before touching shared data, and must unlock afterward.

Lock / unlock / blocks

Locking a mutex claims it; unlocking releases it; a thread that tries to lock a mutex another thread already holds blocks — pauses and waits — until it's unlocked.

Critical section

The block of code between lock and unlock — the shared-data operation that needs to run as one uninterrupted unit.

Deadlock

Happens when two or more threads are each waiting on a lock the other one holds, and neither can ever proceed — a program can be perfectly race-free and still hang permanently this way.

Unit 7 — The CPU and Machine Code

Register

A small storage location built directly into the CPU itself — a processor has only a few dozen, each dramatically faster to access than RAM since there's no memory bus to cross.

ALU (arithmetic logic unit)

The CPU component that actually performs arithmetic and logic operations on values held in registers, writing the result back into a register.

Program counter (PC) / Fetch-decode-execute cycle

The program counter is the register holding the next instruction's address; the fetch-decode-execute cycle is the CPU's endlessly repeating job of fetching that instruction, decoding it, and executing it before advancing the PC.

Mnemonic / Operands

A mnemonic is a short, human-readable name (like mov or add) standing in for one machine instruction; operands are the registers or values that instruction acts on.

Calling convention

A fixed, agreed-upon rule compilers follow for which registers hold a function's arguments and return value, with no explicit statement needed in the source code.

Memory hierarchy

The layered set of storage a CPU can reach, trading size for speed at every step: registers → cache → RAM → disk.

Cache / Cache line

A cache is small, very fast memory that automatically keeps recently and nearby-used data close to the CPU; a cache line (commonly 64 bytes) is the fixed-size chunk memory actually moves in between RAM and cache.

Spatial locality / Temporal locality

Spatial locality is the tendency to access nearby memory addresses close together in time (like walking an array); temporal locality is the tendency to reuse the exact same address again soon (like a loop counter).

Unit 8 — Putting It Together

Segmentation fault ("segfault")

Happens when a process tries to access memory outside its own valid address space; the kernel detects the illegal access and immediately terminates the process.

Core dump

An optional file the OS can write at the moment of a crash, capturing the process's full memory and register state for later inspection.

Breakpoint

A marker that pauses a running program at a specific line, handing control to the programmer instead of letting it run to completion or to a crash.

Backtrace

A list of every currently active stack frame, showing the exact chain of function calls that led to the current point, innermost call first.

Undefined behavior (UB)

Any operation the C standard places absolutely no requirement on — anything is a conforming result — and which the compiler is entitled to assume never happens, including signed integer overflow, out-of-bounds writes, and dereferencing dangling or null pointers.

Implementation-defined behavior

Behavior the standard requires each compiler to handle with one specific, documented, consistent answer — like the exact byte size of an int — even though the standard itself doesn't dictate which answer.

Systems programming language

A language like C, C++, or Rust giving the programmer direct, manual control over memory layout and object lifetime, with no runtime safety net, in exchange for predictable, minimal-overhead performance.

Managed language

A language like Python, Java, JavaScript, or Go that inserts a runtime automatically enforcing safety — bounds checking, automatic memory reclamation — trading some performance and control for eliminating entire categories of bugs.
