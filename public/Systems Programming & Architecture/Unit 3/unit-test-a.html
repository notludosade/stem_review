1. What is a pointer, fundamentally?

A pointer is an ordinary variable that happens to store an address.

2. Fill in the blank: following a pointer to the address it holds, in order to read or write the value stored there, is called ___.

The * operator dereferences a pointer, following it to its target's actual value.

3. Given int x = 5; int *p = &x; *p = 20;, what does x equal afterward?

Writing through *p modifies x's own storage directly.

4. Fill in the blank: adding an integer to a pointer, moving it by whole elements (scaled by the pointed-to type's size) rather than raw bytes, is called ___.

Pointer arithmetic automatically scales by sizeof the pointed-to type.

5. What is arr[3] equivalent to, given int arr[10]?

Array indexing and pointer arithmetic compile to identical machine code in C.

6. A C program accesses arr[20] on a 5-element array. Answer both parts:

(a) Does C check that 20 is a valid index before performing the access?

(b) What happens as a result is best described as...

Out-of-bounds access is undefined behavior in C — no guaranteed single outcome.

7. Fill in the blank: a pointer that still holds an address, but whose target memory is no longer valid to use, is called a ___ pointer.

Dangling pointers look identical to valid pointers, holding the same address, but the underlying memory is no longer good.

8. Why is a use-after-free bug's behavior unpredictable from run to run?

Whatever else has since claimed that freed memory determines the result, and that's not guaranteed to be consistent.

9. What goes wrong when free() is called twice on the same pointer?

Double free corrupts allocator state, since it isn't designed to be told the same block is free twice.

10. Fill in the blank: a common defensive habit is to set a pointer to ___ immediately after freeing it, so a later dereference crashes loudly and obviously instead of silently misbehaving.

NULL-after-free turns a silent, unpredictable bug into a loud, obvious one — for that one variable.
