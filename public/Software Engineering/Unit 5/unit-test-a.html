Unit 5 Test — Version A

Software Architecture. 10 points across every lesson in this unit — 5 questions worth 1 point, 5 worth 1 point split across two parts. Score 90% or higher to clear this unit.

1. A team debates whether to rename a local variable, versus whether two services should share one database or each own their own. Which of these is the architectural decision, and why?

Cost of reversal, not perceived importance, is the defining test for whether a decision is architectural.

2. Lesson 13 taught that unclear speculative flexibility usually isn't worth building upfront (YAGNI), since it's cheap to add later. Why doesn't that same reasoning let a team skip careful upfront thought about architecture?

The high cost of reversing an architectural decision is exactly why it gets more upfront care than an ordinary implementation choice.

3. Two companies build similar products. One picks a monolith, the other microservices, and both are making the right call for their own situation. What does this best illustrate?

Architectural decisions exist to serve a specific system's constraints, not to chase one universally "correct" structure.

4. Fill in the blank: an architecture that builds an entire application as a single, unified codebase, deployed and run as one unit, is called a ___.

A monolith runs every part of the system in the same process, deployed as one unit.

5. Fill in the blank: because microservices communicate over a ___ instead of direct in-process function calls, splitting a system introduces new failure modes a monolith never has to plan for.

Network calls between services can fail in ways an in-process function call structurally cannot.

6. A four-person startup, six weeks into building its first product, is deciding on architecture. No two teams are blocked on the same shared code, and no part of the system has a scaling need different from the rest. Answer both parts:

(a) According to the lesson's decision framework, which architecture fits this situation right now?

(b) Fill in the blank: the right question is never which approach is more modern — it's which specific ___ the system actually has right now.

Real, current constraints — not trend or popularity — should drive the monolith-versus-microservices trade-off.

7. A class directly opens a connection to a specific MySQL server and writes raw SQL against the exact inventory table schema, all inside its own method. Answer both parts:

(a) What does this reveal about the class's coupling to the database?

(b) Fill in the blank: rewriting the class to depend only on an object with a decrement() method, with no knowledge of what database is behind it, makes the class loosely ___.

Depending only on a small, stable interface instead of another component's internal details is what loose coupling means.

8. A single class named UserManager handles user authentication, sends marketing emails, and generates PDF invoices. Answer both parts:

(a) What does this reveal about the class's cohesion?

(b) Fill in the blank: splitting this class into Authenticator, EmailSender, and InvoiceGenerator gives each class one clear, ___ job.

Splitting unrelated responsibilities into separate classes is what raises cohesion — each piece gets one clear purpose.

9. A teammate asks how coupling and cohesion relate to the broader idea of separation of concerns. Answer both parts:

(a) What's the correct relationship?

(b) Fill in the blank: separation of concerns is the principle that each part of a system should be responsible for one distinct ___, with clear boundaries between them.

Coupling and cohesion are the concrete, checkable signals underneath the broader separation-of-concerns principle.

10. A team hardcodes a single tax rate to ship two weeks earlier for an important launch, fully aware they'll need to generalize it once the product expands internationally. Answer both parts:

(a) What kind of technical debt is this, and why?

(b) Fill in the blank: unlike this deliberate case, debt that accumulates from vague requirements or an untested regression nobody noticed is called ___ debt.

Deliberate debt is chosen and tracked; accidental debt accumulates without anyone deciding to take it on, which makes it more dangerous.
