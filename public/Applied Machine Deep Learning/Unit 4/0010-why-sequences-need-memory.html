Why Sequences Need Memory

Unit 3 built an architecture around an assumption that fit images: spatial locality and translation invariance. Text, audio, and time series break that assumption in a specific way — order itself carries meaning, and nothing about a CNN or a plain fully-connected layer is built to track it.

"The dog bit the mail carrier" and "The mail carrier bit the dog" use exactly the same six words. A bag-of-words representation — treating a sentence as an unordered collection of words, ignoring order entirely — produces the identical representation for both, despite them describing opposite events. Any model built only from Unit 1 and Unit 3's tools, applied naively to text, inherits this same blindness unless something is specifically added to track order.

Python — the problem, made concrete 
from collections import Counter

sentence_a = "the dog bit the mail carrier".split()
sentence_b = "the mail carrier bit the dog".split()

bag_a = Counter(sentence_a)
bag_b = Counter(sentence_b)

print(bag_a == bag_b)   # True — identical bag-of-words, opposite meaning

There's a second, separate problem beyond order: sentences have variable-length input. Unit 1's weight matrices and Unit 3's convolutional filters both assume a fixed input shape — a fixed number of pixels, a fixed number of features. A 4-word sentence and a 40-word sentence can't both feed cleanly into the same fixed-size fully-connected layer without padding or truncating, which is a workaround bolted on afterward, not something the architecture handles natively. A genuine sequence model needs to process elements one at a time, in order, carrying forward whatever it's learned from earlier elements — and needs to do that regardless of how long the sequence happens to be.

Definition A bag-of-words representation treats input as an unordered collection, discarding sequence order entirely. Variable-length input means different examples can have different numbers of elements, unlike a fixed-size image or feature vector. A sequence model is built to process elements in order, one at a time, regardless of how many there are.
Why padding a sentence to a fixed length doesn't actually fix the order problem Padding every sentence out to, say, 40 words and feeding the result into a fully-connected layer solves the variable-length problem well enough — but it does nothing for order. That fixed-size layer still has one independent set of weights per word position, with none of Unit 3's weight sharing built in: "dog" appearing in position 2 and "dog" appearing in position 15 would be handled by completely unrelated weights, learned separately, with nothing forcing the network to recognize them as the same word. Sequence models fix both problems together, deliberately — Lesson 11 is exactly that fix.

2. What problem does padding every sentence to a fixed length solve, and what does it leave unsolved?

3. Why does a fully-connected layer over a padded, fixed-length sentence still fail to recognize the same word in two different positions as related?

Without something like Unit 3's parameter sharing applied across time steps, position-specific weights learn independently of each other.
