Transfer Learning and Fine-Tuning

AI Developer's Unit 6 covered fine-tuning versus RAG for an LLM accessed through an API — weights you can't see, let alone choose which ones update. This lesson is about a network you trained yourself, where that choice is completely explicit, layer by layer.

← Lesson 16 Lesson 18 → Contents Glossary →

Transfer learning starts from a network already trained on a large, different dataset instead of training from scratch. For a CNN (Unit 3), this works because of what Lesson 9's receptive field argument implied: early convolutional layers tend to learn genuinely generic features — edges, corners, color gradients, simple textures — useful for almost any visual task, while later layers learn increasingly task-specific combinations of those features. A network trained on a million general photos has already learned those early-layer basics; a new, smaller, more specific dataset doesn't need to re-teach them.

Python — PyTorch, two different transfer strategies 
import torchvision.models as models
import torch.nn as nn

model = models.resnet18(weights='IMAGENET1K_V1')   # pretrained on ImageNet

# Strategy 1: feature extraction -- freeze everything pretrained
for param in model.parameters():
    param.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, num_classes)   # only this new layer trains

# Strategy 2: fine-tuning -- unfreeze the later layers too, train with a small LR
for param in model.layer4.parameters():
    param.requires_grad = True
optimizer = torch.optim.Adam([
    {'params': model.layer4.parameters(), 'lr': 1e-5},   # small — don't wreck pretrained features
    {'params': model.fc.parameters(), 'lr': 1e-3},        # larger — this part is brand new
])

Feature extraction freezes every pretrained weight and trains only a new head attached on top — fast, needs little data, and works well when the new task is visually similar to what the pretrained model already saw. Fine-tuning goes further, unfreezing some of the later pretrained layers so they can adjust too, for tasks that differ more from the original training data. The learning rate on unfrozen pretrained layers is deliberately kept small — a large update could wreck weights that already encode something genuinely useful, a failure called catastrophic forgetting: aggressively training on new data overwrites what the network already knew, instead of building on it.

Definition Transfer learning starts from a network already trained on a different, usually larger dataset. Feature extraction freezes all pretrained weights and trains only a new head. Fine-tuning also unfreezes some pretrained layers, typically with a small learning rate. Catastrophic forgetting is losing previously learned, useful weights by updating them too aggressively on new data.
Why the choice depends on how similar — and how large — the new dataset is A small new dataset, similar to the pretrained model's original data, favors feature extraction: there isn't enough new data to safely retrain deeper layers without overfitting (Unit 2), and the pretrained features already fit well. A larger new dataset, or one meaningfully different in domain (medical scans versus everyday photos, for instance), can afford — and often needs — fine-tuning further into the network, since the pretrained model's task-specific later layers may not transfer as cleanly as its generic early ones. Dataset size and similarity, not a fixed rule, decide how deep to unfreeze.

1. Why do early CNN layers transfer well to a completely new visual task?

Generic low-level features like edges are broadly useful, unlike a later layer's task-specific combinations of them.

2. What is the key difference between feature extraction and fine-tuning?

Feature extraction keeps the pretrained network entirely fixed; fine-tuning allows some of it to keep learning.

3. Why is the learning rate kept small when fine-tuning unfrozen pretrained layers?

Small updates let pretrained weights adjust gently instead of being aggressively overwritten.
