Ports and Multiplexing

An IP address gets data to the right computer. It says nothing about which of the dozens of programs running on that computer should actually receive it — that's a separate address, one layer up.

← Lesson 13 Lesson 15 → Contents Glossary →

Right now, your computer is probably running a browser with several tabs open, a video call, a background sync tool, and an email client — all sending and receiving data over the internet, at the same time, over the same single network connection and the same single IP address. Unit 3's addresses can't distinguish between any of these; they only get data to the right device. This lesson is the piece that finishes the job: getting data to the right program.

Ports

Definition A port is a 16-bit number (0 to 65,535) that identifies a specific program or service on a device, used alongside an IP address to fully address a network conversation. Every Transport-layer connection is really identified by the combination of an IP address and a port number together — the IP address says which device, and the port says which program on that device.
An apartment building analogy An IP address is like a building's street address — it gets mail to the correct building, but says nothing about which apartment inside. A port number is the apartment number: the same street address serves many different apartments, each receiving only the mail addressed specifically to it. A letter addressed to "123 Main St." with no apartment number would leave the building's front desk with no idea which resident it's for — exactly the problem a port number solves for network traffic arriving at one IP address serving many different programs.

Multiplexing: many conversations, one connection

Definition Multiplexing is the process of combining multiple separate conversations onto one shared connection (or, in this context, one shared IP address), and demultiplexing is sorting an incoming stream of traffic back out to the correct individual program based on its port number. Your device's Transport layer demultiplexes every arriving segment by looking at its destination port and handing it to whichever program is listening on that specific port.

Well-known ports

Definition Well-known ports are a reserved range (0-1023) of port numbers assigned by convention to specific, common services, so that a client doesn't need to be told in advance which port to connect to for a standard service. A web browser, for example, always tries port 80 for plain HTTP and port 443 for HTTPS (Lesson 19) by default, without a human ever needing to specify it.

Why well-known ports matter for interoperability Imagine every web server picked a random port number for HTTP. Every browser would need to somehow discover the right port before it could even ask for a web page — an extra lookup step for literally every connection, for every website, every time. By convention, "web servers listen on port 80 (or 443 for HTTPS)" is simply assumed by every browser and every web server in existence, eliminating that discovery step entirely. This is exactly the same kind of pre-agreed rule Lesson 1 described as the essence of a protocol — just applied to "which door to knock on" instead of "how to format the message."
Worked example: three simultaneous connections, one IP address Your laptop (IP address 203.0.113.9, after NAT) has a browser tab open to a website (using local port 51772, connecting to the server's port 443), a video call running (local port 54210), and an email client checking for new mail (local port 58901). All three share the exact same IP address. When a reply arrives at your laptop, the Transport layer looks at which local port the reply is addressed to and hands it to the correct program — the browser never sees the video call's traffic, and vice versa, even though all three shared the same underlying IP address the entire time.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does a port number identify, on top of what an IP address already identifies?

An IP address identifies the device; a port number identifies which program on that device the data belongs to.

2. In the apartment building analogy, what does the port number represent?

IP address = street address (the building); port number = apartment number (the specific resident within it).

3. Why do web browsers not need to be told which port to connect to for a standard website?

Well-known ports are a pre-agreed convention that eliminates the need for a separate port-discovery step.

4. Fill in the blank: a 16-bit number identifying a specific program on a device, used alongside an IP address, is called a ___.

A port lets multiple programs on the same device share one IP address without their traffic getting mixed up.
