1. A traversal algorithm places the line that records a node's value between its two recursive calls (visit left subtree, record node, visit right subtree). Which traversal order is this, and what would moving that line above both calls produce instead?

Recording the value between the two recursive calls is exactly in-order; moving it above both calls turns it into pre-order.

2. Fill in the blank: pre-order, in-order, and post-order are three depth-first variants of visiting every node in a tree, collectively called a ___.

All three variants share this same name, differing only in when the current node is visited.

3. A depth-first recursive traversal naturally tracks a single path from root to one deep node. Why doesn't that make it suitable for grouping nodes by depth the way level-order traversal does?

A queue's discovery-order processing is exactly what gives level-order traversal its depth-by-depth structure.

4. Fill in the blank: every node popped during round k of level-order traversal is exactly k steps of depth from the root — this round-by-round discovery order is exactly what a ___ provides.

First in, first out is exactly the order level-order traversal needs.

5. When a recursive BST validator moves into a node's right child, how does the valid (min, max) range change?

Everything in the right subtree must be greater than the current node, so the current node's value becomes the new floor.

6. Consider the tree with root 7 (left child 4, right child 9), where 4 has left child 2 and right child 6. Answer both parts:

(a) What is the post-order traversal of this tree?

(b) Fill in the blank: the pre-order traversal of this same tree is 7, 4, 2, 6, ___.

(a) Post-order visits both subtrees before the node itself: the left subtree in post-order (2, 6, 4), then the right subtree (9), then finally the root (7), giving 2, 6, 4, 9, 7. (b) Pre-order visits the node first: 7, then its left subtree in pre-order (4, 2, 6), then its right subtree (9).

7. Using the same tree (root 7; left child 4 with children 2 and 6; right child 9, a leaf), answer both parts:

(a) What does level-order traversal return?

(b) Fill in the blank: during the third round (level 2), the queue's captured levelSize is ___, since exactly two nodes (2 and 6) are processed that round.

(a) Level 0 holds just the root (7); level 1 holds its two children (4, 9) in the order they were enqueued; level 2 holds only node 4's two children (2, 6), since node 9 is a leaf. (b) levelSize is captured as the queue's length before the round's loop starts — with exactly 2 and 6 in the queue at that point, levelSize is 2.

8. Consider the tree root=5 (left child 4, right child 6), where 6 has left child 3 and right child 7. Answer both parts:

(a) What happens when checking node 6's left child (3) using the (min, max) range approach?

(b) Fill in the blank: a naive check comparing each node only to its immediate children would wrongly call this tree ___, since 3 < 6 < 7 looks fine locally.

(a) Node 6 inherits the range (5, ∞) from being root 5's right child; passing that down, node 3 must satisfy 5 < 3, which is false, so the recursive range check correctly rejects the tree. (b) The naive immediate-children check only sees node.left(3) < node(6) < node.right(7), which holds, so it would incorrectly call the tree valid.

9. Consider the tree root=3 (left child 5, right child 1), where 5's children are 6 and 2, and 2's children are 7 and 4. Trace the LCA algorithm for p=5, q=4. Answer both parts:

(a) What happens at the very first recursive call into node 5?

(b) Fill in the blank: since node 5's branch returns node 5 itself, and node 1's branch returns null, the final lowest common ancestor of 5 and 4 is node ___.

(a) The base case (root is p or q) triggers before any recursion into children, so node 5 returns itself immediately — this is what lets a node serve as its own ancestor when the problem calls for it. (b) Node 5's non-null result is the only one surviving at the root, making node 5 the final LCA — correct, since node 4 does sit inside node 5's own subtree.

10. For the path 5 → 4 → 11 → 7 (each step a parent-to-child edge) with target sum 22, answer both parts:

(a) Trace the running "remaining target" as the path descends. What is the remaining target upon reaching leaf node 7, and does this path sum to the target?

(b) Fill in the blank: this problem and lowest common ancestor share the same recursive shape — a base case, a recursive call into each child, and a ___ step that merges what both children returned.

(a) Subtracting each node's value in sequence (22→17→13→2→−5) overshoots past zero rather than landing on it exactly, so this particular path fails to sum to 22 — a different path in the same tree (5→4→11→2) does work. (b) "Combining" names the shared step both problems rely on, even though what gets combined differs — an ancestor check for LCA, a target comparison for path sum.
