1. At a high level, what does an exchange argument prove about a greedy algorithm?

The core move is showing a hypothetical optimal solution can be nudged toward greedy's choices one swap at a time without ever getting worse, which forces greedy's solution to match optimal quality.

2. Why does "always pick the shortest available interval" fail as a greedy rule for interval scheduling, unlike "always pick the earliest finish time"?

A direct counterexample (a blocking short interval versus two better non-overlapping longer ones) refutes the underlying exchange step, which is exactly the sign a greedy rule is wrong rather than merely unproven.

3. Why does Kruskal's algorithm use Union-Find rather than a full graph traversal to decide whether to include a candidate edge?

Two vertices already in the same Union-Find set are already connected, so joining them again would close a cycle — a query Union-Find answers far cheaper than repeating a full traversal after every candidate edge.

4. What does the cut property state?

The cut property is specifically about the minimum-weight edge crossing a given cut being forced into every MST — the fact both Kruskal's and Prim's exploit at every step.

5. Fill in the blank: the key lemma in Huffman's proof shows that in some optimal tree, the two ___-frequent symbols are siblings at the maximum depth.

This lemma is exactly what licenses Huffman's first greedy move — merging the two least-frequent symbols — as consistent with some optimal solution.

6. Consider four intervals given as [start, finish]: I1=[1,3], I2=[2,5], I3=[4,7], I4=[6,9]. Using the earliest-finish-time greedy rule, answer both parts:

(a) Which interval does the greedy algorithm select first, and why?

(b) Fill in the blank: after selecting I1, the next interval greedy selects (the earliest-finishing interval that starts no earlier than I1 finishes) is I___.

(a) Earliest-finish-time greedy compares finish times directly; I1 finishes at 3, earlier than I2 (5), I3 (7), and I4 (9). (b) I2 starts at 2, before I1's finish at 3, so it conflicts and is skipped; I3 starts at 4 ≥ 3, so it's the next valid pick, giving the optimal 2-interval solution {I1, I3}.

7. Run Prim's algorithm starting at vertex A on this graph: edges A–B=4, A–C=1, B–C=2, B–D=5, C–D=8. Answer both parts:

(a) Which edge does Prim's algorithm add first, and why?

(b) Fill in the blank: after A and C are both visited, the next edge Prim's adds is the minimum-weight edge crossing the boundary, which is B–C with weight ___.

(a) Prim's picks the minimum-weight edge crossing (visited, unvisited); with visited={A}, A–C=1 is smaller than A–B=4. (b) With visited={A,C}, the crossing edges are A–B=4, B–C=2, C–D=8; the minimum is B–C=2, so B joins next.

8. Answer both parts about Kruskal's and Prim's algorithms:

(a) For a sparse graph (E close to V), which statement about their runtimes is correct?

(b) Fill in the blank: if a graph has tied edge weights, Kruskal's and Prim's may output different-looking spanning trees, but both are still valid MSTs because only the total ___ of an MST is guaranteed unique, not its exact edge set.

(a) Both algorithms are close to Θ(E log V) in practice; the choice usually comes down to graph density rather than a fundamental asymptotic gap. (b) An MST's total weight is always unique; the exact edges are only guaranteed unique when no weights tie.

9. Answer both parts about the cut property and the two MST algorithms:

(a) How is Kruskal's algorithm, at the moment it considers an edge e connecting two different components, an instance of the cut property?

(b) Fill in the blank: Prim's algorithm applies the cut property using the cut (visited, unvisited), while Kruskal's applies it using the cut (one connected ___, everything else).

(a) At that moment, e is exactly the minimum-weight edge crossing the cut (u's component, everything else), satisfying the cut property's hypothesis directly. (b) The two algorithms differ only in which cut they happen to examine at a given step — Kruskal's uses connected components, Prim's uses visited-versus-unvisited.

10. Build a Huffman tree for symbols with frequencies W:2, X:3, Y:6, Z:10. Answer both parts:

(a) Which two nodes does the algorithm merge first?

(b) Fill in the blank: after merging W and X into a node of weight 5, then merging that node with Y into a node of weight 11, the final merge combines that node with Z (10) into the root, giving Z a codeword length of ___ bit(s).

(a) Huffman always merges the two smallest available weights first: W(2) and X(3). (b) Z, merged last at the root, sits at depth 1 — the shortest possible codeword, appropriate for the most frequent symbol — while W and X end up at depth 3, each requiring 3 bits.
