Versioning and Rollbacks

Lesson 26 gave you a way to notice something has gotten worse. This lesson is about what actually happens the moment it does.

Lesson 28 → Contents Glossary →

Every lesson in Unit 6 wrote model="gpt-4o-mini" — a name, not a fixed version. Providers periodically update what that name points to behind the scenes, which means the exact same code can start behaving differently with no change on your end at all. Version pinning means using an exact, dated model snapshot instead of a name that can silently shift underneath you, so behavior only changes when you deliberately choose to change it.

Python — pinning and rollback 
PROMPT_VERSIONS = {
    "v1": 'Classify urgency as "low", "medium", or "high". Reply with JSON.',
    "v2": 'Classify urgency as "low", "medium", or "high", erring toward '
          '"high" for anything mentioning data loss or security. Reply with JSON.',
}

ACTIVE_VERSION = "v2"
PINNED_MODEL = "gpt-4o-mini-2024-07-18"   # exact snapshot, not the movable "gpt-4o-mini" alias

def rollback():
    global ACTIVE_VERSION
    ACTIVE_VERSION = "v1"

PINNED_MODEL locks in an exact model snapshot, so nothing changes unless the code itself is edited. PROMPT_VERSIONS applies the same idea to the prompt: each version is kept, named, and never overwritten, so switching ACTIVE_VERSION back to "v1" is a rollback — reverting to a previous known-good version the instant monitoring flags that a new one regressed — rather than trying to hastily patch the new version under pressure. Real deployments often go further and roll out a new version to a small fraction of traffic first, comparing it against the old one before switching everyone over.

Definition Version pinning is using an exact, fixed model or prompt version instead of one that can change silently over time. A rollback is reverting to a previous known-good version once a new one is found to have regressed.

Check your recall

1. Why pin an exact model snapshot instead of using a movable name like "gpt-4o-mini"?

An unpinned alias can point to a different underlying model over time, changing behavior with no code change.

2. What does rollback() actually do?

It simply switches ACTIVE_VERSION back to "v1", reverting to the previous prompt without touching the model.

3. Why keep PROMPT_VERSIONS as a dictionary of every version, rather than overwriting the prompt in place?

Overwriting the only copy of a prompt would make rollback impossible once a regression is caught.
