Unit 5 Test — Version B

Bias & Fairness in Algorithms. 10 points across every lesson in this unit — 5 questions worth 1 point, 5 worth 1 point split across two parts. Score 90% or higher to clear this unit.

1. Fill in the blank: a program can produce a systematic, unfair difference in treatment across groups even when not a single line of code mentions group membership — this is called ___ ___.

This commonly enters through historical data, a design choice, or a narrow set of testers — not necessarily through anyone's intent.

2. Which of these is one of the three common entry points for bias into a program, as described in this unit?

Biased training data is one of the three named entry points, alongside biased rules and biased testing.

3. Fill in the blank: a lending policy that never mentions race but rejects one racial group at a far higher rate than others demonstrates ___ ___, regardless of what anyone intended.

No intent is required — only a measurable gap in outcomes between groups.

4. A teammate argues that building a demographic evaluation set for fairness testing directly violates the "collect only what you need" principle from Lesson 7. What's the resolution this unit describes?

Collecting demographic data for a separate evaluation set is a different decision than what a production pipeline gathers from every user.

5. A developer insists a "first_name" field can't possibly be a proxy for a protected characteristic because it's just a name. What's the flaw in that reasoning?

A proxy relationship is invisible from the field name alone — it has to be measured against real outcomes.

6. Answer both parts about the shipping-eligibility example from this unit:

(a) Fill in the blank: the variable that ended up correlating with income and, in many U.S. cities, race — despite being chosen only for warehouse-proximity reasons — was ___ ___.

(b) What did the fixed version of the process do that the original skipped?

(a) Zip code was built for an operationally defensible reason but still correlated with income and race. (b) Measuring real-world coverage against census data is what surfaced the gap — the code itself didn't need to change to reveal it.

7. Answer both parts about a test suite for a hiring-recommendation model:

(a) Fill in the blank: a standard test only checks ___ — whether the function returns the expected output on its given test cases — which says nothing about whether that accuracy holds evenly across groups.

(b) Why is it possible for this kind of test suite to pass 100% and still ship an unfair system?

(a) Correctness is the narrower of the two questions a test suite can ask. (b) A passing suite only proves what it was actually designed to check.

8. Answer both parts about strengthening a correctness-only test suite:

(a) Fill in the blank: a fairness-aware test iterates over several ___ test sets and asserts that accuracy for each one clears a minimum acceptable bar.

(b) What happens in the fixed test if one group's accuracy falls below the minimum threshold?

(a) Looping across demographic test sets is what lets a gap for any one group get caught. (b) Failing loudly, with the specific group named, is what turns a hidden gap into something a team can actually fix before release.

9. Answer both parts about proxy variables:

(a) Which best defines a proxy variable?

(b) Fill in the blank: shopping category history, first name, and years at current address are all examples this unit gives of possible ___ variables.

(a) The correlation with a protected characteristic, not any label, is what makes a field a proxy. (b) Each of these can predict a protected characteristic closely enough to reproduce its effect.

10. Answer both parts about the credit-scoring example in this unit:

(a) Fill in the blank: dropping the "race" field from the list of fields used for credit scoring is necessary, but not ___ on its own.

(b) What's the well-intentioned mistake teams make when they rely only on dropping the protected field?

(a) Removing the field is a real step, just not a complete one. (b) A true statement ("we don't collect race") can still coexist with a discriminatory outcome produced through proxies.
