1. What does the recursive case do in a recursive function?

factorial(n) calling factorial(n - 1) is the recursive case — each call works on a strictly smaller input than the last.

2. Which best defines recursion?

factorial calling itself on n - 1, fibonacci calling itself on n - 1 and n - 2, and merge sort calling itself on each half are all this same idea.

3. What happens to a function's call frame the moment that function returns?

Popping the frame is what lets execution resume exactly where it left off in the call that made this one.

4. What does Python specifically raise when recursion exhausts the call stack?

Each language names its own version of this failure differently: Python's is RecursionError specifically.

5. What error does JavaScript raise when its call stack overflows?

Python, Java, and JavaScript each raise their own distinctly-named, catchable error; only C++ lacks one entirely.

6. Given this function:
def factorial(n): if n == 0: return 1; else: return n * factorial(n - 1)
answer both parts:

(a) Fill in the blank: factorial(3) returns ___.

(b) Which line is the recursive case?

(a) factorial(3) = 3 × 2 × 1 × factorial(0) = 3 × 2 × 1 × 1 = 6. (b) The line calling factorial(n - 1) is the recursive case — it calls the function again on a strictly smaller input.

7. Recall this function from the lesson:
def countdown(n): if n == 0: print("Liftoff!"); return; print(f"{n}..."); countdown(n - 1); print(f"Back from {n}")
calling countdown(2), answer both parts:

(a) Which line prints last?

(b) Fill in the blank: "Back from 1" prints before "Back from 2" because the call stack is ___ — the most recently pushed frame is the first to finish.

(a) The full order is: 2..., 1..., Liftoff!, Back from 1, Back from 2 — countdown(2)'s own frame is the first pushed and the last to finish. (b) countdown(1)'s frame was pushed after countdown(2)'s, so it's popped first, printing its "Back from" line first.

8. Given def fibonacci(n): if n <= 1: return n; return fibonacci(n - 1) + fibonacci(n - 2), answer both parts:

(a) What is fibonacci(4)?

(b) Fill in the blank: fibonacci(n) has ___ base cases (for n = 0 and n = 1).

(a) fibonacci(4) = fibonacci(3) + fibonacci(2) = 2 + 1 = 3, following 0, 1, 1, 2, 3. (b) n <= 1 covers both n = 0 (returns 0) and n = 1 (returns 1) directly, with no further call.

9. Python offers a one-line memoization tool. Answer both parts:

(a) Fill in the blank: decorating a function with @functools.___ caches every call automatically.

(b) Why does memoization make repeated fibonacci calls fast?

(a) functools.lru_cache is Python's built-in decorator for exactly this. (b) Caching keyed by input means fibonacci(4), for example, is only ever actually computed once, no matter how many branches would otherwise ask for it.

10. Given def broken(n): if n == 0: return 0; else: return n + broken(n) — note the recursive call passes n, not n - 1. Answer both parts:

(a) What's wrong with this function?

(b) Fill in the blank: fixing it requires calling broken(n - ___) so each call moves closer to the base case.

(a) Having a base case isn't enough by itself — the recursive case must actually move toward it, which broken(n) never does. (b) Subtracting 1 (or any consistently decreasing amount) guarantees n eventually reaches 0, the base case.
