Try, Catch, and Throw

Unit 1 was about shaping objects. Unit 2 is about shaping what happens when something goes wrong.

Lesson 5 → Contents Glossary →

An exception is a signal that something went wrong, raised at the point of failure and handled somewhere else — possibly far away in the call stack. A try block wraps code that might fail; a matching catch block runs if it does. Below, all four attempt to convert text the user typed into a number, and handle the case where it isn't one.

Python 
try:
    age = int(text)
except ValueError:
    print("That wasn't a number.")
Java 
try {
    int age = Integer.parseInt(text);
} catch (NumberFormatException e) {
    System.out.println("That wasn't a number.");
}
JavaScript 
try {
    let age = parseInt(text, 10);
    if (isNaN(age)) throw new Error("Not a number");
} catch (e) {
    console.log("That wasn't a number.");
}
C++ 
try {
    int age = std::stoi(text);
} catch (const std::invalid_argument& e) {
    std::cout << "That wasn't a number." << std::endl;
}

Python's int(), Java's Integer.parseInt(), and C++'s std::stoi() all throw automatically the instant they receive text they can't convert — ValueError, NumberFormatException, and std::invalid_argument, respectively. Each catch/except names the exact exception type it's prepared to handle; anything else would pass straight through unhandled. JavaScript's parseInt() is the odd one out — it never throws at all, just quietly returns NaN ("not a number") on bad input. To get the same fail-loud behavior here, the code has to check for NaN itself and manually throw. That's the same throw keyword doing the same job either way: raising an exception for some other code to catch.

Definition An exception is a signal raised when something goes wrong. A try block wraps code that might raise one; a matching catch (Python: except) block runs if it does. throw (Python: raise) creates and raises an exception, either automatically inside a built-in operation or manually in your own code.
Why it matters here A program that silently produces a wrong answer instead of failing is far more dangerous than one that stops and says so — that's the same honest-failure instinct the ethics course built earlier in this strand, now given real mechanics. try/catch is how a program fails loudly on purpose, in exactly the place equipped to do something about it.

Check your recall

1. What does a try block do?

The try block itself doesn't stop failures — it just gives you a place to catch them.

2. Why is JavaScript's parseInt() different from the other three languages' conversion functions here?

NaN is a valid number-typed value in JavaScript, which is exactly why it's easy to miss without an explicit isNaN() check.

3. What determines which catch/except block handles a given exception?

A ValueError won't be caught by an except clause written for a different exception type.

4. Fill in the blank: a signal raised when something goes wrong during a program's execution is called an ___.

See the definition box above.

5. Fill in the blank: the keyword used in Java, JavaScript, and C++ to manually raise an exception is ___.

Python uses raise instead — the same job, a different keyword.
