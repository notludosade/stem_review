1. Why are registers dramatically faster to access than RAM?

Being built into the processor itself, with no bus crossing required, is what makes register access so fast.

2. Fill in the blank: the special register holding the memory address of the next instruction to fetch is the ___.

The program counter is what the fetch step reads to know exactly where the next instruction lives.

3. What does the "decode" step of the fetch-decode-execute cycle actually do?

Decode is what turns a fetched instruction's raw bits into a specific operation and specific register operands.

4. What is a calling convention?

The calling convention is why compiled functions call each other correctly with no explicit per-call register agreement in the source.

5. Fill in the blank: a short, human-readable name like mov or add, standing in for a single machine instruction, is called a ___.

Mnemonics are what make assembly readable, standing in for raw binary opcodes.

6. Why might gcc -O0 and gcc -O2 produce very different assembly for the exact same C function?

Optimization changes how the same logical computation is translated into instructions, never what it computes.

7. What does the memory hierarchy trade off, moving from registers toward disk?

Registers, cache, RAM, and disk each trade more capacity for less speed, in that order.

8. Fill in the blank: the fixed-size chunk of memory (commonly 64 bytes) fetched from RAM into the cache at once is called a ___.

Caching moves data in whole cache lines, not individual bytes.

9. Two loops have identical Big-O complexity, but one walks an array sequentially and the other jumps around unpredictably. Why can they run at very different real speeds?

Cache-friendly access patterns can separate two same-complexity loops by a large real-world speed gap.

10. A 64-byte cache line holds 4 instances of a tightly-packed 16-byte struct, but only 3 instances of a 20-byte struct with wasted padding. Answer both parts:

(a) Which struct requires fewer cache-line fetches to visit the same number of instances in a large array?

(b) Does this cache-line effect show up in a Big-O analysis of the loop?

Fitting more instances per cache line means fewer trips to RAM to visit the same array — a real speed effect invisible to complexity analysis alone.
