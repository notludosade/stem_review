Inside the CPU: Registers, ALU, and the Fetch-Decode-Execute Cycle

Unit 6 was about many threads sharing one CPU's attention. This lesson asks what that CPU is actually doing, underneath every language and every lesson in this course so far — one instruction at a time, forever, without exception.

← Unit 6, Lesson 18 Lesson 20 → Contents Glossary →

Every abstraction this course has built — processes, the stack, pointers, threads — eventually bottoms out in the same place: a physical CPU executing one machine instruction after another. This lesson looks at that bottom layer directly, with no C code and no operating system in between.

Registers: the CPU's own tiny, blazing-fast storage

Definition A register is a small storage location built directly into the CPU itself — a modern processor has only a few dozen of them, each holding a single value (typically 4 or 8 bytes). Registers are dramatically faster to read and write than RAM, precisely because they sit inside the processor with no memory bus to cross at all. Every arithmetic operation a CPU performs works on values already sitting in registers, not directly on values sitting out in RAM.
Definition The ALU (arithmetic logic unit) is the CPU component that actually performs arithmetic (add, subtract, multiply) and logic (AND, OR, comparison) operations on values held in registers, producing a result that's written back into a register. The ALU doesn't know or care what a "variable" or a "loop" is — it only ever does one small operation on register contents, over and over, as directed by the current instruction.

The fetch-decode-execute cycle

Definition The program counter (PC) is a special register holding the memory address of the next instruction to run. The fetch-decode-execute cycle is the CPU's entire job, repeated without stopping: fetch the instruction at the address the PC holds; decode it to figure out which operation it specifies and which registers it touches; execute it, usually via the ALU, updating a register or memory; then advance the PC to the next instruction and repeat. Every program this course has discussed — compiled C, an interpreter's own machine code, anything — runs as this exact cycle, over and over, billions of times a second.

Interactive: the fetch-decode-execute cycle

Worked example LOAD R1, 2 — fetch (read this instruction from address in PC), decode (it's a load-immediate into R1), execute (R1 now holds 2), PC advances. LOAD R2, 3 — same cycle: R2 now holds 3, PC advances. ADD R3, R1, R2 — fetch, decode (an ALU addition, operands R1 and R2, destination R3), execute (the ALU adds R1 and R2, writes 5 into R3), PC advances. Three trips through the exact same cycle, and x — now sitting in R3 — is 5.
Why registers are few and RAM is enormous — and why that gap is the rest of this unit A CPU has only a few dozen registers because they're built from expensive, power-hungry, physically-on-die circuitry — there is no way to have millions of them and keep them this fast. RAM (Unit 2's stack and heap) holds gigabytes, but every single access to it is dramatically slower than a register access, because the request has to leave the processor entirely and cross a memory bus. Every instruction that touches memory instead of just registers pays that cost. The next two lessons are about exactly that gap: Lesson 20 shows what real compiled code actually looks like at this level, and Lesson 21 shows the layer of fast-but-limited memory — the cache — that exists specifically to soften the cost of that gap.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why are registers dramatically faster to access than RAM?

Being built into the processor itself, with no bus crossing required, is exactly what makes register access so fast.

2. What does the ALU actually do?

The ALU is the component that actually carries out an instruction's arithmetic or logic operation.

3. What does the program counter hold?

The PC is what tells the fetch step exactly where in memory to read the next instruction from.

4. Fill in the blank: the CPU's continuously repeating cycle of reading an instruction, figuring out what it means, and carrying it out is called the ___ cycle.

Fetch, decode, execute, repeat — every running program is this cycle at the hardware level.

5. Fill in the blank: a small, extremely fast storage location built directly into the CPU, of which there are only a few dozen, is called a ___.

Registers are where the ALU's operands and results actually live during execution.
