Structs, Padding, and Memory Alignment

A C struct's size is not simply the sum of its fields' sizes — the compiler inserts invisible gaps to keep every field aligned, and reordering the exact same fields can shrink a struct without changing a single value it stores.

← Lesson 11 Unit 5, Lesson 13 → Contents Glossary →

A struct groups related fields into one block of memory, the same way a class groups fields in Java or Python — but in C, that block's exact byte layout is something you can reason about directly, and it doesn't always look like what you'd expect from just adding up field sizes.

Alignment: why the CPU cares where a value starts

Definition Memory alignment is a hardware requirement (or at minimum, a strong performance preference) that a value of a given size start at an address that's a multiple of its own size — a 4-byte int should start at an address divisible by 4, an 8-byte double at an address divisible by 8. Misaligned access is at best slower on many processors, since the CPU may need two separate memory reads instead of one, and on some processor architectures, it isn't allowed at all.
Definition Padding is unused filler bytes the compiler silently inserts between struct fields (or after the last one) purely to keep every field properly aligned. Padding bytes hold no meaningful data — they exist only to push the next field's starting address to the correct multiple.

Try it: reorder fields, watch the struct shrink

The struct below holds a char (1 byte), an int (4 bytes), and a double (8 bytes) — the same three fields, every time. Try each ordering and compare the total size.

Interactive: struct field order vs. total size

Worked example struct A { char c; int i; double d; }; lays out as: c at offset 0 (1 byte), then 3 padding bytes so i can start at offset 4 (a multiple of 4), then i at offset 4–7, then d at offset 8–15 (already aligned to 8) — total size 16 bytes, with 3 of them pure padding. Reorder to struct B { double d; int i; char c; };: d at offset 0–7, i at offset 8–11, c at offset 12 — total size, after trailing padding to keep the whole struct's size a multiple of its largest field's alignment, comes to 16 bytes too in this particular case, but with only 3 bytes of trailing padding instead of an interior gap. The general lesson holds broadly: ordering fields from largest to smallest alignment requirement tends to minimize wasted padding, and for structs with more fields, or arrays of many struct instances, that savings adds up fast.
Why this is a real, practical optimization — not just trivia A struct with wasted padding costs real memory when you allocate an array of thousands or millions of them — a struct that could be 12 bytes but pads out to 16 wastes 25% more memory across the whole array, and worse, it means fewer struct instances fit in a CPU cache line at once (Unit 7 covers exactly why that hurts performance). Reordering fields from largest alignment requirement to smallest is a free, purely mechanical change — it doesn't alter what the struct represents at all — that a systems programmer working with large arrays of structs genuinely does think about.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is padding, in the context of a C struct?

Padding bytes carry no meaningful data — they only exist to satisfy alignment.

2. Why might reordering a struct's fields change its total size, even though the fields themselves are unchanged?

Padding depends on the order fields are declared in, so reordering can reduce (or increase) total wasted space.

3. Why does minimizing struct padding matter for a large array of struct instances?

Padding's cost scales with however many instances exist, and it directly affects cache efficiency, covered in Unit 7.

4. Fill in the blank: the requirement that a value start at a memory address that's a multiple of its own size is called ___.

Alignment is the hardware constraint that padding exists specifically to satisfy.

5. Fill in the blank: the invisible filler bytes a compiler inserts between struct fields purely to satisfy alignment are called ___.

Padding holds no meaningful value — it exists purely to keep the next field aligned.
