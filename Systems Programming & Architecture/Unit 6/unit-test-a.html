1. What do multiple threads within the same process share, that separate processes do not?

Shared heap and data-segment access is exactly what distinguishes threads from separate, isolated processes.

2. Why is creating a new thread generally cheaper than creating a new process?

Skipping full address-space isolation is exactly what makes thread creation lighter weight than process creation.

3. Why is counter++ not actually a single atomic step at the machine level?

Read-add-write is the hidden three-step sequence a race condition can interleave badly.

4. Two threads each increment a shared counter starting at 0, with no synchronization, and it ends at 1 instead of 2. What happened?

Both threads reading the same stale value, then both writing, is exactly how a lost update happens.

5. Fill in the blank: an object a thread must lock before touching shared data, and unlock afterward, forcing other threads to wait their turn, is called a ___.

A mutex (mutual exclusion lock) is the standard tool for protecting a critical section.

6. Two threads exist inside the same process. Answer both parts:

(a) Can both threads directly read and write the same heap-allocated variable, with no special mechanism required?

(b) Does each thread still keep its own private stack and CPU register values?

Shared heap, private stack — that split is exactly what defines a thread inside a multithreaded process.

7. A test suite runs a multithreaded program a thousand times and it passes every time. Answer both parts:

(a) Does this guarantee the program has no race condition?

(b) Fill in the blank: a race condition often depends on precise ___ that may only occur rarely, letting most runs produce the correct result by luck.

Race conditions can hide behind mostly-correct interleavings for a very long time before ever surfacing.

8. Thread A holds a mutex and is in the middle of its critical section when Thread B calls lock() on that same mutex. Answer both parts:

(a) What does Thread B do?

(b) Fill in the blank: the block of code between lock and unlock, which needs to run as one uninterrupted unit, is called the ___.

Blocking is exactly how a mutex enforces that only one thread's critical section runs at a time.

9. Thread A holds lock 1 and waits for lock 2; Thread B holds lock 2 and waits for lock 1. Answer both parts:

(a) Fill in the blank: this permanent standoff, where neither thread can ever proceed, is called a ___.

(b) What is the standard defense against this situation?

Consistent lock ordering is simple to state and is the standard way to prevent this exact standoff.

10. Answer both parts about thread terminology:

(a) Fill in the blank: an independent sequence of instructions the CPU can schedule, existing inside a process, is called a ___.

(b) Fill in the blank: a process running more than one thread at once is described as ___.

Every process starts with one main thread; a multithreaded process has added more, all sharing its heap.
