What an Operating System Actually Does

Units 2 through 4 quietly assumed a lot: that your process gets its own private address space, that memory it asks for is actually there, that it can't peek at another program's data. None of that happens by accident — it's all the operating system's job, and this lesson names exactly what that job is.

Every program in this course so far has quietly relied on something that was never actually there: a single, dedicated computer, entirely for itself. In reality, dozens or hundreds of programs share one machine's CPU, memory, and disk at the same time, and something has to referee that sharing constantly, invisibly, and without the programs' cooperation. That something is the operating system.

The operating system as resource manager

Definition An operating system (OS) is the software that manages a computer's hardware resources — the CPU, memory, storage, and peripheral devices — and provides a controlled, consistent way for programs to use them. It sits directly between every running program and the raw hardware, deciding which program gets the CPU at any given instant, which physical memory backs which process's address space, and which program is allowed to touch which file or device.
Definition The kernel is the operating system's core — the part that runs with full, privileged access to the hardware itself, making the actual resource-allocation decisions. Everything else commonly thought of as "the OS" — a file manager, a settings app, a command-line shell — is ordinary software running on top of the kernel, using the exact same restricted access every other program gets.

Three jobs, one referee

ResourceWhat the OS decides
CPUWhich of many waiting processes actually runs on the processor right now, and for how long, before switching to another (Lesson 14 covers this handoff in detail).
MemoryWhich physical memory backs each process's private address space (Lesson 4), and keeping one process from ever reading or writing another's.
Devices & filesWhich program is allowed to read or write a given file or device at a given moment, mediating every request rather than letting programs touch hardware directly.
Worked example You have a code editor, a web browser, and a music player all open at once, on a machine with far fewer CPU cores than that. None of those three programs is aware the others exist, let alone coordinating with them. The OS is silently giving each one tiny slices of CPU time, dozens of times per second, switching between them fast enough that all three appear to run simultaneously — and enforcing that the music player's memory is never visible to the browser, even though both are running on the exact same physical machine at the exact same moment.
Why every program needs the same referee, and can't be trusted to self-police If ordinary programs were allowed to decide for themselves which memory to use or when to use the CPU, one badly written or malicious program could simply seize everything — read another program's private data, corrupt a shared device, or hog the entire CPU forever. The OS solves this not by asking programs nicely, but by controlling the hardware directly and only ever letting ordinary programs make requests through a narrow, controlled interface (Lesson 15 covers exactly how). This is also why an OS itself has to run with a level of hardware access no ordinary program is ever given — it's the one piece of software actually trusted to enforce the rules everyone else has to follow.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the operating system's core job?

Resource management — CPU, memory, storage, devices — is the OS's fundamental role, beneath any visible desktop interface.

2. What is the kernel?

The kernel is the privileged core; a file manager or shell is ordinary software running on top of it.

3. Why can't ordinary programs be trusted to manage CPU time or memory access among themselves, without the OS?

The OS enforces fairness and isolation precisely because ordinary programs cannot be relied on to police themselves.

4. Fill in the blank: the privileged core of the operating system, with full direct access to the hardware, is called the ___.

The kernel is the trusted layer making actual resource-allocation decisions.

5. Fill in the blank: the software that sits between every running program and the raw hardware, deciding CPU time, memory, and device access, is the ___.

The operating system is exactly this resource-managing layer, referenced throughout this whole unit.
