1. Why can't ordinary programs be trusted to manage CPU time and memory access among themselves, without an OS?

The OS enforces fairness and isolation because ordinary programs cannot be relied on to self-police.

2. Fill in the blank: a file manager or command-line shell runs as ordinary software on top of the ___, using the same restricted access as any other program.

Only the kernel itself runs with full, privileged hardware access.

3. You double-click the same application's icon three times, opening three separate windows. What does this demonstrate?

Each launch creates a fully independent process, isolated from the others despite sharing the same program file.

4. Fill in the blank: a process that is fully able to run, just waiting for the scheduler to actually give it CPU time, is in the ___ state.

Ready processes are eligible to run but haven't yet been given the CPU.

5. Why does a machine running twenty background processes at once still feel responsive to the one active foreground program?

The waiting state is what keeps idle background processes from competing meaningfully for CPU time.

6. A process wants to read another process's private memory directly. Answer both parts:

(a) Is this permitted from user mode?

(b) Could a legitimate system call be designed to grant this kind of cross-process access at all?

Process isolation is a core guarantee the kernel enforces; any legitimate cross-process access is narrow and checked, not unrestricted.

7. Fill in the blank: ordinary program code runs in ___, a restricted privilege level with no direct hardware access.

User mode is the restricted level; kernel mode, reached via system calls, has full access.

8. From the calling program's point of view, printf looks like a single, ordinary function call. What is actually happening underneath?

The system call underneath printf triggers a temporary mode switch, invisible at the source-code level.

9. What would be lost if system calls didn't exist as a narrow, well-defined set of entry points into the kernel?

Removing the narrow doorway removes the kernel's one enforceable checkpoint for every privileged operation.

10. Fill in the blank: the process-control system call a program uses to terminate itself is ___.

exit() is the counterpart to fork() in the process-control category of system calls.
