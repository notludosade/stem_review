The Process Address Space

Unit 1 ended with a runnable executable. This lesson asks the next question: once that program is actually running, where does everything — its instructions, its global variables, its function calls, its dynamically allocated data — actually live in memory?

← Unit 1, Lesson 3 Lesson 5 → Contents Glossary →

In Python or Java, "memory" is mostly invisible — the interpreter or runtime manages it for you, and you rarely think about where a specific variable actually sits. In C, and in every running program regardless of language, memory has real structure: a fixed layout of regions, each with a different purpose, different lifetime, and different rules for what can go wrong. This lesson is the map for the rest of this unit.

A process gets its own private view of memory

Definition A process is a running instance of a program, given its own private address space — a range of memory addresses that only it can see, laid out into distinct regions by the operating system. Two processes running the same executable at once each get their own separate address space; a variable at "address 0x1000" in one process is completely unrelated to whatever sits at that same address in the other. (Unit 5 covers exactly how the OS enforces this isolation.)

The four regions, from bottom to top

Definition Every process's address space is divided into regions with fixed jobs: the text segment (also called the code segment) holds the program's compiled machine instructions, and is normally read-only, so a bug can't accidentally overwrite the program's own code. The data segment holds global and static variables that have an initial value baked into the executable. The heap holds memory the program requests dynamically while running, and grows upward as more is allocated (Lesson 6). The stack holds local variables and function-call bookkeeping, and grows downward as functions call other functions (Lesson 5).

Worked example In this tiny program, int global_count = 0; declared outside main lands in the data segment — it has an initial value and exists for the whole life of the program. Inside main, int local_x = 5; lands on the stack — it only exists while main is running. int *p = malloc(sizeof(int)); creates a pointer variable on the stack, but the memory it points to — the four bytes malloc hands back — lives on the heap. And the compiled instructions for main itself live in the text segment, already sitting in memory before main ever runs.
Why the stack and heap grow toward each other Placing the stack and heap at opposite ends of the address space, growing toward each other across a large region of unused addresses in between, is a deliberate design: neither region has to commit to a fixed maximum size in advance. A program that allocates very little on the heap but recurses deeply gets a huge stack and a tiny heap; a program that recurses shallowly but allocates gigabytes on the heap gets the opposite — both without the OS having to guess ahead of time which one needs more room. The tradeoff, covered later this unit, is that if they ever actually meet, something has gone seriously wrong.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does the text segment normally get marked read-only?

Making instructions read-only protects the program's own code from being corrupted by a bug elsewhere in the program.

2. A global variable declared with an initial value outside of any function lives in which region?

Global and static variables with a baked-in initial value belong in the data segment, distinct from stack locals and heap allocations.

3. Why do two separate processes running the same executable not interfere with each other's memory?

Address space isolation, enforced by the operating system, is exactly what makes two running instances of the same program independent.

4. Fill in the blank: the region that holds local variables and function-call bookkeeping, growing downward as functions call other functions, is called the ___.

The stack is dedicated to local variables and call bookkeeping, covered in full in the next lesson.

5. Fill in the blank: the region that holds memory a program requests dynamically while running, growing upward as more is allocated, is called the ___.

The heap is where dynamically allocated memory lives, in contrast to the stack's automatic local variables.
