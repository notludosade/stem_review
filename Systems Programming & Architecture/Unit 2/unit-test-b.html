1. Two separate processes run the same executable at the same time. Why doesn't one process's memory interfere with the other's?

Address space isolation is what makes two instances of the same program independent of each other.

2. Fill in the blank: a global variable declared with an initial value outside of any function is stored in the ___ segment.

The data segment holds globals and statics with a baked-in initial value, for the whole program's lifetime.

3. What happens to a function's stack frame the instant it returns?

Popping a frame is a single operation — its memory simply becomes available for the next call.

4. Fill in the blank: three nested function calls are active at once; the innermost one returns first. This ordering is called ___.

Last-in-first-out describes exactly how nested calls unwind on the stack.

5. A C function returns the address of a local array declared inside it. What is the resulting risk?

The frame is gone once the function returns, so that memory is unsafe to keep using.

6. A function allocates int *buf = malloc(40) and also declares int count = 0;. Answer both parts:

(a) count's memory is reclaimed...

(b) The block buf points to is reclaimed...

Stack locals are automatic; heap blocks require an explicit free call.

7. Fill in the blank: the standard C function that requests a block of heap memory of a given size, returning a pointer to it, is ___.

malloc is the request-side function, paired with free for releasing memory back.

8. A long-running server program allocates heap blocks in a loop but never frees any of them, and never keeps a reference to any block after the loop iteration ends. What happens over time?

This is a textbook memory leak — worse over a long-running process than a short script that exits quickly.

9. Why don't Python or Java programmers write an equivalent of C's free() call?

Garbage collection automates exactly what free() does manually in C, at the cost of CPU time and possible pauses.

10. Fill in the blank: a recursive function with no working base case eventually causes a ___ once it pushes frames past the space reserved for the stack.

A stack overflow is exactly this failure mode — the OS terminates the program before it corrupts adjacent memory.
