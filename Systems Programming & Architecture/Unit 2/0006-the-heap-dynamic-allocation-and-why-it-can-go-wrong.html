The Heap: Dynamic Allocation and Why It Can Go Wrong

The stack cleans up after itself automatically. The heap does not — and that one difference is responsible for an entire category of bugs that simply cannot happen in a language like Python, where something else is doing this bookkeeping for you.

← Lesson 5 Unit 3, Lesson 7 → Contents Glossary →

Every local variable's lifetime is tied to its function, decided automatically by the stack. But plenty of real data needs a lifetime the stack can't express — an array whose size isn't known until the program is running, or data that needs to outlive the function that created it. That's what the heap is for, and it comes with a cost: nothing frees it for you.

Requesting memory at run time

Definition Dynamic memory allocation means requesting a block of memory from the heap while the program is running, of a size decided at run time rather than baked in at compile time. In C, malloc(size) requests size bytes and returns a pointer to the start of that block, or a null pointer if the request fails. That memory is not automatically released when the function that requested it returns — unlike a stack local, it stays reserved until the program explicitly gives it back with free(pointer).
Worked example int *scores = malloc(n * sizeof(int)); reserves enough heap space for n integers — where n might come from user input, so the size genuinely couldn't have been known when the code was compiled. That block survives function returns, gets passed around by pointer, and stays valid right up until something calls free(scores). Forget that call, and the block simply stays reserved forever — the program has no other way to find it again once every pointer to it is gone.

Memory leaks: reserved forever, reachable by nothing

Definition A memory leak happens when a program loses every pointer to a heap block without ever calling free on it. The block is still fully reserved — the operating system doesn't reclaim it while the process is running — but nothing in the program can reach it anymore to free it later. A long-running program (a server, not a script that exits in a second) that leaks steadily will keep consuming more and more memory until it's killed or the machine runs out.
Why languages like Python and Java don't make you call free() Python and Java use garbage collection: a background system that periodically scans for heap objects nothing can reach anymore, and reclaims them automatically, so the programmer never calls anything equivalent to free. That safety isn't free, in the other sense of the word — garbage collection costs CPU time and can pause a program briefly while it runs, and it's part of why those languages generally use more memory and run slower than equivalent C for the same task. C hands that control, and that responsibility, directly to the programmer: total control over exactly when memory is released, in exchange for the fact that forgetting to release it is now entirely possible, and entirely your bug.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the key difference between heap memory and stack memory in terms of cleanup?

This is the core distinction the whole lesson is built on: automatic (stack) vs. manual (heap) lifetime management.

2. What exactly is a memory leak?

A leak is specifically about losing the ability to reach and free a block — the memory itself is never automatically reclaimed by the OS while the process runs.

3. Why does garbage collection in Python or Java have a real performance cost?

Garbage collection trades some CPU time and pause risk for the safety of never having to call free yourself.

4. Fill in the blank: the standard C function that requests a block of heap memory of a given size and returns a pointer to it is ___.

malloc is the standard dynamic allocation function, paired with free for releasing memory back.

5. Fill in the blank: the background system in languages like Python and Java that automatically reclaims heap objects nothing can reach anymore is called ___.

Garbage collection is exactly what removes the need for an explicit free call in those languages.
