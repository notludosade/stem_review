Pointers: Variables That Hold Addresses

Unit 2 kept saying "a pointer to X" without stopping to define what a pointer actually is. This lesson stops. A pointer is nothing exotic — it's just a variable, like any other, whose value happens to be a memory address.

← Unit 2, Lesson 6 Lesson 8 → Contents Glossary →

Every variable you've ever declared, in any language, lives at some address in memory — you just never had to write that address down or think about it. C is different only in that it lets you: a pointer is a variable that stores an address instead of an ordinary value, and gives you a way to write it down, pass it around, and use it to reach the data it points to.

Declaring, and the two core operators

Definition A pointer is a variable whose value is a memory address, declared with an asterisk: int *p; declares p as "a pointer to an int." The address-of operator & takes an ordinary variable and produces its address: int x = 5; int *p = &x; makes p hold x's address. The dereference operator *, applied to a pointer, means "go to the address it holds, and give me the value stored there": *p reads (or, on the left of an assignment, writes) the int that x itself occupies.
Worked example int x = 5; creates an int somewhere in memory — say, address 0x7ffee2a, holding the value 5. int *p = &x; creates a second variable, p, holding the value 0x7ffee2a — p's own address is somewhere else entirely. *p = 10; doesn't change what p points to; it follows p's address to 0x7ffee2a and overwrites the 5 stored there with 10. After this line, both x and *p read as 10 — because they're the exact same four bytes in memory, viewed two different ways.

Pointer types matter

Definition A pointer's declared type — the int in int *p — tells the compiler how many bytes to read or write when the pointer is dereferenced, and how far to move for pointer arithmetic (Lesson 8). int * and double * both just hold an address underneath, but dereferencing one reads 4 bytes as an int, while the other reads 8 bytes as a double starting from the same address — the type is what tells C how to interpret the bytes it finds there.
Why pointers exist at all, instead of just passing values Passing a large struct, or an array, by value would mean copying every byte of it every time it's handed to a function — slow, and wasteful when the function only needs to read or modify a small part of it. Passing a pointer instead means handing over just one address, however large the actual data is, letting the function reach and modify the original data directly instead of a copy. This is also exactly how a function can "return" more than one value in C: pass pointers to several variables, and let the function write results directly into the caller's own memory through them.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a pointer, fundamentally?

A pointer is an ordinary variable, just one whose stored value happens to be an address.

2. Given int x = 5; int *p = &x; *p = 10;, what is x after the third line?

Writing through *p writes to x's own memory, since p holds x's address.

3. Why does a pointer's declared type (int * vs. double *) matter, even though both just store an address?

The type is how the compiler knows how to interpret the bytes found at that address, and how far one "step" of pointer arithmetic should move.

4. Fill in the blank: the operator that takes an ordinary variable and produces its memory address is the ___ operator.

The address-of operator (&) is the counterpart to dereferencing (*).

5. Fill in the blank: following a pointer to the address it holds, to read or write the value stored there, is called ___.

Dereferencing with * is how a pointer is actually used to reach its target's value.
