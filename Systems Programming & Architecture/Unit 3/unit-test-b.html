1. Declaring int *p; creates a variable p. What kind of value does p itself store?

A pointer variable's stored value is an address, regardless of what type it points to.

2. Fill in the blank: the operator that takes an ordinary variable and produces its memory address, for use in initializing a pointer, is the ___ operator.

The address-of operator (&) produces the address later stored in a pointer.

3. A function receives a pointer to a caller's variable and writes a new value through it via dereferencing. What happens to the caller's variable?

Passing a pointer, and dereferencing it, is exactly how a function modifies the caller's own data.

4. Fill in the blank: p + 1 for an int * pointer moves the address forward by one whole int's worth of bytes, not by one byte — this scaled movement is called ___.

Pointer arithmetic always scales by the size of the pointed-to type.

5. Why do arr[i] and *(arr + i) compile to the identical machine code in C?

Array subscripting is defined in the C standard directly in terms of pointer arithmetic and dereferencing.

6. Two programs each access arr[15] on a 5-element array, on different machines. Answer both parts:

(a) Is C guaranteed to catch this and raise a clean error?

(b) Could the two programs behave differently from each other as a result?

Out-of-bounds access is undefined behavior — no bounds check, and no guaranteed consistent outcome.

7. Fill in the blank: after a stack frame is popped, or a heap block is freed, any pointer still holding that now-invalid address is called a ___ pointer.

The pointer's own value doesn't change, only the validity of the memory it refers to.

8. A program frees a heap block, then dereferences the same pointer twenty lines later. What determines whether this crashes, returns stale data, or returns different data entirely?

This is exactly why use-after-free bugs are notoriously hard to reproduce consistently.

9. Why does calling free() twice on the same pointer cause a problem, rather than simply doing nothing the second time?

A double free corrupts the allocator's internal state, with unpredictable downstream effects.

10. Fill in the blank: setting a freed pointer to ___ makes a later accidental dereference crash immediately and loudly, instead of silently reading or corrupting reused memory.

This habit only protects the one variable that was set to NULL, not every pointer that might hold the same address.
