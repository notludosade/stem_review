1. What is the core difference between how a compiler and an interpreter turn source code into something a processor can run?

Ahead-of-time translation defines compiling; repeated on-the-fly translation defines interpreting.

2. Fill in the blank: the raw binary instructions a processor executes directly, specific to that processor's design, are called ___.

Machine code is the only thing a processor can actually execute — every language eventually becomes this.

3. What does it mean that V8's JIT compilation "blurs the line" between compiled and interpreted execution?

JIT mixes both strategies: interpret first, compile the hot paths on the fly, during execution.

4. Fill in the blank: the pipeline stage that performs purely textual substitution — expanding #include files and #define macros — before any real compiling happens, is the ___.

The preprocessor's output is still plain C source code, just fully expanded.

5. What does the compiler stage (in the narrower, four-stage sense) actually produce from preprocessed C source?

The compiler stage translates preprocessed source into assembly — this is where most syntax and type errors are caught.

6. A program calls a function that is declared in a header but never actually implemented anywhere in the linked files. Answer both parts:

(a) This mistake is caught by...

(b) Before that stage runs, the compiler and assembler...

A missing implementation is invisible to the compiler and assembler — only the linker discovers it while resolving references.

7. Fill in the blank: a ___ library is copied directly into the final executable at link time, unlike a dynamic library, which stays a separate file loaded at run time.

Static linking bakes the library's code directly into the executable; dynamic linking keeps it external.

8. What does the gcc flag -c do?

-c means "compile and assemble only," stopping right before the linker runs.

9. A C program compiles and links with zero errors, but produces the wrong output when run. What does this tell you?

A clean build guarantees structural correctness, not logical correctness — those are separate concerns.

10. Fill in the blank: after running gcc hello.c -o hello successfully, the command used to run the resulting program on the same machine is ___.

The leading ./ tells the shell to run the executable sitting right here, not a system-wide command of the same name.
