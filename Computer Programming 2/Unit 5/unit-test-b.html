1. Which of these does Big-O notation deliberately ignore?

A Big-O class is a shape of growth, not a stopwatch reading — it ignores exactly which computer or constant overhead is involved.

2. What is this function's Big-O time complexity?
def has_pair_summing_to(items, target): for i in range(len(items)): for j in range(len(items)): if items[i] + items[j] == target: return True; return False

The inner loop runs n times for every one of the n outer iterations — roughly n × n total, the same shape as has_duplicate_pair.

3. Fill in the blank: of O(log n), O(n), and O(n²), the class describing an algorithm that cuts the problem in half at each step is O(log ___).

Repeated halving is exactly what produces logarithmic growth — the second-best class in the ranking, right after constant time.

4. Which of these is an actual advantage linear search has over binary search?

Linear search has no precondition at all — that flexibility is its whole advantage, even though it's O(n) rather than O(log n).

5. What would go wrong if binary search were run on unsorted data?

Discarding half the remaining data based on a single comparison is only safe because sorted order guarantees where the target must be.

6. Binary search runs on the sorted list [1, 3, 5, 7, 9, 11, 13, 15] (indices 0–7) looking for target 3. Answer both parts:

(a) Fill in the blank: binary search returns index ___.

(b) How many total comparisons does this search take?

(a) mid = 3 → value 7, too high, search the left half. mid = 1 → value 3, a match — index 1. (b) That trace took just two comparisons: at mid 3, then mid 1.

7. Answer both parts about scaling:

(a) A sorted list has about 1,000 elements. Roughly how many comparisons does binary search need in the worst case?

(b) Fill in the blank: as input size n grows very large, the gap between linear search's O(n) and binary search's O(log n) only ___.

(a) Each comparison halves the remaining range, so about 1,000 elements collapse to a match in roughly 10 steps, since 2¹⁰ = 1,024. (b) That gap only widens as n grows — the larger the list, the more binary search's advantage matters.

8. Bubble sort begins on [2, 8, 5, 1]. Answer both parts:

(a) Fill in the blank: after one full pass, the array becomes 2, 5, 1, ___.

(b) Why is bubble sort considered O(n²) rather than O(n)?

(a) Comparing adjacent pairs left to right: (2,8) doesn't swap, (8,5) swaps to [2,5,8,1], then (8,1) swaps to [2,5,1,8]. (b) That "scan almost the whole list again, for every element" behavior is exactly the nested-loop shape that produces O(n²).

9. Answer both parts about merge sort:

(a) Fill in the blank: merge sort's recursive case splits the list at its ___, then recursively sorts each half.

(b) What does the merge step do, once both halves are individually sorted?

(a) Splitting at the midpoint is the halving step that makes merge sort's recursion tree only log n levels deep. (b) That comparison-and-append process is the O(n) merge step that combines with the halving to give O(n log n) overall.

10. Answer both parts about quicksort and real-world sorting:

(a) Fill in the blank: quicksort's average-case time complexity, like merge sort's, is O(n log ___).

(b) Which statement about built-in sorting correctly pairs a language with its behavior?

(a) Quicksort's partition-and-recurse approach gives O(n log n) on average, the same class as merge sort, though its worst case is O(n²). (b) Every mainstream language here ships a fast, well-tested O(n log n) sort already — that's exactly why hand-writing one is rarely needed.
