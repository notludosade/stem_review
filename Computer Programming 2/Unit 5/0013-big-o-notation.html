Big-O Notation

A way to describe how an algorithm's running time grows as its input grows — without depending on a particular computer, language, or day.

Lesson 14 → Contents Glossary →

Big-O notation describes how the number of operations an algorithm performs grows relative to the size of its input, written n. It ignores constant factors and hardware speed — a Big-O class is a shape of growth, not a stopwatch reading. Below, sum_list visits each of the n elements exactly once, no matter how large the list is: that's O(n), linear time.

Python 
def sum_list(numbers):
    total = 0
    for x in numbers:      # runs n times
        total += x
    return total
Java 
static int sumList(int[] numbers) {
    int total = 0;
    for (int x : numbers) {    // runs n times
        total += x;
    }
    return total;
}
JavaScript 
function sumList(numbers) {
    let total = 0;
    for (const x of numbers) {  // runs n times
        total += x;
    }
    return total;
}
C++ 
int sumList(const std::vector<int>& numbers) {
    int total = 0;
    for (int x : numbers) {     // runs n times
        total += x;
    }
    return total;
}

Now compare that to a function checking every pair of elements for a match — a loop inside a loop.

Python 
def has_duplicate_pair(numbers):
    for i in range(len(numbers)):
        for j in range(len(numbers)):   # n runs of n runs
            if i != j and numbers[i] == numbers[j]:
                return True
    return False
Java 
static boolean hasDuplicatePair(int[] numbers) {
    for (int i = 0; i < numbers.length; i++) {
        for (int j = 0; j < numbers.length; j++) {   // n runs of n runs
            if (i != j && numbers[i] == numbers[j]) {
                return true;
            }
        }
    }
    return false;
}
JavaScript 
function hasDuplicatePair(numbers) {
    for (let i = 0; i < numbers.length; i++) {
        for (let j = 0; j < numbers.length; j++) {   // n runs of n runs
            if (i !== j && numbers[i] === numbers[j]) {
                return true;
            }
        }
    }
    return false;
}
C++ 
bool hasDuplicatePair(const std::vector<int>& numbers) {
    for (size_t i = 0; i < numbers.size(); i++) {
        for (size_t j = 0; j < numbers.size(); j++) {   // n runs of n runs
            if (i != j && numbers[i] == numbers[j]) {
                return true;
            }
        }
    }
    return false;
}

The nested loop runs its inner body roughly n * n times — O(n²), quadratic time. Doubling the input roughly quadruples the work, where the linear version's work only doubled. A handful of classes cover almost everything you'll see: O(1) constant — Lesson 9's hash map lookup, the same cost regardless of size; O(log n) logarithmic — cutting the problem in half each step, coming up next lesson; O(n) linear — this lesson's sum_list; O(n²) quadratic — this lesson's nested loop; and O(2ⁿ) exponential — Lesson 12's naive Fibonacci, whose call tree doubled in size with every added level. Ranked from best to worst: O(1) < O(log n) < O(n) < O(n²) < O(2ⁿ).

Definition Big-O notation describes how an algorithm's number of operations grows as its input size n grows, ignoring constant factors and hardware. Common classes, best to worst: O(1), O(log n), O(n), O(n²), O(2ⁿ).
Why it matters here This gives precise names to costs this unit already showed you informally: the hash map's near-instant lookup (Unit 3), the linked list's linear walk, and naive Fibonacci's exponential blowup (Lesson 12) were all Big-O differences in disguise. Now you have the vocabulary to compare any two approaches to the same problem — starting with search, next lesson.
