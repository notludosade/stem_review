# Computer Programming 2 Resources

## Knowledge

- [CS50: Introduction to Computer Science (Harvard)](https://cs50.harvard.edu/x/)
  Its later problem sets (data structures, algorithms, recursion) are pitched at exactly this level. Use for: pacing and problem framing for the data-structures and recursion units.
- [MIT OpenCourseWare — 6.006 Introduction to Algorithms](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/)
  Free full lecture notes/videos on core data structures and algorithmic complexity, university-rigor but approachable. Use for: Big-O and sorting/searching units — the primary source to check any complexity claim against.
- [Dev.java](https://dev.java/) and [cppreference.com](https://en.cppreference.com/)
  Same official references as Computer Programming 1. Use for: Java's collections framework and exception model; C++'s memory model, RAII, and standard containers specifically.
- [MDN Web Docs — JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript)
  Use for: JavaScript's prototype-based inheritance (genuinely different from the other three languages' class models) and its `try/catch` and error-object semantics.
- [Python docs — Errors and Exceptions](https://docs.python.org/3/tutorial/errors.html) and [Data Structures](https://docs.python.org/3/tutorial/datastructures.html)
  Official, always-current Python reference. Use for: Python's exception hierarchy and built-in collection types.

## Wisdom (Communities)

- [r/learnprogramming](https://www.reddit.com/r/learnprogramming/)
  Continued from Computer Programming 1 — still the right level for data-structures/recursion confusion specifically.
- [r/cpp](https://www.reddit.com/r/cpp/)
  Focused, higher-signal community for C++-specific questions, especially memory-model and ownership questions that don't map cleanly onto the other three languages.

## Gaps

- No single free resource walks recursion, data structures, and Big-O side by side in all four languages — synthesized per-lesson from the language-specific references above, cross-checked for consistent terminology.
