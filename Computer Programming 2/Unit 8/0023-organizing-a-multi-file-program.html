Organizing a Multi-File Program

Every example so far has fit in one file. A real program doesn't — it splits by responsibility across many, and each language connects those pieces back together differently.

Lesson 24 → Contents Glossary →

A module is a file whose contents can be used from another file. Below, a Circle class — built the same way as Unit 1's classes — lives in its own file and gets used from a separate main file. Watch how many files each language actually needs to make that work.

Python — 2 files 
# shapes.py
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2

# main.py
from shapes import Circle

c = Circle(5)
print(c.area())   # 78.53975
Java — 2 files 
// Circle.java
public class Circle {
    private double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    public double area() {
        return 3.14159 * radius * radius;
    }
}

// Main.java
public class Main {
    public static void main(String[] args) {
        Circle c = new Circle(5);
        System.out.println(c.area());   // same package: no import needed
    }
}
JavaScript — 2 files 
// shapes.js
export class Circle {
    constructor(radius) {
        this.radius = radius;
    }
    area() {
        return 3.14159 * this.radius ** 2;
    }
}

// main.js
import { Circle } from './shapes.js';

const c = new Circle(5);
console.log(c.area());   // 78.53975
C++ — 3 files 
// shapes.h  — the declaration: what Circle offers, not how
class Circle {
public:
    Circle(double radius);
    double area();
private:
    double radius;
};

// shapes.cpp  — the definition: how Circle actually works
#include "shapes.h"

Circle::Circle(double radius) : radius(radius) {}

double Circle::area() {
    return 3.14159 * radius * radius;
}

// main.cpp
#include "shapes.h"
#include <iostream>

int main() {
    Circle c(5);
    std::cout << c.area() << std::endl;   // 78.53975
}

Python's import, Java's same-package visibility, and JavaScript's export/import all do the same job with two files: one file defines the class, another uses it. C++ is the outlier one more time — it needs a header file (.h) listing what Circle offers, separate from the .cpp file saying how it actually works, because C++ compiles each file independently and the header is how main.cpp learns about Circle without seeing its implementation at all.

Definition A module is a file whose contents (classes, functions) can be used from another file. A C++ header file declares what a class offers, separately from the .cpp file that defines how it works.
Why it matters here Every class from Unit 1 onward has lived in one file for simplicity. Real programs split by responsibility — one file per class or feature — precisely so a change to one piece doesn't require rereading the whole program. This is the last idea needed before the capstone in Lesson 24, which pulls every unit in this course together into one small multi-file design.
