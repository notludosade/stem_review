1. What must every recursive function have in order to eventually stop?

Without a base case that returns directly, the recursive case has nothing to stop it from calling itself forever.

2. Fill in the blank: a function that calls itself to solve a smaller version of the same problem is performing ___.

factorial(5) calling factorial(4) calling factorial(3), and so on, is recursion in action.

3. What does each active function call get on the call stack?

Each call frame is pushed when its call begins and popped when that call returns.

4. What causes a stack overflow?

With no base case ever reached, frames keep stacking up with nowhere to stop, eventually running out of room.

5. Which of these four languages does NOT raise a specific, catchable error when its call stack overflows?

C++'s stack overflow is undefined behavior — the one outlier among these four languages, which all otherwise name the problem clearly.

6. Given this function:
def factorial(n): if n == 0: return 1; else: return n * factorial(n - 1)
answer both parts:

(a) What does factorial(4) return?

(b) Fill in the blank: the base case, factorial(0), returns ___ directly with no further call.

(a) factorial(4) = 4 × 3 × 2 × 1 × factorial(0) = 4 × 3 × 2 × 1 × 1 = 24. (b) factorial(0) is the base case and returns 1 with no recursive call — every other pending multiplication builds on that 1.

7. Given this function:
def visit(n): if n == 0: return; visit(n - 1); print(n)
calling visit(3), answer both parts:

(a) What does this print, in order?

(b) Fill in the blank: 1 prints before 3 because the call stack is ___ — the most recently pushed frame is the first to finish its remaining work.

(a) print(n) only runs after the recursive call returns, so the deepest call (visit(0), which prints nothing) finishes first, then visit(1) prints 1, then visit(2) prints 2, then visit(3) prints 3. (b) visit(1)'s frame was pushed last among the pending ones, so it's the first to resume and finish — the same LIFO order as any stack.

8. Given def fibonacci(n): if n <= 1: return n; return fibonacci(n - 1) + fibonacci(n - 2), answer both parts:

(a) Fill in the blank: fibonacci(5) evaluates to ___.

(b) How many recursive calls does the recursive case make per invocation?

(a) fibonacci(5) = fibonacci(4) + fibonacci(3) = 3 + 2 = 5, following 0, 1, 1, 2, 3, 5. (b) That double call per invocation is exactly what makes the call tree branch out exponentially.

9. A programmer notices naive recursive fibonacci(30) takes several seconds, while a fixed version returns instantly on repeated calls. Answer both parts:

(a) What technique fixes this without changing the function's recursive structure?

(b) Fill in the blank: memoization typically stores cached results in a ___ map, keyed by the input value.

(a) Memoization caches each result the first time it's computed, so a repeated call with the same input skips the recomputation entirely. (b) A hash map's near-instant lookup by key is exactly what makes checking "have I already computed this?" cheap.

10. Given def mystery(n): return n * mystery(n - 1) with no base case at all, answer both parts:

(a) Fill in the blank: mystery is missing a ___ case, so it never stops calling itself.

(b) What actually happens when mystery(5) is called as written?

(a) Every recursive function needs a base case that returns directly, with no further call. (b) With no base case, every call reaches the recursive case again, pushing frame after frame until the stack's memory runs out.
