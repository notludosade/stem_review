Classic Recursion Examples

Factorial made one recursive call per invocation. This example makes two — and that small change has a large cost.

Lesson 13 → Contents Glossary →

The Fibonacci sequence defines each number as the sum of the two before it: 0, 1, 1, 2, 3, 5, 8, 13… Written recursively, fibonacci(n) has two base cases (0 and 1) and a recursive case that calls itself twice.

Python 
def fibonacci(n):
    if n <= 1:                                   # base cases
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)   # two recursive calls

print(fibonacci(6))  # 8
Java 
static int fibonacci(int n) {
    if (n <= 1) {                                 // base cases
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);    // two recursive calls
}

System.out.println(fibonacci(6)); // 8
JavaScript 
function fibonacci(n) {
    if (n <= 1) {                                  // base cases
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);     // two recursive calls
}

console.log(fibonacci(6)); // 8
C++ 
int fibonacci(int n) {
    if (n <= 1) {                                   // base cases
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);      // two recursive calls
}

std::cout << fibonacci(6) << std::endl; // 8

Trace fibonacci(6) by hand and something wasteful shows up fast: it calls fibonacci(5) and fibonacci(4), but fibonacci(5) itself calls fibonacci(4) again — the exact same computation, redone from scratch. Every one of those recomputes its own two children the same way. The call tree branches out exponentially, redoing enormous amounts of duplicate work for larger n. Unit 5's Big-O lesson gives that blowup a precise name; for now, the fix worth knowing is called memoization — caching each result the first time it's computed, keyed by its input, using exactly Lesson 9's hash map. Python even has a one-line version of this built in: decorating the function with @functools.lru_cache caches every call automatically. Java, JavaScript, and C++ don't have an equivalent decorator, but reach the same result by hand, storing results in a HashMap, Map, or unordered_map keyed by n and checking it before recursing.

Definition Memoization is caching the result of a function call keyed by its input, so a repeated call with the same input returns instantly instead of redoing the work.
Why it matters here This lesson closes the loop on the whole unit. A recursive definition (this unit) that keeps recomputing the same subproblem is fixed by caching those results in a hash map (Unit 3) — two ideas from different lessons combining into one practical technique. Recognizing when recursive work is being needlessly repeated, and knowing exactly which structure fixes it, is the kind of judgment Unit 5 builds on directly.
