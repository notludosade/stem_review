Custom Exceptions

Built-in exceptions describe generic failures. Your own domain has its own — and Lesson 1's inheritance is exactly how you define them.

Lesson 6 → Contents Glossary →

A custom exception is a named exception type specific to your program's own domain — not a generic ValueError, but something like "insufficient funds," so calling code can catch precisely that failure and nothing else. In every language, defining one means inheriting from the language's built-in exception class, exactly the mechanism Lesson 1 introduced.

Python 
class InsufficientFundsError(Exception):
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError("Not enough funds.")
    return balance - amount
Java 
class InsufficientFundsException extends Exception {
    InsufficientFundsException(String message) {
        super(message);
    }
}

double withdraw(double balance, double amount) throws InsufficientFundsException {
    if (amount > balance) {
        throw new InsufficientFundsException("Not enough funds.");
    }
    return balance - amount;
}
JavaScript 
class InsufficientFundsError extends Error {
    constructor(message) {
        super(message);
        this.name = "InsufficientFundsError";
    }
}

function withdraw(balance, amount) {
    if (amount > balance) {
        throw new InsufficientFundsError("Not enough funds.");
    }
    return balance - amount;
}
C++ 
class InsufficientFundsError : public std::runtime_error {
public:
    InsufficientFundsError(const std::string& msg) : std::runtime_error(msg) {}
};

double withdraw(double balance, double amount) {
    if (amount > balance) {
        throw InsufficientFundsError("Not enough funds.");
    }
    return balance - amount;
}

Every version is a subclass of the language's base exception type — Exception in Python and Java, Error in JavaScript, std::runtime_error in C++ — carrying a message string through to whatever eventually catches it. Java has one extra wrinkle worth noting: withdraw's signature must declare throws InsufficientFundsException. This is a checked exception — Java's compiler forces every caller to either catch it or declare it themselves, all the way up the call stack. Python, JavaScript, and C++ have no equivalent compile-time enforcement; nothing stops a caller from forgetting to handle any of their exceptions until the failure actually happens at runtime.

Definition A custom exception is a named exception type specific to a program's own domain, defined by inheriting from a built-in exception class. A checked exception (Java-specific) is one the compiler forces every caller to either catch or explicitly declare.
Why it matters here A generic exception tells you something failed. A specific one tells you what — and lets calling code catch exactly that failure while letting unrelated bugs propagate instead of being silently swallowed by a catch-all. Catching InsufficientFundsError specifically means a genuine typo elsewhere in the program still surfaces as a crash, instead of being mistaken for a funds problem.

Check your recall

1. How is a custom exception type defined in all four languages?

InsufficientFundsError/Exception is a subclass in every one of the four examples — the same inheritance mechanism from Lesson 1.

2. What does Java's throws InsufficientFundsException on the method signature require of callers?

This is Java's checked exception system — unique among these four languages.

3. Why catch a specific exception type like InsufficientFundsError instead of catching everything?

A catch-all can accidentally swallow a genuine bug that has nothing to do with the failure it was meant to handle.
