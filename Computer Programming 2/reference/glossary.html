Every term introduced in this course, defined once and kept consistent everywhere it's used.

OOP Deep Dive

Inheritance

A mechanism where a subclass acquires the data and methods of a parent class, and may override or extend them.

Subclass / parent class

A subclass (or "derived class") inherits from a parent class (or "superclass"). The subclass may override the parent's methods.

Interface

A contract specifying required method(s) a class must provide, without necessarily providing their implementation.

Abstract class

A class that cannot be instantiated directly, mixing implemented methods with unimplemented ("pure virtual" or "abstract") ones.

Duck typing

Relying purely on an object having the right methods, with no formal declared contract. JavaScript's default style.

Polymorphism

Treating objects of different but related types uniformly through a shared interface or base type, with each object responding according to its own actual type.

Virtual dispatch

The mechanism that makes polymorphism work — automatic in Python, Java, and JavaScript, and opt-in in C++ via the virtual keyword.

Error Handling & Exceptions

Exception

A signal raised when something goes wrong during a program's execution, handled somewhere else in the call stack.

try / catch

A try block wraps code that might raise an exception; a matching catch (Python: except) block runs if it does.

throw

Creates and raises an exception, either automatically inside a built-in operation or manually in your own code. Python: raise.

Custom exception

A named exception type specific to a program's own domain, defined by inheriting from a built-in exception class.

Checked exception

Java-specific: an exception the compiler forces every caller to catch or explicitly declare.

Defensive handling (LBYL)

Checking a condition before attempting a risky operation, preventing failure rather than reacting to it.

Corrective handling (EAFP)

Attempting a risky operation directly and reacting via try/catch if it fails. Python's culturally preferred style.

Core Data Structures

Stack (LIFO)

A structure restricted to one end: last in, first out.

Queue (FIFO)

A structure that adds at one end and removes at the other: first in, first out.

Node

An element in a linked list, holding a value and a reference to the next node.

Linked list

A chain of nodes accessed starting from its head, allowing cheap insertion anywhere at the cost of direct indexed access.

Head

The first node in a linked list, from which the rest of the chain is reached.

Hash map (hash table)

A structure storing key-value pairs, using a hash of each key to jump directly to its storage slot for average constant-time access.

Key / value

In a hash map, the key is the lookup identifier; the value is what it's associated with.

Recursion

Recursion

A function calling itself on a smaller version of its own problem, until it reaches a base case.

Base case

The simplest input a recursive function answers directly, with no further recursive call.

Recursive case

The general input, which calls the function again on something smaller, moving toward the base case.

Call stack

The LIFO structure a language runtime uses to track active function calls.

Call frame

The record of an active call's local state and return point, held on the call stack.

Stack overflow

Exhausting the call stack's memory because a base case is never reached and frames keep pushing.

Memoization

Caching a function's result keyed by its input, so a repeated call returns instantly instead of redoing the work.

Algorithms & Complexity

Big-O notation

A way to describe how an algorithm's number of operations grows as its input size grows, ignoring constants and hardware.

O(1) / O(log n) / O(n) / O(n²) / O(2ⁿ)

Common Big-O classes, ranked best to worst: constant, logarithmic, linear, quadratic, exponential.

Linear search

Checking each element in order until a match is found — O(n), works on any data.

Binary search

Repeatedly halving the remaining search range on sorted data — O(log n), requires sorted input.

Bubble sort

Repeatedly swapping adjacent out-of-order elements until none remain — O(n²).

Merge sort

Recursively splitting a list in half, sorting each half, and merging the sorted halves — O(n log n).

Quicksort

Recursively partitioning a list around a chosen pivot element — O(n log n) on average.

Memory Models

Stack (memory)

The region holding function-local data, freed automatically with each call frame.

Heap

The region holding data whose lifetime outlives the call that created it.

Garbage collection

Automatically freeing heap memory once nothing in the program can still reach it.

Memory leak

Heap memory that's become unreachable but was never freed, permanently wasting that memory.

Pointer

A variable whose value is the memory address of some other piece of data.

Reference

A variable referring to another piece of data, typically without exposing a raw address.

Dangling pointer / use-after-free

A pointer to already-freed memory, and the bug caused by reading or writing through it.

Smart pointer / RAII

A C++ object (unique_ptr, shared_ptr) that automatically frees its owned memory via its own scope-tied lifetime.

Testing & Debugging

Assertion

A check that halts the program if a condition the programmer assumed would always hold turns out false.

Unit test

Automated code that calls one small piece of code with known inputs and asserts the output is correct.

Test framework

A tool (pytest, JUnit, Jest, Google Test) that automatically discovers and runs many tests, reporting pass/fail.

Debugging

The process of locating the cause of a bug: reproduce, read the error, then narrow down the cause.

Bisecting (a bug)

Repeatedly narrowing the suspect range in half to locate a bug's exact cause — binary search applied to debugging.

Breakpoint

A line where a debugger pauses execution so the program's state can be inspected directly.

Capstone — Putting It Together

Module

A file whose contents (classes, functions) can be used from another file.

Header file

In C++, a file declaring what a class offers, separate from the .cpp file defining how it works.

Capstone project

A project deliberately designed to combine ideas from many earlier lessons at once.
