Interfaces, Protocols and Abstract Classes

Inheritance shares an implementation. This lesson is about sharing a requirement instead — a promise that certain methods will exist.

Lesson 3 → Contents Glossary →

An interface is a contract: it names methods a class must provide, without necessarily saying how. The four languages enforce that contract very differently — and JavaScript, honestly, barely enforces it at all. Below, anything that can fly() is treated as Flyable.

Python 
from abc import ABC, abstractmethod

class Flyable(ABC):
    @abstractmethod
    def fly(self):
        pass

class Bird(Flyable):
    def fly(self):
        return "Flap flap, off I go!"
Java 
interface Flyable {
    String fly();
}

class Bird implements Flyable {
    public String fly() {
        return "Flap flap, off I go!";
    }
}
JavaScript 
// JavaScript has no interface keyword.
// A Bird "satisfies" Flyable just by having a fly() method.
class Bird {
    fly() {
        return "Flap flap, off I go!";
    }
}
C++ 
class Flyable {
public:
    virtual std::string fly() = 0; // pure virtual: no body
};

class Bird : public Flyable {
public:
    std::string fly() override {
        return "Flap flap, off I go!";
    }
};

Java's interface is a dedicated language feature: Bird implements Flyable fails to compile unless Bird provides every method Flyable declares. C++ has no separate interface keyword, but reaches the same result with an abstract class — a class made entirely of pure virtual methods, marked = 0 instead of given a body. An abstract class can't be instantiated directly; only a subclass that fills in every pure virtual method can. Python's abc module gives you the same compiler-checked-at-runtime enforcement, but it's opt-in — you only get it if you inherit ABC and mark methods @abstractmethod. JavaScript has nothing built in at all: Bird works as a Flyable purely because it happens to have a fly() method — a style called duck typing. Nothing stops you from passing an object that's missing fly() until the moment it's actually called and crashes.

Definition An interface is a contract specifying required method(s) without necessarily providing their implementation. An abstract class is a class that cannot be instantiated directly, and may mix implemented methods with unimplemented ("pure virtual" or "abstract") ones. Duck typing is relying purely on an object having the right methods, with no formal declared contract at all.
Why it matters here A contract lets independent pieces of code work together without knowing each other's exact class hierarchy. Anything that promises to be Flyable can be handed to code that only asks "can this fly?" — a new bird, a plane, a paper airplane class written next year, all interchangeable at that boundary. That's the setup for the next lesson: treating different types uniformly through the interface they share.

Check your recall

1. What does an interface specify?

Flyable only names fly() — it says nothing about how each class implements it.

2. How does C++ achieve interface-like behavior without an interface keyword?

= 0 marks a pure virtual method — no body, and any subclass must supply one to become instantiable.

3. What is the risk of JavaScript's duck typing approach compared to Java's interface?

Java's compiler rejects a missing method before the program ever runs; JavaScript only discovers it at the moment of the call.

5. Fill in the blank: relying purely on an object having the right methods, with no formal contract, is called ___ typing.

"If it walks like a duck and quacks like a duck" — JavaScript's default style.
