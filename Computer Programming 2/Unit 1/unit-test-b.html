1. What does a subclass acquire from its parent class through inheritance?

Dog automatically has everything Animal defines, plus whatever it overrides or adds itself.

2. Fill in the blank: replacing a parent class's method with a same-named method in the subclass is called ___ the method (not to be confused with overloading).

Calling speak() on a Dog instance runs Dog's overridden version, not Animal's, without touching Animal itself.

3. Which of these best describes what an interface guarantees, in language-neutral terms?

An interface names required methods, like fly(), without saying anything about their internal implementation.

4. Fill in the blank: "if it walks like a duck and quacks like a duck, treat it as a duck" describes JavaScript's ___ typing, where having the right methods is all that matters.

JavaScript has no interface keyword — Bird works as Flyable purely because it happens to have a fly() method.

5. A C++ programmer removes the virtual keyword from Animal::speak(). What changes about a polymorphism loop over vector<Animal*>?

Without virtual, C++ decides which function to call based on the pointer's declared type (Animal*), not the object's actual type — that's static dispatch.

6. Both parts trace the same Dog/Animal relationship in two different languages:

(a) In JavaScript: class Animal { constructor(name){this.name=name;} speak(){return `${this.name} makes a sound.`;} } class Dog extends Animal { speak(){return `${this.name} says Woof!`;} } let rex = new Dog("Rex"); console.log(rex.speak()); — what prints?

(b) Fill in the blank: in C++, Dog(std::string name) : Animal(name) {} — the part after the colon and before the braces is called the constructor's initializer ___.

(a) Dog defines no constructor of its own in JavaScript, so a default one runs that passes "Rex" through to Animal's constructor automatically, setting this.name correctly. (b) C++'s initializer list is how Dog's constructor runs Animal's constructor before its own body executes.

7. Both parts are about instantiating and defining abstract requirements:

(a) What happens if you try to directly instantiate C++'s abstract Flyable class with new Flyable()?

(b) Fill in the blank: in Python, marking a method abstract requires inheriting from ABC and decorating the method with @___.

(a) A pure virtual method (= 0) has no body, and C++ refuses to instantiate any class that still has one unimplemented. (b) @abstractmethod on a method inside a class inheriting ABC is what makes Python enforce the requirement, at instantiation time.

8. Both parts are about extending the polymorphic loop with a brand-new subclass, using Python this time:

(a) class Bird(Animal): def speak(self): return f"{self.name} tweets!" then animals = [Dog("Rex"), Bird("Tweety")]; for a in animals: print(a.speak()) — what prints, in order?

(b) Why does adding this brand-new Bird class require zero changes to the existing loop?

(a) Each object's own speak() runs, in the order the list holds them: Dog first, then Bird. (b) This is exactly the payoff of polymorphism — code written against "any Animal" keeps working as new subclasses appear.

9. Both parts are about std::vector<Animal> animals; animals.push_back(Dog("Rex"));

(a) What specifically goes wrong here?

(b) Fill in the blank: storing a subclass object by value in a base-class variable, losing its subclass-specific parts, is called object ___.

(a) A vector<Animal> only ever holds the Animal portion of any object placed inside it, no matter what subclass was originally constructed. (b) Storing by pointer or reference instead avoids this by preserving the object's real type.

10. Both parts compare how strictly each language checks that a class fulfills an interface:

(a) Which language's compiler rejects a class outright if it fails to implement every method its declared interface requires?

(b) Fill in the blank: C++ has no dedicated interface keyword, but achieves the same effect with an abstract class made of pure ___ methods.

(a) Bird implements Flyable fails to compile in Java unless Bird provides every method Flyable declares. (b) Pure virtual methods, marked = 0, are what makes a C++ class abstract and unable to be instantiated on its own.
