Polymorphism — One Interface, Many Behaviors

Inheritance and interfaces both set this up. Polymorphism is the payoff: code that works with "any Animal" without caring which one.

Lesson 4 → Contents Glossary →

Polymorphism means treating objects of different but related types uniformly through a shared type, while each object still responds according to what it actually is. Below, a collection holds both Dog and Cat — both subclasses of Lesson 1's Animal — and calling speak() on each gets the right answer automatically, with no if statement checking which one it is.

Python 
animals = [Dog("Buddy"), Cat("Whiskers")]
for a in animals:
    print(a.speak())
# Buddy says Woof!
# Whiskers says Meow!
Java 
List<Animal> animals = List.of(new Dog("Buddy"), new Cat("Whiskers"));
for (Animal a : animals) {
    System.out.println(a.speak());
}
// Buddy says Woof!
// Whiskers says Meow!
JavaScript 
let animals = [new Dog("Buddy"), new Cat("Whiskers")];
for (const a of animals) {
    console.log(a.speak());
}
// Buddy says Woof!
// Whiskers says Meow!
C++ 
std::vector<Animal*> animals = { new Dog("Buddy"), new Cat("Whiskers") };
for (Animal* a : animals) {
    std::cout << a->speak() << std::endl;
}
// Buddy says Woof!
// Whiskers says Meow!

Python, Java, and JavaScript give you this "correct override runs automatically" behavior for free. C++ does not — and this is exactly where Lesson 1's virtual keyword earns its keep. The loop variable a is declared as Animal*, not Dog* or Cat*. Without virtual on Animal::speak(), C++ would call Animal's version for every element, because it decides which function to run based on the declared type, not the actual object — a behavior called static dispatch. Marking the method virtual switches C++ to virtual dispatch: it checks the object's real type at runtime and calls the matching override, exactly like the other three languages do automatically. Also notice the C++ collection holds pointers (Animal*), not plain Animal values — storing a Dog by value in an Animal slot would truncate it down to just its Animal part, a bug called object slicing. (These raw new-allocated pointers are also never freed here, which leaks memory — Unit 6 covers how C++ manages this properly.)

Definition Polymorphism is the ability to treat objects of different but related types uniformly through a shared interface or base type, with each object responding according to its own actual type. Virtual dispatch is the mechanism that makes this happen — automatic in Python, Java, and JavaScript, and opt-in via C++'s virtual keyword.
Why it matters here This is what inheritance and interfaces were building toward. Code written against "any Animal" or "any Flyable" doesn't need to know every subclass that exists today, or that will exist next year. Add a brand new Bird subclass later, and the loop above prints its sound too — without a single line of it changing.

Check your recall

1. What does polymorphism let you do?

The same loop, calling the same method name, gets different correct behavior per object.

2. Why does the C++ example specifically need Animal::speak() marked virtual?

This is static dispatch versus virtual dispatch — Python, Java, and JavaScript always use the equivalent of virtual dispatch.

3. Why does the C++ example store Animal* pointers instead of plain Animal values?

Pointers (or references) preserve the object's actual type, which is what virtual dispatch depends on.
