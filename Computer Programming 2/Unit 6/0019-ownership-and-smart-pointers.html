Ownership and Smart Pointers

If a raw pointer outlives what it points to, using it doesn't fail loudly. It fails silently — until it doesn't.

Lesson 20 → Contents Glossary →

A dangling pointer points to memory that has already been freed. Reading or writing through it is use-after-free — one of the most notorious categories of bug in C++, because it often doesn't crash immediately; it silently corrupts whatever now happens to occupy that freed memory.

Python 
# There is no direct equivalent of this bug in Python.
# The garbage collector will never free an object while
# any reference to it still exists, so a "dangling reference"
# to already-freed memory simply cannot happen here.
Java 
// Same guarantee as Python: the garbage collector will never
// free an object while a reference to it still exists.
// Dangling references of this kind cannot happen in Java.
JavaScript 
// Same guarantee again: JavaScript's garbage collector will
// never free an object that's still reachable from a live
// reference. This category of bug does not exist here.
C++ 
int* makeDangling() {
    int value = 42;
    return &value;      // returns the ADDRESS of a stack variable —
}                          // 'value' is destroyed the instant this returns

int* p = makeDangling();
std::cout << *p;          // undefined behavior: p points to freed stack memory

int* q = new int(10);
delete q;                  // the heap memory is freed
std::cout << *q;          // undefined behavior: use-after-free

This is the one bug category unique to C++ among these four languages — and it exists precisely because C++ hands you a raw pointer with no built-in tracking of whether what it points to is still alive. Modern C++ has a fix that doesn't give up manual control: smart pointers. std::unique_ptr owns its heap memory exclusively and frees it automatically the instant it goes out of scope — no delete required, and no way to accidentally share ownership. std::shared_ptr allows multiple owners, keeping a running count and freeing the memory only once the last owner is gone. This pattern — tying a resource's lifetime to an object's own scope — is called RAII (Resource Acquisition Is Initialization), and it's how modern C++ gets close to garbage-collector convenience while keeping deterministic, immediate cleanup.

Definition A dangling pointer points to already-freed memory; using it is use-after-free. A smart pointer (unique_ptr, shared_ptr) automatically frees its memory when it goes out of scope — a pattern called RAII.
