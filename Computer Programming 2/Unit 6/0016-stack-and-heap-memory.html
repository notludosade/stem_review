Stack and Heap Memory

Two regions of memory, two very different lifetimes — and this unit is where C++ stops just differing in syntax and starts differing in kind.

Lesson 17 → Contents Glossary →

Unit 4 already introduced the call stack — the LIFO structure holding each function call's local variables, popped automatically when the call returns. That's the stack. The heap is a separate region for data that needs to outlive the function call that created it: objects, arrays, anything whose size or lifetime isn't known until the program is running. A stack variable disappears the instant its frame pops; heap data sticks around until something explicitly frees it or a garbage collector notices nothing references it anymore.

Python 
def make_list():
    numbers = [1, 2, 3]   # the list object lives on the heap;
    return numbers        # 'numbers' itself is a stack reference to it

result = make_list()      # the heap object outlives the call that made it
Java 
static int[] makeArray() {
    int[] numbers = {1, 2, 3};  // the array object lives on the heap;
    return numbers;             // 'numbers' is a stack reference to it
}

int[] result = makeArray();     // the heap object outlives the call
JavaScript 
function makeArray() {
    const numbers = [1, 2, 3];  // the array object lives on the heap;
    return numbers;             // 'numbers' is a stack reference to it
}

const result = makeArray();     // the heap object outlives the call
C++ 
int localValue() {
    int x = 5;              // x lives on the stack — gone when the function returns
    return x;                // the VALUE is copied out before that happens
}

int* heapValue() {
    int* p = new int(5);    // *p lives on the heap — explicitly requested
    return p;                // the POINTER is copied out; *p still exists after return
}

In Python, Java, and JavaScript, this distinction happens automatically and mostly invisibly — every object you create lives on the heap, and a variable is always just a reference to it sitting on the stack; there's no syntax for choosing otherwise. C++ is the outlier: it gives you a direct choice. int x = 5; is a genuine stack variable, allocated and destroyed automatically with its scope. new int(5) explicitly requests heap memory that outlives the current scope — and, unlike the other three languages, C++ will not clean it up for you. That single difference is what the next three lessons are about.

Definition The stack holds function-local data, sized and freed automatically with each call frame. The heap holds data whose lifetime outlives the call that created it, sized and freed independently of any one function's frame.
Why it matters here Every bug this unit covers — memory leaks, dangling pointers, use-after-free — happens on the heap, never the stack. The stack cleans up after itself by construction; the heap only cleans up if something makes sure it does. Knowing which region a piece of data lives in is the first step to knowing whether that "something" is even necessary.
