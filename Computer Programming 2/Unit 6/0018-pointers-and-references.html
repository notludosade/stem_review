Pointers and References

Every variable in these four languages that isn't a raw number is, underneath, pointing at something else. C++ is just the one language that lets you see it.

Lesson 19 → Contents Glossary →

A pointer is a variable whose value is a memory address — literally the location of some other piece of data. A reference is the same underlying idea, usually with the raw address hidden: a variable name that refers to an object elsewhere in memory, without exposing the address itself. Python, Java, and JavaScript variables holding objects, arrays, or lists are always references in this sense — assigning one variable to another doesn't copy the data, it copies what it points to.

Python 
a = [1, 2, 3]
b = a          # b references the SAME list object as a
b.append(4)
print(a)       # [1, 2, 3, 4] — a sees the change too
Java 
int[] a = {1, 2, 3};
int[] b = a;         // b references the SAME array object as a
b[0] = 99;
System.out.println(a[0]); // 99 — a sees the change too
JavaScript 
let a = [1, 2, 3];
let b = a;          // b references the SAME array object as a
b.push(4);
console.log(a);     // [1, 2, 3, 4] — a sees the change too
C++ 
int x = 5;
int* p = &x;    // p holds the ADDRESS of x, made explicit with &
*p = 99;         // *p means "the value p points to" — this changes x
std::cout << x << std::endl;  // 99 — x itself was changed

int& ref = x;    // a reference: another name for x, no explicit address
ref = 7;          // changes x directly, no * needed
std::cout << x << std::endl;  // 7

In Python, Java, and JavaScript, every assignment of an object, array, or list works the way b = a does above — the underlying reference behavior is always on, with no separate syntax for "copy the data instead." C++ makes the choice explicit at every step: &x takes the address of a variable, producing a pointer; *p dereferences a pointer, meaning "the value at that address"; and int& ref = x declares a true reference — like Python's b = a, but for any type, including plain numbers. Lesson 3's a->speak() and Lesson 8's linked-list -> were both this same mechanism at work: a->speak() is shorthand for (*a).speak(), dereferencing a pointer and calling a method in one step.

Definition A pointer is a variable holding a memory address. A reference is a variable that refers to another piece of data, typically without exposing a raw address. C++: & takes an address, * dereferences a pointer.
Why it matters here "Reference semantics" for objects isn't a C++-only idea — it's the default in all four of these languages. C++ just requires naming the mechanism explicitly, which is exactly why the next lesson's bugs (dangling pointers, use-after-free) show up as a distinct, nameable category there, instead of being silently prevented the way garbage collection prevents them elsewhere.
