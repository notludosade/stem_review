1. What happens to stack-allocated data when its function returns?

This automatic cleanup is the same call-stack behavior introduced back in Unit 4 — each frame is freed the instant it pops.

2. Fill in the blank: data whose lifetime needs to outlive the function call that created it is allocated on the ___.

make_list's returned list, and heapValue's *p in C++, both need to survive past the function that created them — that's exactly what the heap is for.

3. In C++, what does new int(5) do that int x = 5; does not?

C++ is the one language of the four that gives code a direct choice between stack and heap — new explicitly requests heap memory.

4. What does a garbage collector do?

This is what Python, Java, and JavaScript all do automatically — no delete or free call is required from the developer.

5. What is a memory leak?

makeAndLeak's array is exactly this — the pointer to it is gone the moment the function returns, but the memory itself was never released.

6. Given these two C++ functions:
void makeAndLeak() { int* data = new int[500000]; }
void makeAndFree() { int* data = new int[500000]; delete[] data; }
answer both parts:

(a) Which function produces a memory leak?

(b) Fill in the blank: makeAndFree avoids the leak by calling ___[] to explicitly release the array.

(a) makeAndLeak's data pointer disappears when the function returns, but the array it pointed to is never released — permanently unreachable, permanently allocated. (b) delete[] is the array form of C++'s explicit free; a single new requires exactly one matching delete or delete[].

7. Given this C++ code:
int x = 10; int* p = &x; *p = 50;
answer both parts:

(a) After this code runs, what is the value of x?

(b) Fill in the blank: p is a pointer whose value is the memory ___ of x.

(a) &x takes x's address into p, and *p = 50 dereferences p to write through it — changing x itself to 50. (b) A pointer's entire value is the address of the thing it points to.

8. Given this Python code:
a = [1, 2, 3]; b = a; b.append(9)
answer both parts:

(a) What does print(a) show after this code runs?

(b) Fill in the blank: this happens because b and a both ___ the same underlying list object, rather than b being a separate copy.

(a) There's only one list object in memory; a and b are just two names pointing at it, so appending through either name is visible through both. (b) Every object assignment in Python, Java, and JavaScript works this way — the underlying reference behavior is always on.

9. Given this C++ function:
int* makeDangling() { int value = 42; return &value; }
answer both parts:

(a) What's wrong with makeDangling?

(b) Fill in the blank: reading through a pointer to memory that has already been freed is called ___-after-free.

(a) value lives on the stack and is gone the moment the function returns, but the returned pointer still holds its old address. (b) Use-after-free is one of the most notorious bug categories in C++ specifically because it often corrupts data silently instead of crashing right away.

10. Answer both parts about modern C++ memory management:

(a) What does a std::unique_ptr do automatically that a raw pointer does not?

(b) Fill in the blank: tying a resource's cleanup to an object's own automatic scope, the pattern smart pointers use, is called ___.

(a) unique_ptr borrows the stack's "cleans up on its own" guarantee and applies it to heap memory, with no explicit delete required. (b) RAII — Resource Acquisition Is Initialization — is how modern C++ gets close to garbage-collector convenience while keeping deterministic cleanup.
