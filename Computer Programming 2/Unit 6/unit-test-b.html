1. Which best describes stack memory?

The stack cleans up after itself by construction — its data is sized and freed automatically as call frames push and pop.

2. Which of these needs to live on the heap rather than the stack?

Anything that must survive past the call that created it — like make_list's returned list — needs the heap; a stack frame disappears the instant it pops.

3. Fill in the blank: unlike Python, Java, and JavaScript, C++ lets code explicitly choose between stack and heap allocation — heap memory is requested with the ___ keyword.

new int(5) explicitly requests heap memory that outlives the current scope — a choice the other three languages make invisibly and automatically.

4. What do Python, Java, and JavaScript have in common regarding heap memory cleanup?

This is the automatic cleanup that comes bundled with automatic heap allocation in all three of these languages — unlike C++.

5. Why does calling a leaking C++ function repeatedly eventually crash a program?

Every leaked allocation stays permanently unreachable and permanently allocated, so repeated leaks accumulate until the program runs out of memory.

6. Answer both parts about garbage collection versus manual memory management:

(a) What tradeoff does garbage collection make compared to manual memory management?

(b) Fill in the blank: in C++, forgetting to call delete on every allocation, on every code path, causes a memory ___.

(a) The collector periodically scans for unreachable objects — a small ongoing cost that trades away the need to get manual freeing right by hand. (b) Getting that delete right, for every allocation on every path including error paths, is exactly the discipline garbage collection removes.

7. Given this C++ code:
int y = 3; int* q = &y; *q = *q + 7;
answer both parts:

(a) Fill in the blank: after this code runs, y equals ___.

(b) What does the * do in the expression *q = *q + 7?

(a) *q reads y's current value (3), adds 7 to get 10, then writes that back through q — changing y itself to 10. (b) Both uses of * on the same line dereference q: one to read the current value, one to write the new one.

8. Given this Java code:
int[] a = {5, 5, 5}; int[] b = a; b[0] = 1;
answer both parts:

(a) Fill in the blank: after this code runs, a[0] equals ___.

(b) Why does modifying b also change what a shows?

(a) There's only one array object; b is just another name for it, so writing through b[0] changes what a[0] shows too. (b) int[] b = a copies the reference, not the array data — standard behavior for object assignment in Java.

9. Answer both parts about why this bug category is unique to C++ among these four languages:

(a) Why can dangling pointers never occur in Python, Java, or JavaScript?

(b) Fill in the blank: a pointer that still holds the address of already-freed memory is called a ___ pointer.

(a) This guarantee is the direct payoff of garbage collection — an object simply can't be freed while something still points to it. (b) makeDangling's returned pointer, pointing at a destroyed stack variable, is exactly this.

10. Answer both parts about C++'s two common smart pointers:

(a) Fill in the blank: a std::___ allows multiple owners of the same heap memory, freeing it only once the last owner is gone.

(b) What is the general default recommendation between unique_ptr and shared_ptr?

(a) shared_ptr keeps a running count of owners, freeing the memory only once that count reaches zero. (b) unique_ptr's exclusive ownership is simpler and cheaper, so it's the default; shared_ptr's bookkeeping is reserved for when sharing is actually needed.
