Garbage Collection and Manual Memory

Three of these languages clean up heap memory for you. One expects you to do it yourself — and punishes you quietly if you forget.

Lesson 18 → Contents Glossary →

Python, Java, and JavaScript all use garbage collection: a background process that tracks which heap objects are still reachable from active variables, and automatically frees the ones that aren't. C++ has no such process built in — heap memory allocated with new stays allocated until something calls delete on it, even after every variable that pointed to it is gone.

Python 
def make_and_forget():
    data = [1] * 1000000   # allocated on the heap
    # function ends; 'data' goes out of scope
    # nothing else references it — the garbage collector
    # will reclaim that memory automatically, no action needed

make_and_forget()
Java 
static void makeAndForget() {
    int[] data = new int[1000000];  // allocated on the heap
    // method ends; 'data' goes out of scope
    // the garbage collector reclaims that memory automatically
}

makeAndForget();
JavaScript 
function makeAndForget() {
    const data = new Array(1000000);  // allocated on the heap
    // function ends; 'data' goes out of scope
    // the garbage collector reclaims that memory automatically
}

makeAndForget();
C++ 
void makeAndLeak() {
    int* data = new int[1000000];  // allocated on the heap
    // function ends; 'data' goes out of scope...
    // but *data is NOT freed — nothing called delete[]
    // that memory is now unreachable AND still allocated: a leak
}

void makeAndFree() {
    int* data = new int[1000000];
    delete[] data;   // explicitly frees the heap memory
}

makeAndLeak is a memory leak: the pointer that could reach that heap memory is gone the moment the function returns, but the memory itself was never freed, so it's permanently unusable for the rest of the program's run. Call a leaking function enough times and a program's memory usage climbs without bound until it crashes. makeAndFree fixes it with one line — but that line has to be written correctly, for every allocation, on every path through the code, including error paths. Garbage collection trades a small, ongoing runtime cost (the collector has to periodically scan for unreachable objects) for never having to get that right by hand.

Definition Garbage collection automatically frees heap memory once nothing references it anymore. Manual memory management requires code to explicitly free heap memory (C++'s delete); forgetting causes a memory leak.
Why it matters here This is the practical cost of Lesson 16's stack/heap choice. Automatic heap allocation in Python, Java, and JavaScript comes with automatic cleanup as part of the same deal. C++ separates the two: you choose to allocate on the heap, and that choice comes with an unwritten promise to also handle freeing it — a promise the compiler does not enforce for you.

Check your recall

1. What does a garbage collector do?

This is what Python, Java, and JavaScript all do automatically, with no code required from the developer.

2. What exactly is a memory leak?

makeAndLeak's array is exactly this — the pointer to it is gone, but the memory itself was never released.

3. What does C++ require that Python, Java, and JavaScript do not, for heap-allocated memory?

This manual step, and the discipline it requires on every code path, is unique to C++ among these four languages.
