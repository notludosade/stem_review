Unit Testing

A unit test is last lesson's assertions, aimed at one small piece of code, organized so they run automatically — every time, not just once by hand.

Lesson 22 → Contents Glossary →

A unit test calls one small piece of code — a "unit," typically a single function — with known inputs, and asserts the output matches what's expected. Below, each test targets Unit 4's factorial function, checking both its base case and a general case in one test.

Python 
def test_factorial():
    assert factorial(0) == 1     # base case
    assert factorial(5) == 120   # general case

test_factorial()
print("All tests passed")
Java 
static void testFactorial() {
    assert factorial(0) == 1;     // base case
    assert factorial(5) == 120;   // general case
}

testFactorial();
System.out.println("All tests passed");
JavaScript 
const assert = require('assert');   // Node's built-in assert module —
                                     // unlike console.assert, this one throws

function testFactorial() {
    assert.strictEqual(factorial(0), 1);      // base case
    assert.strictEqual(factorial(5), 120);    // general case
}

testFactorial();
console.log("All tests passed");
C++ 
#include <cassert>

void testFactorial() {
    assert(factorial(0) == 1);     // base case
    assert(factorial(5) == 120);   // general case
}

int main() {
    testFactorial();
    std::cout << "All tests passed" << std::endl;
}

Notice the JavaScript panel's callback to last lesson: console.assert only warns, so it's useless for testing — a failed test needs to actually stop and report failure, which is exactly what Node's assert module does instead. These hand-rolled test functions are the real idea in miniature. Real projects use a dedicated test framework instead of writing this by hand: Python's pytest or built-in unittest, Java's JUnit, JavaScript's Jest or Mocha, C++'s Google Test or Catch2. What they add on top of plain assertions is automatic discovery of every test in a project, a report of exactly which ones passed or failed, and the ability to run hundreds of tests with one command — turning "did I break anything?" from a manual question into an automated one, run before every change ships.

Definition A unit test calls a single small piece of code with known inputs and asserts the output is correct. A test framework (pytest, JUnit, Jest, Google Test) automatically discovers and runs many tests, reporting pass/fail for each.
Why it matters here A test suite is what turns "I think this still works" into "I know this still works" — especially valuable after a refactor, where behavior should stay identical even as the implementation changes underneath it. Writing tests for the functions built across this entire course, starting with the ones in this unit's examples, is exactly what the capstone in Unit 8 will ask you to do.
