1. A function assumes its input list is never empty and checks that with assert len(numbers) > 0. What does it mean if that assertion fails?

Assertions guard against bugs — conditions the programmer believed could never happen in correct code. Exceptions, by contrast, handle failures that can occur even when the code is correct.

2. A JavaScript test writer expects console.assert(factorial(5) === 120) to halt the test loudly if factorial is broken. If factorial(5) actually returns 100, what happens?

console.assert only logs a warning and lets execution continue — it never actually stops anything. That's exactly why real tests use Node's assert module (or a framework) instead, which throws on failure.

3. Which of the following best describes what a unit test checks?

A unit test targets one small unit — often a single function like factorial — in isolation from the rest of the program.

4. A bug only shows up occasionally, and it isn't yet clear what triggers it. What should happen before anything else, per this unit's debugging strategy?

A bug that can't be reliably triggered is very hard to confirm has actually been fixed — reproducing it comes first.

5. Fill in the blank: when no error message points to the mistake, checking a value halfway through the suspect code and repeatedly narrowing to the half where things went wrong is a technique called doing a ___ — the same idea as Unit 5's binary search.

Bisecting turns "somewhere in this function" into the exact line in a handful of steps, whether or not a clear error exists.

6. Assertions are not equally reliable across these four languages. Answer both parts:

(a) Which language's assert keyword does nothing at all unless the program is deliberately run with an extra flag?

(b) Fill in the blank: in C++, assert() is stripped out entirely in release builds when the ___ macro is defined.

(a) Java's assert is off by default — it needs -ea to run at all — the opposite direction from Python (on by default, disabled with -O) and C++ (present unless NDEBUG strips it). (b) NDEBUG is exactly the macro C++ release builds define to remove assert() entirely.

7. A developer considers using an assert statement to validate a user-entered age, instead of raising an exception. Answer both parts:

(a) What's the main risk of validating input this way?

(b) Fill in the blank: unlike an assertion, which should only guard against bugs that could never happen in correct code, an exception represents a failure that can happen even in ___ code, such as receiving bad user input.

(a) Java's -ea requirement and C++'s NDEBUG stripping mean the check can vanish in exactly the builds shipped to users. (b) Exceptions handle failures that happen even in bug-free code; assertions exist for the opposite case.

8. Real projects rarely keep hand-writing test functions like testFactorial forever. Answer both parts:

(a) What does a dedicated test framework like pytest or JUnit add on top of plain hand-written assertions?

(b) Fill in the blank: the Java test framework named in this unit, used to automatically discover and run tests, is ___.

(a) Frameworks turn a pile of individual test functions into one automated, reportable run — that's their real value over plain asserts. (b) JUnit is Java's dedicated test framework, alongside pytest for Python, Jest/Mocha for JavaScript, and Google Test/Catch2 for C++.

9. A bug produces a clear error message and stack trace. Answer both parts:

(a) What should be done with that error and stack trace?

(b) Fill in the blank: once bisecting narrows a bug down enough, pausing execution at a specific line using a debugger's ___ is usually faster than sprinkling print statements.

(a) A stack trace names the exact line and the call chain leading to it — that's exactly what makes it worth reading first. (b) Breakpoints let a debugger pause and inspect state directly at any line.

10. The same off-by-one loop — reading one index past the end of an array — behaves differently in each language. Answer both parts:

(a) Which language's behavior here carries no guarantee at all — it might print garbage, might crash, or might appear to work?

(b) Fill in the blank: instead of crashing or throwing an error, JavaScript silently returns ___ for the out-of-range index and keeps running.

(a) C++'s [] gives no promise of any error at all — the true outlier. Python and Java fail loudly with a real error; JavaScript fails quietly but predictably. (b) JavaScript returns undefined for an out-of-range index rather than throwing, which is what makes the wrong value dangerous — it flows forward silently.
