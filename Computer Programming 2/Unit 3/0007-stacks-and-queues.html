Stacks and Queues

Computer Programming 1's lists could grow and shrink from anywhere. These two structures deliberately restrict where you're allowed to touch them — and that restriction is the point.

Lesson 8 → Contents Glossary →

A stack only lets you add or remove from one end — the last thing pushed on is the first thing to come off, a rule called LIFO (last-in, first-out). Push 1, 2, 3 and pop, and you always get 3 back first.

Python 
stack = []
stack.append(1)
stack.append(2)
stack.append(3)
print(stack.pop())  # 3
Java 
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
stack.push(3);
System.out.println(stack.pop()); // 3
JavaScript 
let stack = [];
stack.push(1);
stack.push(2);
stack.push(3);
console.log(stack.pop()); // 3
C++ 
std::stack<int> s;
s.push(1);
s.push(2);
s.push(3);
std::cout << s.top() << std::endl; // 3
s.pop(); // removes it — pop() itself returns nothing

A queue is the opposite restriction: add at one end, remove from the other — FIFO (first-in, first-out). Enqueue 1, 2, 3 and dequeue, and you get 1 back first.

Python 
from collections import deque
queue = deque()
queue.append(1)
queue.append(2)
queue.append(3)
print(queue.popleft())  # 1
Java 
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1);
queue.offer(2);
queue.offer(3);
System.out.println(queue.poll()); // 1
JavaScript 
let queue = [];
queue.push(1);
queue.push(2);
queue.push(3);
console.log(queue.shift()); // 1
C++ 
std::queue<int> q;
q.push(1);
q.push(2);
q.push(3);
std::cout << q.front() << std::endl; // 1
q.pop();

Two details worth flagging. First, C++'s pop() on both std::stack and std::queue returns nothing at all — you must read the value with top() or front() first, then call pop() separately to remove it. Every other language here combines "read and remove" into a single call. Second, Python's queue example deliberately avoids using a plain list — removing from the front of a list (pop(0)) has to shift every remaining element down by one, making it slow for large queues. Python's collections.deque is built specifically to make both ends fast, and JavaScript's array-based queue above has that exact same shifting cost with no built-in alternative — worth knowing if a queue ever needs to hold a very large number of items.

Definition A stack is LIFO: last in, first out. A queue is FIFO: first in, first out. Both restrict access to specific ends, trading the flexibility of a general-purpose list for a guaranteed, predictable order of removal.
Why it matters here An undo history is a stack — the most recent action is always the one undone first. A print queue or a task queue is a queue — the first job submitted is the first one handled. Picking the structure that matches the real access pattern isn't a style choice; it's what makes the code both correct and fast without extra bookkeeping.

Check your recall

1. If you push 1, 2, then 3 onto a stack and pop once, what do you get?

LIFO: last in, first out.

2. If you enqueue 1, 2, then 3 onto a queue and dequeue once, what do you get?

FIFO: first in, first out — the opposite order from a stack.

3. Why does the Python queue example use collections.deque instead of a plain list?

deque is built to make operations at both ends fast, unlike a plain list's front-removal cost.

4. Fill in the blank: a stack's removal order is called ___ (last in, first out).

5. Fill in the blank: a queue's removal order is called ___ (first in, first out).

The opposite order from a stack's LIFO.
