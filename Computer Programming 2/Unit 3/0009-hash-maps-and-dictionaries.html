Hash Maps and Dictionaries

A linked list finds something by walking the whole chain. This structure finds it in roughly one step, no matter how much data it holds.

Lesson 10 → Contents Glossary →

A hash map stores key-value pairs. Instead of searching for a key, it converts the key into a number — a hash — and uses that number to jump almost directly to the right storage slot. That's why lookup, insertion, and deletion all run in roughly constant time on average, regardless of how many entries exist.

Python 
ages = {"Alice": 30, "Bob": 25}
ages["Carol"] = 40
print(ages["Alice"])  # 30
Java 
Map<String, Integer> ages = new HashMap<>();
ages.put("Alice", 30);
ages.put("Bob", 25);
ages.put("Carol", 40);
System.out.println(ages.get("Alice")); // 30
JavaScript 
let ages = new Map();
ages.set("Alice", 30);
ages.set("Bob", 25);
ages.set("Carol", 40);
console.log(ages.get("Alice")); // 30
C++ 
std::unordered_map<std::string, int> ages;
ages["Alice"] = 30;
ages["Bob"] = 25;
ages["Carol"] = 40;
std::cout << ages["Alice"] << std::endl; // 30

Python's dict, Java's HashMap, JavaScript's Map, and C++'s unordered_map are all hash maps under different names. C++'s name is the most literal: it also has a std::map, which keeps keys in sorted order using a tree instead of a hash table, trading that average constant-time lookup for guaranteed-ordered iteration at O(log n) per operation — the "unordered" in unordered_map is what signals "this one's the hash map." JavaScript deserves one more note: plain {} objects can also hold key-value pairs and are extremely common for this, but they carry inherited properties from Object.prototype that can collide with certain keys — Map avoids that entirely and is the more deliberate choice when a lookup structure is really what you mean.

Definition A hash map (hash table) stores key-value pairs, using a hash of each key to jump directly to its storage slot — giving average constant-time lookup, insertion, and deletion.
Why it matters here This unit covered three structures, each optimized for a different access pattern: a stack for last-in-first-out, a queue for first-in-first-out, a linked list for cheap insertion anywhere, and now a hash map for near-instant lookup by key. None of them is the "best" structure — each is the right tool for a specific job, and picking correctly is exactly what Unit 5's look at algorithmic complexity will give you the vocabulary to justify precisely.

2. What does the "unordered" in C++'s unordered_map signal, compared to std::map?

std::map is tree-based and keeps keys sorted, at O(log n) per operation instead of average O(1).

3. Why might JavaScript's Map be a more deliberate choice than a plain {} object for a lookup structure?

Both are common in real JavaScript code, but Map signals "this is a lookup structure" more precisely.
