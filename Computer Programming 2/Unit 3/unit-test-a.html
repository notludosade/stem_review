1. If you push 5, then 10, then 15 onto a stack, what does the first pop() return?

LIFO: last in, first out — 15 was the last value pushed, so it's the first one popped.

2. Fill in the blank: a queue's removal order — first in, first out — is abbreviated ___.

The opposite order from a stack's LIFO.

3. What does each node in a singly linked list store?

Each node only knows about the one node that comes immediately after it.

4. What do you call the first node in a linked list, from which the rest of the chain is reached?

Losing the head reference without saving it elsewhere means losing access to the entire list.

5. How does a hash map achieve average constant-time lookup by key?

This is what gives hash maps their average constant-time performance, unlike a linear search through a list.

6. Both parts trace the same push/pop and enqueue/dequeue pattern in two different languages:

(a) In Python: stack = []; stack.append(10); stack.append(20); stack.append(30); print(stack.pop()); print(stack.pop()) — what prints, in order?

(b) In JavaScript: let queue = []; queue.push(10); queue.push(20); queue.push(30); console.log(queue.shift()); console.log(queue.shift()); — what prints, in order?

(a) A stack's pop() always removes the most recently pushed value first: 30, then 20. (b) An array used as a queue removes from the front with shift(): 10, then 20, in the order they were enqueued.

7. Both parts are about C++'s split "read" and "remove" operations:

(a) In C++, what does std::stack's pop() method return?

(b) Fill in the blank: to read then remove the top element of a C++ std::stack, you call top() first, then call ___() separately to remove it.

(a)/(b) Every other language here combines "read and remove" into a single call, but C++'s std::stack and std::queue split them into top()/front() plus a separate, value-less pop().

8. Both parts are about inserting new nodes at the front of a chain:

(a) head = Node(5); head = Node(1, head); head = Node(0, head); print(head.value, head.next.value, head.next.next.value) — what prints?

(b) Why is this front-insertion cheap regardless of how many nodes already exist in the chain?

(a) Each new Node becomes the head with next pointing at the old head, so walking from the final head gives 0, then 1, then 5. (b) Contrast this with an array-backed list, where inserting at the front shifts every existing element over by one.

9. Both parts are about C++'s two map types:

(a) What does C++'s std::map (as opposed to std::unordered_map) use internally to keep keys in sorted order?

(b) What does the word "unordered" in unordered_map specifically signal?

(a) std::map is tree-based and keeps keys sorted, at O(log n) per operation instead of hash-based average O(1). (b) "unordered" is what signals "this one's the hash map" — the plain std::map name is reserved for the ordered, tree-based version.

10. Both parts are about matching a real access pattern to the right structure from this unit:

(a) An undo history, where the most recently performed action must always be the first one undone, is best modeled by which structure?

(b) Fill in the blank: in JavaScript, using a plain {} object as a lookup table risks key collisions with inherited properties from Object.___, which is exactly what Map avoids.

(a) The most recent action undone first is exactly LIFO — a stack, the same pattern as an undo button in most real apps. (b) Object.prototype properties can collide with certain keys in a plain object; Map avoids that entirely.
