1. In Java, if you call stack.push(1); stack.push(2); stack.push(3); on a Deque used as a stack, what does stack.pop() return?

LIFO: the last item pushed — 3 — is the first one popped.

2. Fill in the blank: enqueuing 7, then 8, then 9, and then dequeuing once returns 7 — this removal order is called ___.

The first item enqueued is the first one dequeued — first in, first out.

3. In C++'s struct Node { int value; Node* next; ... };, what does the next member store?

A singly linked list's next only ever points forward, to the one node that comes after it.

4. If you lose the reference to a linked list's head without saving it elsewhere first, what happens?

The list itself is just a reference to the head — losing that reference loses the whole chain, since each node only knows about the one after it.

5. Unlike a hash map, a linked list finds a specific value by which method?

A linked list has no direct indexed access — reaching any position, or finding any value, means following next from the head one step at a time.

6. Both parts trace the same push/pop and offer/poll pattern in two different languages:

(a) In C++: std::stack<int> s; s.push(4); s.push(8); s.push(12); std::cout << s.top() << std::endl; s.pop(); std::cout << s.top() << std::endl; — what prints, in order?

(b) In Java: Deque<Integer> queue = new ArrayDeque<>(); queue.offer(4); queue.offer(8); queue.offer(12); System.out.println(queue.poll()); System.out.println(queue.poll()); — what prints, in order?

(a) top() reads the most recently pushed value without removing it; after one pop(), the next-most-recent becomes the top: 12, then 8. (b) A Deque used as a queue with offer/poll removes in the order items were added: 4, then 8.

7. Both parts are about C++'s split "read" and "remove" operations on a queue:

(a) In C++, what must you do before calling pop() on a std::queue, if you want to know what value is being removed?

(b) Fill in the blank: in C++, std::queue lets you read the front element with front(), then remove it separately by calling ___().

(a)/(b) std::queue uses front() to read the next value to be removed and a separate, value-less pop() to actually remove it — unlike Python, Java, and JavaScript, which combine both in one call.

8. Both parts are about inserting a new node at the front of a chain:

(a) head = Node(9); head = Node(3, head); print(head.value); print(head.next.value) — what prints, in order?

(b) Compare inserting at the front of a linked list to inserting at the front of an array-backed list of the same length. What's different?

(a) The new node (value 3) becomes head with next pointing at the old head (value 9), so head.value is 3 and head.next.value is 9. (b) An array's front-insertion shifts every remaining element down by one; a linked list's front-insertion touches only the new node and the head reference.

9. Both parts are about choosing between C++'s two map types:

(a) Which of C++'s two map types would you choose if you needed to iterate over key-value pairs in sorted key order?

(b) What performance trade-off does std::map accept in exchange for guaranteed sorted iteration order?

(a) std::map's tree-based structure is what keeps keys sorted, unlike unordered_map's hash table. (b) That sorted order costs O(log n) per operation, compared to unordered_map's average O(1).

10. Both parts are about matching a real access pattern to the right structure from this unit:

(a) A print queue, where the first job submitted must always be the first one handled, is best modeled by which structure?

(b) Fill in the blank: JavaScript's Map class is often a more deliberate choice than a plain {} object for a lookup table because plain objects inherit properties from Object.prototype that can ___ with certain keys.

(a) The first job submitted being the first one handled is exactly FIFO — a queue, the same pattern as a task queue. (b) Object.prototype properties can collide with certain keys in a plain object; Map avoids that entirely.
