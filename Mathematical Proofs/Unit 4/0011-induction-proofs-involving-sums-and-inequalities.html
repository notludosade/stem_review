Induction Proofs Involving Sums and Inequalities

The same base case / inductive step skeleton from Lesson 10, run on a longer sum formula and then on an inequality — where the base case doesn't even have to be n = 1.

← Lesson 10 Lesson 12 → Contents Glossary →

Lesson 10's sum formula was the simplest possible induction target. This lesson runs the same two-step skeleton on a sum with more moving parts, and then on an inequality — where the base case is free to start wherever the claim actually first becomes true, not necessarily at n = 1.

Theorem — Sum of Squares For every natural number n ≥ 1, 1² + 2² + ⋯ + n² = n(n+1)(2n+1)/6.
Proof Base case (n=1): left side = 1; right side = 1(2)(3)/6 = 1. Equal.
Inductive step: assume 1² + 2² + ⋯ + k² = k(k+1)(2k+1)/6 for some k ≥ 1 (inductive hypothesis). Then 1² + ⋯ + k² + (k+1)² = k(k+1)(2k+1)/6 + (k+1)². Factor out (k+1): = (k+1)[k(2k+1)/6 + (k+1)] = (k+1)[k(2k+1) + 6(k+1)]/6 = (k+1)(2k² + 7k + 6)/6 = (k+1)(k+2)(2k+3)/6. This matches n(n+1)(2n+1)/6 with n = k+1. So P(k) → P(k+1). By induction, the formula holds for all n ≥ 1. ∎
Why "factor out (k+1) first" is the entire strategy Every induction proof of a sum formula has the identical shape: the inductive hypothesis replaces the first k terms with a closed formula, one new term gets added, and then algebra has to reshape the result into P(k+1)'s target formula. Factoring out (k+1) immediately — rather than expanding everything and hoping it simplifies — is what turns a messy cubic into the recognizable (k+1)(k+2)(2k+3)/6 shape. Knowing the target shape in advance is what tells you which factoring move to make.

Induction on an inequality — and a base case that isn't 1

Theorem For every integer n ≥ 4, n! > 2ⁿ.
Why the base case is n = 4, not n = 1 Check small cases directly: 1! = 1 vs 2¹ = 2 (claim false); 2! = 2 vs 2² = 4 (false); 3! = 6 vs 2³ = 8 (false); 4! = 24 vs 2⁴ = 16 (true, finally). The claim is simply false for n = 1, 2, 3 — induction can only ever prove what's actually true, and starting the base case at n = 4 is not a stylistic choice, it's the first point where P(n) holds at all. Induction proves P(n) for all n at or above whatever base case you can actually establish.
Proof Base case (n=4): 4! = 24 and 2⁴ = 16, and 24 > 16. True.
Inductive step: assume k! > 2ᵏ for some k ≥ 4 (inductive hypothesis). Then (k+1)! = (k+1) · k! > (k+1) · 2ᵏ, using the inductive hypothesis. Since k ≥ 4, k+1 ≥ 5 > 2, so (k+1) · 2ᵏ > 2 · 2ᵏ = 2ᵏ⁺¹. Chaining the two inequalities: (k+1)! > 2ᵏ⁺¹. So P(k) → P(k+1). By induction, n! > 2ⁿ for every integer n ≥ 4. ∎
Why the direction of every inequality had to be tracked carefully An inequality-induction proof lives or dies on multiplying or adding the right quantity on the right side without ever silently flipping a direction. The step (k+1)·2ᵏ > 2·2ᵏ relies specifically on k+1 > 2, which is exactly where the hypothesis k ≥ 4 gets used — try this same proof with a claimed base case of k ≥ 0 and this step breaks immediately, since k+1 isn't guaranteed to exceed 2 for small k.

1. For the sum of squares formula, what does the base case n = 1 check?

Plugging n = 1 into both sides of the claimed formula and confirming they match (both equal 1) is exactly the base case.

2. Why can't the theorem "n! > 2ⁿ" be proved by induction starting at n = 1?

The claim is simply false for n = 1, 2, and 3 — the base case has to be a value where the statement is actually true, which here first happens at n = 4.

3. Fill in the blank: in the inductive step of the n! > 2ⁿ proof, the key inequality uses k + 1 ≥ ___, which follows from k ≥ 4.

k ≥ 4 gives k + 1 ≥ 5, which is what guarantees (k+1)·2ᵏ > 2·2ᵏ in the next step.

4. In the sum-of-squares inductive step, after substituting the inductive hypothesis, what is the very next algebraic move made?

Factoring out (k+1) immediately, rather than expanding blindly, is what makes the algebra land on the recognizable (k+1)(k+2)(2k+3)/6 form.

5. Fill in the blank: the inequality n! > 2ⁿ is proved by induction starting at the base case n = ___.

n = 4 is the first value where n! actually exceeds 2ⁿ, so that's where the base case has to be set.
