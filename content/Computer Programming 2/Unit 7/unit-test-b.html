Unit 7 Test — Version B

1. A team debates whether a failed assertion and a caught exception mean the same thing. What's the actual distinction?

Assertions document an assumption that must always hold in correct code. Exceptions are for failures — like a missing file — that can happen regardless of whether the code is correct.

2. Which statement correctly contrasts JavaScript's console.assert with Node's built-in assert module, as used for testing?

A real test needs to actually fail when something is wrong — console.assert can't do that, since it never stops anything.

3. A programmer writes testFactorial(), which calls factorial(0) and factorial(5) and asserts each returns the correct value. What kind of test is this?

testFactorial targets factorial specifically — exactly the "one small piece of code" a unit test is defined by.

4. A crash happens somewhere in a large program, but the exact cause isn't obvious yet. What's the recommended first move, before reading any error message?

Reproducing the bug on demand comes first — without that, it's very hard to confirm a fix actually worked.

5. Fill in the blank: the technique of checking a value halfway through suspect code, then repeatedly narrowing to the half where things went wrong, is compared in this unit to Unit 5's binary search — the technique itself is called doing a ___.

This is binary search applied to a bug's location instead of a sorted list — the same halving idea, a different target.

6. Different languages give very different guarantees about whether an assert statement actually runs. Answer both parts:

(a) Which language's assert() is stripped out entirely from compiled code in release builds?

(b) Fill in the blank: Python's assert statements can be globally disabled by running the interpreter with the ___ flag.

(a) C++'s assert() vanishes entirely once NDEBUG is defined for a release build — Java's -ea instead controls whether assertions are enabled at all, the opposite direction. (b) Python's -O flag globally disables assert statements.

7. A team debates checking a network request's user-supplied email using an assert statement instead of proper validation. Answer both parts:

(a) Why is the assert approach a poor fit here, especially in Java or C++?

(b) Fill in the blank: assertions guard against bugs that should be impossible in correct code; a proper ___ instead handles a failure — like bad input — that can happen even in correct code.

(a) Assertions can vanish silently in a release build in exactly the languages where user input validation would matter most. (b) Exceptions are the tool for expected failures; assertions are for bugs.

8. A team moves away from calling hand-written test functions manually and adopts a dedicated tool to manage all their tests instead. Answer both parts:

(a) What capability does this shift give the team that hand-rolled test functions alone don't?

(b) Fill in the blank: the Python test framework built into the standard library, mentioned alongside pytest, is ___.

(a) Automatic discovery and a clear pass/fail report are exactly what a framework adds over plain hand-written assertions. (b) unittest ships with Python itself, alongside the separately installed pytest.

9. A Java program throws an ArrayIndexOutOfBoundsException along with a full stack trace. Answer both parts:

(a) What should be done with that stack trace?

(b) Fill in the blank: when there's no clear error to read, a debugger's ___ let a programmer pause execution at a specific line and inspect state directly.

(a) A stack trace names the exact line and call chain — reading it is usually the fastest path once one exists. (b) Breakpoints are usually faster than sprinkling print statements once bisection has narrowed the search.

10. The same off-by-one bug — a loop reading one index past the end of an array — runs in both a Python version and a C++ version. Answer both parts:

(a) What happens in the Python version?

(b) Fill in the blank: the same bug in C++, using operator[], produces ___ behavior — it might print garbage, might crash, or might appear to work, with no guarantee either way.

(a) Python fails loudly with a clear IndexError and traceback. (b) C++'s operator[] gives no such promise — this is exactly what "undefined behavior" means.
