1. What does each individual thread still keep private to itself, even inside a multithreaded process?

Each thread still needs its own stack to track its own local variables and call history independently.

2. A video game's rendering thread and physics thread both need to read and write the same game-world data. Why is this cheap and direct, compared to doing it across two separate processes?

Shared heap access is exactly what makes cooperating threads cheaper and simpler than cooperating processes.

3. What is a race condition?

Race conditions depend on exactly how threads' steps happen to interleave at run time.

4. Fill in the blank: the specific outcome where two threads each increment a shared counter, but one increment is silently overwritten by the other's stale write, is called a ___.

A lost update is the classic, concrete symptom of an unprotected shared counter race condition.

5. What happens if a thread tries to lock a mutex that another thread currently holds?

Blocking is exactly how a mutex enforces that only one thread's critical section runs at a time.

6. Compare creating a new thread to creating a new process. Answer both parts:

(a) Does creating a new thread require setting up a brand-new, isolated address space?

(b) Does creating a new process require setting up a brand-new, isolated address space?

Skipping full address-space isolation is exactly what makes thread creation lighter weight than process creation.

7. A race condition shows up once in ten thousand production runs, but never during local testing. Answer both parts:

(a) Does this mean the bug wasn't real during local testing?

(b) Why might heavier production load make the bad interleaving more likely?

Race conditions can hide behind mostly-correct interleavings for a long time before surfacing under heavier, more varied load.

8. Answer both parts about protecting shared data:

(a) Fill in the blank: the object that must be locked before entering a critical section, and unlocked afterward, is a ___.

(b) Why does wrapping the read-add-write sequence in a mutex fix the lost-update bug?

A mutex doesn't speed anything up — it guarantees the critical section can't be interrupted by another thread's critical section.

9. What is a deadlock? Answer both parts:

(a) Which of these describes it?

(b) Does adding more locking to a program automatically make it safer from every concurrency bug?

Locks solve race conditions but introduce deadlock as a brand-new possible failure mode of their own.

10. A process starts with exactly one thread. Answer both parts:

(a) What is that starting thread usually called?

(b) Fill in the blank: once more threads are added, the process is described as ___.

Every process starts with one main thread; a multithreaded process has simply added more, all sharing its heap.
