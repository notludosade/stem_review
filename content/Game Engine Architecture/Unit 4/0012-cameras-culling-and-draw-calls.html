Cameras, Culling, and Draw Calls

A large open-world scene might contain tens of thousands of objects. The player's screen shows a few hundred at most, at any given moment. This lesson is about the step that decides which is which, before Lesson 10's pipeline ever gets involved.

← Lesson 11 Unit 5, Lesson 13 → Contents Glossary →

Sending every object in a scene through the full render pipeline every frame, whether the camera can actually see it or not, would waste enormous amounts of GPU time on work whose result is invisible. Culling is the fix.

The frustum, and throwing away what's outside it

Definition A camera defines the viewpoint a scene renders from — position, direction, and field of view. The view frustum is the pyramid-shaped (truncated at a near and far plane) region of space the camera can actually see. Frustum culling discards any object entirely outside that region before rendering, so the pipeline never spends work on it. Each remaining, visible object typically costs one draw call — an instruction telling the GPU "render this object now" — and since each draw call carries its own fixed overhead, fewer, larger draw calls generally outperform many tiny ones, even at an identical total triangle count.

Worked example An open-world game might have 50,000 objects in its scene graph total, but the camera standing in a canyon can geometrically see at most a few thousand of them — everything behind the canyon walls, or simply outside the field of view, is culled before the GPU ever touches it. If the engine skipped culling and issued a draw call for all 50,000 objects every frame regardless of visibility, most of that GPU work would be entirely wasted on triangles that end up nowhere on screen.
Why draw call count matters even at a fixed triangle count It's tempting to think only total triangle count determines render cost, but issuing a draw call itself has fixed overhead — the CPU has to prepare and submit state to the GPU for each one, and that overhead doesn't shrink just because the object is small. A scene with 1,000 tiny separate draw calls can be slower than an equivalent scene with 10 large ones, even with the same total triangles — which is why engines often batch multiple small objects into fewer, larger draw calls wherever the scene allows it.

1. What does frustum culling actually do?

Culling removes invisible objects from the render workload, not from the scene itself.

2. Why can 1,000 tiny separate draw calls be slower than 10 large ones with the same total triangle count?

Per-draw-call overhead is fixed, so fewer, larger calls tend to outperform many small ones.

3. What is the view frustum?

The frustum is specifically the camera's visible region in space.

4. Fill in the blank: an instruction telling the GPU to render one object, typically issued once per visible object, is called a ___.

A draw call is the per-object instruction submitted to the GPU.

5. Fill in the blank: discarding objects outside the camera's visible region before they reach the render pipeline is called ___.
