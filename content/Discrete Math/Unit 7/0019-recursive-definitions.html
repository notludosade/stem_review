Recursive Definitions

This closing unit ties the whole course together: counting, graphs, and number theory all leaned on facts that were never actually proven, just asserted. Unit 7 supplies the missing proof technique — starting here, with how to define something in terms of a smaller version of itself.

1. Recursive definitions

Definition — Recursive Definition A recursive definition defines a sequence or structure in two parts: one or more base cases, giving the value(s) directly, and a recursive rule, defining every later term in terms of earlier ones. Every recursive definition needs both parts — the recursive rule alone never bottoms out to an actual value without a base case to stop at.
Worked example — factorial 0! = 1 (base case). n! = n · (n−1)! for n ≥ 1 (recursive rule). Unwinding: 4! = 4·3! = 4·3·2! = 4·3·2·1! = 4·3·2·1·0! = 4·3·2·1·1 = 24 — the same factorial from Lesson 8, now defined by referring to itself on a smaller input instead of written as a single product formula.
Worked example — the Fibonacci sequence F(0) = 0, F(1) = 1 (base cases — this one needs two, since the recursive rule below looks back two terms). F(n) = F(n−1) + F(n−2) for n ≥ 2 (recursive rule). This generates 0, 1, 1, 2, 3, 5, 8, 13, 21, ... — each term built entirely from the two before it.

2. Recursively defined sets

Recursive definitions apply to sets too, not just sequences This course's own convention for ℕ (Lesson 4) can itself be stated recursively: 0 ∈ ℕ (base case); if n ∈ ℕ, then n + 1 ∈ ℕ (recursive rule). Every natural number is reachable by starting at 0 and applying "+1" some finite number of times — which is exactly the structure Lesson 20's induction proofs exploit directly.
Why this lesson exists before induction A recursive definition and a proof by induction are the same shape, wearing different clothes: a base case plus a rule that reaches every case from a smaller one. Lesson 20 formalizes induction as a proof technique; this lesson makes sure the object being reasoned about — a recursively-defined sequence or set — is itself already understood as "base case, plus a rule that builds everything else from something smaller." Without this lesson, induction would be a proof technique with nothing natural to apply it to.

1. Why does every recursive definition need at least one base case?

The recursive rule only ever refers to smaller cases of itself — without a base case to stop at, unwinding it never terminates in an actual value.

2. Why does the Fibonacci definition need two base cases (F(0) and F(1)), unlike factorial's one?

Since F(n) depends on both F(n−1) and F(n−2), unwinding down to n=1 still needs F(0) directly given — a single base case wouldn't cover both values the recursive step needs.

3. Using this course's recursive definition of ℕ (0 ∈ ℕ; if n ∈ ℕ then n+1 ∈ ℕ), how is every natural number reached?

Every natural number is 0 plus some finite number of "+1" applications — exactly the base case plus recursive rule structure.

4. Fill in the blank: the part of a recursive definition that gives a value directly, without referring back to the definition itself, is called the ___.

The base case is the non-recursive anchor a recursive definition needs to actually terminate at a value.

5. Fill in the blank: using F(0)=0, F(1)=1, F(n)=F(n−1)+F(n−2), the sequence is 0, 1, 1, 2, 3, 5, ___.

F(6) = F(5) + F(4) = 5 + 3 = 8.
