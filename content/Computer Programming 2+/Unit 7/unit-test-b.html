1. In the subsets recursion, what happens immediately after backtrack(i + 1) returns inside the for loop?

Popping the most recent choice restores path to a clean state so the loop's next iteration can try a different number in its place.

2. Consider subsets([1, 2, 3]) using Lesson 23's backtracking algorithm. Answer both parts:

(a) How many total subsets does it return?

(b) Fill in the blank: listing all 2ⁿ subsets this way is unavoidably ___ time, since the answer itself has that many entries.

(a) 2³ = 8 — every combination of include/exclude across 3 elements produces one distinct subset. (b) No algorithm can list 2ⁿ results in fewer than roughly 2ⁿ steps, so this is inherently exponential.

3. Why can permutations place any unused number at each step, while subsets only ever consider numbers from a forward-moving start index?

Since {1, 2} and {2, 1} count as the same subset but different permutations, subsets can safely move forward only, while permutations must track usage instead.

4. Fill in the blank: in Combination Sum, checking candidates[i] > remaining and abandoning that branch immediately — rather than continuing to explore it — is an example of ___.

Recognizing failure before fully exploring a doomed branch is exactly what pruning means.

5. Trace combination_sum([2, 3, 5], target=8). Answer both parts:

(a) Which three combinations appear in the result?

(b) Fill in the blank: recursing with the same index rather than i + 1 lets each candidate be ___ multiple times.

(a) 2+2+2+2=8, 2+3+3=8, and 3+5=8 are the only three non-decreasing ways to reach 8 from {2, 3, 5} with repetition allowed; the last option is missing the third combination, a common trap when stopping the trace early. (b) Passing the same index forward is exactly what lets a candidate appear more than once in one combination.

6. In Combination Sum, what would go wrong if the loop used break to prune without first sorting the candidates array?

break only skips every remaining candidate safely because ascending order guarantees they're all at least as large as the one just checked — without sorting, that guarantee disappears.

7. Suppose Word Search's recursion never restored board[r][c] after trying a direction. Answer both parts:

(a) What would go wrong?

(b) Fill in the blank: marking a cell as visited before recursing into its neighbors is the ___ step, later undone by restoring it.

(a) Since the board is reused across every starting cell and every direction, a permanently blocked cell from one failed attempt would incorrectly rule out otherwise-valid later attempts. (b) Marking board[r][c] = '#' is the choose step; restoring it afterward is the matching unchoose.

8. Consider backtrack(r, c, i) inside exist(board, word). Answer both parts:

(a) If i reaches word.length() during the recursion, what does that indicate?

(b) Which single condition, if true, guarantees backtrack returns true without recursing any further?

(a) Reaching the end of the word means every prior letter matched in order, so nothing further needs checking. (b) The i == word.length() check is the very first line of the function, returning true immediately before any bounds or letter check even runs.

9. Why is Word Search's exponential worst-case runtime rarely actually reached in practice?

A single mismatched letter fails a branch on the spot, so in practice far fewer than 4^L paths per starting cell ever get explored.

10. Consider what happens to the remaining parameter as combination_sum recurses. Answer both parts:

(a) Fill in the blank: instead of tracking a running sum directly, the recursion tracks how much of the target is still ___ to be reached.

(b) In a version of this code without the prune, if remaining became negative partway through, what has gone wrong?

(a) Tracking what's left rather than a running total is the same trick as Lesson 14's path-sum problems. (b) Since every candidate is positive, an overshoot can only get worse from there — exactly the situation the prune exists to catch before it happens.
