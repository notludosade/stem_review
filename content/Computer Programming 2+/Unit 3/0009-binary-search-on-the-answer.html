Binary Search on the Answer Space

Some problems never mention an array to search at all — the thing being searched is the space of possible answers.

← Lesson 8 Lesson 10 → Contents Glossary →

Problem: Koko has piles of bananas and h hours to eat them all. Each hour she picks one pile and eats up to k bananas from it (if the pile has fewer than k, she finishes it and stops for the hour). Find the minimum integer k that lets her finish within h hours.

There's no array of "candidate speeds" to search — but there's still a search space: every integer from 1 up to the largest pile size. And it has exactly the property binary search needs: define canFinish(k) as "can Koko finish in time eating at speed k?" — if canFinish(k) is true, it's also true for every speed faster than k. That's a monotonic condition, and monotonicity is the real requirement binary search runs on — sortedness (Lesson 8) is just one common way to get it.

The idea Binary search directly over candidate speeds. For each midpoint speed, simulate whether Koko finishes in time. If she does, that speed (or something smaller) might work — search lower. If she doesn't, search higher.
Python 
import math

def min_eating_speed(piles, h):
    def hours_needed(speed):
        return sum(math.ceil(p / speed) for p in piles)

    left, right = 1, max(piles)
    while left < right:
        mid = (left + right) // 2
        if hours_needed(mid) <= h:
            right = mid       # mid works; try slower
        else:
            left = mid + 1    # mid too slow; go faster
    return left
Java 
int minEatingSpeed(int[] piles, int h) {
    int left = 1, right = 0;
    for (int p : piles) right = Math.max(right, p);
    while (left < right) {
        int mid = (left + right) / 2;
        long hours = 0;
        for (int p : piles) hours += Math.ceil((double) p / mid);
        if (hours <= h) right = mid;   // mid works; try slower
        else left = mid + 1;             // mid too slow; go faster
    }
    return left;
}
JavaScript 
function minEatingSpeed(piles, h) {
  let left = 1, right = Math.max(...piles);
  while (left < right) {
    const mid = Math.floor((left + right) / 2);
    const hours = piles.reduce((sum, p) => sum + Math.ceil(p / mid), 0);
    if (hours <= h) right = mid;   // mid works; try slower
    else left = mid + 1;             // mid too slow; go faster
  }
  return left;
}
C++ 
int minEatingSpeed(std::vector<int>& piles, int h) {
    int left = 1, right = *std::max_element(piles.begin(), piles.end());
    while (left < right) {
        int mid = (left + right) / 2;
        long long hours = 0;
        for (int p : piles) hours += (p + mid - 1) / mid; // ceiling division
        if (hours <= h) right = mid;   // mid works; try slower
        else left = mid + 1;             // mid too slow; go faster
    }
    return left;
}

Each check costs O(piles) to simulate, and the search space of size O(max pile) is halved every step — O(piles · log(max pile)) total, dramatically better than trying every speed one by one starting from 1.

Why it matters here "Binary search the answer" is one of the highest-leverage patterns for competitive programming specifically: it turns any problem of the shape "find the minimum/maximum value for which some condition holds" into O(log(range)) checks, as long as the condition is monotonic — true past some threshold and false before it (or vice versa). Recognizing that shape — rather than the presence of a sorted array — is the actual skill.
