Design Intent — Editing a Feature Tree Without Breaking Downstream Features

Every CAD user eventually deletes or resizes a feature and watches three other features turn red. This lesson is about why that happens, and how to design so it happens less.

← Lesson 5 Unit 3, Lesson 7 → Contents Glossary →

Lesson 3 introduced the feature tree as a record of what happened, in order. This lesson is about what it takes to change that record safely — which turns out to be the single most common source of frustration in real CAD work.

Parent and child features

Definition A parent feature is one that a later feature depends on for its geometry — a face, edge, sketch plane, or dimension it references. A child feature is the one doing the referencing. A single feature can be a parent to several children, and a child to several parents at once.

Editing or deleting a parent forces every child to recompute against the new (or missing) geometry. If a child referenced something specific — a particular edge, a particular face — that no longer exists in the same form after the edit, the child feature fails to rebuild. Most CAD software makes this visible immediately: the failed feature is flagged, usually in red, in the tree.

Definition Design intent is the plan for how a model is supposed to behave as it's edited — which surfaces, edges, and relationships are meant to stay meaningful as parameters change, and which are just incidental byproducts of how the geometry happens to look right now.
Worked Example — A Broken Reference A bracket has Sketch2 (mounting holes) drawn on the flat top face created by Extrude1. Later, Fillet1 rounds the bracket's front edge. Still later, a designer adds Sketch3 (a label engraving) referencing the new rounded edge that Fillet1 just created, instead of the original flat face. Weeks later, someone increases Fillet1's radius to meet a new safety spec — and Sketch3 fails to rebuild, because the specific edge geometry it was anchored to no longer exists in the same shape. The label engraving is now broken, for a reason that has nothing to do with the label itself.
Why this is the most common real-world CAD frustration A small, reasonable-looking early change — resizing one hole, adjusting one fillet — can cascade into failed features throughout the rest of the tree, often in places that seem unrelated to the change on its face. This isn't a bug; it's the direct consequence of every feature depending on specific geometry left behind by earlier ones. The fix isn't avoiding the feature tree — it's deliberate about which features are safe to reference.

Practices that preserve design intent

Reference stable geometry, not incidental geometry Where possible, reference original, stable faces and named planes rather than edges created by rounding or chamfering operations — those are exactly the features most likely to be tuned later, and least likely to be something a later feature should actually depend on.
Order refinement features last Build a model's rough shape first (the sketches and extrudes that define its basic form), then add refinement features — fillets, chamfers, cosmetic details — toward the end of the tree. Refinement features are the most likely to be tweaked repeatedly during a design's life, and putting them last means tweaking them has nothing built on top of them left to break.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a "child" feature, in feature-tree terms?

A child feature depends on geometry (a face, edge, sketch plane, or dimension) that a parent feature produced.

2. In the worked example, why does increasing Fillet1's radius break Sketch3, even though Sketch3 is nominally about a label engraving, not a fillet?

Sketch3 referenced Fillet1's rounded edge specifically — when that edge's shape changed, the reference Sketch3 depended on no longer matched, so it failed to rebuild.

3. Why is it good practice to place cosmetic features like fillets and chamfers late in the feature tree?

Refinement features like fillets are among the most likely to change during a design's life — ordering them last minimizes how much downstream work depends on geometry that's still likely to move.

4. Fill in the blank: a feature that a later feature depends on for its geometry is called that later feature's ___.

The feature being depended on is the parent; the dependent feature is its child.

5. Fill in the blank: the plan for which relationships in a model should stay meaningful as parameters change, rather than being incidental, is called ___.

Design intent is what separates a model that edits gracefully from one that shatters at the first parameter change.
