Handling Multiple Sensors and Priorities

Real systems rarely have just one input — and not every input deserves an equal vote.

← Lesson 36 Lesson 38 → Contents Glossary →

Both case studies so far used sensors feeding into one single control decision. Real systems often need to watch several sensors at once, and — critically — not all of them should be treated equally.

The key idea: some conditions override, they don’t just contribute A normal control loop blends its inputs into one smooth decision (Units 5–6). A safety condition — a limit switch tripped, a temperature reading past a safe maximum, an over-current detection — shouldn't be blended in as "one more input to average." It should override the normal control output entirely, the moment it's detected.
Example: the temperature-controlled fan, with a safety override added 
loop():
    smoothedTemp = readAndFilterTemp()
    overTempLimit = (smoothedTemp > MAX_SAFE_TEMP)
    switchTripped = (digitalRead(LIMIT_SWITCH_PIN) == LOW)

    if overTempLimit OR switchTripped:
        setPwmDutyCycle(FAN_PWM_PIN, 100)   // full speed, no negotiation
    else:
        error = smoothedTemp - TARGET_TEMP
        output = clamp(Kp * error, 0, 100)
        setPwmDutyCycle(FAN_PWM_PIN, output)

Notice the structure: the safety check runs first, and if it trips, the normal proportional-control math (Lesson 35) never even executes — the override completely bypasses it, rather than being folded into the same calculation. This if/else priority structure, not a weighted blend, is the standard pattern for safety-critical conditions throughout real mechatronic systems.

A lighter idea: combining multiple readings of the same quantity

Definition Sensor fusion is combining readings from multiple sensors (or multiple sensor types) measuring the same or related quantities, to produce a single, more reliable estimate than any one sensor alone would give. A simple example: averaging two redundant temperature sensors so a single sensor's failure or noise doesn't wholly determine the reading.

Sensor fusion can get mathematically sophisticated (weighting sensors by how much each is trusted, for instance) — well beyond this course's scope — but the core idea is worth carrying forward: multiple sensors watching the same thing, combined thoughtfully, beat relying on just one.

1. Why shouldn’t a safety condition (like an over-temperature limit or a tripped limit switch) be blended into a control loop’s normal weighted calculation?

A tripped safety condition demands an immediate, full override — treating it as just one more weighted input would let the normal control math dilute a response that needs to be immediate and complete.

2. In the example pseudocode, what happens to the normal proportional-control calculation if overTempLimit or switchTripped is true?

The if/else structure means the safety branch and the normal control branch are mutually exclusive — the safety override completely bypasses the normal math when triggered.

3. What is sensor fusion?

Sensor fusion combines multiple sensors’ information into a single, more trustworthy estimate — distinct from a safety override, which is about priority, not combining readings.
