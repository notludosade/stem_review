Microcontroller Architecture Basics

CPU, memory, and peripherals, all on one chip — and the two-phase program structure almost every embedded program follows.

← Lesson 12 Lesson 14 → Contents Glossary →

A microcontroller packs several distinct pieces onto a single chip. Knowing what each piece does makes the rest of this course's code and circuits much easier to reason about.

The core pieces The CPU (central processing unit) executes program instructions, one at a time, at a rate set by a clock (a crystal oscillator ticking at a fixed frequency — faster clocks execute instructions faster but draw more power). Flash memory stores the actual program code, and keeps it even with power off (non-volatile). RAM holds working data — variables, sensor readings in progress — but loses everything the instant power is removed (volatile). Some chips also include a small block of EEPROM, non-volatile memory meant for saving small amounts of data (like a calibration constant) across power cycles.

Beyond the CPU and memory, a microcontroller includes peripherals — dedicated hardware blocks for specific jobs, so the CPU doesn't have to do everything in software. The ones this course leans on most: GPIO (general-purpose input/output pins, Lesson 14), an ADC (Unit 1 and Unit 4), and timers capable of generating PWM signals (Unit 4). Many chips also include communication peripherals like UART, I2C, or SPI for talking to other chips — useful in real projects, though outside this course's scope.

Why dedicated peripherals matter Generating a PWM signal purely in software — flipping a pin on and off at exactly the right instants using nothing but CPU instructions — would tie up the processor almost completely and still struggle to keep precise timing. A dedicated timer peripheral generates that same signal in hardware, freeing the CPU to do other work (like reading a sensor) at the same time.

The universal program shape: setup, then loop forever

Because a microcontroller runs one dedicated program with no operating system to return control to, embedded programs follow a distinctive two-phase shape: a setup phase that runs exactly once (configuring pins, initializing peripherals), followed by a loop phase that repeats forever for as long as the chip has power.

Example In pseudocode: setup(): configure pin modes, then loop(): read sensor, decide, write actuator, repeat. This exact shape reappears, filled in with real logic, throughout the rest of this course — it's where a control loop (Unit 5) actually lives in code.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the key difference between a microcontroller’s flash memory and its RAM?

Flash keeps the program code even with power removed; RAM holds temporary working data and loses it the instant power is cut.

2. Why does a microcontroller include a dedicated timer peripheral for generating PWM signals, instead of just doing it in software?

Generating precise, repeating timing purely in software would consume most of the CPU’s attention — a dedicated peripheral handles it in hardware instead.

3. What runs during a microcontroller program’s "loop" phase?

Loop is the repeating phase — it runs over and over for as long as power is applied, in contrast to setup, which runs exactly once.

4. Fill in the blank: the memory that stores a microcontroller’s program code and retains it even with power removed is called ___ memory.

Flash memory is non-volatile — it holds the program between power cycles, unlike RAM.

5. Fill in the blank: dedicated hardware blocks on a microcontroller for specific jobs like timing or analog conversion, so the CPU doesn’t have to do everything in software, are called ___.

Peripherals — GPIO, ADC, timers, and more — offload specific jobs from the CPU into dedicated hardware.
