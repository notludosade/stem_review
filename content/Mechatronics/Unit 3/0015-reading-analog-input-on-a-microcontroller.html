Reading Analog Input on a Microcontroller

Putting Unit 1’s sensors to work — the actual function call that turns a voltage divider’s output into a number your code can use.

← Lesson 14 Lesson 16 → Contents Glossary →

GPIO pins handle HIGH and LOW. Reading one of Unit 1's analog sensors — a thermistor divider, a photoresistor divider — needs a different kind of pin: one connected to the chip's ADC, introduced back in Lesson 1 of this course.

Not every pin on a microcontroller can do this — only a specific subset are wired to the ADC peripheral, and there are usually far fewer of them than there are GPIO pins. This is the scarce-resource trade-off Lesson 1 first raised, now made concrete: plan a sensor layout with that limited count in mind.

Definition Calling an analog-read function (commonly analogRead()) samples the voltage on an ADC-capable pin and returns a raw digital number representing that voltage, scaled across the ADC's resolution — for example, 0 to 1023 on a common 10-bit ADC, exactly as introduced back in Lesson 6 of Unit 1.
Example: reading Unit 1’s thermistor divider 
setup():
    // ADC pins usually need no pinMode() call — they default to analog input

loop():
    raw = analogRead(THERMISTOR_PIN)      // 0-1023 on a 10-bit ADC
    voltage = (raw / 1023.0) * 5.0        // Lesson 6’s raw-to-voltage formula
    // voltage still needs the two-point calibration from Lesson 6
    // before it becomes an actual temperature
Why this lesson is short Nothing here is new physics — it's the same voltage divider from Unit 1, the same raw-count-to-voltage math from Unit 1 Lesson 6, now expressed as one function call inside a real microcontroller program. The point of this lesson is the connection: everything Unit 1 taught about sensors becomes usable the moment it's wrapped in analogRead() and dropped into the loop phase.

One practical detail worth flagging: an analog read takes measurably longer than a digital read — the ADC hardware needs a short settling time to sample and convert. It's not slow enough to matter for most sensor-reading loops in this course, but it's worth knowing it isn't instantaneous the way digitalRead() effectively is.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why can’t every pin on a microcontroller be used for analogRead()?

ADC-capable pins are a limited, dedicated subset of a chip’s total pins — exactly the scarce-resource point raised back in Unit 1, Lesson 1.

2. What does analogRead() return on a 10-bit ADC?

analogRead() gives a raw scaled count, not a finished physical unit — converting that count to volts, and then to a real-world quantity, are separate steps (Unit 1, Lesson 6).

3. In the example code, why is the "voltage" variable still not a usable temperature reading?

Raw voltage is only an intermediate step — turning it into degrees still requires the calibration mapping introduced in Unit 1, Lesson 6.

4. Fill in the blank: the common function name used to sample a voltage on an ADC-capable pin and return a raw digital count is ___.

analogRead() is the standard call for sampling an analog-capable pin and getting back a scaled raw count.

5. Fill in the blank: compared to digitalRead(), an analog read takes measurably longer because the ADC hardware needs time to sample and ___ the voltage.

Analog-to-digital conversion isn’t instantaneous — the ADC needs a short settling and conversion time, unlike a simple digital HIGH/LOW read.
