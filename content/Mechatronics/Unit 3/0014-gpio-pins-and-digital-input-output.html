GPIO Pins and Digital Input/Output

The most flexible pins on the chip — configurable in software as either an input or an output.

← Lesson 13 Lesson 15 → Contents Glossary →

A microcontroller connects to the outside world through its pins, and the most common, flexible type is GPIO — general-purpose input/output. Unlike a pin permanently wired for one job, a GPIO pin's role is set in software.

Definition A GPIO pin can be configured, in code, as either a digital input (reading an external HIGH/LOW voltage, as with the limit switch from Unit 1, Lesson 5) or a digital output (driving an external HIGH/LOW voltage, as with an LED or a control-line signal). Which role it plays is set once — typically during the setup phase from the previous lesson.

Digital output

Setting a GPIO pin HIGH drives it to roughly the chip's supply voltage (5 V or 3.3 V depending on the board); setting it LOW drives it to roughly 0 V. This is exactly the signal used to turn an LED on and off, or to send a direction command to a motor driver's control-line inputs (Unit 2, Lesson 8).

A limit worth remembering A GPIO output pin can only source a small amount of current — typically tens of milliamps. That's plenty for an LED (with a current-limiting resistor) but nowhere near enough for a motor, which is exactly why Lesson 8's H-bridge exists: the GPIO pin sends a small control signal, and the driver IC handles the real current.

Digital input

Configured as an input, a GPIO pin reads whatever voltage an external circuit presents to it, reporting HIGH or LOW. This is exactly how a limit switch (Unit 1, Lesson 5) gets read — and the same floating-pin problem from that lesson applies here: an input pin with nothing firmly driving it can read unpredictably, which is why a pull-up or pull-down resistor (often built into the chip itself, enabled in software) matters.

Pseudocode 
setup():
    pinMode(LED_PIN, OUTPUT)
    pinMode(BUTTON_PIN, INPUT_PULLUP)

loop():
    if digitalRead(BUTTON_PIN) == LOW:   // pressed, thanks to the pull-up
        digitalWrite(LED_PIN, HIGH)
    else:
        digitalWrite(LED_PIN, LOW)

This tiny program is a complete read-decide-write cycle — a button (digital input) controls an LED (digital output), running inside the loop phase from the previous lesson. Every control loop later in this course is a more elaborate version of exactly this shape.

Check your recall

No peeking back up — answer from memory first, then check.

1. What determines whether a GPIO pin acts as a digital input or a digital output?

A GPIO pin’s general-purpose flexibility comes from being configurable in code as either an input or an output, unlike a pin hard-wired for one role.

2. Why can’t a GPIO output pin directly drive a DC motor?

GPIO output current is limited to roughly tens of milliamps — enough for an LED, nowhere near enough for a motor, hence the need for a driver IC.

3. In the pseudocode example, why does the button read LOW when it’s actually pressed?

With a pull-up enabled, the pin idles HIGH; the button’s job is to pull it to ground when pressed, which reads as LOW — matching Unit 1, Lesson 5’s pull-up explanation.

4. Fill in the blank: a pin whose role as input or output is set in software rather than fixed in hardware is called a ___ pin.

GPIO — general-purpose input/output — is exactly this flexible, software-configurable pin type.

5. Fill in the blank: the function used in the pseudocode example to set a GPIO pin’s role before the loop runs is called ___.

pinMode() is the setup-phase call that configures a GPIO pin as INPUT, OUTPUT, or INPUT_PULLUP.
