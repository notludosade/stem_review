Structuring a Microcontroller Program

Setup once, loop forever — closing out this unit by writing the pattern every later lesson builds on.

← Lesson 16 Unit 4, Lesson 18 → Contents Glossary →

Every idea in this unit — GPIO configuration, digital input and output, analog input — has been leading toward one structural pattern. This lesson makes it explicit, because it's the skeleton every remaining lesson in this course fills in with more detail.

Definition A microcontroller program has exactly two phases: setup, which runs once when the chip powers on or resets (configuring pin modes, initializing peripherals, setting starting values), and loop, which repeats indefinitely afterward, for as long as power is applied.
Why this shape, specifically Configuration only needs doing once — repeatedly reconfiguring a pin's mode inside a fast-repeating loop would be wasted, redundant work. But actually sensing the world and reacting to it is inherently ongoing, with no natural stopping point — so it belongs in a phase that keeps running for as long as the system is powered. Splitting the two apart cleanly is what makes embedded programs both efficient and easy to reason about.

A complete example, combining this unit’s pieces

Reading a switch, reading a sensor, and driving an LED together 
setup():
    pinMode(SWITCH_PIN, INPUT_PULLUP)
    pinMode(LED_PIN, OUTPUT)
    // ADC pin needs no pinMode() call

loop():
    switchPressed = (digitalRead(SWITCH_PIN) == LOW)
    raw = analogRead(LIGHT_SENSOR_PIN)

    if switchPressed AND raw < 400:      // dark AND switch pressed
        digitalWrite(LED_PIN, HIGH)
    else:
        digitalWrite(LED_PIN, LOW)

Nothing in that example is new — a digital input (Lesson 14), an analog input (Lesson 15), a digital output (Lesson 16), and a decision combining them, all running inside the loop phase. What's new is seeing them work together as one program, reading multiple inputs and producing one coordinated output every single pass through the loop.

Where this is headed Right now, the decision inside loop() is a simple fixed rule — an if statement. Starting in Unit 5, that decision becomes a control loop: instead of a fixed rule, the output gets computed from how far a sensor reading is from some target value, recalculated fresh on every single pass through loop(). The setup/loop skeleton doesn't change at all — only what happens inside loop() gets more capable.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does pin configuration belong in setup() rather than loop()?

Setup runs exactly once for a reason — configuration is a one-time task, unlike sensing and reacting, which are ongoing.

2. In the example program, what two conditions must both be true for the LED to turn on?

The AND condition requires switchPressed to be true and raw < 400 (a dark reading) — both must hold for the LED to turn on.

3. What changes about the setup/loop skeleton once a fixed if-statement decision (like in this lesson’s example) becomes a full control loop in Unit 5?

The setup/loop shape is the constant throughout this entire course — control loops are just a more sophisticated version of the logic that runs inside loop(), not a different program structure.

4. Fill in the blank: the phase of a microcontroller program that runs exactly once, used for pin configuration and initialization, is called ___.

Setup is the one-time configuration phase, distinct from the continuously repeating loop phase.

5. Fill in the blank: the phase that repeats indefinitely for as long as the microcontroller has power is called ___.

Loop is where ongoing sensing and reacting happens — it never naturally stops on its own, only when power is removed.
