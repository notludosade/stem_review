Moving-Average Smoothing in Practice

Averaging without starting over every time — and the trade-off between smoothness and responsiveness that never fully goes away.

← Lesson 21 Unit 5, Lesson 23 → Contents Glossary →

The previous lesson's fix — average N fresh samples, every time — works, but wastes time restarting from scratch on every reading. A moving average filter smooths a signal continuously instead, using a small rolling window of recent readings.

Definition A moving average filter keeps a buffer of the last N readings. Each time a new reading comes in, it's added to the buffer (and the oldest reading drops out), and the filter's output is the average of whatever's currently in that buffer.
The unavoidable trade-off: smoothness vs. responsiveness A larger window (bigger N) averages over more readings, producing a smoother output that resists noise well — but it also lags further behind a genuine, real change in the underlying quantity, since old readings linger in the average longer. A smaller window responds faster to real changes but filters out less noise. There's no window size that's simply "better" in both directions at once — choosing N means picking a point on that trade-off, matched to how fast the real quantity actually changes and how much noise needs suppressing.
Example Smoothing a fast-changing signal (like a joystick's raw position) with a large window would make it feel sluggish and delayed. Smoothing a slow-changing signal (like room temperature) with a large window costs almost nothing, since the true value barely moves within the time the window spans anyway.

A lighter alternative: the exponential moving average

Keeping an entire buffer of N past readings costs memory and a bit of bookkeeping. A simpler technique, the exponential moving average (EMA), achieves a similar smoothing effect using just one stored number, updated each time a new reading arrives.

filtered = filtered + α × (newReading − filtered)
Pseudocode 
filtered = analogRead(SENSOR_PIN)   // seed with the first reading

loop():
    raw = analogRead(SENSOR_PIN)
    filtered = filtered + ALPHA * (raw - filtered)   // ALPHA between 0 and 1
    // use "filtered" instead of "raw" from here on

The constant α (alpha) plays the same role as window size did for a moving average: a small α (close to 0) smooths heavily but responds slowly; a large α (close to 1) responds quickly but smooths less. Unlike a moving average, the EMA needs no stored history at all — just one running number — which is exactly why it shows up constantly in resource-limited microcontroller code.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does a moving average filter’s window size (N) control?

A larger window smooths more but lags further behind real changes; a smaller window responds faster but filters less noise — a direct trade-off controlled by N.

2. Why might a large moving-average window be a poor choice for smoothing a fast-changing joystick position signal?

Since old readings linger longer in a large window’s average, it responds more slowly to genuine fast changes — a real cost for something like a joystick that needs quick response.

3. What is the main advantage of an exponential moving average (EMA) over a standard moving average filter?

An EMA needs just one running number updated each cycle, unlike a moving average’s buffer of N past readings — a real memory savings on a resource-limited microcontroller.

4. Fill in the blank: a filter that keeps a rolling buffer of the last N readings and outputs their average is called a ___ average filter.

Moving average is the standard name for this rolling-window smoothing technique.

5. Fill in the blank: in the exponential moving average formula, a small value of alpha produces heavier smoothing but a ___ response to real changes.

A small alpha weights new readings lightly, smoothing heavily but responding more slowly to a genuine change — the same trade-off a large window size produces for a standard moving average.
