The Autonomy Stack — How the Pieces Fit Together

Seven units built seven separate capabilities. This lesson draws the map showing how they actually connect into one running system.

← Unit 7, Lesson 41 Lesson 43 → Contents Glossary →

Every unit of this course built one piece of a robot's overall capability: kinematics, sensing, localization, planning, motion control, decision-making, manipulation. Real robots don't run these as separate, disconnected programs — they form a layered autonomy stack, each layer consuming the output of the layers below it and feeding the layers above.

Definition An autonomy stack is the full software architecture connecting a robot's perception, state estimation, planning, and control into one running system — the concrete answer to "how does all of this actually fit together," as opposed to any single algorithm in isolation.
Tracing one data path through the whole stack A single LIDAR scan (Unit 2) feeds into localization and mapping (Unit 3), producing a pose estimate and an updated occupancy grid. That grid and pose feed into global path planning (Unit 4), producing a route. That route feeds into trajectory generation and tracking control (Unit 5), producing motor commands — but only once decision-making (Unit 6) has confirmed navigating is actually the current priority, and only for a route to a location a manipulation task (Unit 7) needs to reach. Every arrow in that chain is a real dependency: a fault in an early stage (bad localization, Unit 3) doesn't stay contained — it propagates through planning, control, and ultimately into what the robot's manipulator physically attempts to do.
Example Real navigation frameworks are built exactly this way. The Nav2 project, a widely used open-source robot navigation system, structures its behavior as a behavior tree (Unit 6) coordinating a planner (Unit 4's A*-style global planning), a controller (Unit 5's trajectory-tracking), and recovery behaviors — all consuming localization (Unit 3) built from sensor data (Unit 2) — the same layered structure this lesson just diagrammed, running on real deployed robots rather than as a course diagram.

This lesson gave the map. The rest of this unit grounds it in real systems: three case studies of full autonomy stacks doing real work in the world, then a lesson on how these integrated systems actually fail, and finally a capstone that asks you to design one yourself.
