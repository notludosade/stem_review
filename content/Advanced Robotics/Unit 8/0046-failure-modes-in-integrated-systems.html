Failure Modes in Integrated Systems

Every unit of this course studied one capability's failure modes in isolation. Integrated systems fail differently — often at the seams between capabilities, not within any one of them.

← Lesson 45 Lesson 47 → Contents Glossary →

Nearly every unit of this course covered a specific failure mode: sensor noise (Unit 2), dead-reckoning drift (Unit 3), an unreachable path (Unit 4), tracking error (Unit 5), an undefined FSM transition (Unit 6), a slipping grasp (Unit 7). This closing lesson before the capstone is about a different category: failures that only show up once these pieces are integrated, at the boundaries between them.

Definition A seam failure is a failure that occurs not because any single component malfunctioned, but because two correctly-functioning components made incompatible assumptions about each other — each one working exactly as designed, in isolation, while the combination produces a wrong or unsafe outcome.
Why seam failures are harder to catch than single-component failures Unit-testing each capability in isolation — verifying localization accuracy, verifying planning correctness, verifying grasp success rate — is necessary but not sufficient, precisely because a seam failure can occur even when every individual component passes its own tests perfectly. Catching seam failures requires testing the integrated system, under realistic timing and realistic sensor conditions, not just its parts — which is exactly why this course's case studies (Lessons 43-45) emphasized real, deployed, fully integrated systems rather than isolated algorithm demonstrations.
Example A robot's localization (Unit 3) reports its pose with a small delay — perfectly reasonable and correctly documented behavior for that component alone. A robot's motion controller (Unit 5) was built assuming pose estimates arrive instantly, with no delay accounted for. Individually, both components pass their own tests: localization accurately reports where the robot was a moment ago, and the controller correctly steers toward wherever the pose estimate it receives claims the robot to be. Combined, at high speed, this small mismatched assumption about timing can cause the controller to steer based on stale position data — an error that shows up only once the two correctly-functioning pieces are actually connected together and run at realistic speed.

Another common seam failure, connecting directly back to Unit 6: a behavior tree's navigation branch and its manipulation branch (Unit 7) might each independently assume they have exclusive control of the robot's arm, if the tree wasn't designed carefully — a state achievable by each branch's individually correct logic, that neither branch's own testing would ever catch alone.

The lesson to carry into the capstone is not "integration is scary" but "integration is a real, distinct engineering task" — verifying that components' assumptions about each other actually hold, not just that each component works correctly on its own. This closes the case-study-and-failure portion of Unit 8. The final lesson asks you to design a complete integrated system yourself, with exactly this seam-checking discipline in mind.

1. What is a seam failure?

A seam failure occurs at the boundary between components, each working exactly as designed individually, while their combination produces a wrong outcome.

2. Why is testing each capability in isolation (localization accuracy, planning correctness, grasp success rate) necessary but not sufficient?

Seam failures arise from mismatched assumptions between components, which isolated per-component testing cannot catch — only testing the integrated system can.

3. In the localization-delay-versus-controller example, why does the mismatch only show up once the components are connected and run at realistic speed?

Both components behave correctly and pass their own tests individually — the mismatch is purely about how their outputs interact once connected under realistic timing.

4. Fill in the blank: a failure caused by incompatible assumptions between two individually correct components, rather than by either one malfunctioning, is called a ___ failure.

Seam failure describes exactly this category — occurring at the boundary between components rather than within either one.

5. Fill in the blank: catching seam failures requires testing the ___ system under realistic conditions, not just its individual parts in isolation.

Only running the full, connected system under realistic timing and sensor conditions can reveal seam failures that per-component testing misses.
