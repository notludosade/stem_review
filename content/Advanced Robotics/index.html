Lesson 1

What Makes a Robot a Robot?

Every robot is a machine, but not every machine is a robot — the difference is a loop that closes over what it senses.

Degrees of Freedom

One number that answers a surprisingly deep question: how many independent ways can this thing move?

 Lesson 3

Coordinate Frames and Robot Pose

Position by itself is not enough to describe a robot part — you also need to know which way it's facing, and relative to what.

 Lesson 4

Forward Kinematics

Given every joint angle, computing exactly where the end-effector ends up — a straightforward calculation, once you see it as chaining frames.

 Lesson 5

Kinematic Chains and Workspace

Link lengths and joint limits carve out a fixed region the end-effector can ever reach — and everything outside it is off the table, permanently.

 Lesson 6

Inverse Kinematics — An Intuitive Introduction

Forward kinematics has exactly one answer. Its reverse can have many, one, or none — and that difference is the whole difficulty.

Unit 2: Sensing & Perception
Lesson 7

How Robots Sense the World

A robot never has direct access to the truth about itself or its surroundings — only measurements, and measurements are never perfect.

 Lesson 8

Wheel Encoders and Proprioception

Counting wheel rotations sounds like it should give exact distance traveled. It doesn't — and the gap matters more than it looks.

 Lesson 9

LIDAR and Range Sensing

Firing thousands of laser pulses a second and timing their return turns out to be one of the most direct ways a robot can measure its surroundings.

 Lesson 10

Cameras and Visual Perception

A camera hands a robot enormous amounts of information and almost none of it for free — depth, in particular, has to be earned back through computation.

 Lesson 11

Noise, Uncertainty, and Sensor Limitations

No sensor reports the true value of anything — every reading is the truth plus some error, and not all error behaves the same way.

 Lesson 12

Sensor Fusion — Combining Imperfect Information

Two mediocre sensors, combined the right way, can beat one excellent sensor — because their weaknesses rarely overlap.

Unit 3: Localization & Mapping
Lesson 13

The Localization Problem

Every plan, every map, every sensor conversion in this course assumes the robot knows where it is. This unit is about how shaky that assumption really is.

 Lesson 14

Odometry and Dead Reckoning

Add up every small motion since the start, and you get an estimate of where you are now — no landmarks required, and no correction either.

 Lesson 15

Why Dead Reckoning Drifts

Small, honest measurement errors don't cancel out when you're adding them up in sequence — they compound, and the longer you drive, the worse it gets.

 Lesson 16

Representing the Environment — Maps and Occupancy Grids

Before a robot can check its position against a map, something has to decide what a 'map' even looks like as data a computer can use.

 Lesson 17

SLAM — The Conceptual Idea

To build a good map you need to know where you are. To know where you are, you need a good map. SLAM is the trick that breaks this circle.

 Lesson 18

Loop Closure and Correcting Drift

Recognizing 'I have been exactly here before' is a small-sounding event that unlocks a correction across an entire path already driven.

Unit 4: Path Planning
Lesson 19

From the World to a Graph

Before any search algorithm can find a path, the continuous, messy real world has to be turned into something a computer can actually search.

 Lesson 20

Configuration Space

A robot isn't a point — but planning gets dramatically simpler once you shrink it into one, by growing the obstacles instead.

 Lesson 21

Graph Search Fundamentals — BFS, Dijkstra, and Heuristics

Three ideas, each building on the last, lead directly to the algorithm every modern path planner is built around.

 Lesson 22

A* Search for Robot Path Planning

Real cost so far, plus an honest estimate of cost still to go — combining the two is what makes A* the workhorse of robot path planning.

 Lesson 23

Obstacle Avoidance — Local vs. Global Planning

A* finds a path through the map the robot had. Obstacle avoidance is about the obstacles the map didn't have — the ones the robot only discovers by driving.

 Lesson 24

Replanning and Dynamic Obstacles

Sometimes steering around an obstacle isn't enough — the whole plan has to be thrown out and recomputed, on the fly, without stopping the robot's mission.

Unit 5: Motion Control
Lesson 25

From Path to Motion Commands

A* hands back a list of waypoints. Motors need voltages and velocities. Something has to bridge that gap, continuously, in real time.

 Lesson 26

Trajectory Generation and Timing

A path says where. A trajectory says where, and exactly when — and that second piece is what a motion controller actually needs.

 Lesson 27

Waypoint Following and Steering Control

Knowing where you're supposed to be is only half the job — the other half is deciding, moment to moment, how hard to steer to actually get there.

 Lesson 28

Feedback Control for Path Tracking

Steering toward a lookahead point gets a robot roughly on track. Feedback control is what keeps measuring and correcting so 'roughly' becomes 'reliably.'

 Lesson 29

Trajectory Smoothing

The best correction is the one you never had to make — smoothing a path's sharp corners before execution reduces the whole burden on everything downstream.

Unit 6: Autonomy & Decision-Making
Lesson 30

Reactive vs. Deliberative Control

Should a robot think before it acts, or act before it thinks? Real robots need both — the trick is knowing which situations call for which.

 Lesson 31

Finite State Machines for Robot Behavior

A robot's high-level behavior can often be described as a small number of named modes, and clear rules for switching between them.

 Lesson 32

Designing a Robot FSM — A Worked Example

Turning a task description into states and transitions is a specific skill — worth walking through completely once, on a task with real edge cases.

 Lesson 33

Behavior Trees — A Scalable Alternative to FSMs

Instead of naming every possible mode and every transition between them, describe behavior as a tree of smaller, reusable pieces.

 Lesson 34

Building and Reading a Behavior Tree

With the vocabulary in place, the remaining skill is purely practical: tracing execution through a tree, and building one for a task from scratch.

 Lesson 35

Combining Reactive and Deliberative Layers

This unit's whole arc, made explicit: a robot's decision-making works best as reflexes and reasoning layered together, not one chosen over the other.

Unit 7: Robotic Manipulation
Lesson 36

Manipulation Is a Different Problem Than Locomotion

Every unit so far was about moving the robot. This unit is about the robot moving something else — a genuinely different problem, not a smaller version of the same one.

 Lesson 37

Grippers and End-Effectors

The end-effector was a name so far — this lesson gives it real hardware, and a first sense of why 'just close the fingers' hides real design decisions.

 Lesson 38

Grasp Planning — Choosing a Grasp

A gripper that closes in the wrong place fails no matter how well-built it is. Deciding where and how to grasp is its own planning problem.

 Lesson 39

Force, Friction, and Grasp Stability

A grasp isn't secure because it looks secure — it's secure because friction and applied force genuinely add up to hold the object against gravity and motion.

 Lesson 40

Specialized End-Effectors

A rigid two-finger gripper is the default answer, not the only one — some objects are handled far better by hardware built specifically for them.

 Lesson 41

Manipulation Pipelines — Perceive, Plan, Grasp, Place

Every piece from this unit, and several from earlier ones, chained into the one sequence a robot actually runs to pick something up and put it down correctly.
