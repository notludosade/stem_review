Representing the Environment — Maps and Occupancy Grids

Before a robot can check its position against a map, something has to decide what a 'map' even looks like as data a computer can use.

← Lesson 15 Lesson 17 → Contents Glossary →

Lesson 15 ended on a fix for drift: check the accumulating estimate against something independent. That "something" is a map — but a map has to be represented as actual data before any of that checking can happen in software. This lesson covers the most common representation.

Definition An occupancy grid represents the environment as a grid of small, fixed-size cells, each holding a value estimating the probability that the cell is occupied by an obstacle. A cell near certainty of being occupied (a wall) is marked accordingly; a cell near certainty of being empty (open floor) is marked the other way; a cell the robot has never sensed is marked unknown — a genuinely distinct third state, not just "assumed empty."

LIDAR scans (Lesson 9) are a natural fit for building an occupancy grid: each ray that returns a distance marks the cells along its path as likely free (nothing blocked the beam that far) and the cell at the return point as likely occupied. Sweep enough scans from enough positions, and the grid fills in.

Why "unknown" has to be a real third option A robot that treats unexplored space as "assumed empty" will happily plan a path straight through a room it has never actually seen — a dangerous assumption. Marking unsensed cells as explicitly unknown lets later planning (Unit 4) treat "go check that unexplored area" differently from "drive confidently through known-open floor," which matters enormously for both safety and for deciding where to explore next.
Example A robot vacuum's 2D occupancy grid of an apartment starts entirely unknown. After its first few passes through the living room, that region's cells settle toward "free" (open floor) except for a thin band of "occupied" cells tracing the walls and furniture legs it detected. The kitchen, not yet visited, remains entirely unknown — not marked as free, and not marked as occupied, simply not yet informed by any sensor reading.

For 3D environments, the same idea extends to volumetric occupancy grids, often organized as an octree — a data structure that subdivides only the regions that need fine detail, keeping large empty or large solid regions cheap to store instead of representing every tiny cube individually.

A map by itself doesn't build itself, and dead reckoning by itself can't correct itself. The next lesson is about the genuinely clever part: doing both of these jobs — mapping the environment and localizing within it — at the same time, from the same stream of sensor data, each one helping the other.

Check your recall

No peeking back up — answer from memory first, then check.

1. In an occupancy grid, what does a cell marked 'unknown' represent?

Unknown is a genuine third state — the robot has no sensor evidence about that cell at all, which is different from evidence that it's empty.

2. Why is treating unexplored space as 'assumed empty' (rather than explicitly 'unknown') a dangerous design choice?

Treating unsensed space as safe-by-default risks planning through areas that could actually contain unseen obstacles — 'unknown' must be distinguished from 'confirmed free.'

3. How does a single LIDAR scan typically update an occupancy grid?

A LIDAR ray that travels some distance before returning implies the cells it passed through were unobstructed (likely free), while the cell where it stopped is likely occupied.

4. Fill in the blank: a representation of the environment as a grid of cells, each estimating the probability of being occupied by an obstacle, is called an occupancy ___.

Occupancy grid is the standard term for this cell-based environment representation.

5. Fill in the blank: a tree-based data structure that subdivides only the regions needing fine detail, commonly used for 3D occupancy mapping, is called an ___.

Octrees keep large empty or solid regions cheap to store while still allowing fine detail where it's needed.
