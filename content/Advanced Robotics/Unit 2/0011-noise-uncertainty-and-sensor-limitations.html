Noise, Uncertainty, and Sensor Limitations

No sensor reports the true value of anything — every reading is the truth plus some error, and not all error behaves the same way.

← Lesson 10 Lesson 12 → Contents Glossary →

The last three lessons each ended with a version of the same warning: encoders assume no slip, LIDAR assumes a clean return, cameras are ambiguous about depth. This lesson generalizes that pattern into two distinct kinds of error every sensor has, because the fix for one is not the fix for the other.

Definition Bias (or systematic error) is a consistent offset between what a sensor reports and the true value — the same direction and roughly the same size every time, often from miscalibration. Noise (or random error) varies unpredictably from one reading to the next, scattered around the true value rather than consistently off to one side.
Example An ultrasonic distance sensor pointed at a wall exactly 2.00 m away reports, across five readings: 2.05, 1.97, 2.06, 1.94, 2.03 m. The average of these is close to 2.01 m — the small scatter around that average is noise. If the same sensor consistently read 2.15 m no matter how many times you averaged, that steady 0.15 m offset would be bias — a miscalibration, not random scatter.
Why the distinction matters practically Averaging repeated readings reduces the effect of random noise — scatter above and below the true value partly cancels out. Averaging does nothing for bias, because a consistent offset stays the same offset no matter how many readings you average together. This is why "just take more measurements" is a real fix for noisy sensors but a false fix for miscalibrated ones — bias has to be corrected by calibration against a known reference, not by collecting more data.

Every sensor in this unit carries both kinds of error, in different proportions. A wheel encoder's tick-counting is quite precise (low noise) but can be systematically biased if the wheel's true diameter differs slightly from its assumed value. A LIDAR return's occasional bad reading off a reflective surface is closer to an outright error than ordinary noise. A camera's depth ambiguity from Lesson 10 isn't noise or bias in this technical sense at all — it's missing information, a different failure mode entirely.

The honest conclusion this unit has been building toward is that "get a better sensor" only ever narrows the gap between measurement and truth — it never closes it. Every robot has to be built assuming its sensor data is an estimate with some uncertainty attached, not a fact. The next lesson is the first real answer to what to do about that: instead of trusting one imperfect sensor, combine several.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the key difference between bias and noise in a sensor reading?

Bias is systematic (same direction, roughly consistent size); noise is random scatter around the true value.

2. Why does averaging many repeated readings reduce the effect of noise but not bias?

Noise cancels out somewhat when averaged; bias is a systematic offset that averaging cannot remove — only calibration against a known reference can.

3. What is the correct fix for a sensor with significant bias (systematic miscalibration)?

Bias is a consistent offset that averaging cannot fix — it requires calibration against something known to be accurate.

4. Fill in the blank: a consistent, repeatable offset between a sensor's reading and the true value is called ___ (or systematic error).

Bias is the standard term for a consistent, one-directional measurement offset.

5. Fill in the blank: unpredictable, scattered variation in a sensor's readings around the true value is called ___ (or random error).

Noise is the standard term for random, unpredictable measurement variation.
