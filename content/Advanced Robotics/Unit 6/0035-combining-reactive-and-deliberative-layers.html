Combining Reactive and Deliberative Layers

This unit's whole arc, made explicit: a robot's decision-making works best as reflexes and reasoning layered together, not one chosen over the other.

← Lesson 34 Unit 7, Lesson 36 → Contents Glossary →

Lesson 30 opened this unit by arguing reactive and deliberative control each solve problems the other can't. FSMs and behavior trees, the four lessons since, are ways to structure that combination in software. This closing lesson makes the layering explicit and names the architectural pattern behind it.

Definition A layered (or hybrid) control architecture organizes a robot's decision-making into multiple levels running at different speeds and different degrees of lookahead: a fast, reactive layer handling immediate safety and reflexes; a slower, deliberative layer handling planning and goal selection; often with a coordination layer between them. Higher layers set goals and priorities; lower layers execute quickly and can override higher-layer output when immediate conditions demand it.
Why layering, not choosing one architecture, is the actual answer A purely deliberative robot is slow to react and brittle when reality doesn't match its model. A purely reactive robot has no way to pursue a distant goal coherently. Neither flaw is fixed by getting better at the one architecture chosen — it's fixed by combining both, with an explicit way for the fast layer to interrupt the slow one. Lesson 34's behavior tree already demonstrated this concretely: a high-priority battery-check branch (fast, reactive) sits structurally able to interrupt a long-running navigation action (slow, deliberative) at any point, without either layer needing to know the internal details of the other.
Example: the whole course's control layers, named explicitly Unit 4's global A* is deliberative planning. Unit 4's local obstacle avoidance and Unit 5's feedback path-tracking are reactive layers running underneath it, correcting for what the plan couldn't foresee. Unit 6's behavior trees are the coordination layer, deciding which high-level task (navigate, pick, report failure, return to charge) is currently active — itself capable of being interrupted by a reactive condition like critical battery level. Every piece from every previous unit fits into exactly this layered picture: fast reactive layers protecting against the immediate and unexpected, slower deliberative layers pursuing the actual goal, and a coordination structure — FSM or behavior tree — deciding which layer's output currently governs.

This closes Unit 6. A robot can now not just execute a single planned task (Units 1 through 5), but decide which task to be doing, structure that decision cleanly, and stay responsive to conditions that demand immediate reaction. Unit 7 shifts focus to a specific class of task this unit's machinery would coordinate: manipulation — actually grasping and moving objects, a problem meaningfully different from the locomotion this course has covered so far.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the core idea of a layered (hybrid) control architecture?

Layered architectures combine fast reactive layers and slower deliberative layers, with the fast layer able to interrupt or override when immediate conditions demand it.

2. How did Lesson 34's behavior tree already demonstrate a layered architecture concretely?

The tree's own re-evaluation structure let a fast, high-priority branch interrupt a slower, longer-running one — layering built directly into the same structure, not a separate bolted-on system.

3. According to this lesson, why is neither a purely reactive nor a purely deliberative architecture a good final answer, even if improved?

The flaws of each architecture are complementary, not fixable by refining just one choice — which is why combining both, with an explicit interruption mechanism, is the actual solution.

4. Fill in the blank: a control architecture that organizes decision-making into multiple levels running at different speeds, combining reactive and deliberative control, is called a ___ (or hybrid) architecture.

Layered architectures are the standard term for combining fast reactive layers with slower deliberative ones.

5. Fill in the blank: in a layered architecture, ___ layers handle immediate safety and reflexes, while deliberative layers handle planning and goal selection.

Reactive layers provide the fast, reflexive response that deliberative planning alone is too slow to offer.
