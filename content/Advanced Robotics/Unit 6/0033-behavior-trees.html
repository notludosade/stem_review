Behavior Trees — A Scalable Alternative to FSMs

Instead of naming every possible mode and every transition between them, describe behavior as a tree of smaller, reusable pieces.

← Lesson 32 Lesson 34 → Contents Glossary →

Lesson 32's worked example showed states and transitions multiplying fast once real failure handling was included. Behavior trees (BTs) are an alternative way to structure robot decision logic, designed specifically to scale better as behaviors grow more complex.

Definition A behavior tree is a tree of nodes, evaluated top-down, repeatedly, where each node returns Success, Failure, or Running. Leaf nodes are actions ("navigate to shelf") or conditions ("is battery above 20%?"). Composite nodes combine children according to a rule: a Sequence runs its children in order, succeeding only if all succeed (failing and stopping immediately if any child fails); a Selector (or Fallback) tries its children in order, succeeding as soon as any one succeeds (only failing if all of them do).
Why trees scale where flat state machines don't An FSM's transitions form a flat, sprawling web — Lesson 32's retry loop and failure-escalation path were each separate, manually wired transitions, and every new failure case meant more wiring. A behavior tree expresses the same logic structurally: "try this, and if it fails, try that instead" is just a Selector node; "do these steps in order, bailing out if any fails" is just a Sequence node. Complex behavior is built by composing small, independently understandable subtrees — including reusing the same subtree (like a generic "retry up to N times" pattern) in multiple places — rather than hand-wiring an ever-growing web of named states and transitions.
Example Lesson 32's picking logic becomes a small subtree: a Selector containing [a Sequence of "attempt grasp" then "verify grasp succeeded," repeated up to 3 times] followed by ["report picking failure"]. Read left to right: keep trying the grasp-and-verify sequence; if it never succeeds after enough attempts, fall through to the failure report. This is the same retry-then-escalate logic Lesson 32 built as several explicitly wired FSM states and transitions, expressed here as a compact, reusable structural pattern instead.

The Running status is what makes behavior trees naturally reactive as well as structured: a long-running action (like "navigate to shelf," which takes many control cycles) returns Running on every tick until it finishes, and the tree re-evaluates from the top each cycle — meaning higher-priority branches (like "battery critically low, abort and return to dock") can interrupt a Running action if conditions change, without any separate mechanism bolted on.

This lesson covered the vocabulary and the "why." The next lesson gets hands-on: reading and building an actual behavior tree, node by node, for a complete robot task.

Check your recall

No peeking back up — answer from memory first, then check.

1. What are the three possible return statuses of a behavior tree node?

Every behavior tree node returns exactly one of Success, Failure, or Running on each evaluation.

2. What is the difference between a Sequence node and a Selector (Fallback) node?

Sequence is an 'all must succeed, in order' composite; Selector is a 'try until one succeeds' composite — the two core building blocks of behavior tree logic.

3. Why does the 'Running' status help behavior trees be naturally reactive?

Because the tree re-evaluates from the root every cycle, a Running action can be preempted by a higher-priority branch (like a critical battery check) without any separate interrupt mechanism.

4. Fill in the blank: a behavior tree node that runs its children in order, succeeding only if all of them succeed, is called a ___ node.

Sequence nodes model 'do these steps in order, stopping on first failure.'

5. Fill in the blank: a behavior tree node that tries its children in order, succeeding as soon as any one succeeds, is called a ___ (or Fallback) node.

Selector nodes model 'try this, and if it fails, try the next option instead.'
