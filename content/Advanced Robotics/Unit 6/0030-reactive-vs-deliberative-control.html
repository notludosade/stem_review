Reactive vs. Deliberative Control

Should a robot think before it acts, or act before it thinks? Real robots need both — the trick is knowing which situations call for which.

← Unit 5, Lesson 29 Lesson 31 → Contents Glossary →

Everything so far in this course assumed the robot already knew what it wanted to do: reach this pose (Unit 1), track this trajectory (Unit 5). This unit asks a different question — how does a robot decide what to do in the first place, and how is that decision-making actually structured in software? This lesson starts with the most basic split in how that decision-making can work.

Definition Reactive control maps sensed conditions directly to actions, with little or no internal state or lookahead — "if an obstacle is close on the left, turn right," evaluated fresh every instant. Deliberative control builds and reasons over a model of the situation before acting — planning a full route (Unit 4's A*) before taking a single step, weighing options against a goal rather than reacting to the immediate instant alone.
Why neither one alone is good enough Purely deliberative control is too slow for anything requiring an immediate response — a robot that has to fully replan before dodging a sudden obstacle will collide first. Purely reactive control has no memory or goal-directedness — a set of "if this, then that" rules can get a robot stuck oscillating between two obstacles, or wandering indefinitely with no sense that it's supposed to be heading somewhere specific. Real robots need fast, reflexive responses and goal-directed reasoning, layered together — which is exactly what this course has already been building toward without naming it directly.
Example This course has already covered one clean instance of each. Unit 4's global A* planning is deliberative: it reasons over the whole known map before committing to a route. Unit 4's local obstacle avoidance is reactive: it responds immediately to whatever the sensors detect right now, with no lookahead beyond the robot's current surroundings. The two were already designed to work together — global planning setting an informed route, local avoidance reacting fast to what the plan couldn't have known — which is precisely the reactive-plus-deliberative pattern this lesson is now naming explicitly.

This unit's remaining lessons give this split concrete software structure. Finite state machines and behavior trees — the next four lessons — are both ways of organizing a robot's decision logic that can mix reactive rules and deliberative planning within the same coherent structure, rather than leaving the split as an unstructured pile of separate code.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the defining feature of reactive control?

Reactive control responds immediately to current sensed conditions, without building or reasoning over a broader model of the situation.

2. Why is purely deliberative control, by itself, insufficient for handling a sudden obstacle?

Building and reasoning over a plan takes time — too much time to respond to something requiring an immediate reflexive reaction.

3. How did this course already demonstrate the reactive-plus-deliberative pattern before this lesson named it?

Global A* planning reasons over the whole map ahead of time (deliberative); local avoidance reacts immediately to current sensor data (reactive) — exactly the combination this lesson describes.

4. Fill in the blank: control that maps sensed conditions directly to actions, with little or no internal state, is called ___ control.

Reactive control is fast and reflexive but has no memory or lookahead.

5. Fill in the blank: control that builds and reasons over a model of the situation before acting, such as full route planning, is called ___ control.

Deliberative control is goal-directed and reasons ahead, at the cost of being slower than a pure reflex.
