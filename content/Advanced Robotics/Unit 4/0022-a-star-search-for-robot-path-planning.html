A* Search for Robot Path Planning

Real cost so far, plus an honest estimate of cost still to go — combining the two is what makes A* the workhorse of robot path planning.

← Lesson 21 Lesson 23 → Contents Glossary →

The last lesson built up to exactly this point: Dijkstra's algorithm searches correctly but wastefully; a heuristic estimates which direction is promising. A* search (pronounced "A-star") combines both into a single score for every node under consideration.

Definition For each node n, A* computes f(n) = g(n) + h(n), where g(n) is the actual known cost from the start to n (exactly what Dijkstra tracks), and h(n) is the heuristic estimate of remaining cost from n to the goal (Lesson 21's addition). A* always expands the unvisited node with the lowest f(n) — the best combination of "cheapest to reach so far" and "looks closest to the goal."
f(n) = g(n) + h(n)
Why the heuristic must never overestimate A* is guaranteed to find the true lowest-cost path only if h(n) never overestimates the actual remaining cost — a property called admissibility. Straight-line distance is a standard admissible heuristic for grid-based planning, because the true path (which must go around obstacles) can never be shorter than a straight line, so h(n) never claims a node is closer than it truly is. An overestimating heuristic can cause A* to expand a worse path first and settle for it, believing (wrongly) that the truly optimal path looked more expensive than it actually was.
Example A robot planning across a grid uses straight-line distance as h(n). At a node 3 steps of true cost from the start (g = 3), with a straight-line distance to the goal of 5 (h = 5), f = 3 + 5 = 8. A neighboring node with g = 4 but a straight-line distance to the goal of only 2 (h = 2) has f = 4 + 2 = 6 — lower, so A* expands the second node next, even though it cost more to reach, because the combined estimate suggests it's more promising overall. This is exactly the balance BFS and plain Dijkstra couldn't strike on their own.

Pseudocode-level, A* maintains a priority queue of nodes ordered by f(n), repeatedly pulling the lowest-f node, checking whether it's the goal, and otherwise expanding its neighbors (updating their g values if a cheaper route to them was just found) — a direct extension of the CP1-level priority-queue and graph-traversal ideas you already have, with the heuristic bolted onto the ordering rule.

A* answers "what is the best sequence of graph nodes from start to goal." It does not, by itself, guarantee the resulting path avoids getting uncomfortably close to obstacle edges, or handles obstacles that weren't in the map when the graph was built. The next lesson covers both.

Check your recall

No peeking back up — answer from memory first, then check.

1. What does A* compute for each node it considers?

A* combines Dijkstra's real cost-so-far g(n) with the heuristic's estimate of remaining cost h(n) into a single priority f(n).

2. What does it mean for a heuristic to be 'admissible,' and why does A* require it for a correctness guarantee?

An admissible heuristic never claims a node is farther from optimal than it truly is, which is what guarantees A* finds the true lowest-cost path.

3. Why is straight-line distance a standard admissible heuristic for grid-based robot path planning?

A straight line is the shortest possible route between two points, so any real obstacle-avoiding path must be at least that long — the heuristic never overestimates.

4. Fill in the blank: in A*, the actual known cost from the start to a node n is written g(n); the heuristic estimate of remaining cost to the goal is written ___(n).

h(n) is the heuristic estimate; f(n) = g(n) + h(n) combines both into A*'s priority score.

5. A node has g(n) = 6 and h(n) = 4. Fill in the blank: its A* priority score f(n) is ___.

f(n) = g(n) + h(n) = 6 + 4 = 10.
