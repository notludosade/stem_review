Graph Search Fundamentals — BFS, Dijkstra, and Heuristics

Three ideas, each building on the last, lead directly to the algorithm every modern path planner is built around.

← Lesson 20 Lesson 22 → Contents Glossary →

With a graph in hand (Lesson 19) and obstacles correctly inflated (Lesson 20), the remaining question is purely algorithmic: given a start node and a goal node, how does a computer actually find a path? This lesson builds up the ideas in order, ending exactly where the next lesson picks up.

Definition Breadth-first search (BFS) explores a graph outward from the start node one "ring" of distance at a time — visiting all nodes one edge away, then all nodes two edges away, and so on — guaranteeing the shortest path in number of edges is found first. It assumes every edge has equal cost, which real planning graphs (edges of different lengths) usually violate.

BFS's equal-cost assumption is the problem Dijkstra's algorithm fixes: instead of exploring in strict rings, it always expands whichever unvisited node currently has the lowest known total cost from the start, correctly handling edges of different lengths or difficulty. This guarantees the true lowest-cost path is found — a real improvement over BFS for realistic graphs, but Dijkstra still has a specific inefficiency worth noticing.

Why Dijkstra searches in every direction, even away from the goal Dijkstra has no idea where the goal is relative to any given node — it only knows cost-from-start, so it explores equally in every direction, including directly away from the goal, until it happens to reach it. For a goal far across a large map, this means exploring a large, mostly wasted circular region before the search ever gets close. What's missing is a way to prefer expanding nodes that seem to be heading toward the goal.
Example Picture a large open warehouse floor with the goal in the far corner. Dijkstra, run from the start, expands outward roughly like ripples on a pond — checking nodes to the left, right, and behind the start just as eagerly as nodes toward the goal, because nothing in its rule tells it any direction is more promising. A huge fraction of the nodes it checks turn out to be irrelevant to the eventual path, simply because they were checked before the search "knew" which direction actually mattered.

A heuristic is exactly the missing piece: an estimate of remaining distance (or cost) from any given node to the goal, computed cheaply (often just straight-line distance, ignoring obstacles). A search that uses a heuristic to prioritize nodes that seem closer to the goal, on top of Dijkstra's honest cost-from-start, no longer wastes effort exploring in obviously wrong directions. Combining both pieces — real cost-so-far, plus an estimate of cost-still-to-go — is precisely A*, the subject of the next lesson.

Check your recall

No peeking back up — answer from memory first, then check.

1. What guarantee does breadth-first search (BFS) provide, and what assumption does that guarantee depend on?

BFS explores ring by ring, guaranteeing fewest edges — but only matches 'shortest distance' when every edge costs the same, which real planning graphs often violate.

2. How does Dijkstra's algorithm improve on BFS for graphs with edges of different costs?

Dijkstra expands by true accumulated cost rather than by ring distance, correctly finding the lowest-cost path even with unequal edge costs.

3. What specific inefficiency does Dijkstra have that a heuristic is meant to fix?

Without any estimate of remaining distance to the goal, Dijkstra wastes effort exploring nodes that are clearly not on the way there — exactly what a heuristic addresses.

4. Fill in the blank: an estimate of remaining cost from a node to the goal, computed cheaply (often straight-line distance), is called a ___.

A heuristic is the estimate that lets a search prioritize nodes likely to be closer to the goal.

5. Fill in the blank: the search algorithm that always expands the node with the lowest known total cost from the start, correctly handling unequal edge costs, is called ___'s algorithm.

Dijkstra's algorithm generalizes BFS's ring-by-ring exploration to handle graphs with varied edge costs.
