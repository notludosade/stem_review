From the World to a Graph

Before any search algorithm can find a path, the continuous, messy real world has to be turned into something a computer can actually search.

← Unit 3, Lesson 18 Lesson 20 → Contents Glossary →

Unit 3 gave a robot a map — an occupancy grid, free cells and occupied cells and unknown ones. Knowing the map and knowing your position on it (Unit 3, done) is not the same as knowing how to get somewhere. This unit is about that next step: path planning, deciding a route from here to a goal. The first job, and this lesson's whole focus, is turning the map into a structure a search algorithm can actually work with — a graph.

Definition A graph (in this planning sense, not a chart) is a set of nodes representing discrete locations or states, connected by edges representing valid, direct transitions between them, often labeled with a cost (distance, time, or difficulty of that transition). Path planning becomes the problem of finding a sequence of edges from a start node to a goal node — a well-studied problem with well-understood algorithms, once the graph exists.

An occupancy grid from Unit 3 converts into a graph almost directly: each free cell becomes a node, and edges connect each cell to its neighboring free cells (often the four or eight adjacent cells), each edge costing roughly the distance between cell centers. Occupied and unknown cells simply don't get nodes, or get nodes explicitly excluded from search — the graph only contains places the robot could actually be.

Why the grid resolution is itself a design decision A coarse grid (large cells) makes the graph small and fast to search, but can miss real gaps a robot could actually fit through, or falsely block paths near obstacle edges. A fine grid captures the map more faithfully but produces a much larger graph, more expensive to search. This is the same trade-off Unit 1's workspace lesson raised about link lengths — a design decision made deliberately, not a detail to ignore.
Example A warehouse floor plan, gridded at 0.2 m resolution, might produce a graph with tens of thousands of nodes for a modest-sized building — plenty for a computer to search quickly with the right algorithm. Gridded at 0.02 m resolution "for extra safety," the same floor plan could produce a graph a hundred times larger, dramatically slowing every planning query for a precision gain the robot's own size doesn't actually need.

Grid-based graphs are the simplest version of this idea, and this course sticks with them — but the same "discrete nodes connected by valid transitions" idea generalizes to non-grid representations too. The next lesson covers one specific refinement that matters a great deal in practice: making sure the graph reflects not just where the map is free, but where the robot's own physical size can actually fit.

Check your recall

No peeking back up — answer from memory first, then check.

1. In path planning, what is a graph's edge?

Nodes represent locations/states; edges represent the valid transitions between them, typically weighted by cost such as distance.

2. How does an occupancy grid typically convert into a planning graph?

Free cells become searchable nodes with edges to their free neighbors; occupied (and often unknown) cells are excluded entirely from the graph.

3. What is the trade-off in choosing a grid's cell resolution for path planning?

Cell size trades graph fidelity against graph size and search speed — a deliberate design decision, similar to the workspace/link-length trade-offs from Unit 1.

4. Fill in the blank: in a planning graph, a discrete location or state is represented by a ___.

Nodes are the discrete points a search algorithm can be at; edges connect them.

5. Fill in the blank: the overall problem of finding a route from a start location to a goal is called path ___.

Path planning is the umbrella term for this unit's whole subject — finding a route once the map is turned into a searchable graph.
