Gradient Descent: Finding the Downhill Direction

AI Developer's Lesson 13 walked one weight downhill. A real network has thousands of weights moving at once, the learning rate has real failure modes in both directions, and "just use gradient descent" quietly hides a few practical refinements worth naming.

← Lesson 2 Unit 2, Lesson 4 → Contents Glossary →

With thousands of weights instead of one, the gradient stops being a single slope and becomes a gradient vector: one partial derivative per weight, each one saying how that specific weight's tiny nudge would change the loss, holding every other weight fixed. Gradient descent still does the same thing Lesson 2's loss function set up — step every weight a little in the direction that reduces loss the most — just simultaneously, across every entry in that vector, every step.

Python — gradient descent on two weights at once 
import numpy as np

def loss(w):
    return (w[0] - 3) ** 2 + (w[1] + 1) ** 2   # minimized at w = [3, -1]

def gradient(w):
    return np.array([2 * (w[0] - 3), 2 * (w[1] + 1)])   # one partial derivative per weight

w = np.array([0.0, 0.0])
learning_rate = 0.1

for step in range(30):
    w = w - learning_rate * gradient(w)   # every weight steps at once

print(w)   # converges toward [3.0, -1.0]

Nothing here is conceptually new next to Lesson 13's single-weight version — gradient(w) just returns a whole array instead of one number, and the update line applies to all of it at once via NumPy's elementwise subtraction. What is new at this scale is how much more the learning rate's size matters. Too small, and thousands of tiny, correct steps still take forever to add up. Too large, and a weight doesn't just converge slowly — it can overshoot the minimum, land further from it than where it started, and diverge outward step after step, each one worse than the last.

Definition The gradient vector holds one partial derivative per weight — how much that weight alone would change the loss. Gradient descent steps every weight opposite its own entry in that vector. A local minimum is a point where loss is lower than every nearby point but not necessarily the lowest possible; a saddle point curves downward in some directions and upward in others, so the gradient there is technically zero without actually being a minimum at all.
Why real training rarely uses plain gradient descent as shown above Plain gradient descent tends to zig-zag across narrow, steep-sided valleys in the loss surface instead of moving smoothly toward the minimum. Momentum fixes this by accumulating a running average of recent gradients — like a ball with real inertia rather than one that stops and recalculates from scratch at every step — which smooths out the zig-zag and speeds up consistent downhill progress. Adam, the optimizer used in most real training scripts, builds on momentum further by giving every individual weight its own effectively adapted learning rate, based on how that weight's gradient has behaved recently. Both are refinements on exactly the loop above, not a different idea.

2. What can happen if the learning rate is set too large?

Overshooting the minimum by more than the original distance makes each subsequent step worse, not better.

3. What does momentum add to plain gradient descent?

Momentum behaves like inertia, carrying recent direction forward rather than recalculating from scratch each step.
