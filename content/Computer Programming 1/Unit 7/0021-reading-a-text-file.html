Reading a Text File

Files behave a lot like standard input — open a stream, read from it a line at a time, close it when done.

Lesson 22 → Contents Glossary →

Reading a file follows the same shape in every language: open it, read through its contents, then close it. Here, all four read scores.txt line by line and print each one — reusing the same iteration ideas from Lesson 17 and Lesson 8.

Python 
with open("scores.txt") as f:
    for line in f:
        print(line.strip())
Java 
Scanner fileScanner = new Scanner(new File("scores.txt"));
while (fileScanner.hasNextLine()) {
    System.out.println(fileScanner.nextLine());
}
fileScanner.close();
JavaScript (Node.js) 
const fs = require('fs');
const lines = fs.readFileSync('scores.txt', 'utf8').split('\n');
for (const line of lines) {
    console.log(line);
}
C++ 
std::ifstream file("scores.txt");
std::string line;
while (std::getline(file, line)) {
    std::cout << line << std::endl;
}
file.close();

Python's with open(...) as f and JavaScript's single readFileSync call both close the file automatically once finished — Python closes it when the with block ends, JavaScript closes it because readFileSync reads the whole file at once and hands back a finished string. Java and C++ open a file handle that stays open until you explicitly call close() — forgetting to do so leaves the file locked or wastes a system resource, the same category of bug as the infinite loop from Lesson 8 where a program keeps running long after it should have stopped.

The loop shapes should look familiar too: Java's while (fileScanner.hasNextLine()) is the same "keep going while a condition holds" pattern from Lesson 8, and Python's and JavaScript's for loops are iterating over a sequence exactly the way Lesson 17 iterated over a list — a file's lines behave like just another collection to loop through.

Definition A file handle (or file stream) is an open connection to a file that a program reads from or writes to, similar to how standard input is a stream connected to the keyboard. Like any open resource, it should be closed once you're done with it.
Why it matters here Console input disappears the moment a program ends, but a file persists — it's how programs save settings, load data sets, or write out logs that survive after the program has finished running. Every data-driven program eventually needs this same three-step pattern: open, read (or write), close.

Check your recall

1. What happens if a Java or C++ program opens a file but never calls close() on it?

This is the same category of bug as an infinite loop — something that should have stopped but didn't.

2. Why doesn't the Python example need an explicit close() call?

The with statement guarantees cleanup even if an error occurs while reading.

3. How does looping over a file's lines in Java resemble Lesson 8's while loop?

hasNextLine() plays the same role as any other while-loop condition.

4. Fill in the blank: an open connection to a file that a program reads from or writes to is called a file ___.

5. Fill in the blank: the three-step pattern every file operation follows is open, read (or write), and ___.

Some languages do this automatically; others require it explicitly.
