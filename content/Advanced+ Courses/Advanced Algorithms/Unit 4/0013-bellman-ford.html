Bellman-Ford

Dijkstra's algorithm breaks the instant an edge weight goes negative. Bellman-Ford handles negative weights correctly — and, as a side effect, can detect a negative cycle that would make "shortest path" meaningless in the first place.

← Lesson 12 Lesson 14 → Contents Glossary →

CP2+'s Lesson 22 ("Dijkstra's Algorithm & Network Delay Time") taught single-source shortest paths under one unstated assumption: every edge weight is non-negative. Dijkstra's greedy step — always finalize the closest unvisited vertex — relies on that assumption; once an edge can be negative, a vertex "finalized" as closest so far can later turn out to have a cheaper path through an edge that looked worse at the time. Bellman-Ford drops the non-negativity assumption entirely, at the cost of a slower runtime, and gains something Dijkstra's can't even express: a way to detect when "shortest path" doesn't have a well-defined answer at all.

Why Dijkstra's breaks with negative weights

Counterexample Vertices S, A, B. Edges: S→A weight 1, S→B weight 4, A→B weight −3. Dijkstra's finalizes A first (distance 1, smaller than B's 4), then finalizes B using the direct S→B edge (distance 4), since A is already "done" and Dijkstra's never revisits finalized vertices. But the true shortest S→B path is S→A→B, with cost 1+(−3) = −2, far less than 4. Dijkstra's greedy finalization step assumed no edge could make an already-finalized vertex's neighbors even cheaper — negative weights break exactly that assumption.

The algorithm

Algorithm 
function bellmanFord(graph, source):
    dist[source] = 0, dist[v] = infinity for all other v
    repeat (|V| - 1) times:
        for each edge (u, v, weight) in graph:
            if dist[u] + weight < dist[v]:
                dist[v] = dist[u] + weight     // relax the edge
    // one extra pass to detect negative cycles
    for each edge (u, v, weight) in graph:
        if dist[u] + weight < dist[v]:
            report "negative-weight cycle reachable from source"
    return dist
Why exactly |V|−1 rounds of relaxation Any shortest path in a graph with no negative cycle visits at most |V|−1 distinct edges (a shortest path never repeats a vertex, since removing a repeated-vertex loop of non-negative-or-not total weight — wait, more precisely: with no negative cycle, a shortest path is never improved by revisiting a vertex, so it has at most |V|−1 edges). Each full pass over all edges guarantees that the true shortest path to some vertex gets "one more edge correct" — after k passes, every shortest path using at most k edges is guaranteed correctly computed. After |V|−1 passes, every shortest path (which uses at most |V|−1 edges) is correct, by induction on path length.
Detecting negative cycles If a graph has a reachable negative-weight cycle, "shortest path" is undefined — you could loop the cycle forever, driving the cost to −∞. After |V|−1 rounds have already stabilized every simple-path distance, one more full pass that still finds an edge to relax is only possible if some path is using more than |V|−1 edges to improve — which can only happen by looping a negative cycle. That's exactly the extra check in the algorithm's last step.
Runtime Θ(V·E): |V|−1 rounds, each scanning all E edges. This is asymptotically worse than Dijkstra's Θ(E log V) with a heap, which is the price paid for correctness under negative weights — there is no known algorithm that handles arbitrary negative edges as fast as Dijkstra's handles non-negative ones.
Why this connects forward to Unit 4's flow algorithms Ford-Fulkerson (Lesson 16) reasons about "augmenting paths" in a residual graph that can contain negative-weight-like backward edges in spirit — the relaxation-based thinking Bellman-Ford introduces here (repeatedly improving a distance estimate until it stabilizes) reappears as the underlying mental model for why flow algorithms terminate and are correct.

Check your recall

No peeking back up — answer from memory first, then check.

1. Why does Dijkstra's algorithm give the wrong answer on a graph with a negative edge weight?

Dijkstra's correctness depends on the invariant that once a vertex is finalized, no cheaper path to it can appear later — negative edges directly violate that invariant.

2. Why does Bellman-Ford run exactly |V|−1 rounds of edge relaxation?

The inductive guarantee — after k rounds, all shortest paths of at most k edges are correct — is exactly what caps the needed rounds at |V|−1.

3. How does Bellman-Ford detect a negative-weight cycle?

Since |V|−1 rounds already stabilize every simple-path distance, any further improvement is only possible through a path that loops a negative cycle.

4. Fill in the blank: each round of Bellman-Ford scans every edge and attempts to ___ it, updating a distance estimate if a cheaper path is found.

Edge relaxation is the single repeated operation the whole algorithm is built from.

5. Fill in the blank: if a graph contains a reachable ___ , shortest path is undefined, since looping it repeatedly drives the cost toward negative infinity.

A negative cycle makes "shortest path" meaningless, which is exactly the condition Bellman-Ford's final pass is built to detect.
