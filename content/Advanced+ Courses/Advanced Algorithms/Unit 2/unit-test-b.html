1. A recursive algorithm calls itself on a subproblem of size n/4 and another of size 3n/4. Why does correctness require strong induction instead of ordinary induction?

Ordinary induction's "assume n−1" step doesn't reach a jump to n/4 or 3n/4, so the hypothesis must hold for every smaller size simultaneously — even equal splits like n/2 need this same strengthened hypothesis, not just uneven ones.

2. While recursively counting inversions on an array split into L and R, which statement about cross-inversions is correct?

Recursion on L only ever compares indices inside L, and likewise for R, so a pair straddling both halves is structurally outside what either recursive call could ever detect — only the merge step, which compares across the split, can find it.

3. What would go wrong if median-of-medians used groups of 3 instead of groups of 5?

Groups of 5 are the smallest odd size that produces a strong enough "at least roughly 3n/10 on each side" guarantee to make the recurrence resolve to O(n); groups of 3 give a guarantee too weak for that.

4. What is the essential change Strassen's algorithm makes to block matrix multiplication that allows it to beat Θ(n³)?

Since multiplications set the recurrence's branching factor a (and hence its exponent log_b a), trading one multiplication for extra Θ(n²) additions strictly improves the asymptotics without changing the combine step's order.

5. Fill in the blank: strong induction discharges the recursive calls, but a divide-and-conquer proof still needs a separate, direct argument that the ___ step correctly stitches subproblem answers together.

Induction only covers "trust the subproblems"; the non-recursive glue code needs its own direct correctness argument, which is exactly the gap the combine step's proof fills.

6. A divide-and-conquer algorithm computes the sum of an array by splitting it into two halves, recursively summing each half, then adding the two sums. Answer both parts:

(a) What is the correct base case?

(b) Fill in the blank: the inductive step must directly show that adding the two recursively-computed half-sums equals the true sum of all n elements — a fact that holds because every element belongs to exactly one ___.

(a) An empty array (size 0) trivially sums to 0 with no recursive call needed, making it a clean base case. (b) Each element is in exactly one of the two halves, so summing both halves' sums covers every element exactly once — the direct argument the combine step needs.

7. During mergeAndCount on left half L = [3, 6, 10] and right half R = [2, 4, 5] (both already sorted), answer both parts:

(a) Fill in the blank: merging L and R via mergeAndCount detects ___ total cross-inversions.

(b) If mergeAndCount instead compared every pair of elements individually across L and R (brute force) rather than using the sorted-array shortcut, what would change?

(a) Tracing the merge: R[0]=2 < L[0]=3, count += (3−0) = 3; then R[1]=4 < L[1]=6, count += (3−1) = 2; then R[2]=5 < L[1]=6, count += (3−1) = 2. Total = 3+2+2 = 7, matching the direct pair count (3>2; 6>2,6>4,6>5; 10>2,10>4,10>5) = 1+3+3 = 7. (b) Sortedness is what licenses jumping to "all remaining L elements" instead of comparing every pair individually, giving the same count in linear rather than quadratic time.

8. In the recurrence T(n) ≤ T(n/5) + T(7n/10) + Θ(n) for median-of-medians, answer both parts:

(a) Which term corresponds to recursively finding the pivot itself (the median of the group medians)?

(b) Fill in the blank: substituting the guess T(n) ≤ cn gives c(n/5) + c(7n/10) + Θ(n) = c(9n/10) + Θ(n); since 9/10 < 1, a large enough c can absorb the Θ(n) term, confirming T(n) = O(___).

(a) The ⌈n/5⌉ group medians are themselves searched recursively via select(medians, ...), which is exactly the T(n/5) term; T(7n/10) is the separate recursive call into the larger partition after pivoting. (b) This matches the lesson's conclusion: worst-case linear-time selection, T(n) = O(n).

9. Compared to the naive T(n) = 8T(n/2) + Θ(n²) (which solves to Θ(n³)), answer both parts:

(a) Why does cutting to seven multiplications change the result at all, given that both recurrences still have a Θ(n²) combine cost?

(b) Fill in the blank: since f(n)=n² is polynomially smaller than n^(log₂7)≈n^2.807, Strassen's recurrence falls into Master Theorem Case ___, so T(n) = Θ(n^(log₂7)).

(a) log_b(a) directly determines the leaf-dominated exponent in Case 1; dropping a from 8 to 7 lowers the exponent from 3 to ≈2.807, with the Θ(n²) combine term unaffected either way. (b) Case 1 applies since n² is polynomially smaller than n^2.807.

10. In the direct correctness argument for mergeAndCount, answer both parts:

(a) Why does R[j] forming an inversion with L[i] guarantee it also inverts with every element from L[i+1] onward?

(b) Fill in the blank: this shortcut — counting (length of L − i) inversions at once instead of checking each element of L individually — is exactly what keeps mergeAndCount's extra work at O(1) per ___, preserving merge sort's overall runtime.

(a) Sortedness of L guarantees every element from L[i] onward is at least as large as L[i], which is already greater than R[j] — and since R[j]'s original position is to the right of the whole R-half, each such pair is a genuine inversion. (b) Adding a constant-time increment per comparison, instead of checking every remaining L element one by one, is what keeps the recurrence identical to plain merge sort's.
