1. For a sum-segment tree built over the array [6, 2, 5, 4] (indices 0–3), what value is stored at the node covering range [2, 3]?

The node covering [2,3] aggregates arr[2]+arr[3] = 5+4 = 9. The root (covering [0,3]) would store 17, and the node covering [0,1] would store 6+2=8.

2. Answer both parts about segment tree operations:

(a) Why does updating a single array element only require recomputing O(log n) nodes instead of the whole tree?

(b) Fill in the blank: a segment tree over n elements has Θ(___) levels, which is what bounds both queries and updates to touching that many nodes.

(a) Nodes whose range excludes the updated index provably can't change, so only the single root-to-leaf path needs recomputing. (b) The tree's recursive range-halving structure is exactly what gives it Θ(log n) levels.

3. Answer both parts about a Fenwick tree's lowbit trick:

(a) What is lowbit(40), computed as 40 & (−40)?

(b) Fill in the blank: so tree[40] covers the range (40−8, 40], meaning indices ___ through 40.

(a) 40 in binary is 101000; its lowest set bit is 1000 = 8. (b) That makes the covered range (32,40], i.e., indices 33 through 40.

4. Fill in the blank: computing a range sum as prefixSum(r) − prefixSum(l−1) only works because addition is ___ — subtraction can exactly undo it, which is why this same trick fails for an aggregate like min that has no "undo" operation.

Sum is invertible (subtraction undoes addition), which is exactly what lets two prefix sums be combined into a range sum — min and max have no equivalent inverse operation to exploit the same way.

5. During an AVL insertion, ancestor v ends up with balance(v) = −2 (right-heavy) and balance(v.right) ≤ 0. Which rebalancing case is this, and what fixes it?

balance(v) = −2 means v is right-heavy, and balance(v.right) ≤ 0 means the imbalance is concentrated on the outer (right) side — the Right-Right case, the mirror of Left-Left, fixed with one single left rotation at v.

6. Answer both parts about the AVL balance invariant:

(a) Which of these best explains why AVL height is Θ(log n) rather than Θ(n)?

(b) Fill in the blank: for every node v, balance(v) must be an element of the set {−1, 0, ___} for the AVL invariant to hold.

(a) Inverting an exponential lower bound on node count as a function of height produces a logarithmic upper bound on height as a function of node count. (b) Any balance factor outside {−1, 0, 1} triggers a rotation to restore the invariant.

7. In the union-by-rank proof, a tree's root has rank 4. What is the minimum number of nodes such a tree must contain?

By the theorem, a rank-r tree has at least 2ʳ nodes. With r=4, that's 2⁴=16 nodes at minimum.

8. Answer both parts about union by rank and path compression:

(a) Using union by rank alone, with no path compression at all, what is the worst-case cost of a single find operation?

(b) Fill in the blank: Kruskal's algorithm relies on Union-Find's near-constant same-set queries to keep its total runtime at Θ(E log E) rather than the slower Θ(E·___).

(a) Union by rank alone already guarantees a tree's height (and so any find's cost) is bounded by O(log n), even without path compression's extra help. (b) Without a fast Union-Find, Kruskal's would have to pay a full O(V) cost per same-set check instead.

9. Fill in the blank: after inserting "cat", "car", "card", and "dog" into an empty trie, a query startsWith("car") walks ___ edges from the root.

startsWith("car") walks exactly 3 edges — c, then a, then r — the shared path that both "car" and "card" pass through.

10. Answer both parts about tries:

(a) Why do "cat" and "car" share the same first two edges in a trie?

(b) Fill in the blank: a trie's per-character node overhead can make it use more memory than a hash set, especially when the alphabet is large and prefixes are rarely ___.

(a) A trie's entire organizing principle is shared prefixes — two strings that agree for their first two characters follow the identical path for that length before splitting. (b) When few strings actually share prefixes, that structural sharing which normally saves memory doesn't pay off, and per-character node overhead dominates instead.
