Quantum Parallelism

One quantum query can evaluate a function on every input at once — a genuinely remarkable fact that, on its own, buys you nothing at all. This lesson shows exactly why, setting up the trick that actually fixes it.

← Lesson 25 Lesson 27 → Contents Glossary →

Every quantum algorithm this course studies is built around a function f whose values are computed by a black-box unitary gate, called an oracle. This lesson introduces the oracle model and the first, most basic trick every quantum algorithm exploits — and immediately shows why that trick alone isn't enough to be useful.

1. The oracle model

Definition — Oracle For a function f: {0,1} → {0,1}, its oracle is a unitary gate Uf acting on two qubits: Uf|x⟩|y⟩ = |x⟩|y ⊕ f(x)⟩, where ⊕ is addition mod 2 (XOR). The input register |x⟩ is left unchanged; the output register |y⟩ is flipped exactly when f(x) = 1.

Uf is unitary (in fact a permutation matrix on the relevant basis states) precisely because XOR-ing with a fixed value is always invertible — applying Uf twice with the same x returns y to its original value. This oracle framing treats f as a resource you can query, without caring how f is actually computed internally — exactly the right abstraction for comparing classical and quantum query counts, which Lesson 30 makes precise.

2. Evaluating f on a superposition

Fact — Quantum Parallelism Apply Uf to H|0⟩ ⊗ |0⟩ = |+⟩ ⊗ |0⟩ = (|0⟩|0⟩ + |1⟩|0⟩)/√2:
Uf[(|0⟩|0⟩ + |1⟩|0⟩)/√2] = (|0⟩|f(0)⟩ + |1⟩|f(1)⟩)/√2

A single application of Uf — one query — has produced a state that encodes both f(0) and f(1) simultaneously, in superposition. Classically, computing both f(0) and f(1) requires two separate calls to f. This is quantum parallelism: superposition lets one oracle query touch every input at once.

3. Why this alone is not yet a speedup

Why measuring this state right away wastes the parallelism entirely Measure (|0⟩|f(0)⟩ + |1⟩|f(1)⟩)/√2 immediately, and Lesson 12's collapse takes over: you get x = 0 together with f(0), or x = 1 together with f(1), each with 50% probability — never both. You learn the value of f at exactly one input, chosen at random, exactly as if you had classically picked one input at random and evaluated f there directly. The "both values at once" promise of quantum parallelism evaporates the instant you measure carelessly — it is not, by itself, a free lunch. Getting an actual advantage out of this state requires processing it further, before measuring, in a way that combines information from both branches into something a single measurement can usefully reveal. That processing is interference, and it's the entire subject of Lesson 27.
Example — Scaling to n Input Bits For f: {0,1}ⁿ → {0,1}, the same idea scales up directly: apply H to n input qubits, all starting at |0⟩, to get an equal superposition of all 2ⁿ inputs, then apply Uf. The result is (1/√2ⁿ) Σₓ |x⟩|f(x)⟩, summed over all 2ⁿ possible n-bit strings x — every value of f, computed with a single oracle query, sitting in one superposition. Lessons 29 and 31 both build directly on exactly this construction.

1. What does the oracle Uf do to |x⟩|y⟩?

The oracle's defining action is exactly U_f|x⟩|y⟩ = |x⟩|y⊕f(x)⟩ — a reversible way to compute f into the output register without disturbing the input.

2. What is the result of applying Uf to |+⟩ ⊗ |0⟩?

One query to U_f, applied to a superposed input, evaluates f at both 0 and 1 simultaneously, encoded in a single two-qubit state.

3. What happens if you immediately measure the state (|0⟩|f(0)⟩ + |1⟩|f(1)⟩)/√2?

Immediate measurement collapses to one branch, revealing only one of the two function values — quantum parallelism alone provides no advantage without further processing before measuring.

4. Fill in the blank: a black-box unitary gate representing a function f, queried without regard to how f is internally computed, is called an ___.

The oracle model is the standard framework for comparing classical and quantum query counts, treating f purely as a resource to be queried.

5. Fill in the blank: turning quantum parallelism into an actual speedup requires combining the superposition's branches, before measuring, through ___.

Interference is the missing ingredient — Lesson 27's subject — that turns "many values computed in parallel" into "one useful measurement outcome."
