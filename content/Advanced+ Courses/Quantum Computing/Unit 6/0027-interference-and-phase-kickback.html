Interference and Phase Kickback

One trick, applied to Lesson 26's oracle, turns "f's value" into a relative phase instead of a measured bit — and a relative phase, unlike a measured bit, can be steered by later gates into a genuinely useful interference pattern.

← Lesson 26 Lesson 28 → Contents Glossary →

Lesson 26 left off with a problem: quantum parallelism computes every value of f at once, but a careless measurement throws almost all of it away. Phase kickback is the fix — a specific choice of target-register state that redirects f's output from a place measurement destroys into a place later gates can still work with.

1. Preparing the target in |−⟩

Fact — Phase Kickback If the target register of the oracle Uf is prepared in the state |−⟩ = (|0⟩ − |1⟩)/√2, then: Uf|x⟩|−⟩ = (−1)f(x)|x⟩|−⟩.
Derivation Uf|x⟩|−⟩ = Uf|x⟩(|0⟩−|1⟩)/√2 = [|x⟩|f(x)⟩ − |x⟩|1⊕f(x)⟩]/√2, applying the oracle's definition to each term. If f(x) = 0: this is |x⟩(|0⟩−|1⟩)/√2 = |x⟩|−⟩ — unchanged, a factor of (−1)⁰ = +1. If f(x) = 1: this is |x⟩(|1⟩−|0⟩)/√2 = −|x⟩(|0⟩−|1⟩)/√2 = −|x⟩|−⟩ — a factor of (−1)¹ = −1. Both cases match (−1)f(x)|x⟩|−⟩ exactly.

Notice what happened: the target register |−⟩ comes out completely unchanged (up to that overall sign) — the "output" of f didn't get written into the target at all. Instead, f(x) "kicked back" onto the control register as a phase factor multiplying |x⟩. This is exactly why the technique is called phase kickback.

2. Kicking back onto a superposition

Example — Phase Kickback on |+⟩ Apply Uf to |+⟩ ⊗ |−⟩ = [(|0⟩+|1⟩)/√2] ⊗ |−⟩: linearity gives [Uf|0⟩|−⟩ + Uf|1⟩|−⟩]/√2 = [(−1)f(0)|0⟩|−⟩ + (−1)f(1)|1⟩|−⟩]/√2. The |−⟩ factors out entirely: [(−1)f(0)|0⟩ + (−1)f(1)|1⟩]/√2 ⊗ |−⟩. The target register can now be set aside completely — every bit of information about f that survives is sitting entirely in the relative phase between the |0⟩ and |1⟩ terms of the control register.
Why this is the missing ingredient from Lesson 26 Compare the two versions directly. Without phase kickback: (|0⟩|f(0)⟩ + |1⟩|f(1)⟩)/√2 — f's value sits in the target register's amplitude location, and measuring collapses to one term, destroying the other, exactly Lesson 26's problem. With phase kickback: [(−1)f(0)|0⟩ + (−1)f(1)|1⟩]/√2 — f's value sits entirely in relative phase on a single register. Relative phase, unlike a value hidden in a soon-to-collapse second register, is exactly the kind of information a later Hadamard gate can convert into a measurably biased outcome — Lesson 13's basis-change trick and Lesson 1.5's "relative phase is physically detectable" fact, both now doing real algorithmic work. Lesson 28 runs this exact construction through one more Hadamard and shows the interference pattern it produces.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is Uf|x⟩|−⟩?

Phase kickback produces a sign flip exactly when f(x) = 1, and leaves the state unchanged when f(x) = 0 — captured compactly as the (−1)^f(x) factor.

2. If f(x) = 1, what phase factor does Uf|x⟩|−⟩ pick up?

(−1)^f(x) with f(x) = 1 gives (−1)¹ = −1, matching the direct derivation: |1⟩ − |0⟩ = −(|0⟩ − |1⟩).

3. Why is this technique called "phase kickback"?

The name reflects exactly what happens: f(x)'s information "kicks back" from the target register onto the control register, appearing there as a relative phase.

4. Fill in the blank: after phase kickback, information about f is encoded entirely in relative ___ on the control register, not in the target register's value.

Relative phase is exactly what phase kickback produces — the quantity a later Hadamard can turn into a biased, informative measurement outcome.

5. Fill in the blank: after phase kickback, the target register factors out completely and can be safely ___ for the rest of the algorithm.

Since |−⟩ multiplies through unchanged, the target register no longer holds any information relevant to the rest of the computation and can be set aside.
