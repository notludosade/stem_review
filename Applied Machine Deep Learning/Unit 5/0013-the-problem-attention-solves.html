The Problem Attention Solves

AI Developer's Lesson 17 opened with attention already in hand, solving a bottleneck it never named. This lesson names it — the specific failure of the architecture attention actually replaced.

← Lesson 12 Lesson 14 → Contents Glossary →

Before attention, sequence-to-sequence tasks like translation used an encoder-decoder architecture: an encoder LSTM reads the entire input sentence, one word at a time, and compresses everything it read into a single fixed-size final hidden state — a context vector. A separate decoder LSTM then generates the output sentence using only that one vector as its summary of the entire input. Every word the encoder ever read has to be squeezed through that same fixed-size bottleneck before the decoder can use any of it.

Python — the bottleneck, made concrete 
import torch.nn as nn

encoder = nn.LSTM(input_size=256, hidden_size=512, batch_first=True)
decoder = nn.LSTM(input_size=256, hidden_size=512, batch_first=True)

# Encoding: read the whole input, keep only the final hidden state
_, (context, _) = encoder(input_sequence)   # context has shape (1, 512) -- always, regardless of length

# Decoding: generate output using only that one fixed-size vector as its summary
output, _ = decoder(output_so_far, (context, cell_state))

context's shape never changes — 512 numbers, whether the input sentence was 5 words or 50. For a short sentence, that's plenty of room. For a long one, cramming 50 words of meaning into the same fixed 512 numbers a 5-word sentence used means something has to get compressed away, and in practice, translation quality from this architecture degrades noticeably as sentences get longer — exactly the pattern you'd expect from an information bottleneck, not from the LSTM's mechanics being wrong. Attention is the fix, and its actual idea is closer than it might sound to something already familiar: instead of forcing everything through one fixed-size summary, let the decoder look directly back at every encoder hidden state, at every single output step, weighted by how relevant each one is right now.

Definition An encoder-decoder architecture uses one network to read an input sequence and another to generate an output sequence from it. A context vector is a fixed-size summary the encoder compresses its entire input into. Attention replaces reliance on that one fixed vector with direct, weighted access to every one of the encoder's hidden states.
Why this reframes what AI Developer's Lesson 17 already said "Lets a model directly relate any two positions in a sequence... without passing information step by step through everything in between" is a description of attention's mechanism. This lesson supplies the motivation underneath it: the "everything in between" it's avoiding isn't merely a slow relay race between time steps, like Lesson 11's vanishing gradients across many steps — it's a hard information ceiling, one fixed-size vector, that no amount of clever gating could ever fully get around. Attention doesn't shrink the ceiling. It removes it.
