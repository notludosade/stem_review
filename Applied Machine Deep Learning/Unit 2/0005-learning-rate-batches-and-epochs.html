Learning Rate, Batches, and Epochs

Lesson 4's tiny network computed a gradient from one example. Real training sets have thousands or millions of examples — this lesson covers how much of that data gets looked at before each update, and the vocabulary every real training script's output is printed in.

← Lesson 4 Lesson 6 → Contents Glossary →

Computing a gradient from every single training example before taking one step — batch gradient descent — gives the most accurate gradient possible, but on a large dataset it's painfully slow: one update per full pass over everything. The opposite extreme, stochastic gradient descent (SGD), updates after just one example at a time — fast per update, but each individual gradient is a noisy, unreliable estimate of the true downhill direction. Almost nobody uses either extreme. Real training uses mini-batch gradient descent: split the dataset into small chunks, compute one averaged gradient per chunk, and update once per chunk.

Python — the training loop's actual shape 
batch_size = 32
num_epochs = 10

for epoch in range(num_epochs):
    shuffle(training_data)
    for batch in split_into_batches(training_data, batch_size):
        predictions = forward_pass(batch)
        loss = compute_loss(predictions, batch.labels)
        gradients = backward_pass(loss)   # Lesson 4, averaged over the whole batch
        update_weights(gradients, learning_rate)   # Lesson 3
        # this one update is one "iteration" or "step"

One full pass through the entire training set is an epoch — with 10,000 examples and a batch size of 32, one epoch takes 313 iterations (also called steps), each one a single weight update. Training almost always runs for many epochs, since one pass rarely drives the loss anywhere near its minimum. Batch size sits in a real tradeoff: a small batch (say, 8) gives a noisier gradient estimate — closer to SGD — but fits easily in memory and updates weights often; a large batch (say, 512) gives a smoother, more reliable gradient closer to full batch descent, but costs more memory per step and updates less frequently for the same amount of data seen.

Definition A mini-batch is a small subset of the training set used to compute one averaged gradient. Batch size is how many examples are in it. An iteration (or step) is one weight update, using one mini-batch's gradient. An epoch is one full pass through the entire training set. Stochastic gradient descent (SGD) is the batch-size-1 extreme case.
Why a noisier gradient isn't purely a downside A small batch's noisy gradient estimate sounds like a defect, but it isn't only that — the same randomness that makes any one step less accurate can also help a network step past a shallow local minimum or saddle point (Lesson 3) that a perfectly smooth, large-batch gradient would settle into and get stuck at. In practice, batch size is chosen less for "which gradient is more correct" and more for what fits in memory and what Unit 6's hardware can process efficiently in parallel — accuracy of any single gradient estimate turns out to matter less than it initially seems.

1. Why does almost no real training use full batch gradient descent on a large dataset?

Full batch descent gives the most accurate gradient, but only one update per full pass over the data.

2. With 10,000 training examples and a batch size of 32, roughly how many iterations happen in one epoch?

One iteration processes one batch; the number of batches per epoch is dataset size divided by batch size.

3. What is a genuine upside of a small batch size's noisier gradient estimate?

Noise from small batches can act like a useful nudge away from getting stuck, not purely a downside.
