Overfitting and Regularization

AI Developer's Unit 2 defined overfitting once, in general: memorizing training data instead of learning the pattern. Neural networks overfit unusually easily — millions of weights are more than enough to just memorize — so this closes Unit 2 with the specific tools built to fight it.

← Lesson 5 Unit 3, Lesson 7 → Contents Glossary →

A large enough network has enough weights to essentially memorize a training set outright — driving training loss toward zero while validation loss quietly climbs back up. Regularization is any technique that trades away a little training accuracy on purpose, in exchange for a network that generalizes better to data it hasn't seen. Two techniques do almost all of the real work in practice.

Python — PyTorch, both techniques in one model 
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(784, 256),
    nn.ReLU(),
    nn.Dropout(p=0.5),     # randomly zeroes 50% of activations, only during training
    nn.Linear(256, 10)
)

optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
    weight_decay=1e-4      # penalizes large weights directly in the loss
)

Dropout randomly zeroes out a fraction of a layer's activations on every training step — a different random subset each time — which prevents any single neuron from becoming so specialized that the network only works with that exact neuron intact. It's active only during training; at inference time every neuron participates, scaled to compensate. Weight decay (L2 regularization) adds a penalty term to the loss function itself, proportional to the sum of the squared weights, so gradient descent is now pulling weights toward being smaller at the same time it's minimizing prediction error — large weights have to be worth their cost. A network with mostly small weights tends to produce smoother, less erratic predictions than one where a few weights have grown huge to fit training data's noise exactly.

Definition Regularization trades training accuracy for better generalization. Dropout randomly zeroes a fraction of activations during training only. Weight decay (L2 regularization) adds a penalty proportional to squared weight size directly into the loss. Early stopping halts training once validation loss stops improving, even if training loss is still falling.
Why dropout works: it removes a shortcut, not information Without dropout, a network can quietly lean on one specific neuron (or a small clique of them) to handle a pattern, the way a group project can lean on one person who happens to be good at a particular part. Zeroing that neuron out at random, unpredictably, on different training steps forces every other neuron to be able to pick up the slack — the network ends up spreading the same task across more of its weights redundantly, instead of concentrating it fragile-ly in one place. That redundancy is what tends to generalize better to new data.

1. What does dropout actually do during training?

The random subset changes every step, and dropout is active only during training, not at inference time.

2. How does weight decay change what gradient descent optimizes?

weight_decay adds a squared-weight penalty term directly into what's being minimized.

3. Why can dropout improve generalization even though it seems to make training strictly harder?

Redundant, spread-out representations tend to be more robust to data the network hasn't seen before.
