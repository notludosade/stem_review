Evaluation Metrics Beyond Accuracy

AI Developer's Unit 3 named precision and recall once, briefly. Every model this course has built since deserves the full picture — the single object every one of these metrics is actually computed from, and exactly when accuracy alone goes badly wrong.

← Lesson 18 Lesson 20 → Contents Glossary →

Every binary classification result falls into exactly one of four buckets, and a confusion matrix is simply a table counting how many predictions landed in each one: a true positive (predicted positive, actually positive), a false positive (predicted positive, actually negative), a false negative (predicted negative, actually positive), and a true negative (predicted negative, actually negative). Every metric in this lesson is computed from just these four counts.

Python — every metric, derived from the same four numbers 
tp, fp, fn, tn = 50, 10, 5, 935   # a spam filter's results on 1,000 emails

accuracy = (tp + tn) / (tp + fp + fn + tn)
precision = tp / (tp + fp)          # of predicted positives, how many were right?
recall = tp / (tp + fn)             # of actual positives, how many did it catch?
f1 = 2 * precision * recall / (precision + recall)   # harmonic mean of the two

print(accuracy, precision, recall, f1)
# 0.985  0.833  0.909  0.870

Precision answers "of everything the model called positive, how much actually was?" — a low precision means a lot of false alarms. Recall answers "of everything that actually was positive, how much did the model catch?" — a low recall means a lot of real cases slipping through undetected. These two usually trade off against each other: a model that predicts "positive" more freely tends to catch more real cases (higher recall) at the cost of more false alarms (lower precision), and vice versa. The F1 score is the harmonic mean of the two — closer to whichever of precision or recall is lower, so a model can't earn a good F1 score by excelling at one while badly neglecting the other.

Worked example — why accuracy alone misleads A rare disease affects 1% of patients. A "model" that always predicts "healthy," never once actually looking at the input, still scores 99% accuracy — and is completely useless, with 0% recall for the disease it exists to catch. Accuracy alone can't tell these two situations apart: a genuinely excellent model, and a lazy one exploiting a heavily imbalanced dataset. Precision, recall, and F1 can.
Why precision and recall aren't equally important for every task A spam filter's false positive — a real email marked spam — is actively costly, so it's usually tuned to favor precision. A cancer-screening model's false negative — a real case missed entirely — can be far worse than a false alarm that just leads to an unnecessary follow-up test, so it's usually tuned to favor recall instead. Neither task is wrong to make that tradeoff; "beyond accuracy" doesn't mean one correct metric exists. It means the actual cost of each kind of mistake has to be part of choosing which metric to optimize.

1. What question does precision answer?

precision = tp / (tp + fp) — it's about the quality of positive predictions specifically.

2. Why can a model that always predicts "healthy" for a rare disease still score 99% accuracy?

With only 1% of cases actually diseased, always guessing "healthy" is right 99% of the time by default.

3. Why is F1 score the harmonic mean of precision and recall, rather than their plain average?

The harmonic mean penalizes a large gap between precision and recall more than a plain average would.
