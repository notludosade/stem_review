Why Images Need a Different Architecture

AI Developer's Lesson 15 introduced CNNs by naming the pieces. Before wiring any of them together, it's worth actually doing the arithmetic on the alternative — a plain fully-connected network on raw pixels — to see exactly why nobody does that.

← Lesson 6 Lesson 8 → Contents Glossary →

The most direct way to feed an image into Unit 1's network is to flatten it into one long vector of pixel values and run it through an ordinary fully-connected layer — every input connected to every neuron, exactly like every layer built so far. It works, technically. It also doesn't scale.

Python — counting parameters, the direct way 
# A modest 224x224 color image, flattened
image_inputs = 224 * 224 * 3          # 150,528 pixel values

# One fully-connected hidden layer of 1,024 neurons
fc_weights = image_inputs * 1024      # 154,140,672
fc_params = fc_weights + 1024         # + one bias per neuron
print(fc_params)                      # over 154 million, for one layer

# A convolutional layer instead: 32 filters, each 3x3 over 3 color channels
conv_weights = 32 * (3 * 3 * 3)       # 864
conv_params = conv_weights + 32       # + one bias per filter
print(conv_params)                    # 896 — for a layer covering the same image

One fully-connected hidden layer over a single modest image needs more parameters than most classical machine learning models will ever see, and that's before adding a second layer or a larger image. A convolutional layer covering that exact same image needs 896. The 170,000-times difference isn't a rounding error — it comes from two assumptions a fully-connected layer refuses to make, and an image happens to satisfy both of them.

The first is spatial locality: a pixel is most related to the pixels immediately around it, not to a pixel on the opposite corner of the image. A filter that only ever looks at a small local neighborhood — say, 3×3 pixels — isn't throwing away useful structure; it's matching the structure that's actually there. The second is translation invariance: an edge, a curve, or a patch of texture means the same thing regardless of where in the image it happens to sit. A fully-connected layer would need to learn to recognize "vertical edge" separately at every single position in the image, spending a huge number of independent weights re-learning the same pattern over and over. A convolutional filter learns it once and reuses those same weights everywhere the filter slides — the parameter sharing AI Developer named without deriving the actual arithmetic behind it.

Definition A fully-connected layer connects every input to every neuron independently, with no assumption about structure. Spatial locality is the assumption that nearby pixels are more related than distant ones. Translation invariance is the assumption that a pattern means the same thing no matter where in the image it appears.
Why these two assumptions don't transfer to arbitrary tabular data A row in a spreadsheet — age, income, zip code — has no meaningful "neighboring" column the way a pixel has neighboring pixels, and shuffling its columns doesn't preserve any real-world structure the way sliding a pattern across an image does. That's precisely why classical models and Unit 1's plain fully-connected layers remain the right tool for tabular data, while CNNs exist specifically for data where locality and translation invariance are actually true. Choosing an architecture, this course keeps demonstrating, is about matching the shape of the assumption to the shape of the data — never a default.

1. Why does a fully-connected layer over a raw image need so many more parameters than a convolutional layer?

Every pixel-to-neuron connection in a fully-connected layer is its own independent weight, with nothing reused.

2. What does "translation invariance" mean, in the context of image data?

The same filter weights are reused at every position specifically because a pattern's meaning doesn't depend on its location.

3. Why don't spatial locality and translation invariance generally apply to a spreadsheet of tabular features?

Tabular columns don't have the kind of spatial relationship pixels do, so a CNN's assumptions don't fit that shape of data.
