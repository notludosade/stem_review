Convolutions, Filters, and Feature Maps

Lesson 7 established why a filter's weights get reused across an entire image. This lesson is the actual arithmetic of "reused" — computing a real feature map, by hand, one position at a time.

← Lesson 7 Lesson 9 → Contents Glossary →

A convolution slides a small filter across an input, and at every position, computes one number: the elementwise product of the filter and whatever patch of input it's currently sitting on top of, summed. That single number goes into the corresponding position of the output — the feature map.

Python — a convolution, one position at a time 
import numpy as np

image = np.array([
    [1, 2, 0, 1, 3],
    [0, 1, 2, 3, 1],
    [2, 0, 1, 2, 0],
    [1, 3, 0, 1, 2],
    [0, 1, 2, 0, 1],
])

filt = np.array([          # a vertical-edge-detecting filter
    [1, 0, -1],
    [1, 0, -1],
    [1, 0, -1],
])

def conv_at(img, f, row, col):
    patch = img[row:row+3, col:col+3]
    return np.sum(patch * f)   # elementwise multiply, then sum

print(conv_at(image, filt, 0, 0))   # 1*1+2*0+0*-1 + 0*1+1*0+2*-1 + 2*1+0*0+1*-1 = 0
print(conv_at(image, filt, 0, 1))   # slide one column right, same filter

How far the filter moves between positions is the stride. A stride of 1 checks every possible position; a stride of 2 skips every other one, producing a smaller feature map faster, at the cost of some spatial resolution. With a 5×5 input, a 3×3 filter, and stride 1, the filter fits in 3 positions per row and 3 per column — a 3×3 output. In general, output size is ⌊(W − F) / S⌋ + 1, where W is input width, F is filter width, and S is stride. Notice this shrinks the output relative to the input every time — a real cost for deep networks stacking many convolutional layers. Padding — adding a border of zeros around the input before sliding the filter — is the fix: "same" padding adds just enough zeros that the output comes out the same size as the input, letting a network stack convolutional layers without silently losing spatial size at every one.

Definition Stride is how many positions the filter moves between computations. Padding adds a border of zeros around the input before convolving, most often to keep the output the same size as the input ("same" padding) instead of shrinking it ("valid" padding, no border at all).
Why stride and padding are chosen together, not independently Stride 2 is a cheap way to downsample — Lesson 9's pooling does something similar with a different mechanism — but it also throws away detail the way skipping every other row of a scan would. Padding doesn't add any real information either; it's zeros. Real architectures combine both deliberately: "same" padding with stride 1 in early layers to preserve detail while the network is still building up basic features, and stride 2 (or Lesson 9's pooling) later on, once the network can afford to trade spatial precision for a more compact, higher-level representation.
