Hyperparameter Tuning: What Actually Matters

This course has handed you a learning rate, a batch size, a dropout rate, and an architecture in almost every widget so far. This lesson is about how those numbers actually get chosen for a real project, instead of assumed.

← Lesson 17 Unit 7, Lesson 19 → Contents Glossary →

A hyperparameter is any setting chosen before training starts and left fixed throughout it — learning rate, batch size, dropout rate, weight decay strength, number of layers — as opposed to a parameter (a weight or bias), which gradient descent adjusts automatically. Of every hyperparameter across this entire course, learning rate has consistently mattered the most: too small and training crawls, too large and it diverges outright, and Lesson 3, Lesson 5, and Lesson 16's widgets all demonstrated some version of exactly this same sensitivity.

Python — two ways to search a hyperparameter space 
import itertools, random

learning_rates = [0.001, 0.01, 0.1]
dropout_rates = [0.0, 0.3, 0.5]

# Grid search: every combination, exhaustively
grid_trials = list(itertools.product(learning_rates, dropout_rates))   # 9 trials

# Random search: the same budget, sampled instead of enumerated
random_trials = [
    (random.uniform(0.001, 0.1), random.uniform(0.0, 0.5))
    for _ in range(9)
]

Grid search tries every combination of a fixed set of values per hyperparameter — thorough, but the number of trials explodes multiplicatively with every hyperparameter added, and it wastes trials re-testing every value of a hyperparameter that barely matters, combined with every value of one that matters a great deal. Random search, given the identical trial budget, instead samples each hyperparameter's value independently and randomly on every trial. Counterintuitively, this usually finds a better configuration for the same budget — because it never repeats the exact same value for an unimportant hyperparameter, it ends up testing far more distinct values of whichever hyperparameter actually matters, without knowing in advance which one that is.

Definition A hyperparameter is a setting fixed before training, chosen by the practitioner rather than learned by gradient descent. Grid search exhaustively tries every combination from fixed value sets. Random search samples each hyperparameter's value independently at random, using the same total trial budget.
Why random search tends to beat grid search on equal budgets With 9 trials split across a 3×3 grid, grid search only ever tests 3 distinct learning rate values, no matter how many dropout values it pairs each one with — if learning rate turns out to be the hyperparameter that actually matters and dropout barely does, most of that budget was effectively wasted re-testing dropout. Random search's same 9 trials sample 9 distinct learning rate values and 9 distinct dropout values, with no advance assumption about which one deserved more attention. Bergstra and Bengio's 2012 result formalized exactly this: when only a few hyperparameters really drive the outcome — nearly always true in practice — random search's broader per-dimension coverage outperforms grid search's exhaustive but shallow coverage, for the same cost.

1. What distinguishes a hyperparameter from a parameter?

Learning rate, batch size, and dropout rate are all chosen ahead of time; weights and biases are what gradient descent actually updates.

2. Why does grid search's trial count explode as more hyperparameters are added?

itertools.product's combination count multiplies across every additional hyperparameter's value list.

3. Why can random search outperform grid search on the same trial budget?

Since most trials don't repeat exact values, random search covers each individual dimension more broadly for the same total budget.
