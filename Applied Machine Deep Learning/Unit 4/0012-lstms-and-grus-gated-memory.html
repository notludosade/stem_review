LSTMs and GRUs: Gated Memory

AI Developer's Lesson 16 said LSTM gates "decide what to keep, forget, and output" without the formulas. This lesson writes them out, and finally answers that lesson's closing question about what a GRU actually is.

← Lesson 11 Unit 5, Lesson 13 → Contents Glossary →

An LSTM keeps two running values instead of an RNN's one: the hidden state, and a separate cell state that acts as its actual long-term memory. Three gates — each just a small sigmoid layer, outputting a value between 0 and 1 per memory slot — control what happens to it at every step.

Python — one LSTM step, written out explicitly 
import numpy as np

def sigmoid(z): return 1 / (1 + np.exp(-z))

def lstm_step(x, h_prev, c_prev, params):
    combined = np.concatenate([h_prev, x])

    f = sigmoid(params['Wf'] @ combined + params['bf'])   # forget gate: what to erase
    i = sigmoid(params['Wi'] @ combined + params['bi'])   # input gate: what to add
    o = sigmoid(params['Wo'] @ combined + params['bo'])   # output gate: what to expose
    c_candidate = np.tanh(params['Wc'] @ combined + params['bc'])

    c_new = f * c_prev + i * c_candidate    # cell state: erase some, add some
    h_new = o * np.tanh(c_new)              # hidden state: a filtered view of memory

    return h_new, c_new

The forget gate f decides, per memory slot, how much of the old cell state survives — near 1 keeps it, near 0 erases it. The input gate i decides how much of the new candidate value gets written in. The output gate o decides how much of the (now-updated) cell state actually gets exposed as this step's hidden state — the cell can keep remembering something internally without necessarily surfacing it every single step. The line that actually fixes Lesson 11's vanishing gradient is c_new = f * c_prev + i * c_candidate: it's an addition, not a repeated multiplication through a squashing nonlinearity. When f stays close to 1 across many steps, the gradient can flow backward through the cell state largely unchanged — no compounding shrinkage the way a plain RNN's hidden state update forced.

Definition An LSTM's cell state is its long-term memory, separate from the hidden state. The forget gate, input gate, and output gate each output a 0–1 value per memory slot, controlling erasure, writing, and exposure respectively. A GRU (Gated Recurrent Unit) simplifies this into two gates — an update gate (merging forget and input into one) and a reset gate — and merges cell state and hidden state into a single vector, with fewer parameters and often comparable performance.
Why "addition, not multiplication" is the whole trick Lesson 11's vanishing gradient came specifically from many multiplicative factors under 1 compounding across time. An addition doesn't compound that way — adding a small, bounded correction to c_prev at every step doesn't shrink c_prev's own gradient path exponentially the way passing it through a tanh and a weight matrix, repeatedly, does. This is the same shortcut-connection idea that shows up under different names all over deep learning (residual connections in very deep CNNs are the same trick, applied to depth instead of time) — give the gradient at least one path that isn't forced through a squashing nonlinearity at every single step.

1. What does the forget gate control?

f * c_prev in the cell state update controls exactly how much of the old memory is retained.

2. Why does c_new = f * c_prev + i * c_candidate help avoid a vanishing gradient, compared to a plain RNN's hidden state update?

An addition with f near 1 lets the cell state's gradient largely pass through, unlike a chain of multiplicative, squashed updates.

3. How does a GRU differ structurally from an LSTM?

A GRU's update gate merges the forget and input roles, and it drops the separate cell state entirely.
