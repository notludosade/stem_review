Unit 1 — What Modding Actually Is

Mod / modification

Any change a player makes to a game that the original developer didn't ship by default — from a single recolored texture to a total conversion.

Total conversion

A mod that replaces nearly all of a game's original content — assets, rules, story — while still running on the original game's engine.

EULA

The license agreement a player accepts when installing or playing a game, setting the legal terms under which the developer's copyrighted work may be used — separate from, and usually more restrictive than, simply owning a copy.

Fair use

A U.S. legal doctrine that can excuse using copyrighted material without permission for purposes like commentary or parody, weighed case by case — not a blanket permission for modding.

Modding SDK

An official set of tools a developer releases specifically so players can build mods — often the same internal tools the developer's own team used to build the game.

Abandonware

A game no longer sold, supported, or actively defended by its rights holder — a practical state, not a change in the game's underlying copyright status.

Unit 2 — Reading Game Files & Asset Formats

Archive format

A studio-specific container file that bundles many individual game assets into one file for faster loading and light tamper-resistance — not encryption.

Extractor / unpacker

A community-built tool that reads a game's proprietary archive format and pulls out its individual files, based on structure the modding community reverse-engineered and shared.

Texture map

A 2D image applied to the surface of a 3D model, defining color, roughness, bumps, or glow — what most cosmetic reskins actually change.

Mesh / rig (skeleton)

A mesh is a model's raw 3D geometry — points, edges, and surfaces; a rig or skeleton is a separate internal bone structure the mesh deforms around during animation.

Proprietary vs. open format

A proprietary format is designed and documented, if at all, by a single studio or engine vendor; an open format like PNG or OBJ is published and usable by anyone — the reason community converters and extractors exist.

Config file / data-driven design

A config file is plain, human-readable text (.ini, .cfg, .json, .xml) holding values game logic reads rather than hardcodes — data-driven design — making it the safest, lowest-skill entry point to modding.

Unit 3 — Scripting APIs & Modding Frameworks

Embedded scripting language

A lightweight programming language interpreter built into a game engine, letting some of the game's logic — and, when exposed, a mod's logic — run as script rather than compiled engine code. Lua is the industry's most common choice.

Sandbox

A restricted execution environment that only exposes the specific functions a game's API deliberately provides to a mod script, blocking everything else — what makes it safe to run untrusted, community-written code.

Event hook / callback

An event hook is a named point where the game announces something happened; a callback is the function registered to automatically run when that event fires — without ever modifying the game's original logic.

API (application programming interface)

The specific set of functions and data a script is allowed to call within a game — the deliberate boundary a studio draws around what a mod is permitted to do.

Hook priority

The order in which multiple mods' callbacks run when they're registered for the same event — since callbacks can modify the same value in sequence, this order can change the final result.

Modding framework (mod loader, load order, dependency)

Infrastructure built on top of a game's scripting API — a mod loader that finds and loads mods, a load order determining whose changes win a conflict, and dependencies declaring what a mod requires to already be present.

Unit 4 — Asset Replacement

UV mapping

The correspondence between points on a 3D model's surface and points on a flat 2D texture image — a replacement texture has to match this layout or it will appear stretched, mirrored, or misplaced.

Compatibility patch

A small, third mod built specifically to reconcile two other mods' conflicting changes, rather than expecting either original mod's author to do it.

Audio sync

The alignment between a sound clip's timing and whatever it's paired with — an animation, a lip-flap, a scripted cutscene beat — that a mismatched-length replacement clip can throw off.

Localization mod / fan translation

A mod replacing a game's voice lines, subtitles, and text with a translation into a language never officially supported; when made entirely by a fan community, it's called a fan translation.

Drop table

The data structure defining what items an enemy, chest, or event can produce, and at what odds — a classic target for data-driven mods changing a game's economy or difficulty.

DPS (damage per second) / data-driven mod

DPS combines a weapon's damage and attack speed into the number that actually reflects gameplay impact; a data-driven mod changes only values already exposed in config files, with no new assets or scripts.

Unit 5 — Reverse-Engineering Behavior

Black-box observation

Studying a program's behavior from the outside — inputs in, outputs out — without reading its original source code, inferring what must be happening internally from patterns in that behavior.

Memory scanner

A tool (like Cheat Engine) that watches a running program's memory for values that change in correlation with an observed action — correlation-hunting, not proof.

Decompiler / disassembler

Tools (like Ghidra and IDA) that work on a compiled executable itself — a disassembler produces low-level assembly, a decompiler attempts a higher-level, approximate reconstruction of the original logic.

Log file / crash dump

A log file is a plain-text record of what a game's internal systems did during play; a crash dump is a snapshot of the program's state at the moment of failure — both readable without any special tool.

Community wiki

A collaboratively edited modding reference maintained by a game's player community rather than its developer — often more complete than official documentation for modding-specific problems.

DMCA Section 1201 / interoperability exception

The U.S. law generally prohibiting circumvention of a technical protection measure on copyrighted work, regardless of otherwise-legal purpose; the interoperability exception is a narrow, court-limited allowance for reverse-engineering done to make independent programs work together.

Unit 6 — Building & Sharing a Mod

Mod manifest

A metadata file — name, author, version, dependencies — that a mod loader reads to identify and manage a mod, distinct from the mod's actual asset or script files.

Semantic versioning (semver)

The widely-used MAJOR.MINOR.PATCH version-numbering convention — PATCH for a bug fix, MINOR for a non-breaking feature, MAJOR for a breaking change — giving dependency declarations something concrete to check against.

Mod conflict

When two independently-made mods both modify the same underlying game element, producing a crash, silently overwritten change, or broken visual that neither mod alone would cause.

Changelog

A running record of what changed in each released version of a mod, letting users and other modders understand what's different without comparing every file by hand.

Attribution

Clearly crediting every asset, code snippet, or idea in a mod that wasn't entirely your own original work — including contributions from other modders, not just the original game's developer.

Mod hosting platform

A site like Nexus Mods or Steam Workshop built specifically for distributing and discovering mods, alongside general-purpose options like itch.io or GitHub.
