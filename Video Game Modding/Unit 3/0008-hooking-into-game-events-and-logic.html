Hooking into Game Events and Logic

Lesson 7's toy script reacted to an item pickup — but how does a mod's code actually get called the moment that happens, without ever touching the base game's original logic?

← Lesson 7 Lesson 9 → Contents Glossary →

The answer is the event hook: the game engine itself announces, at specific moments, that something has happened — a player spawned, a player took damage, an item was picked up — by "firing" a named event. Any script that has registered interest in that event, called a callback, gets called automatically the instant the event fires, and runs whatever logic it wants in response. The original game code that fires the event never needs to know a mod exists at all; it just always announces "this happened," and mods choose whether to listen.

Definition An event hook is a named point in a game's logic where it announces that something happened, allowing any registered script to run code in response — without modifying the game's original logic at all.

Event-driven programming, and why order matters

This pattern — code that runs in response to something happening, rather than being called directly in a fixed sequence — is called event-driven programming, and it isn't unique to games; it's the same idea behind a button's on-click handler in any user interface. What is specific to modding is that multiple, entirely unrelated mods can all register a callback for the exact same event — three different mods might all care about onPlayerDamage. When that happens, hook priority decides which callback runs first, since the order can matter: a mod that reduces incoming damage before a second mod calculates a critical-hit bonus produces a different result than the same two mods running in the reverse order.

Why it matters here Lesson 9's modding frameworks exist largely to manage exactly this problem at scale — dozens of mods, all hooking the same handful of events, need a system deciding what order they run in and catching conflicts before they cause silent, hard-to-diagnose bugs.

1. What is an event hook, in plain terms?

An event hook lets a mod respond to something happening without altering the game's own original logic.

2. Why does the original game code that fires an event not need to know any mod exists?

The event-firing code and the mod's callback are decoupled — the game just announces, and interested scripts opt in.

3. Why does hook priority matter when multiple mods register a callback for the same event?

Since multiple mods' callbacks can all modify the same value in sequence, the order they run in can produce genuinely different outcomes.
