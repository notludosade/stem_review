String Literals and Concatenation

Text is a data type too, with its own rules for how you write it and stick pieces of it together.

Lesson 14 → Contents Glossary →

A string is a sequence of characters — text. A string literal is text written directly in your source code, always wrapped in quotes so the language can tell it apart from a variable name or keyword. Concatenation is joining two or more strings into one.

Python 
first = "Ada"
last = 'Lovelace'
full = first + " " + last  # "Ada Lovelace"
Java 
String first = "Ada";
String last = "Lovelace";
String full = first + " " + last; // "Ada Lovelace"
JavaScript 
let first = "Ada";
let last = 'Lovelace';
let full = first + " " + last; // "Ada Lovelace"
C++ 
std::string first = "Ada";
std::string last = "Lovelace";
std::string full = first + " " + last; // "Ada Lovelace"

Python and JavaScript accept either double quotes or single quotes for a string literal — they mean exactly the same thing, it's a style choice. Java and C++ require double quotes specifically; a single-quoted value in those two languages is a different, narrower type (a single character, covered in the next lesson) rather than a string. All four languages overload the same + operator from Lesson 6 to mean concatenation when used on strings, instead of addition.

Notice also the type name difference: Java and C++ both declare strings with a capitalized type, String and std::string respectively — unlike the lowercase primitive types (int, bool) you've seen so far. That's because in both languages, strings aren't a built-in primitive type the way numbers are; they're implemented as a class, which Unit 8 will make more sense of.

Definition A string is a sequence of characters representing text. A string literal is a string value written directly in source code, delimited by quotes. Concatenation means joining strings end to end into a single longer string.
Why it matters here Strings are the data type you'll use to handle nearly all human-facing input and output — names, messages, file paths, user input. The quoting and typing differences here are small, but they're exactly the kind of thing that produces a confusing error message the first time you switch from one of these languages to another mid-project.
