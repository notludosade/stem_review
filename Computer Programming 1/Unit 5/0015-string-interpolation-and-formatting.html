String Interpolation and Formatting

Building a string out of variables gets unreadable fast with concatenation alone — every language offers something better.

Lesson 16 → Contents Glossary →

Concatenation gets hard to read fast 
# Python
message = "Hello, " + name + "! You are " + str(age) + " years old."

Every + is a place to miscount a space or forget a conversion — notice str(age) is required here, since Python's + can't mix a string with a number directly. String interpolation and string formatting both solve this by letting you write the target string as a single template, with placeholders for the variable parts.

Python — f-string 
message = f"Hello, {name}! You are {age} years old."
Java — String.format 
String message = String.format("Hello, %s! You are %d years old.", name, age);
JavaScript — template literal 
let message = `Hello, ${name}! You are ${age} years old.`;
C++20 — std::format 
std::string message = std::format("Hello, {}! You are {} years old.", name, age);

Python's f-string (an f right before the opening quote) and JavaScript's template literal (backticks instead of regular quotes, with ${...} placeholders) both let you embed the actual variable name directly inside the string — true interpolation. Java's String.format and C++20's std::format instead take a separate template string with generic placeholders (%s/%d in Java, {} in C++) and a list of values matched up in order — this style is usually just called formatting rather than interpolation, since the variable names themselves never appear inside the template.

Notice also that neither String.format nor std::format needed an explicit type conversion for age the way raw concatenation did — both handle converting the number to text automatically as part of formatting it into the template.

Definition String interpolation embeds variable references directly inside a string template (Python's f-strings, JavaScript's template literals). String formatting uses a separate template with generic placeholders, filled in by a list of values in order (Java's String.format, C++'s std::format). Both avoid the readability and type-mixing problems of chained concatenation.
Why it matters here Building readable, correct output strings is something almost every program needs to do — error messages, logs, user-facing text. This is also a direct callback to the Ethics course: Unit 4's lesson on error messages relied on exactly this kind of templating to avoid leaking unintended detail into what gets shown to a user versus what gets logged.

Check your recall

1. What makes Python's f-strings and JavaScript's template literals true "interpolation," as opposed to Java/C++'s formatting?

Java and C++'s formatting keeps the template and values separate, matched up by position instead.

2. In the bad concatenation example, why was str(age) necessary?

Interpolation and formatting both handle this conversion automatically, which is part of why they're preferred.

3. What are JavaScript template literals delimited with, instead of regular quotes?

The backtick-delimited string can then contain ${...} placeholders for interpolated expressions.

4. Fill in the blank: embedding a variable reference directly inside a string template, as Python's f-strings do, is called string ___.

See the definition box above — this is distinct from formatting, which uses a separate value list.

5. Fill in the blank: using a template with generic placeholders filled in by a separately supplied list of values, as Java's String.format does, is called string ___.

C++20's std::format works the same way, using {} placeholders instead of Java's %s/%d.
