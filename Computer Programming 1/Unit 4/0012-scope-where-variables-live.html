Scope — Where Variables Live

A variable created inside a function doesn't exist anywhere else — and that's a feature, not a limitation.

Lesson 13 → Contents Glossary →

Scope is the region of a program where a variable can be referred to by name. A variable declared inside a function is local to that function — it's created when the function runs and disappears when the function finishes, invisible to any code outside it.

Trying to use a local variable outside its function 
# Python
def square(n):
    result = n * n
    return result

square(5)
print(result)  # error: result is not defined out here

result and n only exist while square is running. Once square(5) finishes, both are gone — trying to reference result afterward fails, because it was never in scope outside the function. This behavior is identical in Java, JavaScript, and C++.

Python 
max_attempts = 3  # global — visible everywhere in this file

def is_allowed(attempts):
    return attempts < max_attempts  # reads the global fine
Java 
static int maxAttempts = 3; // class-level — visible to every method in the class

static boolean isAllowed(int attempts) {
    return attempts < maxAttempts; // reads the class-level variable fine
}
JavaScript 
const maxAttempts = 3; // global — visible everywhere in this file

function isAllowed(attempts) {
    return attempts < maxAttempts; // reads the global fine
}
C++ 
int maxAttempts = 3; // global — visible everywhere in this file

bool isAllowed(int attempts) {
    return attempts < maxAttempts; // reads the global fine
}

A variable declared outside any function — at the top level of a file, or (in Java's case) at the class level — is global, meaning any function in that file or class can read it. Functions can read global variables freely, but assigning to one from inside a function generally requires an extra step (different per language, and outside this lesson's scope) — which is a deliberate safeguard, not an oversight.

Definition Scope is the region of code where a variable's name is valid. A local variable is scoped to the function (or block) it's declared in, and stops existing once that function finishes. A global variable is scoped to the entire file (or class), visible to every function within it.
Why it matters here Local scope is what makes functions safely reusable — square's internal result can never accidentally collide with a variable of the same name somewhere else in your program, because it simply doesn't exist outside square. Relying heavily on global variables instead of parameters and return values is a common early mistake, since it makes a function's behavior depend on state scattered elsewhere in the program instead of just its own inputs.
