Parameters and Return Values

A function that always does exactly the same thing is far less useful than one you can hand different input.

Lesson 12 → Contents Glossary →

A parameter is a named input a function accepts, listed inside its parentheses when defined. An argument is the actual value you pass in when calling the function. A return value is the result a function hands back to whatever called it, using a return statement.

Python 
def square(n):
    return n * n

result = square(5)  # 25
Java 
static int square(int n) {
    return n * n;
}

int result = square(5); // 25
JavaScript 
function square(n) {
    return n * n;
}

let result = square(5); // 25
C++ 
int square(int n) {
    return n * n;
}

int result = square(5); // 25

In every version, n is the parameter — the placeholder name used inside the function — and 5 is the argument — the actual value supplied at the call site. The gap between Java/C++ and Python/JavaScript from Lesson 10 shows up again here: Java and C++ replace void with the actual return type (int, since square now hands back a number) and must also state each parameter's type (int n). Python and JavaScript need neither — n could be given any type of value at the call site, and the function would just try to use it as written.

Calling square with the wrong kind of value 
# Python
result = square("5")  # runs — but produces "55", not 25
# multiplying a string by itself repeats it, it doesn't do arithmetic

This is the static-versus-dynamic-typing tradeoff from Lesson 5 showing up concretely: Java and C++ would refuse to compile square("5") at all, since "5" isn't an int. Python runs it — and because * is also defined for strings (repeating them), it produces a confusing result instead of an obvious error.

Definition A parameter is the named placeholder a function declares for its input. An argument is the specific value passed in at a call site. A return value is what a function hands back via return; a function with no return statement (or Java/C++'s void) simply produces no value.
Why it matters here Parameters and return values are what let a function generalize — square works for any number, not just 5. Every function you write from here forward will use this pattern, and the static-typing safety net (or lack of it) shown above is exactly the kind of category of bug worth watching for in Python and JavaScript specifically.

Check your recall

1. In square(5), what is 5 called?

n, the placeholder name in the function's definition, is the parameter; 5 is the argument supplied at the call site.

2. Why does Java refuse to compile a call like square("5") when square is defined to take an int?

This is the same static-typing behavior from Lesson 5, applied to function parameters specifically.

3. Why does Python's square("5") produce "55" instead of an error?

This is exactly the kind of confusing-instead-of-obvious failure dynamic typing can produce.

4. Fill in the blank: the named placeholder a function declares for its input, written inside its parentheses at definition time, is a ___.

See the definition box above — this is distinct from an argument, the actual value passed in.

5. Fill in the blank: the statement a function uses to hand a value back to its caller is ___.

A function with no return statement (or Java/C++'s void) produces no value at all.
