1. A JavaScript function is defined once: function shout() { console.log("Loud!"); }. It is then called three separate times later in the program. How many times does "Loud!" actually print?

Defining shout() once just creates it; each separate call runs its body again, so three calls print "Loud!" three times.

2. Fill in the blank: in Java and C++, a function that produces no return value at all declares its return type as ___.

Python and JavaScript require no keyword for this at all — void is specific to Java and C++.

3. This course's introductory Java examples define a simple function as static void printReceipt() { ... }. Why does it need static here specifically?

Unit 8's coverage of classes explains this fully; for now, static is what lets these introductory examples call a function directly, with no object involved.

4. A Python function is defined as def cube(n): return n ** 3, and then called as volume = cube(4). Answer both parts:

(a) What is 4 called, in this call?

(b) Fill in the blank: in the definition, n is called the ___ — the named placeholder the function declares for its input.

(a) 4 is the actual value supplied at the call site — the argument. (b) n is the placeholder name written inside the function's parentheses when it's defined — the parameter.

5. A Python function is written with no return statement anywhere in its body. What does calling it produce?

A function with no return statement (or Java/C++'s void) simply produces no value — Python has no void keyword, but the underlying idea is identical.

6. A Java method is defined as static int triple(int n) { return n * 3; }. Answer both parts:

(a) What happens when code tries to compile a call like triple("3")?

(b) Fill in the blank: Python and JavaScript use ___ typing instead, so a mismatch like this wouldn't be caught until the line actually runs.

(a) Java checks an argument's type against the declared parameter type before the program ever runs, so this call is rejected at compile time. (b) Dynamic typing waits until runtime to discover this kind of mismatch, if it's ever caught at all.

7. A JavaScript function is defined as function double(n) { return n * 2; }, then called as let result = double(6);. Answer both parts:

(a) Fill in the blank: after this runs, result holds ___.

(b) Suppose the function were rewritten in Python with the return keyword left out entirely — just print(n * 2) inside the function body instead. What would result = double(6) store in that version?

(a) 6 * 2 is 12, handed back via return and stored in result. (b) Printing a value is not the same as returning it — with no return statement, the function produces no value, so result would be Python's None.

8. This Python function computes an average: def average(a, b): total = a + b; return total / 2. After calling average(4, 6), a later line runs print(total). Answer both parts:

(a) What happens when print(total) runs?

(b) Fill in the blank: a variable like total, which stops existing once its function finishes, is described as ___ to that function.

(a) total is created fresh each time average runs and disappears the moment it finishes — this behavior is identical in Java, JavaScript, and C++. (b) That's exactly what local scope means.

9. In JavaScript, const taxRate = 0.08; is declared outside any function, and a function function priceWithTax(amount) { return amount + amount * taxRate; } reads it directly. Answer both parts:

(a) Why can priceWithTax read taxRate, even though taxRate isn't one of its parameters?

(b) Fill in the blank: a variable declared outside any function, and readable by every function in that file, is called a ___ variable.

(a) Declaring taxRate at the top level, outside any function, makes it global — visible to every function that follows. (b) That's the definition of a global variable, in contrast to a local one scoped to a single function.

10. Why is relying heavily on global variables instead of parameters and return values considered a common early mistake?

Parameters and return values keep a function's behavior self-contained and predictable from its own inputs alone — leaning on globals instead breaks that predictability.
