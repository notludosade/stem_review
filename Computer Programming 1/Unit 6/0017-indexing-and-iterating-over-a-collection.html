Indexing and Iterating Over a Collection

The same 0-based index model from strings applies here — and every language has a shortcut for visiting every element.

Lesson 18 → Contents Glossary →

Just like the strings in Lesson 14, every element in a collection has a position — its index — starting at 0. Unlike strings, where Java broke from the pattern and required charAt(0), all four languages use plain square brackets to index into an array or list.

Python 
numbers = [10, 20, 30]
numbers[0]  # 10
Java 
int[] numbers = {10, 20, 30};
numbers[0]; // 10
JavaScript 
let numbers = [10, 20, 30];
numbers[0]; // 10
C++ 
std::vector<int> numbers = {10, 20, 30};
numbers[0]; // 10

What happens when the index doesn't exist — say, numbers[10] on a 3-element collection — differs sharply across languages. Python raises an IndexError, and Java raises an ArrayIndexOutOfBoundsException — both stop the program immediately with a clear error. JavaScript quietly returns undefined instead of raising anything at all. C++ is the riskiest of the four: reading past the end of a std::vector with [] is undefined behavior — it might crash, might silently return garbage, and might appear to work while corrupting unrelated memory. This is exactly the kind of gap that makes bounds-checked accessors, like C++'s .at(), worth reaching for whenever the index isn't guaranteed safe.

Rather than counting indices by hand, every language also offers a dedicated way to visit each element in turn — to iterate over the collection.

Python 
for n in numbers:
    print(n)
Java 
for (int n : numbers) {
    System.out.println(n);
}
JavaScript 
for (const n of numbers) {
    console.log(n);
}
C++ 
for (int n : numbers) {
    std::cout << n << std::endl;
}

Lesson 9 pointed out that Python's for loop was never really about counting — it iterates over a sequence directly, and a collection is exactly the sequence it was built for. Java, JavaScript, and C++ each add a dedicated for-each form here too — for (type n : collection) in Java and C++, for (const n of collection) in JavaScript — instead of forcing the three-part counting header from Lesson 9 every time you just want to visit each element.

Definition To iterate over a collection is to visit each of its elements in turn. A for-each loop (also called an enhanced for or for...of) is loop syntax that iterates directly over a collection's elements, rather than counting an index up by hand.
Why it matters here Out-of-bounds access isn't a theoretical curiosity — inconsistent bounds checking across languages is a real, ongoing source of security bugs in production software, which is exactly why memory-safety-focused languages and modern C++ style guides push toward bounds-checked accessors for anything touching untrusted input.
