Comments and Why Code Needs to Explain Itself

A comment is text the computer completely ignores — which is exactly what makes it worth using carefully.

Lesson 4 → Contents Glossary →

A comment is a piece of text in your source file that the compiler or interpreter skips entirely — it exists only for whoever reads the code, including you, six months later. Every language in this course supports comments, and while the syntax differs, the underlying purpose is identical.

Python 
# single-line comment
"""
multi-line comment
(technically a string literal, but used this way by convention)
"""
print("Hello, world!")  # trailing comment
Java 
// single-line comment
/*
 * multi-line comment
 */
System.out.println("Hello, world!"); // trailing comment
JavaScript 
// single-line comment
/*
 * multi-line comment
 */
console.log("Hello, world!"); // trailing comment
C++ 
// single-line comment
/*
 * multi-line comment
 */
std::cout << "Hello, world!" << std::endl; // trailing comment

Java, JavaScript, and C++ share identical comment syntax — // for a single line, /* ... */ for a block — because all three descend from the same C-family tradition. Python is the odd one out, using # for single lines and repurposing triple-quoted strings for multi-line notes, since Python doesn't have a dedicated block-comment syntax at all.

A comment that restates the code 
# increment count by 1
count = count + 1
A comment that explains something the code can't 
# retries max out at 3 — the payment API rate-limits after that
count = count + 1

The first comment adds nothing: anyone who can read the assignment line already knows it increments count. The second comment answers a question the code alone can't: why does this cap exist? That distinction — what the code already says versus why it says it — is the single most useful rule for deciding whether a comment is worth writing at all, and it holds in every one of these four languages.

Definition A comment restating what code does is usually redundant, since well-named variables and functions already communicate that. A comment worth keeping usually explains why — a constraint, a workaround, a non-obvious reason a piece of code exists in its current form.
Why it matters here This isn't just a style preference — the Computer Programming Ethics course you may have already taken covered this exact idea in its final lesson, on documenting decisions: a comment explaining a deliberate, non-obvious choice is what keeps that choice from being silently undone by someone who didn't know it was intentional. The habit starts here, on day one, with the smallest possible example.
