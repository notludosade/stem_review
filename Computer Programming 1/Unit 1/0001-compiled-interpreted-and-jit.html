Compiled, Interpreted, and JIT — How Your Code Actually Runs

Before writing a single line, it helps to know what happens to that line after you write it.

Lesson 2 → Contents Glossary →

Welcome to Computer Programming 1. This course teaches every core idea in four languages side by side — Python, Java, JavaScript, and C++ — so you can see which parts of programming are universal and which parts are just one language's particular spelling of the same idea. Before any syntax, it's worth understanding a difference between these four languages that explains a lot of what you'll see later: what actually happens between typing source code and a computer doing something with it.

Definition A CPU only understands machine code — raw binary instructions specific to its hardware. Every language you'll ever write in has to get translated into that, one way or another. The three main strategies are compiling, interpreting, and JIT (just-in-time) compiling.

Compiled: translate everything, then run it

C++ is compiled. A separate program, the compiler, reads your entire source file and translates it directly into machine code for your specific CPU and operating system, producing an executable file. Running the program later is just the CPU executing that machine code directly — no translation happens at run time. This makes compiled programs fast to run, but the compile step itself takes time, and the resulting executable only runs on the platform it was compiled for.

Interpreted: translate and run, line by line

Python and (mostly) JavaScript are interpreted. An interpreter reads your source code and executes it more or less directly, translating and running each piece as it goes, without producing a separate standalone executable first. This is why Python and JavaScript feel more immediate — there's no separate "build" step before you can run something — but it also means translation overhead happens every single time the program runs, which is generally slower than a precompiled executable.

JIT: a hybrid of both

Java uses just-in-time (JIT) compilation, and modern JavaScript engines (like V8, which powers Chrome and Node.js) do too, blurring the interpreted/compiled line further. Java source code is first compiled to an intermediate form called bytecode — not machine code yet, but not the original source either — which runs on the Java Virtual Machine (JVM). The JVM then compiles the most frequently-used bytecode into real machine code while the program is running, getting much of compiled code's speed without giving up "write once, run on any machine with a JVM" portability.

Why it matters here This explains real differences you'll notice immediately: why a C++ program needs a separate compile step before you can run it, why Python and JavaScript let you type a line and see a result right away, and why Java code runs inside something called a "virtual machine" instead of directly on your operating system. None of this is trivia — it's the reason the same program can behave differently across these four languages in ways that aren't about syntax at all.

Check your recall

1. Which of the four languages in this course is fully compiled to machine code before it ever runs?

C++ produces a standalone executable ahead of time; the others translate at or during run time.

2. What does Java's compiler produce, before the JVM ever runs the program?

Bytecode runs on the JVM, which then JIT-compiles hot paths to real machine code while the program executes.

3. Why does Python let you type a line and see its result immediately, unlike C++?

An interpreter translates and runs each piece as it goes, so there's no standalone executable to build first.

4. Fill in the blank: the raw binary instructions a CPU directly understands are called ___ ___.

See the definition box above — every language eventually becomes this, one way or another.

5. Fill in the blank: compiling bytecode to machine code while the program is already running, as Java and modern JavaScript engines do, is called ___ compilation.

JIT is the hybrid strategy — see the "JIT: a hybrid of both" section above.
