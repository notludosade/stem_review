1. Which statement correctly compares default newline behavior across these four languages?

Python and JavaScript both default to adding a newline; Java's print() and C++'s plain << share the opposite default, requiring println() or std::endl / "\n" instead.

2. What does the following Java code print to the console?

System.out.print("Score: ");
System.out.print(42);

print() never adds a newline, so both calls continue writing to the same line — the output reads Score: 42 with no break in between.

3. Two related tools for controlling newlines — answer both parts:

(a) What appears on the screen after running this Python code?

print("Loading", end="")
print("...")

(b) Fill in the blank: to add a trailing newline in C++, since plain << never adds one automatically, you append std::endl or "___" to the stream.

(a) end="" replaces print()'s default trailing newline with nothing, so the cursor stays put and the next print continues right where it left off. (b) C++ requires you to append std::endl or the escape sequence \n yourself whenever a newline is wanted.

4. Fill in the blank: the default source a program reads input from — almost always the keyboard — is called standard input, or ___ for short.

Python's input(), Java's Scanner, and C++'s std::cin >> or std::getline all read from this same default source.

5. Why can't a Node.js program simply pause and wait for keyboard input the way Python's input() does?

This callback-based, asynchronous style is fundamentally different from the "stop and wait" model Python, Java, and C++ all share.

6. A user is asked to type their full name and types Ada Lovelace. Answer both parts:

(a) What would std::cin >> name; store in name, given this input?

(b) Fill in the blank: to capture the entire line including the space, the code should instead call std::___(std::cin, name).

(a) >> always stops reading at the first whitespace character, silently cutting off anything after it. (b) std::getline reads a full line, whitespace included, up to the newline.

7. A program asks the user to type their age, expecting a number. Answer both parts:

(a) Why is it risky for the program to use whatever was typed directly as a number, with no checking?

(b) Fill in the blank: no matter what the user types, functions like Python's input() and Java's Scanner.nextLine() always return a ___, so converting to a number requires an explicit step.

(a) Input from outside a program's control should never be assumed to be well-formed. (b) Even a typed number comes back as text first; the program must convert it deliberately.

8. Fill in the blank: an open connection to a file that a program reads from or writes to, which should be closed once you're finished with it, is called a file ___.

Java's Scanner(new File(...)) and C++'s std::ifstream both open a file handle that stays open until close() is called explicitly.

9. Python and JavaScript both skip an explicit close() call when reading a file, but for different reasons. Answer both parts:

(a) What causes Python's file to close automatically in with open("scores.txt") as f: ...?

(b) Fill in the blank: JavaScript's readFileSync doesn't need a close() call because it reads the ___ file in one call and hands back a finished string.

(a) The with statement guarantees cleanup once its block ends, even if an error occurs while reading. (b) Because the whole file is read at once, there's no ongoing handle left open to close.

10. Suppose scores.txt contains exactly 3 lines. Answer both parts about looping over them:

(a) In Java, using

Scanner fileScanner = new Scanner(new File("scores.txt"));
while (fileScanner.hasNextLine()) {
    System.out.println(fileScanner.nextLine());
}

how many times does the loop body run?

(b) What plays the equivalent role in C++'s version of this same loop?

(a) hasNextLine() stays true until every line has been consumed, so the loop runs once per line. (b) std::getline itself returns false once there's nothing left to read, playing the same role as hasNextLine() in Java.
