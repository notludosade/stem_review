1. Which of these statements about default newline behavior is correct?

C++ and Java share the same default: no automatic newline. Python and JavaScript share the opposite default. std::endl and end="" belong to different languages and aren't interchangeable.

2. What does the following Java code print to the console?

System.out.print("A");
System.out.println("B");
System.out.print("C");

print("A") adds no newline, so "B" continues right after it on the same line. println("B") then adds the newline print() never does, so the final print("C") begins on a fresh line.

3. Two related tools for controlling newlines — answer both parts:

(a) What does this Python code print?

print("X", "Y", sep="-", end="!")

(b) Fill in the blank: appending the escape sequence ___ to a C++ std::cout statement adds a newline, the same effect std::endl has.

(a) sep="-" replaces the default space between values, and end="!" replaces the default trailing newline — both defaults can be overridden independently. (b) \n is the newline escape sequence itself; std::endl adds the same character, plus flushes the stream.

4. Which of these is the standard source of input that Python's input(), Java's Scanner, and C++'s std::cin all read from by default?

Standard input, often shortened to stdin, is the default source a program reads from — almost always the keyboard.

5. Fill in the blank: unlike Python, Java, and C++, JavaScript's readline-based input doesn't pause and wait — it registers a ___ that runs once the user finishes typing.

This asynchronous, callback-based style is what makes JavaScript's input model fundamentally different from the other three languages' blocking reads.

6. A user is asked to type a city name and types New York. Answer both parts:

(a) What would std::cin >> city; store in city, given this input?

(b) Fill in the blank: to capture all of New York in one read, the code should call std::getline(std::___, city) instead.

(a) >> always stops at the first whitespace, so York never makes it into city. (b) std::getline needs a source stream as its first argument — std::cin, the same object >> reads from.

7. A program reads an answer with Python's input(), expecting the user's age as a number. Answer both parts:

(a) If the user types twenty instead of 20, what's likely to happen if the program tries to use it directly as a number, with no check?

(b) Fill in the blank: no matter what's typed, input() and Scanner.nextLine() always return a ___, so numeric input still needs an explicit conversion step.

(a) Text input should never be assumed to already be a valid number. (b) Both functions hand back the raw text as a string, converted or not.

8. Fill in the blank: the three-step pattern every file operation follows, in every one of these four languages, is open, read (or write), and ___.

Python and JavaScript handle the closing step automatically in the examples shown; Java and C++ require it explicitly.

9. Answer both parts about why these two languages skip an explicit close() call:

(a) What actually triggers Python's file to close when using with open("scores.txt") as f: ...?

(b) Fill in the blank: JavaScript's readFileSync avoids needing a close() call because it reads the entire file in one call and returns a finished ___.

(a) The with statement's cleanup runs once its block ends, even if an error interrupts the reading. (b) There's no open, ongoing connection left afterward — just a complete string already in memory.

10. Suppose scores.txt contains exactly 5 lines. Answer both parts about looping over them:

(a) In Java, using

Scanner fileScanner = new Scanner(new File("scores.txt"));
while (fileScanner.hasNextLine()) {
    System.out.println(fileScanner.nextLine());
}

how many times does the loop body run?

(b) Fill in the blank: the equivalent C++ loop condition is while (std::getline(file, ___)), which becomes false once the file runs out of lines.

(a) hasNextLine() stays true until every one of the 5 lines has been read. (b) getline's second argument is the string that receives each line — here, line.
