Console Input — Reading What the User Types

A program that can never receive new information can't react to anything — input is what makes it interactive.

Lesson 21 → Contents Glossary →

Just as programs write to standard output, they read from standard input — by default, whatever the user types at the keyboard.

Python 
name = input("What is your name? ")
print("Hello, " + name)
Java 
Scanner scanner = new Scanner(System.in);
System.out.print("What is your name? ");
String name = scanner.nextLine();
System.out.println("Hello, " + name);
JavaScript (Node.js) 
const readline = require('readline').createInterface({ input: process.stdin, output: process.stdout });
readline.question('What is your name? ', name => {
    console.log('Hello, ' + name);
    readline.close();
});
C++ 
std::string name;
std::cout << "What is your name? ";
std::getline(std::cin, name);
std::cout << "Hello, " << name << std::endl;

Python's input(), Java's Scanner, and C++'s std::getline(std::cin, ...) all work the same basic way: the program pauses, waits for the user to type a line and press Enter, and hands that line back as a string. Notice the C++ example uses std::getline rather than std::cin >> name — plain >> stops reading at the first whitespace, so it would silently cut off a name like "Ada Lovelace" at the space.

JavaScript is the odd one out. In a browser there's no equivalent to a blocking keyboard read at all, and even in Node.js the readline module doesn't pause the program the way the other three do — it registers a callback function that runs later, once the user finishes typing. This asynchronous style is a deeper topic than this course covers, but it's worth knowing the difference exists: JavaScript's input model is fundamentally not "stop and wait" the way Python, Java, and C++'s are.

Definition Standard input (often shortened to stdin) is the default source a program reads input from — almost always the keyboard in this course's examples.
Why it matters here Whatever comes in from standard input should be treated the same way the Ethics course discussed treating any input from outside your program's control — never assume it's well-formed. A user asked for their age might type "banana," and code that reads input without checking it will crash or misbehave the moment that happens.
