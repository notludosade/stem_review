1. Which best describes the relationship between a class and an instance?

Once a class defines a shape once, creating a hundred distinct instances is as easy as calling the constructor a hundred times.

2. Every one of these four languages runs a special method automatically when a new instance is created. Answer both parts:

(a) What is the primary purpose of this method?

(b) Fill in the blank: in Python, this method is always named __init__, while in JavaScript it's always named ___().

(a) This special method is called a constructor. (b) Java and C++ instead name it after the class itself; Python spells it __init__.

3. Consider this Python class:

class Cat:
    def __init__(self, name):
        self.name = name

Answer both parts:

(a) What does self refer to inside __init__?

(b) Fill in the blank: the equivalent keyword used in Java and JavaScript, instead of self, to refer to the current instance is ___.

(a) self is bound to whichever instance the constructor is currently building. (b) C++ achieves the same thing implicitly, without needing to name it at all.

4. Fill in the blank: unless explicitly marked public, C++ class members are ___ by default.

This is why the C++ Dog example needed public: written explicitly before name — Python, Java, and JavaScript needed nothing similar.

5. A standalone square(n) function from Unit 4 needs n passed in as an argument. Why doesn't a method like bark() need name passed in the same way?

Calling a method on a specific instance is what gives it automatic access to that instance's data — no extra argument needed.

6. Fill in the blank: data belonging to one specific instance, reachable by any method on that same instance but not by other instances, lives in ___ scope.

This is a new kind of scope beyond the local and global scope covered earlier in the course.

7. Given this class:

class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f"{self.name} says woof!"

rex = Dog("Rex")
milo = Dog("Milo")

Answer both parts:

(a) What does rex.bark() return?

(b) Fill in the blank: milo.bark() returns "Milo says ___!"

(a) Calling bark() on rex uses rex's own name through self, giving Rex says woof! (b) Calling the exact same method on milo uses milo's separate name instead, giving Milo says woof! — the same code, different instance data.

8. What is the core idea behind encapsulation?

Encapsulation is what lets an object make guarantees about itself, since outside code can no longer bypass its rules.

9. Answer both parts about how Python and JavaScript handle private data differently:

(a) What actually stops outside code from writing to account._balance in Python, given _balance is just a leading-underscore attribute?

(b) Fill in the blank: JavaScript's #balance syntax, unlike a leading underscore, is a genuinely ___ private field.

(a) Python trusts the programmer to respect the underscore rather than enforcing it. (b) #fields are a newer JavaScript addition that finally matches Java and C++'s enforced privacy.

10. Given this BankAccount class:

class BankAccount {
    private double balance;

    void deposit(double amount) {
        if (amount > 0) balance += amount;
    }
}

Answer both parts:

(a) If code outside the class calls account.deposit(-50), what happens to balance?

(b) Fill in the blank: this guarantee is only possible because balance is marked ___, forcing every change through deposit().

(a) The if (amount > 0) check silently rejects the negative amount, leaving balance unchanged. (b) If balance weren't private, outside code could bypass deposit() entirely and assign any value directly.
