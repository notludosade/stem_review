1. Suppose a Car class is defined once. Which statement is correct?

The class is the blueprint, defined once; each instance built from it gets its own independent copy of the data it describes.

2. Every one of these four languages runs a special method automatically the moment new Robot(...) (or its equivalent) executes. Answer both parts:

(a) What is this special method called?

(b) Fill in the blank: in Java and C++, this method is always named after the ___ itself, rather than being called __init__ or constructor().

(a) This special method is the constructor. (b) Python and JavaScript instead give it its own dedicated name, __init__ and constructor().

3. Consider this JavaScript class:

class Cat {
    constructor(name) {
        this.name = name;
    }
}

Answer both parts:

(a) What does this refer to inside the constructor?

(b) Fill in the blank: the equivalent keyword Python uses instead of this is ___.

(a) this is bound to whichever instance the constructor is currently building. (b) Python spells the same idea self; C++ achieves it implicitly, with no keyword needed at all.

4. Why did the C++ Dog example need public: written explicitly before name, while Python, Java, and JavaScript needed nothing similar?

Without public:, name would be inaccessible from outside the class entirely — C++'s default is the opposite of the other three languages.

5. How is a method fundamentally different from the standalone functions covered earlier in this course?

Aside from living inside a class and gaining instance access, a method still works just like an ordinary function otherwise.

6. Fill in the blank: even though every Dog instance shares the same class, each one's name lives in separate ___ scope, invisible to other instances.

This is a new kind of scope, distinct from the local and global scope covered earlier in the course.

7. Given this class:

class Dog {
    String name;
    Dog(String name) { this.name = name; }

    String bark() {
        return name + " says woof!";
    }
}

Dog fido = new Dog("Fido");
Dog bella = new Dog("Bella");

Answer both parts:

(a) What does fido.bark() return?

(b) Fill in the blank: bella.bark() returns "Bella says ___!"

(a) Calling bark() on fido uses fido's own name field, giving Fido says woof! (b) The same bark() method called on bella instead uses bella's separate name, giving Bella says woof! — one method, two independent results.

8. A BankAccount class stores its balance as a private field, only reachable through deposit() and getBalance() methods. What core principle does this illustrate?

Restricting direct access and forcing changes through methods is exactly what lets an object guarantee its own rules can't be bypassed.

9. Answer both parts about enforced vs. conventional privacy:

(a) Which of these class members is genuinely enforced by the language itself, not just a naming convention?

(b) Fill in the blank: in Java and C++, marking a field ___ is enforced by the compiler, so outside code simply cannot reach it.

(a) #fields are a genuinely enforced JavaScript feature; a leading underscore is Python convention only. (b) private is enforced by the compiler in both Java and C++.

10. Given this BankAccount class:

class BankAccount:
    def __init__(self, balance):
        self._balance = balance

    def deposit(self, amount):
        if amount > 0:
            self._balance += amount

Answer both parts:

(a) What happens if code calls account.deposit(50) on an account whose self._balance is currently 100?

(b) Fill in the blank: unlike Java's enforced private keyword, Python's leading underscore is only a convention — nothing in the language actually ___ outside code from directly setting account._balance = -1000000.

(a) 100 + 50 = 150, since the amount > 0 check passes. (b) Python trusts the programmer to respect the underscore; nothing actually stops direct outside access the way Java's private does.
