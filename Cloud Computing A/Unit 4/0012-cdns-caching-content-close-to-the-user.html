CDNs — Caching Content Close to the User

A load balancer solves how traffic is spread across your servers. It does nothing about the fact that a user on the other side of the planet still has to wait for their request to physically travel there and back.

← Lesson 11 Unit 5, Lesson 13 → Contents Glossary →

Data doesn't travel instantly, even on the internet. A request from a user in Tokyo to a server in Virginia has to physically cross an ocean and back before a response arrives — tens to hundreds of milliseconds of pure travel time, no matter how fast the server itself responds. Unit 4 has covered getting requests to your servers efficiently; this closing lesson is about not sending every request that far in the first place.

What a CDN does

Definition A Content Delivery Network (CDN) is a globally distributed network of caching servers — called edge locations (or points of presence) — that store copies of content physically close to users all over the world. The server that holds the actual, authoritative copy of the content is the origin server. When a user requests something, the CDN routes them to whichever edge location is geographically nearest, which serves a cached copy directly if it has one, avoiding the long round trip to the origin entirely.
Definition A cache hit is when the nearby edge location already has a valid copy of the requested content and serves it immediately. A cache miss is when it doesn't (the first request for something new, or a cached copy that's expired) — in that case, the edge location fetches a fresh copy from the origin server once, caches it, and serves it, so every subsequent nearby request becomes a fast cache hit.
Worked example A company's origin server for its website sits in a data center in Virginia. Without a CDN, a user in Tokyo waits through the full round-trip travel time to Virginia and back for every single image, script, and stylesheet on the page. With a CDN, that same user's browser instead talks to a nearby edge location — say, in Tokyo itself — which, after the very first request from any nearby user warms its cache, serves those same files in a fraction of the time, without ever touching the Virginia origin server again until the cached copy expires.
Why CDNs help the origin server too, not just the user A CDN doesn't just make requests faster for users far from the origin — it also shields the origin server itself from most of the traffic. Once content is cached at the edge, the vast majority of requests for it never reach the origin server at all, dramatically reducing the load Unit 4's load balancer and Unit 2's compute fleet have to absorb. This is also a real resilience benefit (Unit 6 covers this more directly): if the origin server briefly goes down, cached content at the edge can often keep serving users completely unaffected in the meantime.
The limit: CDNs love static content, not personalized content CDNs work best for content that's the same for every user and doesn't change often — images, videos, scripts, stylesheets. Content that's personalized per user (a logged-in dashboard showing someone's private data) or that must always be perfectly fresh (a live stock price) generally can't be cached at the edge the same way, and still has to reach the origin server or a database close to it. A real application usually uses a CDN for its static assets while routing dynamic, personalized requests straight through — not one strategy for everything.

Check your recall

No peeking back up — answer from memory first, then check.

1. What problem does a CDN primarily solve?

A CDN reduces the distance data has to physically travel by caching it closer to users.

2. What is the difference between a cache hit and a cache miss?

A hit is served instantly from the edge cache; a miss requires one trip back to the origin before it can be cached and served quickly afterward.

3. Why is a live, constantly-changing stock price a poor fit for CDN caching, unlike a website's logo image?

Content that must stay perfectly current is a poor match for caching, which inherently serves a snapshot from some earlier moment.

4. Fill in the blank: the server holding the actual, authoritative copy of content — as opposed to a cached copy at an edge location — is called the ___.

The origin server is the authoritative source a CDN's edge locations cache copies from.

5. Fill in the blank: a CDN's globally distributed caching servers, positioned physically close to users, are called ___.

Edge locations are what let a CDN serve users from nearby instead of routing every request to a single distant origin.
