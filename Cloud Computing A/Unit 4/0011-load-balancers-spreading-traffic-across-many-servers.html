Load Balancers — Spreading Traffic Across Many Servers

Instead of buying one enormous server, the cloud way to handle more traffic is usually many small, identical servers with something out front deciding which one handles each request.

← Lesson 10 Lesson 12 → Contents Glossary →

Lesson 10's public subnet can hold more than one web server. In fact, running several identical, smaller servers instead of one giant one is usually both cheaper and safer — cheaper because smaller instances are easier to size precisely (Lesson 4), and safer because one server crashing doesn't take the whole application down with it. But that only works if something out front is deciding, for every single incoming request, which of those servers actually handles it.

What a load balancer does

Definition A load balancer is a service that sits in front of a group of servers, receives all incoming traffic, and distributes each request among the servers behind it according to some algorithm — so no single server gets overwhelmed while others sit idle. Clients only ever talk to the load balancer's address; they have no idea, and don't need to know, which specific backend server actually handled their request.
Definition Load balancers also run continuous health checks — small automated pings to each server, checking that it's still responding correctly — and stop routing traffic to any server that fails them, automatically. A crashed server doesn't take the application down; it just quietly stops receiving new requests until it recovers, while the healthy servers keep serving everyone else.

Bars show each server's current active connections, which drain over time as requests "finish." With Round Robin, a slow server still gets an equal share of new requests and backs up. Least Connections routes new requests away from whichever server is already busiest.

Why this matters more with a slow server, not less When every server is equally healthy and fast, round robin's simple "take turns" approach works fine. The moment one server is slower, overloaded, or partially degraded — a real and common situation — round robin keeps sending it an equal share of new traffic anyway, making a bad situation worse. Least connections adapts, favoring whichever server currently has room, which is exactly the kind of self-correcting behavior a production load balancer needs. This is also precisely how a load balancer supports Unit 6's elasticity: as new servers join a growing fleet, the load balancer routes traffic to them automatically, with no manual reconfiguration required.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the core job of a load balancer?

Distributing incoming requests across a group of servers is the load balancer's defining job.

2. What does a load balancer's health check accomplish?

Health checks let the load balancer route around a failing server automatically, without any manual intervention.

3. Why does round robin routing handle a slow server worse than least connections routing does?

Round robin ignores current server load entirely; least connections actively adapts to it.

4. Fill in the blank: a service that sits in front of a group of servers and distributes incoming requests among them is called a ___.

Load balancers are the entry point that spreads traffic across a fleet of servers.

5. Fill in the blank: the routing algorithm that always sends the next request to whichever server currently has the fewest active connections is called ___.

Least connections adapts to real-time server load, unlike round robin's fixed rotation.
