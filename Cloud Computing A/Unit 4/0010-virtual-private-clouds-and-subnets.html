Virtual Private Clouds and Subnets

A VM sitting on a shared physical server (Lesson 4) still needs its own private network — otherwise every customer's traffic would be tangled together on the same wires. This lesson is about how a provider gives every customer their own isolated network, virtually.

← Unit 3, Lesson 9 Lesson 11 → Contents Glossary →

Unit 2's VMs and Unit 3's storage don't do much good in isolation — they need to talk to each other, and usually to the internet. But "just connect everything to everything" is a security nightmare: a database should never be directly reachable from a stranger's browser, even though a web server needs to be. Networking in the cloud starts with drawing boundaries before anything is even wired up.

The virtual private cloud: your own isolated network

Definition A Virtual Private Cloud (VPC) is a logically isolated section of a provider's network, dedicated to one customer, where that customer defines their own private IP address ranges, routing rules, and which resources can talk to which other resources — and to the internet. Even though the underlying physical network hardware is shared across many customers (the same multi-tenancy idea from Lesson 4's hypervisor), a VPC makes it behave, from the inside, like a private network no other customer can see into or reach.

Subnets: dividing a VPC into smaller zones

Definition A subnet is a smaller slice of a VPC's IP address range, used to group resources that should share the same routing and access rules. The most common split is public subnets, which have a route to the internet (through an "internet gateway") and hold resources meant to be reachable from outside, and private subnets, which have no such route and hold resources that should only ever be reached from inside the VPC.
Worked example: a typical three-tier web app A web application's servers sit in a public subnet, with a route to the internet, so users' browsers can reach them. Its database sits in a private subnet with no internet route at all — it can only be reached by the web servers inside the same VPC, over the internal network. Even if an attacker somehow learns the database's internal address, there is no path from the public internet into that private subnet to reach it; the subnet boundary itself blocks the connection before any password or firewall rule is even checked.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a Virtual Private Cloud (VPC)?

A VPC is a software-defined, logically isolated network — not a dedicated physical cable or a VM type.

2. What is the key difference between a public subnet and a private subnet?

The presence or absence of an internet route is the defining, functional difference between the two subnet types.

3. In the three-tier web app example, why can't an attacker reach the database directly from the public internet, even knowing its internal address?

The private subnet's lack of an internet route blocks the connection at the network level, before any credential check happens.

4. Fill in the blank: a logically isolated section of a provider's network, dedicated to one customer's own IP ranges and routing rules, is called a ___.

A VPC gives one customer their own private-feeling network on shared underlying hardware.

5. Fill in the blank: a smaller slice of a VPC's IP address range, grouping resources that share the same routing and access rules, is called a ___.

Subnets divide a VPC into smaller, differently-accessible zones, like public-facing versus internal-only.
