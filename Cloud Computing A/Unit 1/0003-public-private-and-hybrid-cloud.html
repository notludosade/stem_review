Public, Private, and Hybrid Cloud

"The cloud" isn't one thing you either use or don't. It's a spectrum of who owns the hardware and who else is allowed to share it — and the right answer depends on what you're building.

← Lesson 2 Unit 2, Lesson 4 → Contents Glossary →

Lessons 1 and 2 talked about "the cloud" as if it were a single kind of arrangement: rent infrastructure from a provider, share responsibility with them. In practice, organizations choose from a few distinct deployment models, and the biggest variable is one word: shared. This lesson closes out Unit 1 by mapping that spectrum — and setting up the compute, storage, and networking concepts the rest of the course builds on top of it.

Public cloud: the default this course assumes

Definition Public cloud means renting resources from a provider's shared infrastructure, where that same physical hardware simultaneously serves many different customers, isolated from each other by software rather than by separate physical machines. AWS, Azure, and GCP are the three dominant public cloud providers. Unless stated otherwise, every lesson from here on in this course assumes a public cloud context — it's the arrangement Lesson 1's cost and elasticity benefits apply to most fully, because it pools demand across the largest possible number of customers.

Private cloud: cloud-style operations, but not shared

Definition Private cloud means infrastructure dedicated to a single organization — either physically on their own premises, or hosted by a provider on hardware not shared with anyone else — but still run with cloud-style tooling: self-service provisioning, virtualization, and automation, instead of the manual on-prem process from Lesson 1. It captures some cloud convenience without the multi-tenant sharing.
Worked example A hospital network stores patient medical records subject to strict regulatory requirements about exactly where the data physically lives and who can possibly access the underlying hardware. Rather than risk any ambiguity about a shared public data center, it runs a private cloud on hardware it fully controls, using the same kind of self-service tooling public cloud users are used to, so its own IT staff can still spin up new capacity quickly — just never sharing a physical machine with another organization.

Hybrid cloud: using both, on purpose

Definition Hybrid cloud means deliberately splitting a system across both private (or on-prem) and public cloud infrastructure, with the two connected and working together, rather than using one or the other exclusively.
Worked example That same hospital network keeps patient records on its private cloud for regulatory reasons, but runs its public-facing appointment-booking website on public cloud, where it benefits from Lesson 1's elasticity during, say, flu-season demand spikes. The two systems talk to each other over a secured connection. Neither side alone would fit every requirement; together, each workload runs on the deployment model actually suited to it.
Why any organization would give up some public cloud benefits on purpose Public cloud's elasticity and pay-as-you-go pricing are real advantages, but they come with tradeoffs: less physical control, and — depending on the industry — real regulatory constraints on exactly where data can live and who could theoretically access it. Private and hybrid cloud trade away some of that convenience for tighter control, which matters enormously for healthcare, finance, and government workloads, and matters not at all for a typical startup with no such regulatory burden. There is no universally "best" deployment model — only the one that fits a given workload's actual constraints, which is precisely the kind of judgment call Unit 7 comes back to when designing a full architecture.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is the key difference between public cloud and private cloud?

The defining difference is multi-tenancy on shared hardware versus dedicated hardware for one organization — not cost, tooling, or who is allowed to use it.

2. In the hospital network example, why does the organization use hybrid cloud instead of choosing one deployment model for everything?

Hybrid cloud is a deliberate choice to match each workload's constraints to the deployment model that actually fits it, not a cost-saving trick or a technical necessity.

3. Why does this course assume a public cloud context by default from here on?

Public cloud is the default assumption because it's where this course's core cost and elasticity concepts show up most clearly, not because the other models are obsolete.

4. Fill in the blank: deliberately splitting a system across both private/on-prem and public cloud infrastructure, connected and working together, is called ___ cloud.

Hybrid cloud is defined by deliberately using both models together for different parts of one system.

5. Fill in the blank: infrastructure dedicated to a single organization, run with cloud-style self-service tooling but not shared with any other tenant, is called ___ cloud.

Private cloud keeps the cloud-style tooling and automation while dedicating the underlying hardware to one organization.
