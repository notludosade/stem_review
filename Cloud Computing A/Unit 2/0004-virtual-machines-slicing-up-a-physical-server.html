Virtual Machines — Slicing Up a Physical Server

When you "rent a server" from a cloud provider, you almost never get a whole physical machine to yourself. You get a slice of one — and the technology that makes that slicing possible is the foundation of everything else in this unit.

← Unit 1, Lesson 3 Lesson 5 → Contents Glossary →

A single physical server in a cloud provider's data center might have 128 processor cores and half a terabyte of memory — vastly more than almost any one customer needs. Selling that whole machine to one small customer would waste most of its capacity, which contradicts everything Unit 1 said about the cloud's efficiency advantage. The fix is virtualization: carving one big physical machine into many smaller, independent-feeling ones.

What a virtual machine actually is

Definition A virtual machine (VM) is a software-based emulation of a complete computer — its own virtual CPU, memory, disk, and network interface — running on top of a physical machine, alongside other VMs it has no awareness of. From inside a VM, an operating system boots up, runs, and behaves exactly as if it had a real, dedicated computer beneath it, even though it's actually sharing physical hardware with several (sometimes hundreds of) other VMs.
Definition The software layer that makes this possible is the hypervisor: a program that runs directly on the physical hardware and creates, manages, and strictly isolates multiple VMs on top of it. The hypervisor decides how much of the physical CPU, memory, and disk each VM is allowed to use, and — critically — prevents any VM from reading another VM's memory or affecting its performance beyond its allotted share, even though they're running on the exact same physical chip.
Worked example A physical server with 128 cores and 512 GB of memory runs a hypervisor that carves it into eight virtual machines, each allotted 16 cores and 64 GB. Customer A rents one of those VMs to run a database; Customer B, a total stranger to Customer A, rents another VM on that exact same physical machine to run a web server. Neither customer can see, access, or even detect the other's VM — as far as either of them can tell, they each have a dedicated computer.

Instance types: paying for a specific slice

Cloud providers sell VMs (often called "instances") in predefined sizes, each with a fixed amount of virtual CPU (vCPU) and memory, so a customer can pick a slice that fits their workload instead of negotiating a custom carve-up every time.

Why virtualization is the foundation of everything in Unit 1 Virtualization is the specific technology that makes the public cloud's economics work. Because a hypervisor can safely and invisibly share one physical machine across many unrelated customers, a provider can sell precisely-sized slices instead of whole machines — which is what lets a small startup rent 2 vCPUs for a few dollars a month instead of being forced to buy (or rent) an entire server. It's also what makes elasticity possible: spinning up a new VM takes seconds, because the hypervisor is just allocating another slice of hardware that's often already running, not provisioning a brand-new physical machine from scratch.

Check your recall

No peeking back up — answer from memory first, then check.

1. What is a virtual machine?

A VM emulates a whole computer in software, letting a full OS run on it as though it had dedicated hardware.

2. What role does the hypervisor play?

The hypervisor is the layer between physical hardware and the VMs, responsible for allocation and isolation.

3. In the worked example, why can't Customer B see or affect Customer A's VM, even though both run on the same physical machine?

Isolation is the hypervisor's core job — many VMs genuinely do share one physical machine, safely.

4. Fill in the blank: the software layer that runs directly on physical hardware and creates, manages, and isolates multiple virtual machines on top of it is called the ___.

The hypervisor sits between the physical hardware and every VM running on top of it.

5. Fill in the blank: cloud providers commonly refer to a rented virtual machine as an ___, sold in predefined sizes with a fixed amount of vCPU and memory.

"Instance" is the industry-standard term for a provisioned VM, sized by vCPU and memory.
