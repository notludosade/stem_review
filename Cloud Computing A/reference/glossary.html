Unit 1 — Why the Cloud?

On-premises ("on-prem") infrastructure

Infrastructure an organization buys, owns, and physically operates itself — usually racked in a server closet or company-owned data center — responsible for every layer from hardware to patching.

Capacity planning

Estimating future demand and buying enough hardware to meet it without buying so much that most of it sits idle — especially hard on-prem, since hardware has a long lead time and demand is only a guess.

Cloud computing

Renting computing resources — processing power, storage, networking — from a provider's shared data centers over the internet, paying only for what you use, and adjusting usage in minutes instead of months.

CapEx vs. OpEx

Capital expenditure (CapEx) is a large upfront purchase of a long-lived asset, like buying a server outright; operating expenditure (OpEx) is an ongoing, recurring cost tied to actual usage, like a monthly cloud bill.

Shared responsibility model

The framework splitting security and reliability into two buckets: the provider secures "of" the cloud (facilities, hardware, network); the customer secures "in" the cloud (their configuration, code, access, and data).

IaaS / PaaS / SaaS

Infrastructure as a Service rents raw VMs the customer patches themselves; Platform as a Service additionally manages the OS and runtime; Software as a Service is a complete, ready-to-use application — each shifts more of the shared responsibility line onto the provider.

Public cloud

Renting resources from a provider's shared infrastructure, where the same physical hardware simultaneously serves many customers, isolated from each other by software.

Private cloud

Infrastructure dedicated to a single organization — on their own premises or provider-hosted — but still run with cloud-style self-service tooling and virtualization, without sharing hardware with another tenant.

Hybrid cloud

Deliberately splitting one system across both private/on-prem and public cloud infrastructure, connected and working together, so each workload runs on the deployment model that actually fits it.

Unit 2 — Compute

Virtual machine (VM) / instance

A software-based emulation of a complete computer — its own virtual CPU, memory, disk, and network interface — running on shared physical hardware alongside other VMs. Cloud providers call a rented VM an "instance," sold in predefined vCPU/memory sizes.

Hypervisor

The software layer that runs on physical hardware and creates, manages, and strictly isolates multiple virtual machines on top of it.

Container / container engine

A container is an isolated, packaged unit with an application and its dependencies that shares the host machine's OS kernel instead of running its own; a container engine (like Docker) enforces isolation between containers at the process level.

Serverless computing / FaaS

Function as a Service lets a developer upload a function's code, with no server, VM, or container provisioned by the developer — the provider runs it only when a triggering event occurs.

Scale-to-zero

Capacity — and cost — dropping all the way to nothing when there's no work to do, in contrast to a VM or container that keeps running (and billing) at some baseline even at zero traffic.

Cold start

The extra delay a serverless function experiences the first time it runs after being idle, while a fresh execution environment spins up; a "warm" function that was recently invoked skips this delay.

Unit 3 — Storage

Object storage

Stores data as discrete objects (a file plus metadata) in a flat namespace, retrieved and written as whole units through an HTTP-based API — not mounted as a traditional filesystem.

Block storage

Raw storage presented as fixed-size blocks, functioning as a virtual hard disk attached to a single VM at a time, suited to frequent small, low-latency reads and writes.

File storage

A traditional hierarchical filesystem provided over the network, mountable and readable/writable by many VMs concurrently — unlike block storage's single-VM attachment.

Durability

The probability that stored data survives over time without being lost or corrupted, achieved by storing redundant copies across separate hardware.

Availability

The percentage of time a service is actually reachable and responding correctly — a separate guarantee from durability; a service can have near-perfect durability while still being briefly unreachable.

Storage tier

A "hot" or "cold"/"archive" option within the same storage model, trading retrieval speed for cost per gigabyte, without changing the underlying model.

Lifecycle policy

An automated rule, like "move any object untouched for 90 days to the archive tier," that migrates data between storage tiers without manual tracking.

Unit 4 — Networking in the Cloud

Virtual Private Cloud (VPC)

A logically isolated section of a provider's network, dedicated to one customer, where that customer defines private IP ranges, routing, and which resources can talk to which others and to the internet.

Subnet (public / private)

A smaller slice of a VPC's IP range grouping resources with shared routing rules; a public subnet has a route to the internet, a private subnet has none.

Load balancer

A service that sits in front of a group of servers, receives all incoming traffic, and distributes each request among them according to a routing algorithm, so no single server is overwhelmed.

Health check

A load balancer's continuous automated ping to each server, checking it's still responding correctly, so traffic automatically stops routing to a failed server.

Round robin / least connections

Round robin cycles through servers in a fixed rotating order regardless of load; least connections routes each new request to whichever server currently has the fewest active connections.

Content Delivery Network (CDN)

A globally distributed network of caching servers ("edge locations") that store copies of content physically close to users, avoiding a long round trip to a distant origin server.

Origin server / edge location

The origin server holds the actual, authoritative copy of content; edge locations are a CDN's distributed caching servers, positioned close to users.

Cache hit / cache miss

A cache hit is served instantly from an edge location's existing copy; a cache miss requires fetching a fresh copy from the origin first, which is then cached for future hits.

Unit 5 — Managed Services

Managed database (DBaaS)

A database engine the provider installs, patches, backs up, and monitors on the customer's behalf, on infrastructure the customer never directly touches — schema design and queries remain the customer's job.

Message queue

A managed service that temporarily holds messages from a producer until a consumer is ready to process them, decoupling the two so neither needs to be online at the same time or run at the same pace.

Producer / consumer / decoupling

A producer sends messages, a consumer processes them; decoupling means neither needs to know about, or run synchronized with, the other.

Publish/subscribe (pub/sub)

A messaging pattern where every subscriber to a topic receives its own copy of each message — a "fan-out" — unlike a plain queue's one-consumer-per-message delivery.

Identity and Access Management (IAM)

A system for defining identities (human users or non-human services) and permissions, and enforcing which identity can take which action on which resource, on every single request.

Role / policy

A policy is the actual rule set defining allowed or denied actions; a role is a named bundle of policies assigned to an identity, so permissions can be granted by job function instead of one at a time.

Principle of least privilege

Granting every identity only the minimum permissions it actually needs, and nothing more, to limit the blast radius of a mistake or a stolen credential.

Unit 6 — Cost, Scale & Reliability

Elasticity / auto scaling group

Elasticity is a cloud environment's ability to automatically add or remove compute capacity in response to real demand; an auto scaling group is the mechanism — a pool of servers with a minimum, maximum, and scaling policy.

Horizontal vs. vertical scaling

Horizontal scaling (scaling out) adds more servers of the same size; vertical scaling (scaling up) makes one existing server bigger, which has a hard ceiling and usually requires a restart.

Itemized bill

A cloud bill broken down into individual, separately-metered line items for each resource used — compute hours, storage GB-months, database instance hours, and more — instead of one flat number.

Egress / ingress

Egress is data leaving a provider's network, typically billed by the gigabyte; ingress (data coming in) is usually free — an asymmetry that can produce a surprisingly large bill.

Region / Availability Zone (AZ)

A region is a broad geographic area containing multiple availability zones — physically separate data center facilities within it, each with independent power, cooling, and networking.

Redundancy / failover

Redundancy is running more than one independent copy of anything critical; failover is the automatic process of switching from a failed component to a healthy redundant one.

Single point of failure

A single component whose failure alone is capable of taking down an entire system — the thing resilient design is meant to eliminate, since preventing all failure outright isn't realistic at scale.

Unit 7 — Putting It Together

Vendor lock-in

The degree to which switching away from a provider, or one of its services, is difficult or costly, because an application depends on that provider's particular, non-standardized way of doing something.

Multi-cloud

Deliberately spreading workloads across more than one cloud provider on purpose, specifically to avoid depending entirely on any single one, at the cost of added complexity.
